# HtmlToUnity — HTML5 게임을 Unity 로 이관하는 오케스트레이션

이 폴더가 저장소의 본체다. 유니티 프로젝트는 이 오케스트레이션이 실제로 도는지 확인하려고 게임을 이관해 본 결과물이다.

```
HtmlToUnity/
├─ README.md      ← 지금 이 파일
├─ sync.sh        ← .claude/skills/ 와 내용을 맞춘다
└─ skills/        ← 스킬 문서 16종 (SKILL.md + 나머지 15종), 바로 아래 평평하다
```

## 왜 같은 것이 두 곳에 있나

`.claude/` 는 `.gitignore` 에 있고(MCP 설정에 OAuth 비밀값이 들어갈 수 있다), Claude Code 는 스킬을 `.claude/skills/` 에서만 찾는다.

| 어디 | 왜 필요한가 | 커밋 |
|---|---|---|
| `HtmlToUnity/skills/` | 커밋되고 남에게 건네진다. md 가 바로 아래 평평하게 있다 | 예 (여기만) |
| `.claude/skills/htmltounity/` | Claude Code 가 스킬을 찾는 곳. 폴더 이름이 스킬 이름이라 한 겹 더 있다(`sync.sh` 가 만든다) | 아니오 |

**둘을 같이 최신화한다.** 한쪽만 고치면 다음 게임이 낡은 쪽을 읽는다.

```bash
bash HtmlToUnity/sync.sh                 # HtmlToUnity → .claude (기본). 받아 간 뒤 이것만 돌리면 스킬이 인식된다
bash HtmlToUnity/sync.sh --from-claude   # .claude → HtmlToUnity
bash HtmlToUnity/sync.sh --check         # 둘이 같은지 확인 — 작업 끝에 반드시
```

- 원장(`.claude/HtmlToUnity_작업내역_<게임명>.md`)은 사람마다 다른 개인 기록이라 여기 없다.
- 이 스크립트는 커밋하지 않는다. 커밋은 사람이 시킬 때만 한다.

## 받아 가서 쓰는 법

`HtmlToUnity/` 만 받아 `bash HtmlToUnity/sync.sh` 를 돌린다 (위).

## 이 오케스트레이션이 지키려는 것 넷

1. 겉(보이는 것·플레이 감각)이 원본과 같은가를 숫자로 판정한다. 골든 벡터·플로우 diff·요소 단위 대조가 전부 `N/N` 으로 남는다.
2. 속(코드·프리팹·데이터)은 이어서 다듬을 수 있게 짠다. 보이는 조정값은 프리팹 필드에 두고, 빌더는 첫 초안만 굽는다 (PD 「속 품질」 · G8). 새로 착수하는 게임부터 적용한다.
3. 의뢰인에게 유니티 조작을 요구하지 않는다. 전부 러너로 돈다(열린 에디터면 다리, 꺼져 있으면 배치모드).
4. 원본의 이상 거동도 그대로 옮긴다. 고치려면 「의도된 차이」로 등재한다. 등재 없이 고친 것은 결함이다.
