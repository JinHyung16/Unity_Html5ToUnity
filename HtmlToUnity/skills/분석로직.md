# 분석 로직 — 프로젝트 문서 2종을 어떻게 만들고 어떻게 적는가

상위: [PD](PD.md)

프로젝트마다 새로 만드는 것은 셋이다: 확정표(규격은 PD.md)와 이 문서가 규격을 정하는 아래 둘.

| 만들 것 | 어디에 | 누가 | 언제 |
|---|---|---|---|
| `HtmlToUnityLogic/` 골격 전부 | 원본 HTML5 폴더 최상위 아래 | 지식 담당자 4인 | 학습 단계 (PD 「학습 단계」) |
| `HtmlToUnity_작업내역_<게임명>.md` | 오케스트레이션 문서들과 같은 폴더 | PD 가 껍데기 생성, 전원이 채움 | 학습 단계 착수 직후 |

**위 둘이 없으면 실행 단계를 열지 않는다.**
캡처 폴더는 만들지 않는다. 원본 실측은 덤프로 남긴다 (공통절차 「캡처는 쌓지 않는다」).

---

## 왜 미리 만들어 두지 않고 매번 생성하나

빈 템플릿의 안 채운 칸은 「해당 없음」으로 읽힌다. 시스템·화면·리스트업 수도 프로젝트마다 다르다.
그래서 이 문서는 규격과 골격만 두고, 생성할 때 골격을 복사해 그 프로젝트의 항목으로 채운다.

---

## 공통 작성 규칙 — 두 문서 모두에 적용

- 원본 라인을 인용하고 인용할 때마다 grep 으로 재확정한다 (예: `원본.html 2769~3036`). 이유: 라인 번호는 빌드마다 어긋난다 (공통절차 「문서의 라인 번호를 믿지 마라」).
- 확인 못 한 것은 「미확인」, 재지 못한 것은 「미측정(사유)」로 적는다. 미측정은 통과가 아니다.
- 회차마다 덮어쓰지 않는다 (「전 회차: … / 이번 회차:」).
- 문장이 아니라 표로, 분수로 적는다 (예: 「9요소 중 6개 → 67%」).
- ~다 평서체 간결형.

### 표를 먼저 만들고 글을 나중에 쓴다

원본 요소를 빠짐없이 나열한 표를 먼저 만들고 빈 칸을 결함 목록으로 쓴다.
이유: 「배치는 맞는데 알맹이가 빠진」 상태는 산문으로 안 잡힌다.

## `HtmlToUnityLogic/` — 학습 산출물 골격

### 위치와 생성 시점

```
<원본 HTML5 폴더>/
├─ 원본.html
├─ scripts/ …
└─ HtmlToUnityLogic/
    ├─ README.md            ← 목차 + 상태표
    ├─ 00_게임개요.md
    ├─ 01_게임플로우.md
    ├─ 02_시스템_<이름>.md   ← 시스템 수만큼
    ├─ 03_데이터.md
    ├─ 04_UIUX규칙.md
    ├─ 05_연출.md
    ├─ 06_리소스.md
    ├─ 07_기대값.md          ← 정답지의 유일한 자리
    └─ 99_원본지도.md
```

- Assets 밖, 원본 옆에 둔다. 원본과 같이 갱신되고 유니티 임포트에 안 섞인다.
- 학습 단계 착수 직후 골격 전부를 빈 파일로라도 먼저 만든다. 파일이 없으면 「이 게임엔 없다」로 넘어간다.
- `02` 의 개수는 「시스템 축 점검표」가 정한다.

### `README.md` — 목차 겸 상태표

```markdown
# HtmlToUnityLogic — 학습 단계 산출물

원본을 실제로 돌려 보며 파악한 것을 정리한다. 규격은 `분석로직.md` 「HtmlToUnityLogic/」.
이관 담당자는 이 문서들을 근거로 작업한다. 최종 판정은 언제나 원본 코드다.

| 파일 | 담당 | 내용 | 회차 | 상태 |
|---|---|---|---|---|
| `00_게임개요.md` | Design | … | 0 | 미작성 |
| …
```

원본의 기획서·사양서는 ②규약·사양이고 이 문서들은 ①원본 코드 실측 기록이다. 어긋나면 원본 코드가 이긴다.

#### `01_게임플로우.md` — Client

**핵심은 「무엇이 안 열리는가」다.** 원본에 없는 창이 한 겹 더 뜨는 결함은 프리팹 대조로 안 잡힌다 (PD 「플로우 diff 를 프리팹 대조보다 먼저」).

```markdown
## 화면 전이 그래프
(화면 → 화면. 조건과 함께)

## 버튼 전수 — 화면별로 한 표씩
| 화면 | 버튼(셀렉터) | 누르면 열리는 것 | 닫는 방법 | 원본 위치 |

## 겹침 순서 (z-index)
| 창 | z-index | 출처 | 비고(원본 명시 / 파생) |

## 메인 루프
| 항목 | 값 | 원본 위치 |
| dt 상한 | | |
| 정지 게이트 조건 전부 | | |
| 그리기는 계속 도는가 | | |
```

```bash
grep -n "addEventListener\|onclick=\|data-act" 원본.html    # 버튼 전수
grep -n "function setScreen" -A 20 원본.html                 # 화면 전이
grep -n "_loopBody\|requestAnimationFrame" -A 6 원본.html    # 메인 루프
grep -n "z-index" 원본.html                                   # 겹침 순서
```

#### `05_연출.md` — FX (전수표가 본체다)

```markdown
## 그리기 파라미터 전수표
| 위치(라인) | 대상 | lineWidth | shadowBlur | globalAlpha | 합성 모드 | 색 |

## 애니메이션
| 셀렉터 | animation | keyframes | 주기 | 이징 |

## :hover
| 셀렉터 | 무엇이 바뀌나 |

## UI 연출 — 창마다 한 줄 (정지 캡처에 원리적으로 안 찍힌다)
| 창 | 디머(색·α) | 버튼 idle 연출(펄스 식·주기) | 호버(배율·틴트) | 눌림 | 등장/퇴장 트윈 | 근거 |

## 엔티티 레이어 수
| 엔티티 | 원본 fill/stroke/drawImage 호출 수 | 층 구성 |
```

`animation` · `:hover` · UI 연출은 정적 캡처에 안 찍힌다. 코드에서 뽑아 창마다 채운다.
「UI 연출」 표가 비면 이관율 분모에서 그 갈래가 빠진다. 전수 대조표는 「있나」만 세고 「움직이나」는 안 묻는다.
캔버스·엔진 게임이면 CSS 가 아니라 업데이트 루프 안의 배율 식을 찾는다.

```bash
grep -n "lineWidth\|shadowBlur\|globalAlpha\|globalCompositeOperation" 원본.html
grep -no "animation:[^;]*;" 원본.html | sort -u -t: -k3
grep -no "[^{]*:hover{[^}]*}" 원본.html
grep -no "pointerenter\|Math.sin(\|alpha:\.[0-9]\|scale.set(" 번들.js | head   # 엔진 게임의 UI 연출
```

#### `07_기대값.md` — Client (정답지의 유일한 자리)

「입력 → 기대 출력」 표다. 채점기는 이 표를 읽기만 한다.
회차용 채점기는 회차 끝에, 게임별 하네스·회귀 검사는 이관 끝에 지워도 이 표는 남는다 (`Transfer_Programmer.md` 「검증 산출물을 유니티 프로젝트 안에 만들지 않는다」).

| 열 | 적는 것 |
|---|---|
| 입력 | 다시 넣을 수 있는 재현 가능한 형태 |
| 기대 출력 | 원본 실측값 |
| `n` | 잰 횟수. `n=1` 은 표본이다. `-1` 은 소스 직독 |
| 출처 구분 | [소스] · [관측] · [파생] (PD 「근거 등급」). 파생은 정답지가 아니다. [소스]가 오면 [관측]으로 되돌리지 않고 실측치는 확인 근거로 남긴다 |
| 기준점 | 시각·좌표의 원점. 표마다 다르면 섞여도 안 보인다 |
| 판정 허용치 | ±얼마까지 통과인가 |

| 갈래 | 뜻 | 채점 |
|---|---|---|
| 정답지 | 원본이 같은 입력에 같은 답을 낸다 | 센다 |
| 비결정 | 원본 자신이 갈린다 (n≥3 으로 확인) | 빼되 「제외 N건」을 리포트에 찍는다 |
| 미측정 | 아직 안 쟀다 | 빼지 않는다. 남아 있으면 전 검사 통과라도 완료가 아니다 |

주의: 점수를 근거로 정답지를 손대지 않는다. 행을 「비결정」으로 옮기려면 원본을 n≥3 회 다시 재서 갈리는 것을 보인다.

#### `99_원본지도.md` — 전원

공통절차 「실측 지도」의 구간표를 그 프로젝트 것으로 채운다. grep 으로 확정한 값만 적는다.

```markdown
## 라인 지도
| 라인 | 담당 | 내용 |

## id / 클래스 → 실제 화면 대응표
| 원본 id | 실제 화면 | 비고 |

## 모듈 파일
| 파일 | 담당 |
```

주의: 원본 id 가 화면 이름과 반대이거나 무관할 수 있다. 대응표를 반드시 같이 적는다.
실측 심화 기법은 `공통절차.md` 「런타임에서 직접 캐내는 법」.

### 시스템 축 점검표 — 장르를 모른 채 질문으로 시스템을 센다

화면에 보이는 시스템만 세면 기전이 안 보이는 축이 빠진다. **아래 질문에 전부 답한다.**
답은 `[소스]` · `[실측]` · `미측정` 중 하나다. 「해당 없음」도 근거를 적는다. 이 표에 값은 적지 않는다.

| 축 | 질문 | 관측으로 못 가르는 이유 |
|---|---|---|
| 개체 생성 | 시간 · 예산/포인트 · 확률 · 저작 배치 중 무엇? 종류마다 따로 도나? 우선순위는? | 「초당 몇 마리」를 내는 기전이 여럿이다 |
| 난이도의 시간축 | 경과 시간 · 레벨 · 웨이브 · 처치 수 중 무엇? 첫 판 온보딩 감산이 있나? | 레벨과 시간이 같이 오른다 |
| 성장 목표 | 표인가 식인가? | 앞 몇 개는 표로 보인다 |
| 강화 적용 | 두 번 먹으면 덧셈인가 곱셈인가? 상한은? | 한 번으로는 못 가른다. 두 번 먹는다 |
| 후보 풀 | 정의는 몇 개? 조건부 가중치 0 항목이 있나? 비복원 추출인가? | 0 인 항목은 안 보인다. 관측 개수는 하한 |
| 보상 값 | 고정값인가 개체 속성에서 파생되나? | 첫 종류만 보면 고정으로 보인다 |
| 대상 선택 | 유지하나 매번 다시 고르나? 후보는 화면 안인가 전체인가? | 갈리는 순간만 최근접과 다르다 |
| 피격·무적 | 체력은? 무적·쿨다운은? | 마지막 타격은 가린다. 관측 최솟값은 하한 |
| 카메라 | 즉시 · 지수 추적 · 리드 · 데드존 중 무엇? 오프셋은? | 「따라온다」는 다 같아 보인다 |
| 접촉 판정 | 원인가 상자인가? 크기는 그림과 같은가? | 그림 크기로 짜도 맞는 것 같다 |
| 목표·퀘스트 | 한 판을 끝내는 것은 시간 · 목표 수 · 연쇄 과제 중 무엇? 다음 단계는 무엇이 여나? | 끝까지 가야 보인다. 소스가 없으면 미측정 등재 |
| 월드·지형 | 저작인가 절차 생성인가? 시드는? 단위(타일 크기)는? 영역 종류(바닥·풀밭·길)의 문턱과 가장자리 규칙은? | 노드 종류(메시 한 장)로는 틀린다. 버퍼를 열고 문턱 식을 읽는다 |
| 월드 오브젝트 | 지형이 놓는 것(나무·모닥불·상자)과 상호작용(막힘·충전·터짐·회복), 배치 규칙(청크·문턱·개수)은? | 배경 장식으로 보여 전수표에서 빠진다 |
| 끝난 뒤 | 클리어 뒤에도 도는 것(반복 조우 · 무한 모드)이 있나? | 클리어해 봐야 보인다 |

「해당 없음」이 아닌 축마다 `02_시스템_*.md` 한 장이 선다.
G0-b(분해표)에서 `미측정` 인 축은 「학습 부족」 표로 떨어지고 단위 착수 전에 채운다.
사례: 축 여덟 개를 관측으로 지어내 상수는 2% 안에 맞고 기전은 하나도 안 맞았다 (재발방지 #128).

#### 장르별 문서는 두지 않는다 — 같은 장르 두 번째 게임이 올 때 질문만 승격한다

지금 `genres/<장르>.md` 를 만들면 한 게임의 실측치가 장르 사양이 되고, 뼈대가 「입력 형태 × 장르」로 갈라진다.
같은 장르 두 번째 게임이 오면 두 원장에서 공통으로 물은 질문만 `genres/<장르>.md` 로 승격한다.
승격 파일에도 질문만 둔다. 숫자가 있으면 결함이다. 값은 원장에만 둔다.
코드의 「두 번째 게임이 요구할 때 공용으로 승격」과 같은 규칙이다 (`GameFramework.md`).

### URL 제공형이면 — 블랙박스가 아니라 이름이 지워진 코드부터 의심한다

골격의 자리와 이름은 그대로다 (PD 「원본 형태 판정」). 「원본 위치」에 적는 것만 번들 소스 수신 여부로 갈린다.

| 소스 | 「원본 위치」 컬럼 | `99_원본지도.md` |
|---|---|---|
| 받았다 (PD 「번들 소스를 받아 읽는다」) | `[소스] <청크 파일>:<앵커>` — 줄번호 대신 앵커(근처 문자열·관측값) | 소스 지도 |
| 못 받았다 (막힌 근거를 `00_원본정보` 에) | `[실측]` + 재현 방법 (URL · 진입 경로 · 입력 시퀀스 · 캡처 파일명) | 실측 세션 지도 |

**「못 받았다」는 시도한 뒤에만 적는다.** 관측으로 지은 규칙은 값이 맞아도 틀린다 (재발방지 #127 · #128).

```markdown
## 소스 지도 (번들 소스를 받았을 때)
| 청크 파일 (해시 포함) | 들어 있는 것 | 앵커 (검색어) | 복원한 이름 대응 | 회차 |

## 실측 세션 지도
| 회차 | 확인한 것 (화면·거동) | 입력 시퀀스 | 캡처 | 남은 미측정 |

## 화면 요소 소속표 (게임 / 플랫폼)
| 요소 | 소속 | 근거 |
```

- 「모든 수치에 원본 위치 인용」은 `[소스]` 앵커 또는 `[실측]` + 재현 방법으로 충족한다.
- 전수 항목(버튼·행 수·연출)은 소스가 있으면 소스 정의로 센다. 관측 개수는 하한이다 (재발방지 #130).
- 소스가 없으면 관측 범위에 한하고, 못 본 범위가 있다는 사실을 미측정으로 적는다. 합격 기준도 이로 갈린다 (PD 확정표 12).

## `frames/` · `motion/` · `paths.md` — 사건 프레임 덤프 (이미지 대신 게임이 쓴 숫자)

**분석의 정본은 원본이 그 프레임에 들고 있던 값이다.** 씬 그래프(노드 · 좌표 · 배율 · 알파 · 텍스처 · 문구), 후킹 시계열, 버퍼(정점·UV)를 텍스트로 뜬다.
이미지는 마지막 눈 확인 한 장뿐이다. 이유: 인상만 남고 토큰이 5~10배이며 오버레이 아래 색을 자산색으로 오독한다 (재발방지 #142 · #144).

```
<원본폴더>/HtmlToUnityLogic/
├─ frames/                    ← 사건 프레임마다 한 쌍
│   ├─ 012_38210ms_event_레벨 업!.tsv        노드 표 (id parent depth name x y sx sy alpha visible tint frame font text)
│   └─ 012_38210ms_event_레벨 업!.tree.txt   들여쓰기 트리 (보이는 것만 · 첫 줄에 label·시각·직전 상태)
├─ motion/                    ← 시계열 표 (t frame heroX heroY tint alpha enemies gems nearest …)
├─ paths.md                   ← 경로 지도 (아래)
└─ art_measure.tsv            ← 프레임별 크기 · bbox · 앵커 · 팔레트(hex·비율) · 행별 폭 — 픽셀은 뽑지 않는다(복사)
```

| 규칙 | 내용 |
|---|---|
| 사건으로 고른다 | 상태가 바뀐 프레임(창 열림/닫힘 · 피격 · 회복 · 폭발 · 퀘스트 전이)과 고정 시각 몇 개만. 판정 키 「표식 문구 + 틴트 + 개체 존재」가 바뀌는 순간이 사건이다 |
| 형식은 자료 모양대로 | 고정 열 표는 TSV, 계층은 들여쓰기 트리, 들쭉날쭉한 필드만 JSON. XML 은 쓰지 않는다(토큰 2.5배) |
| 좌표는 원본 논리 좌표 | 논리 해상도(확정표 3-d) 기준 전역 좌표·배율(worldTransform). 우리 덤프도 같은 좌표계로 떠서 표 대 표로 diff |
| 경로를 전부 밟는다 | 성공 · 실패 · 중간 이탈 · 분기(광고 수락/거절)마다 플레이해서 뜬다. 봇은 사람의 조작(회피 · 줍기 · 포인터 따라가기)만 한다 |
| 판마다 다른 것을 갈라 적는다 | 자리가 판마다 다른 개체(절차 생성물 · 적 · 드랍 · 떠오르는 문구 · 가장자리 표식)는 크기와 존재만 맞추고 곡선은 motion 으로 본다 |
| 사건이 겹치면 겹친 창은 뺀다 | 한쪽만 모달이 떠 있으면 그 창 아래 노드를 양쪽에서 빼고 비교한다 |
| 한 프레임으로 판단하지 않는다 | 움직이는 것은 프레임마다 다르다. 아래 「두 번 플레이한다」를 따른다 |

씬 그래프가 없는 원본(즉시 모드 캔버스)은 `drawImage`/`fill` 호출 인자를 후킹해 같은 표로 만든다.
코드로 그리는 것(도형 · 파티클 · 셰이더)은 파라미터만 남기고 생김새만 이미지 한 장으로 확인한다.

#### 두 번 플레이한다 — ① 몇 프레임이 필요한지 재고 ② 그만큼 뜬다

| 차례 | 무엇을 하나 | 산출 |
|---|---|---|
| ① 파악 플레이 | 화면마다 움직이는 것과 주기(컷 fps · 맥동 주기 · 채워지는 시간 · 깜빡임 간격)를 뜬다 | 개체별 주기표 |
| ② 분석 플레이 | 주기표에서 계산한 프레임 수로 다시 뜬다 | `frames/` · `motion/` |

**프레임 수는 주기에서 계산한다.**

| 무엇 | 필요한 프레임 |
|---|---|
| 컷이 도는 개체 | 두 바퀴 (한 바퀴 = `컷수 ÷ fps` 초). 한 바퀴만 보면 마지막 컷이 빈 것을 놓친다 |
| 주기 연출 (맥동 · 부유 · 회전) | 한 주기 이상. 최소·최대가 둘 다 나와야 한다 |
| 차오르는 것 (링 · 바 · 페이드) | 다 찰 때까지. 프레임 수가 아니라 「다 찼나」가 종료 조건이다 |
| 상태 깜빡임 (무적) | 간격의 세 배 이상. 켜짐·꺼짐·켜짐이 나와야 한다 |

10 프레임은 밑바닥이지 기준이 아니다.
사례: 이동 컷 다섯 중 마지막이 비었는데 모든 검사가 통과했다. 한 바퀴(0.42초)를 안 봤다 (재발방지 #182).

### `paths.md` — 경로 지도

```markdown
| 경로 | 시작 → 끝 | 사건 순서 (frames/ 번호) | 봇 조작 | 결말 |
| 성공 | 시작 → 과제 완료 | 003 시작 → 012 레벨업 → … → 087 과제 완료 | 포인터 따라가기 · 자동 부활 | 「과제 완료」 창 |
| 실패-거절 | 시작 → 첫 사망 → 「아니요」 | … | 첫 사망에 거절 | (원본이 가는 곳) |
```

빠진 경로의 결말 창·연출은 미측정이고 이관율에서 0건으로 센다.

### `paths.md` — 상태 전수표 (경로 지도와 한 쌍)

「무엇이 아직 안 보였나」를 적는다. 소스의 상태 전환을 grep 해 전수로 적고, 관측으로 세지 않는다.

```markdown
| 상태 | 언제 나오나 | 도달 | 뜬 프레임 |
| 개체 A — 대기 모드   | 최초 배치부터            | 예 | 004 |
| 개체 A — 이동 모드   | 조건 X 를 만족한 뒤       | 예 | 031 |
| 개체 B (무리 N명)    | 퀘스트 단계 3 에서만      | 아니오 | — (미측정) |
```

도달 「아니오」는 없음이 아니라 미측정이다. 이관율에서 0건으로 세고 「재측정 대기」로 올린다.
조건부 상태는 봇이 그 경로를 밟아야 보인다. 도달 설계는 `공통절차.md` 「덤프는 도달한 상태만 준다」가 정본이다.

## 캡처 — 대장도 폴더도 만들지 않는다

정본은 [공통절차 「캡처는 쌓지 않는다」](공통절차.md)다. 캡처는 세션 안의 마지막 눈 확인 한 장이다.
부득이 남기면 화면 · 상태(진행도·재화·선택·탭) · 애니메이션 정지 강제 여부 · 근거(원본 위치)를 같이 적는다. 상태가 없는 그림은 A/B 에 못 쓴다.
판정 순서는 ①원본 코드 → ②규약 문서 → ③덤프이고 그림은 그 뒤다.
그래도 저장소에는 남기지 않고 스크래치패드에 둔다.

### 섹션별 기입 규칙

#### 작업 분해표 — 학습이 끝나면 만든다. 이관은 이 순서대로만 돈다

학습 산출물에서 기계적으로 뽑는다: `02` 한 장 = 한 시스템, `01` 의 화면, `03` 의 테이블 묶음, `05` 의 연출 덩어리, `06` 의 리소스군.
문서에 없는 단위를 만들어야 하면 분석이 덜 된 것이다. 학습으로 돌아간다.

| # | 단위 | 무엇을 만드나 | 근거 문서 | 선행 | 완료 조건 (검사·항수) | 상태 |
|---|---|---|---|---|---|---|

- **완료 조건이 비면 그 단위는 시작하지 않는다.**
- 상태는 `대기` · `진행` · `완료 N/N` 셋뿐이다.
- 순서 규칙(의존 → 최소 경로 → 불확실 → 크기)은 `PD.md` 「순서를 매기는 규칙」이 정본이다.
- 한 단위는 패스 ①②③ + 검사까지 완주하고 다음으로 간다 (`PD.md`).
- 끝난 단위를 다시 열었으면 그 단위의 완료 조건을 고쳐 이 표에 반영한다.

#### 이관율 대조표 — 분모는 확정표 범위 · 의도된 차이 밖의 차이는 결함

「원본에 있는 것 중 몇 개가 우리 화면에 나오나」를 센다. 100% 는 이 표로만 선언한다.

| 규칙 | 내용 |
|---|---|
| 분모 | 확정표 이관 범위(모드·월드·「한 판」)의 원본 요소 전수. 갈래: 화면 · 시스템 축 · 무기/행동 · 진행 체인 · 월드 개체 · HUD · 연출 · UI 연출(펄스·호버·디머·트윈) · 지형 · 아트(재제작이면 「퀄리티 동일」 판정 행). 갈래 하나가 빠지면 0건인 채 100% 가 나온다 |
| 원본 개수 | 소스 정의로 센다. 소스가 없으면 관측 + 「관측 범위」 명시 |
| 의도된 차이 | 다르게 두기로 한 것 전부(재제작 아트 · 사운드 · 플랫폼 요소 · 광고 · 이관 밖 화면). 근거 칸에 확정표 행 또는 판정 절 |
| 증명 | 「화면에 나옴/동작함」을 보인 근거(재생 검사 이름 · 사건 프레임 덤프의 줄 · A/B 개체 수). 비면 분자에 넣지 않는다 |
| 판정 | 이 표에 없는 차이는 전부 미흡이다. 표가 없으면 100% 를 말할 수 없다 (PD 「QA 체크 순서」 9) |

### 「우리에게 있다」로 세지 않는다 — 그 사이에 네 겹의 틈이 있다

「만들었나」로 세면 안 쓰이는 것도 100% 가 된다. 아래 넷이 한 회차에 모든 검사를 통과했다 (재발방지 #159).

| 만든 것 | 빠진 것 | 화면에서는 |
|---|---|---|
| 버튼 컴포넌트를 붙였다 | 포인터를 받게 안 켰다 | 눌러도 반응 없음 |
| 상태별 시트를 구웠다 | 뷰가 한 장만 읽는다 | 상태가 바뀌어도 그림이 같다 |
| 문구를 표에 넣었다 | 읽는 곳이 없다 | 그 UI 가 없다 |
| 형태·색 지표가 만점 | 지표가 그림을 안 잰다 | 다른 그림이다 |

「프리팹에 있다」·「표에 행이 있다」·「파일을 구웠다」는 증명이 아니다.

### 분모를 명사로만 채우지 않는다 — 개체마다 행동이 분모다

**개체가 있나가 아니라 원본처럼 하나를 갈래마다 센다.** 개체를 옮길 때 소스 클래스를 통째로 읽고 둘을 수로 적는다.

| 무엇 | 어떻게 |
|---|---|
| 매 프레임 갈래 | `update()` 분기 이름 전수 (`updateFollow`·`updateAttack`·…). 우리 코드 갈래 수와 같아야 한다 |
| 타이머·상수 필드 | `…IntervalMs`·`…DurationMs`·`…Offset`·`…Multiplier`·`…Radius` 전수. 표에 없는 상수는 이관 안 된 규칙이다 |

갈래가 다섯이면 분모가 다섯이다.
사례: 증명까지 있던 동료 개체가 싸우지 않았다. 원본 갈래 다섯 중 둘만 옮겼다.

### 덤프의 열은 셋 같이 읽는다 — 크기만 보면 두 모드가 같아 보인다

덤프 한 줄의 `frame`(원본 컷 크기) · `sx/sy`(배율) · `w/h`(그려진 크기) 관계가 그리는 방식이다.

| 관계 | 뜻 | 엔진에서 |
|---|---|---|
| `w == frame × sx` | 정수배 확대. 테두리도 굵어진다 | 스프라이트 + 배율 |
| `w != frame × sx` | 9슬라이스. 모서리는 그대로, 가운데만 늘어난다 | 슬라이스 + 인셋 |

주의: `w/h` 만 보면 구별이 안 된다. 확대를 9슬라이스로 만들면 테두리가 실오라기가 된다.

### 덤프에 원리적으로 없는 것이 있다 — 그건 소스에 있다

덤프는 속성만 뜨고 생성자 인자는 안 나온다.

| 덤프에 없는 것 | 어디 있나 | 안 캐면 |
|---|---|---|
| 9슬라이스 인셋 | `NineSlicePlane({leftWidth: …})` | 테두리 두께가 다르다 |
| 자리마다 다른 인셋 | 호출부마다 | 카드와 버튼이 같아진다 |
| 9슬라이스가 아닌 것 | 생성자 호출이 없다 | 안 늘어날 것을 늘린다 |
| 값의 식 | `updateLayout()` 류 | 화면비가 바뀌면 어긋난다 |

**빈칸을 공식으로도 그림 실측으로도 메우지 않는다.** 못 캤으면 못 캤다고 적는다.
사례: 임포터가 인셋을 `min(폭,높이)/3` 으로 지어냈고 한 곳(6×6→2)이 우연히 맞았다 (재발방지 #161). 모서리 곡률 휴리스틱은 안티에일리어싱에서 무너진다 (재발방지 #170).
캐는 법: 생성자 이름으로 전수로 훑고 호출부 문맥을 같이 꺼낸다. 같은 텍스처의 다른 인셋(일반 버튼 15 / 카드 10)이 갈린다. 목록에 없는 텍스처는 9슬라이스가 아니다.

### 골든의 분모는 결과물이다 — 「식이 맞다」는 「그림이 맞다」가 아니다

절차가 있는 것(여러 패스 · 캐시 제자리 수정 · 좌표 변환)은 중간값이 맞아도 결과가 갈린다.
사례: 지형 골든 19/19 통과인데 화면이 달랐다. `f(x,y)` 값만 쟀다.

| 골든 밖에 있던 것 | 값으로 안 잡히는 이유 |
|---|---|
| 좌표계 (엔진 y 위 ↔ 원본 y 아래) | 넣는 좌표가 뒤집혔다 |
| 패스 전파 (캐시를 제자리에서 고친다) | 이웃을 읽는 시점이 다르다 |
| 인덱스 범위 (원본은 안 자른다) | 가장자리가 다르다 |

**결과물을 골든으로 만든다.** 지형이면 타일 격자를 창 한 판 전 칸 대조하고, 타일 종류가 거의 다 나오는 창을 고른다.
검사는 통과했는데 그림이 다르면 검사의 분모를 의심한다.

### 세는 검사는 개수를 못 박는다

「0개 실패」는 분모가 0 이어도 통과한다.

- 최소 개수를 못 박는다 (`Check(n >= 최소)`).
- 지금 화면이 아니라 만들어 둔 것 전부(프리팹·표)를 센다. 모달·풀은 게으르게 만들어져 화면에 없다.
- 화면을 봐야 하면 창들이 다 붙어 가라앉기를 기다린다.

#### 리스트업

| 규칙 | 내용 |
|---|---|
| 항목 단위 | 화면·시스템 단위로 자른다. 덩어리는 달성률이 안 움직인다 |
| 완료 정의 | 분모가 있는 문장 (예: 「9요소 중 6개 이식」·「정답지 230행 중 통과 수」·「팝업 9곳」) |
| 달성률 | 완료 정의에서 역산한다. 분모를 못 적으면 전수 대조표(UIUX 「화면 하나를 전수 대조표로 연다」)부터 만든다 |
| 회차 | 손댄 횟수. 3회차인데 60% 면 접근이 틀렸다 (PD 「회차 카운터를 원장에 남긴다」) |
| 100% | PD QA 통과 후에만 붙인다 |
| 미측정 | 0% 로 계산한다 |

#### 학습 내용

- 한 줄에 한 사실. 근거 열이 빈 줄은 적지 않는다.
- 이전 줄을 지우지 않는다. 새 줄에 「전 회차 정정」이라 적는다.

#### 오염된 내용 — 갈래를 반드시 적는다

| 갈래 | 무엇 |
|---|---|
| 캡처를 사양으로 삼음 | 픽셀로 읽은 것을 사양으로 적었다 |
| 문서·라인 번호를 믿음 | 인용 라인이 현재 빌드와 어긋났다 |
| 애니메이션 프레임을 정색으로 오인 | 점멸·페이드 중 한 프레임을 정색으로 봤다 |
| 이름이 비슷해 다른 물건을 가져옴 | 그럴듯한 이름의 다른 용도 것을 썼다 |
| 추측을 결론으로 적음 | 「대략」이 다음 회차에 원본 수치로 인용됐다 |

고치기 전에 먼저 적는다. 조용히 고치면 재발한다.

#### 패스 ①②③ 수행 내용

- 한 항목을 끝낼 때마다 적는다.
- 판정 열에 분모 있는 숫자를 적는다 (예: 「팝업 9/9」·「정답지 120/230」·「A/B 개체 수 통과」).
- 미착수는 회차를 `—` 로 두고 남긴다.
- 패스 ③은 배선 대상 6종(UI · 게임 플로우 · 연출 파라미터 · 게임오브젝트 · 데이터 종속 아트 · 지연 로드 아트) 중 무엇인지 적는다 (PD 「패스 ③이 하는 일」).

#### 회고록 — 세 칸이 다 차야 끝난다

```
무엇을 놓쳤나 | 왜 안 보였나 | 무엇으로 막나
```

세 번째 칸은 도구(예: 양방향 에셋 감사기) · 체크리스트(담당자 md 완료 체크리스트에 한 줄) · 게이트(플로우 diff 를 프리팹 대조보다 먼저) 중 하나로 끝난다. 「주의하겠다」는 대책이 아니다.

#### 재측정 대기 — 미측정을 통과로 넘기지 않는 장치

1. 판정 칸에 숫자를 못 넣으면 `미측정(사유)` 로 적는다. 빈칸·「됨」·「확인함」은 쓰지 않는다.
2. 사유를 3갈래 중 하나로 적는다.
3. 달성률에 0% 로 계산한다.
4. 즉시 재측정 대기 표에 한 줄 올리고, 다음 회차에 신규 작업보다 먼저 처리한다. 실측값이 오면 표에서 지우고 패스 표 판정을 숫자로 덮는다.

| 갈래 | 무엇 | 해소하려면 |
|---|---|---|
| ① 도구 없음 | 브라우저·Unity 제어·이미지 비교 등이 없다 | 사람에게 도구 또는 대체 자료(캡처·로그·DOM 덤프) 요청 |
| ② 상태를 못 맞춤 | 진행도·재화·선택 상태가 다르다 | 치트/디버그 명령을 이식해 한 줄로 같은 상태를 만든다 (공통절차 「A/B 측정」) |
| ③ 하네스 없음 | 채점기·프리뷰·감사기가 없다 | 하네스 제작을 리스트업에 올린다 (PD 「재는 도구를 먼저 만든다」) |

PD 는 QA(PD 「QA 체크 순서」 8번)에서 이 표를 미흡 목록에 자동 편입한다. 대기 회차 규칙은 아래 「갱신 시점」.

#### PD QA 미흡 목록

- 무엇이 · 어디가 · 기대 · 실측 네 칸으로 적는다. 「어색하다」는 QA 결과가 아니다.
- 이 목록이 다음 회차 리스트업이 된다. 해당 항목 달성률을 내리고 회차를 +1 한다.

### 갱신 시점

| 시점 | 누가 | 무엇을 |
|---|---|---|
| 착수 전 | 전원 | 이번 회차 범위를 리스트업에 먼저 적는다 |
| 학습 중 | 지식 담당자 | 학습 내용 · 오염된 내용 |
| 한 항목 완료마다 | 이관 담당자 | 해당 패스 수행 내용 |
| 패스 ③ 완료 | Transfer_Programmer | 회고록 · 회차 +1 |
| 미측정 발생 즉시 | 담당자 | 재측정 대기 표에 한 줄 |
| QA 후 | PD | 미흡 목록 · 달성률 조정 · 재측정 대기 편입 |
| 회차 시작 | PD | 대기 회차 +1. 3 이상이면 사람에게 도구·데이터를 직접 요청 |

### 닫힌 회차는 원장에서 뺀다 — 원장은 아카이브가 아니다

원장은 다음 회차가 판단에 쓰는 문서다. 닫힌 것은 지우지 않고 옮긴다.

| 판정 | 기준 |
|---|---|
| 언제 빼나 | 닫힌 기록이 원장 줄 수의 절반을 넘는 회차 |
| 어디로 | 같은 폴더 `HtmlToUnity_작업내역_아카이브.md`. 계속 늘면 회차별 파일로 |
| 원장에 남기는 것 | 한 줄 요약 + 아카이브 링크 |
| 헤딩 | 옮길 때 레벨을 다시 잡는다 (`##`·`###` 가 섞이면 목차가 무너진다) |

닫혀도 원장에 남긴다: 오염된 내용 · 회고록 · 재측정 대기 · 대조해서 문제 없었던 곳.
「대조해서 문제 없었던 곳」은 근거(원본 위치·실측값)가 없는 줄은 남기지 않는다.

## 안티패턴 — 이렇게 적으면 그 문서는 다음 회차에 쓸모가 없다

위 규칙을 어긴 것(분수 대신 「거의 다」 · 근거 없는 수치 · 덮어쓰기 · 오염 조용히 수정 · 산문 요약 · 「주의하겠다」 · 담당자 100% 선언 · 못 잰 것을 「됨」 · 덩어리 항목 · 원장이 아카이브 겸함 · PNG 쌓기)은 모두 안티패턴이다. 그 밖에:

| 안티패턴 | 왜 나쁜가 | 대신 |
|---|---|---|
| 역할을 바꾸고 기억으로 이어감 | 「우리 코드가 심판」으로 뒤집힌다 | 이전 역할 결론은 md 에 적힌 것만 인정 (PD 「역할 기동 규약」) |
| 본문에 「(추정)」 | 괄호는 안 읽히고 사실로 인용된다 | 추정은 재측정 대기에, 본문은 등급 붙은 것만 (PD 「근거 등급」) |
