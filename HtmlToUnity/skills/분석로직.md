# 분석 로직 — 프로젝트 문서 2종을 **어떻게 만들고 어떻게 적는가**

상위: [PD](PD.md) (PD)

**이 오케스트레이션 문서들은 프로젝트가 바뀌어도 그대로 쓴다.**
프로젝트마다 새로 만드는 것은 **셋**이다 — 확정표(PD 소관 · 규격은 PD.md)와, **이 문서가 규격을 정하는 둘**(원장 · HtmlToUnityLogic/ 골격 전부).

| 만들 것 | 어디에 | 누가 | 언제 |
|---|---|---|---|
| **`HtmlToUnityLogic/` 골격 전부** | 원본 HTML5 폴더 최상위 아래 | 지식 담당자 4인 | 학습 단계 (PD 「학습 단계」) |
| **`HtmlToUnity_작업내역.md`** | 오케스트레이션 문서들과 같은 폴더 | PD 가 껍데기 생성 → 전원이 채운다 | 학습 단계 착수 직후 |

**위 둘이 없는 상태에서 실행 단계를 열지 않는다.**

⚠ **캡처 폴더는 만들 것 목록에 없다** — 원본 실측으로 남기는 것은 **덤프**다
(공통절차 「캡처는 쌓지 않는다」).

---

## 왜 미리 만들어 두지 않고 매번 생성하나

빈 템플릿 파일을 들고 다니면 **채우지 않은 칸이 「해당 없음」으로 읽힌다.**
프로젝트마다 시스템 수도, 화면 수도, 리스트업 항목도 다르다 —
**규격만 들고 다니고 실물은 그 프로젝트를 보고 만든다.**

그래서 이 문서에는 「무엇을 적는가」와 함께 **골격(스켈레톤)** 이 그대로 들어 있다.
생성할 때는 골격을 복사하고 **항목을 그 프로젝트의 것으로 채운다.**

---

## 공통 작성 규칙 — 두 문서 모두에 적용

| 규칙 | 이유 |
|---|---|
| **원본 라인을 인용한다** (**[예시]** `원본.html 2769~3036` — 인용할 때 grep 으로 재확정) | 기억으로 쓰면 다음 회차에 검증이 불가능하다 |
| **라인 번호는 인용할 때마다 grep 으로 재확정한다** | 문서·기억의 라인 번호는 빌드마다 어긋난다 (공통절차 「문서의 라인 번호를 믿지 마라」) |
| **확인 못 한 것은 「미확인」이라고 적는다** | 추측이 다음 회차에 원본 수치처럼 인용되면 그게 오염이다 |
| **재지 못한 것은 「미측정(사유)」이라고 적는다** | **미측정 ≠ 통과.** 빈칸이나 「됨」으로 두면 그 자리는 영원히 안 채워진다 |
| **회차마다 덮어쓰지 않는다** | 「전 회차: … / 이번 회차:」. 무엇이 바뀌었는지가 정보다 |
| **문장이 아니라 표로 적는다** | 빈 칸이 그대로 결함 목록이 된다. 산문은 빠진 것을 숨긴다 |
| **숫자로 적는다** | 「거의 됐다」가 아니라 **[예시]** 「9요소 중 6개 → 67%」 같은 분수 |
| ~다 평서체 간결형 | — |

### 표를 먼저 만들고 글을 나중에 쓴다

**「배치는 맞는데 알맹이가 빠진」 상태는 산문으로는 절대 안 잡힌다.**
원본 요소를 빠짐없이 나열한 표를 먼저 만들고, 표의 빈 칸을 결함 목록으로 쓴다.

## `HtmlToUnityLogic/` — 학습 산출물 골격

### 위치와 생성 시점

```
<원본 HTML5 폴더>/
├─ 원본.html
├─ scripts/ …
└─ HtmlToUnityLogic/        ← 여기
    ├─ README.md            ← 목차 + 상태표 (「README.md」)
    ├─ 00_게임개요.md
    ├─ 01_게임플로우.md
    ├─ 02_시스템_<이름>.md   ← 시스템 수만큼
    ├─ 03_데이터.md
    ├─ 04_UIUX규칙.md
    ├─ 05_연출.md
    ├─ 06_리소스.md
    ├─ 07_기대값.md          ← **정답지(정답지)의 유일한 자리**
    └─ 99_원본지도.md
```

- **Assets 안이 아니다.** 원본 옆에 두어야 원본과 같이 갱신되고 유니티 임포트에 안 섞인다.
- 생성 시점은 **학습 단계 착수 직후**. 빈 파일이라도 **골격 전부**를 먼저 만들고 채운다 (`02` 는 시스템 수만큼 — 「시스템 축 점검표」가 개수를 정한다) —
  파일이 없으면 「그 항목이 이 게임엔 없나 보다」로 넘어간다.

### `README.md` — 목차 겸 상태표

```markdown
# HtmlToUnityLogic — 학습 단계 산출물

원본을 **실제로 돌려 보며** 파악한 것을 정리한다. 규격은 `분석로직.md` 「HtmlToUnityLogic/」.
이관 담당자는 이 문서들을 근거로 작업한다.
단, **최종 판정은 언제나 원본 코드다** — 여기 적힌 요약을 최종 근거로 쓰지 않는다.

| 파일 | 담당 | 내용 | 회차 | 상태 |
|---|---|---|---|---|
| `00_게임개요.md` | Design | … | 0 | 미작성 |
| …
```

원본에 기획서·사양서가 따로 있으면 그건 **②규약·사양**이고, 여기 문서는
**①원본 코드를 직접 훑어 만든 실측 기록**이다. **둘이 어긋나면 원본 코드가 이긴다.**

#### `01_게임플로우.md` — Client

**이 문서의 핵심은 「무엇이 열리는가」가 아니라 「무엇이 안 열리는가」다.**
원본에 없는 창이 한 겹 더 뜨는 결함은 프리팹 대조로 절대 안 잡힌다 (PD 「플로우 diff 를 프리팹 대조보다 먼저」).

```markdown
## 화면 전이 그래프
(화면 → 화면. 조건과 함께)

## 버튼 전수 — 화면별로 한 표씩
| 화면 | 버튼(셀렉터) | 누르면 열리는 것 | 닫는 방법 | 원본 위치 |

## 겹침 순서 (z-index)
| 창 | z-index | 출처 | 비고(원본 명시 / 파생) |

## 메인 루프
| 항목 | 값 | 원본 위치 |
| dt 상한 | | |
| **정지 게이트 조건 전부** | | |
| 그리기는 계속 도는가 | | |
```

```bash
grep -n "addEventListener\|onclick=\|data-act" 원본.html    # 버튼 전수
grep -n "function setScreen" -A 20 원본.html                 # 화면 전이
grep -n "_loopBody\|requestAnimationFrame" -A 6 원본.html    # 메인 루프
grep -n "z-index" 원본.html                                   # 겹침 순서
```

⚠ **「UI 연출」 표가 비면 이관율 분모에서 그 갈래가 통째로 빠진다** — 요소 전수 대조표는 «있나»만 세고
«움직이나»는 안 묻는다. 소스가 있으면 `pointerenter` · `Math.sin(` · `alpha:` · `scale.set(` 을 grep 해 창마다 채운다.
캔버스·엔진 게임이면 CSS 가 아니라 **업데이트 루프 안의 배율 식**을 찾는다.

```bash
grep -n "lineWidth\|shadowBlur\|globalAlpha\|globalCompositeOperation" 원본.html
grep -no "animation:[^;]*;" 원본.html | sort -u -t: -k3
grep -no "[^{]*:hover{[^}]*}" 원본.html
grep -no "pointerenter\|Math.sin(\|alpha:\.[0-9]\|scale.set(" 번들.js | head   # 엔진 게임의 UI 연출은 여기 있다
```

**정적 캡처에는 `animation` 과 `:hover` 가 안 찍힌다.** 코드에서 뽑지 않으면 존재 자체를 모른다.

#### `07_기대값.md` — Client (**정답지의 유일한 자리**)

**「입력 → 기대 출력」 표.** 유니티 쪽 채점기는 **이 표를 읽어 주는 일회용**이고,
이관이 끝나면 채점기는 지우지만 **이 표는 남는다** (「검증 산출물 규칙」).
그래서 이 문서가 비면 **그 계통은 한 번도 수치로 판정되지 않은 채** 회차만 쌓인다.

| 열 | 반드시 |
|---|---|
| **입력** | 재현 가능한 형태로 — 같은 입력을 다시 넣을 수 있어야 한다 |
| **기대 출력** | 원본에서 **실측한 값** |
| **`n`** | 몇 회 재서 얻은 값인가. **`n=1` 은 「값」이 아니라 「표본」이다.** **`-1` 은 소스 직독**(재지 않고 읽었다) |
| **출처 구분** | **[소스]** · **[관측]** · **[파생]** (PD 「근거 등급」). 파생은 「우리 모델이 낸 값」이라 정답지가 아니다. **[소스]가 오면 [관측]을 되돌리지 않는다** — 정본은 소스, 실측치는 「식이 맞는지 확인한 근거」로 남긴다 |
| **기준점** | 시각·좌표의 **원점을 명시**한다. 표마다 기준이 다르면 **섞여도 안 보인다** |
| **판정 허용치** | ±얼마까지 통과인가. 없으면 채점기마다 다르게 잰다 |

**세 갈래를 «표에서» 가른다** — 섞이면 점수의 의미가 사라진다.

| 갈래 | 뜻 | 채점 |
|---|---|---|
| **정답지** | 원본이 같은 입력에 같은 답을 낸다 | 센다 |
| **비결정** | **원본 자신이 갈린다** (n≥3 으로 확인) | **빼되 「제외 N건」을 리포트에 찍는다** |
| **미측정** | 아직 안 쟀다 | **빼지 않는다** — 완료 판정을 막는 항목이다 |

⚠ **「미측정」 칸이 남아 있으면 전 검사 통과라도 이른 것이다.** 검사가 다 통과해도
«아직 안 잰 것»이 있으면 커버리지를 모르는 것이다.

⚠ **점수를 근거로 정답지를 손대지 않는다.** 안 맞는 행을 「비결정」으로 옮기는 것은
**측정이 아니라 조작**이다 — 옮기려면 **원본을 n≥3 회 다시 재서** 갈리는 것을 보여야 한다.

#### `99_원본지도.md` — 전원

공통절차 「실측 지도」 의 구간표를 그 프로젝트의 것으로 채운다.
**grep 으로 확정한 값만 적는다.**

```markdown
## 라인 지도
| 라인 | 담당 | 내용 |

## id / 클래스 → 실제 화면 대응표
| 원본 id | 실제 화면 | 비고 |

## 모듈 파일
| 파일 | 담당 |
```

> ⚠ **원본의 id 가 화면 이름과 반대이거나 무관할 수 있다.** 대응표를 반드시 같이 적는다 —
> 여기서 회차마다 헷갈린다.

> 실측 심화 기법은 **`공통절차.md` 「런타임에서 직접 캐내는 법」**.

### ★★ 시스템 축 점검표 — **장르를 모른 채 «질문»으로 시스템을 센다**

`02_시스템_<이름>.md` 를 몇 장 만들지는 원본을 보고 정한다. 그런데 **화면으로 보이는 시스템만 세면
반드시 빠진다** — 결과만 보이고 기전은 안 보이는 축이 있기 때문이다. 아래 질문에 **전부** 답한다.
답은 `[소스]` · `[실측]` · **`미측정`** 셋 중 하나다. 「해당 없음」도 근거를 적는다.

⚠ **여기에 값은 없다. 질문만 있다.** 값이 적히는 순간 이 표는 지난 게임의 사양이 된다.

| 축 | 질문 | 왜 관측으로는 못 가르나 |
|---|---|---|
| **개체 생성** | 무엇이 개체를 만드나 — **시간**인가 · **예산/포인트**인가 · **확률**인가 · **저작 배치**인가? 종류마다 따로 도나? 우선순위가 있나? | 「초당 몇 마리」는 결과다. 같은 결과를 내는 기전이 여럿이다 |
| **난이도의 시간축** | 무엇이 어렵게 하나 — 경과 시간 · 레벨 · 웨이브 · 처치 수? **첫 판에만** 적용되는 온보딩 감산이 있나? | 레벨과 시간이 같이 오르면 어느 쪽이 원인인지 화면으로 못 가른다 |
| **성장 목표** | 다음 목표는 **표**인가 **식**인가? | 앞 몇 개는 표로 보인다. 식이면 「N레벨 이후 미측정」이 원리적으로 사라진다 |
| **강화 적용** | 같은 강화를 두 번 먹으면 **덧셈**인가 **곱셈**인가? 상한이 있나? | 한 번 먹어서는 구분이 안 된다 — **두 번 먹어서** 가른다 |
| **후보 풀** | 선택지 풀의 정의는 몇 개인가? **조건부로 가중치 0** 이 되는 항목이 있나? 비복원 추출인가? | 0 인 항목은 영원히 안 보인다. 관측 개수는 하한이다 |
| **보상 값** | 경험치·재화가 **고정값**인가 **개체 속성에서 파생**되나? | 첫 종류의 값만 보면 고정으로 보인다 |
| **대상 선택** | 대상을 **유지**하나 매번 **다시 고르나**? 후보 범위는 화면 안인가 전체인가? | 대개 최근접과 같은 결과가 나온다 — 갈리는 순간만 다르다 |
| **피격·무적** | 체력은 몇인가, 무적·쿨다운이 있나? **관측한 최솟값은 하한**이지 값이 아니다 | 마지막 타격이 사망 화면에 가리고, 무적은 간격의 하한으로만 보인다 |
| **카메라** | 대상을 **어떻게** 따라가나 — 즉시 · 지수 추적 · 리드 · 데드존? 오프셋이 있나? | 「따라온다」는 전부 같아 보인다 |
| **접촉 판정** | 원인가 상자인가? 크기는 그림과 같은가 별도 값인가? | 그림 크기로 짜면 «맞는 것 같은» 판정이 된다 |
| **목표·퀘스트** | 한 판을 끝내는 것은 무엇인가 — 시간 · 목표 수 · **연쇄 과제**? 다음 단계는 무엇이 여나? | 끝까지 살아서 가 보기 전엔 안 보인다 — 소스가 없으면 **미측정으로 등재**한다 |
| **월드·지형** | 저작인가 **절차 생성**인가? 시드가 있나? 단위(타일 크기 = 거리 단위)는? 영역 «종류»(바닥·풀밭·길)의 문턱과 가장자리 규칙은? | 노드 종류(메시 한 장)만 보고 판정하면 틀린다 — **버퍼를 연다**. 영역의 «뜻»은 색으로 못 가른다 — 문턱 식을 읽는다 |
| **월드 오브젝트** | 지형이 놓는 것(나무·모닥불·상자)이 있나? **상호작용**(막힘 · 충전 · 터짐 · 회복)이 있나? 배치 규칙(청크 · 문턱 · 개수)은? | 배경 장식으로 보인다. 첫 화면에 «찍혀 있는데» 전수표에서 빠진다 |
| **끝난 뒤** | 클리어 뒤에도 도는 것이 있나(반복 조우 · 무한 모드)? | 클리어를 한 번은 해 봐야 보인다 |

이 표의 답이 곧 `02_시스템_*.md` 의 목록이다 — **「해당 없음」이 아닌 축마다 문서 한 장**이 선다.
G0-b(분해표)에서 답이 `미측정` 인 축은 **「학습 부족」 표**로 떨어지고 단위 착수 전에 채운다.

> **[사고]** 한 프로젝트가 위 표의 축 여덟 개를 **전부 관측으로 지어냈다** — 상수는 2% 안에 맞았는데
> 기전은 하나도 안 맞았다(재발방지 `#128`). 9회차에 소스를 받고서야 물은 질문이 정확히 이 표다.

#### 장르별 문서는 두지 않는다 — **같은 장르 두 번째 게임이 올 때 «질문만» 승격한다**

장르 폴더(`genres/<장르>.md`)를 지금 만들면 **한 게임의 실측치가 장르의 사양으로** 적힌다 —
이 세트가 가장 크게 앓은 오염의 재발 경로다. 게다가 장르 분류는 샌다(서바이버 + 트윈스틱 + 퀘스트).
뼈대가 「입력 형태 × 장르」 2차원이 되어 트렁크 문서마다 분기가 생기는 것은 문서 세트가 죽는 방식이다.

| 지금 | 나중 |
|---|---|
| 위 점검표 하나 — 장르를 모른 채 묻는 질문 | **같은 장르 두 번째 게임**이 오면 두 원장에서 «공통으로 물었던 질문»만 뽑아 `genres/<장르>.md` 로 승격 |
| 값은 원장에만 | 승격 파일에도 **질문만 · 숫자 금지** — 숫자가 보이면 그 파일이 결함이다 |

한 게임만 보고 만든 장르 문서는 **그 게임의 사본**이다. 두 개를 보고 만들어야 «장르»가 된다
(코드의 「두 번째 게임이 요구할 때 공용으로 승격」과 같은 규칙이다 — `GameFramework.md`).

### URL 제공형이면 — **«블랙박스»가 아니라 «이름이 지워진 코드»부터 의심한다**

골격의 **자리와 이름은 그대로다** (PD 「원본 형태 판정」 — 트렁크는 입력 형태를 모른다).
바뀌는 것은 「원본 위치」 컬럼에 **무엇을 적을 수 있느냐**뿐이고, 그것은 **번들 소스를 받았느냐**로 갈린다.

| 소스 | 「원본 위치」 컬럼 | `99_원본지도.md` |
|---|---|---|
| **번들 소스를 받았다** (PD 「번들 소스를 받아 읽는다」) | **`[소스] <청크 파일>:<앵커>`** — 줄번호는 난독화 한 줄이라 쓸모없다. **앵커**(근처의 문자열·관측값)로 적는다 | **소스 지도** — 청크 파일마다 «무엇이 들어 있나»와 앵커, 복원한 이름 대응 |
| **못 받았다** (막힌 근거를 `00_원본정보` 에 적는다) | **`[실측]` + 재현 방법** — URL · 진입 경로 · 입력 시퀀스 · 캡처 파일명 | **실측 세션 지도** (아래) |

⚠ **「못 받았다」는 시도한 뒤에만 적는다.** 시도하지 않고 실측으로 시작하면 «관측으로 규칙을 짓게» 되고,
그 규칙은 값이 맞아도 틀린다 (재발방지 `#127` · `#128`).

```markdown
## 소스 지도 (번들 소스를 받았을 때)
| 청크 파일 (해시 포함) | 들어 있는 것 | 앵커 (검색어) | 복원한 이름 대응 | 회차 |

## 실측 세션 지도
| 회차 | 확인한 것 (화면·거동) | 입력 시퀀스 | 캡처 | 남은 미측정 |

## 화면 요소 소속표 (게임 / 플랫폼)
| 요소 | 소속 | 근거 |
```

완료 판정의 「모든 수치에 원본 위치 인용」은 **`[소스]` 앵커 또는 「`[실측]` + 재현 방법」**으로 읽는다.
**전수 판정 항목(버튼 전수·테이블 행 수·연출 전수)은 소스가 있으면 «소스의 정의»로 센다** —
관측으로 센 개수는 **하한**이다 (재발방지 `#130`). 소스가 없으면 «관측한 범위»에 한하고,
관측 못 한 범위가 있으면 **그 사실 자체를 미측정으로 적는다.** 그래서 합격 기준도 소스 유무로 갈린다
(PD 확정표 12).

## ★★★ `frames/` · `motion/` · `paths.md` — **사건 프레임 덤프** (이미지 대신 «게임이 쓴 숫자»)

**분석의 정본은 스크린샷이 아니라 «원본이 그 프레임에 실제로 들고 있던 값»이다.** 씬 그래프(노드 · 좌표 · 배율 · 알파 · 텍스처 · 문구),
후킹 시계열, 버퍼(정점·UV)를 텍스트로 뜬다. 이미지는 **마지막 눈 확인 한 장**뿐이다 — 값이 아니라 «인상»만 남고,
토큰은 5~10배 들고, 오버레이(디머·창) 아래 색을 자산색으로 오독한다 (재발방지 `#142` · `#144`).

```
<원본폴더>/HtmlToUnityLogic/
├─ frames/                    ← 사건 프레임마다 한 쌍
│   ├─ 012_38210ms_event_레벨 업!.tsv        노드 표 (id parent depth name x y sx sy alpha visible tint frame font text)
│   └─ 012_38210ms_event_레벨 업!.tree.txt   들여쓰기 트리 (보이는 것만 · 첫 줄에 label·시각·직전 상태)
├─ motion/                    ← 시계열 표 (t frame heroX heroY tint alpha enemies gems nearest …)
├─ paths.md                   ← 경로 지도 (아래)
└─ art_measure.tsv            ← 프레임별 크기 · bbox · 앵커 · 팔레트(hex·비율) · 행별 폭 — 픽셀은 «안» 뽑는다(복사)
```

**규칙 넷.**

| 규칙 | 내용 |
|---|---|
| **사건으로 고른다** | 매 프레임이 아니라 **상태가 바뀐 프레임**(창 열림/닫힘 · 피격 · 회복 · 폭발 · 퀘스트 전이)과 고정 시각 몇 개만 뜬다. 판정 키는 «보이는 표식 문구 + 틴트 + 개체 존재» 묶음이고, 키가 바뀌는 순간이 사건이다 |
| **형식은 자료 모양대로** | 열이 고정된 표(노드 · 시계열 · 측정)는 **TSV**, 계층은 **들여쓰기 트리**, 필드가 들쭉날쭉한 것만 JSON. **XML 은 쓰지 않는다** — 같은 정보에 토큰이 2.5배다 |
| **좌표는 원본 논리 좌표** | 캔버스 논리 해상도(확정표 3-d) 기준 «전역» 좌표·배율(worldTransform). 우리 쪽 덤프도 같은 좌표계로 떠서 **표 대 표로 diff** 한다 |
| **경로를 전부 밟는다** | 성공 · 실패 · 중간 이탈 · 분기(광고 수락/거절 등)마다 한 번씩 «플레이해서» 뜬다. 봇은 원본에서 사람이 하는 조작(회피 · 줍기 · 포인터 따라가기)만 한다. 시간이 들어도 된다 — «똑같이»의 근거가 여기서만 나온다 |
| **«판마다 다른 것»을 갈라 적는다** | 시드·진행으로 자리가 달라지는 개체(절차 생성물 · 적 · 드랍 · 떠오르는 문구 · 화면 가장자리 표식)는 **크기와 존재만** 맞춘다. 좌표까지 맞추려 들면 갈림이 수십 개가 되어 진짜 결함이 묻힌다 — 그 대신 **시계열(motion)** 로 «곡선이 같은지»를 본다 |
| **사건이 «겹치면» 겹친 창은 뺀다** | 고정 시각 프레임에 원본만 모달이 떠 있을 수 있다. 그 창 «아래 노드 전부»를 양쪽에서 빼고 비교한다 — 안 그러면 시각 차이가 «미이관»으로 찍힌다 |

### `paths.md` — 경로 지도

```markdown
| 경로 | 시작 → 끝 | 사건 순서 (frames/ 번호) | 봇 조작 | 결말 |
| 성공 | 시작 → 과제 완료 | 003 시작 → 012 레벨업 → … → 087 과제 완료 | 포인터 따라가기 · 자동 부활 | 「과제 완료」 창 |
| 실패-거절 | 시작 → 첫 사망 → 「아니요」 | … | 첫 사망에 거절 | (원본이 가는 곳) |
```

**경로 하나가 빠지면 그 결말의 창·연출은 «미측정»이다** — 이관율 분모에서 빠지는 것이 아니라 0건으로 센다.

### `paths.md` — **상태 전수표** (경로 지도와 한 쌍)

경로가 「어디를 지났나」라면 상태 전수표는 **「무엇이 아직 안 보였나」**다.
소스의 상태 전환을 `grep` 해 **전수로** 적고, 관측으로 세지 않는다.

```markdown
| 상태 | 언제 나오나 | 도달 | 뜬 프레임 |
| 개체 A — 대기 모드   | 최초 배치부터            | ✅ | 004 |
| 개체 A — 이동 모드   | 조건 X 를 만족한 뒤       | ✅ | 031 |
| 개체 B (무리 N명)    | 퀘스트 단계 3 에서만      | ❌ | — (미측정) |
```

⚠ **도달 ❌ 는 「없음」이 아니라 «미측정»이다.** 그 상태의 개체·연출은 이관율에서
**0건으로 세고**, 다음 회차의 「재측정 대기」로 올린다.
⚠ 조건부 상태는 **봇이 그 경로를 밟아야** 보인다 — 도달 설계와 실패 진단은
`공통절차.md` 「덤프는 «도달한» 상태만 준다」가 정본이다.

⚠ 씬 그래프가 없는 원본(즉시 모드 캔버스)은 `drawImage`/`fill` 호출 인자를 후킹해 같은 표로 만든다.
⚠ 코드로 그리는 것(도형 · 파티클 · 셰이더)은 «파라미터»만 남는다 — 생김새의 최종 확인만 이미지 한 장.

## 캡처 — **대장도 폴더도 만들지 않는다**

**규칙과 이유는 [공통절차 「캡처는 쌓지 않는다」](공통절차.md) 가 정본이다.**
분석 정본은 **덤프**이고, 캡처는 세션 안의 «마지막 눈 확인» 한 장이다.
부득이 남길 때 무엇을 같이 적어야 하는지의 골격만 아래 둔다.

부득이 한 장을 남긴다면 **아래 칸을 같이 적는다** — 상태가 없는 그림은 A/B 에 못 쓴다.

| 무엇 | 왜 |
|---|---|
| 화면 | 어느 화면인지 |
| 상태 (진행도·재화·선택·탭) | 상태가 다르면 A/B 가 성립하지 않는다 |
| 애니메이션 정지 강제 여부 | 안 멈추면 매번 다른 프레임이 찍힌다 |
| 근거 (원본 위치) | 판정은 **①원본 코드 → ②규약 문서 → ③덤프** 순이고 그림은 그 뒤다 |

⚠ **그래도 저장소에는 안 남긴다** — 스크래치패드에 두고 세션이 끝나면 사라지게 한다.

### 섹션별 기입 규칙

#### 작업 분해표 — **학습이 끝나면 만든다. 이관은 이 순서대로만 돈다**

**학습 산출물에서 «기계적으로» 뽑는다** — `02` 문서 한 장 = 한 시스템, `01` 의 화면 하나,
`03` 의 테이블 묶음, `05` 의 연출 덩어리, `06` 의 리소스군. **문서에 없는 단위를 만들지 않는다**
(만들어야 하면 **분석이 덜 된 것**이다 — 학습으로 돌아간다).

| # | 단위 | 무엇을 만드나 | 근거 문서 | 선행 | **완료 조건 (검사·항수)** | 상태 |
|---|---|---|---|---|---|---|

- **`완료 조건` 이 비면 그 단위는 시작하지 않는다** — 숫자가 없으면 완료를 «판정»할 수 없다
- **상태는 셋뿐** — `대기` · `진행` · `✔ N/N`. 「거의 다」는 상태가 아니다
- 순서 규칙(**의존 → 최소 경로 → 불확실 → 크기**)은 `PD.md` 「순서를 매기는 규칙」이 정본
- **한 단위는 패스 ①②③ + 검사까지 «완주»하고 다음으로 간다** (`PD.md`)
- ⚠ **끝난 단위를 다시 열었으면 「완료 조건이 약했다」는 뜻**이다 —
  고치고 넘어가지 말고 **그 단위의 완료 조건을 고쳐 이 표에 반영**한다

#### 이관율 대조표 — **분모는 확정표 범위 · «의도된 차이» 밖의 차이는 결함**

리스트업이 「이번 회차에 무엇을 손댔나」라면, 이 표는
**「원본에 있는 것 중 몇 개가 «우리 화면에 나오나»」**다.
둘은 다른 질문이고, 100% 는 **이 표로만** 선언한다.

### ★★★ 「우리에게 있다」로 세지 않는다 — 그 사이에 **네 겹의 틈**이 있다

이 표를 「만들었나」로 세면 **만들어 놓고 안 쓰이는 것이 전부 100% 로 잡힌다.**
실제로 한 회차에 아래 넷이 동시에 있었고, **모든 검사가 통과했다.**

| 만든 것 | 빠진 것 | 화면에서는 |
|---|---|---|
| 버튼 컴포넌트를 붙였다 | 포인터를 받게 안 켰다 | 눌러도 아무 일이 없다 |
| 상태별 시트를 구웠다 | 뷰가 한 장만 읽는다 | 상태가 바뀌어도 그림이 그대로다 |
| 문구를 표에 넣었다 | 읽는 곳이 없다 | 그 UI 가 통째로 없다 |
| 형태·색 지표가 만점 | 그 지표가 «그림»을 안 잰다 | 다른 그림이다 |

⇒ **갈래마다 «무엇이 증명하나» 칸을 채운다.** 검사 이름이든 실측 근거든,
**「화면에 나온다/동작한다」를 보인 것**이어야 한다. 비어 있으면 그 줄은 «존재만 센 것»이고
**분자에 넣지 않는다.**

⚠ 「프리팹에 있다」·「표에 행이 있다」·「파일을 구웠다」는 증명이 아니다 — 그건 **만든 것**이다.

### ★★★ 분모를 «명사»로만 채우지 않는다 — **개체마다 «행동»이 분모다**

위가 「만든 것을 안 쓴다」라면 이건 **「분모에 애초에 없다」**다. 한 겹 더 깊고 더 안 보인다.

실측 사례 — 표에 **「월드 개체 N/N」**이 있었고 그 안에 **어떤 동료 개체**가 있었다. 증명도 있었다
(덤프에 렌더러가 있다 · 상태마다 다른 시트를 쓴다). 그런데 그 동료는 **싸우지 않았다.**
원본 클래스의 `update()` 는 갈래가 **다섯**인데 우리에게는 **둘**뿐이었기 때문이다.

| 물었던 것 | 물었어야 할 것 |
|---|---|
| 그 개체가 **있나** | 그 개체가 원본처럼 **하나** — 갈래마다 |

**세는 법** — 개체를 옮길 때 **소스 클래스를 통째로 읽고** 아래 둘을 «수»로 적는다.

| 무엇 | 어떻게 |
|---|---|
| **매 프레임 갈래** | `update()` 의 분기 이름을 전수로 옮겨 적는다 (`updateFollow`·`updateAttack`·…). **우리 코드의 갈래 수와 같아야 한다** |
| **타이머·상수 필드** | `…IntervalMs`·`…DurationMs`·`…Offset`·`…Multiplier`·`…Radius` 를 전수로 옮긴다. **표에 안 들어간 상수는 이관되지 않은 규칙이다** |

⚠ 개체 하나가 표의 **한 줄**이면 그 줄은 「있다」밖에 못 센다 —
갈래가 다섯이면 **분모가 다섯**이다.

### ★★★ 덤프의 열은 **«셋 같이»** 읽는다 — 크기만 보면 두 모드가 같아 보인다

장면 그래프 덤프의 한 줄에는 `frame`(원본 컷 크기) · `sx/sy`(배율) · `w/h`(그려진 크기)가 **따로** 있다.
**이 셋의 관계가 «그리는 방식»을 말한다.**

| 관계 | 무슨 뜻인가 | 엔진에서 |
|---|---|---|
| `w == frame × sx` | **정수배 확대** — 그림을 통째로 키운다. **테두리도 같이 굵어진다** | 그냥 스프라이트 + 배율 |
| `w != frame × sx` | **9슬라이스 늘림** — 모서리는 그대로, 가운데만 늘어난다 | 슬라이스 + 인셋 |

⚠ **`w/h` 만 보면 둘이 구별되지 않는다.** 「72×72 짜리 상자」로 똑같이 읽히고,
9슬라이스로 만들면 **테두리가 배율만큼 얇아진다** — 화면에서 «실오라기»가 된다.

### 덤프에 **원리적으로 없는 것**이 있다 — 그건 소스에 있다

덤프는 **표시 개체의 «속성»**을 뜬다. 그래서 **생성자 인자**는 안 나온다.

| 덤프에 없는 것 | 어디 있나 | 안 캐면 |
|---|---|---|
| 9슬라이스 **인셋** | 소스의 `NineSlicePlane({leftWidth: …})` | 테두리 두께가 통째로 다르다 |
| 같은 그림을 **자리마다 다른 인셋**으로 쓰는 것 | 소스의 호출부마다 | 카드와 버튼이 같은 모양이 된다 |
| 「이 값이 어디서 나왔나」의 **식** | 소스의 `updateLayout()` 류 | 화면비가 바뀌면 어긋난다 |

⚠⚠ **빈칸을 «공식»으로 메우지 않는다.** 실측 사례로 임포터가 인셋을 `min(폭,높이)/3` 으로 지어냈고,
한 곳(6×6→2)이 우연히 맞아서 **틀린 줄도 몰랐다**. 못 캤으면 **못 캤다고 적는다** (`재발방지` #161).

### ★★★ 골든의 분모는 **«결과물»**이다 — 「식이 맞다」는 「그림이 맞다」가 아니다

절차가 있는 것(여러 패스 · 캐시 제자리 수정 · 좌표 변환)은 **중간값을 아무리 맞춰도** 결과가 갈린다.

실측 사례 — 지형 골든이 **19/19 통과** 상태였다(난수열 · 노이즈 표본 · 나무 자리).
그런데 화면은 달랐다. 골든이 잰 것은 **`f(x,y)` 의 값**이었고, 그림을 만든 것은 셋이었다.

| 골든 밖에 있던 것 | 왜 값으로는 안 잡히나 |
|---|---|
| **좌표계** (엔진 y 위 ↔ 원본 y 아래) | `f(x,y)` 는 맞다. **넣는 좌표**가 뒤집혔다 |
| **패스 전파** (캐시를 제자리에서 고친다) | 한 칸의 값은 맞다. **이웃을 언제 읽느냐**가 다르다 |
| **인덱스 범위** (원본은 안 자른다) | 가운데는 같다. **가장자리**가 다르다 |

⇒ **결과물을 골든으로 만든다.** 지형이면 노이즈 값이 아니라 **타일 격자**다 —
창 한 판을 **전 칸 대조**하고, **타일 종류가 거의 다 나오는 창**을 골라야 갈래를 다 훑는다.

⚠ **「검사가 통과했는데 그림이 다르다」가 나오면 검사의 «분모»를 의심한다.**

### 세는 검사는 **개수를 못 박는다**

「0개 실패」는 **분모가 0 이어도 초록불**이다. 실측으로 두 번 당했다 —
문구를 **1개**만 보고 통과했고(UI 가 다 붙기 전), 버튼을 **5개**만 보고 통과할 뻔했다(모달이 안 열려서).

| 규칙 | 왜 |
|---|---|
| **최소 개수를 못 박는다** (`Check(n >= 최소)`) | 분모가 0/1 이면 그 검사는 아무것도 안 지킨다 |
| **「지금 화면」이 아니라 «만들어 둔 것 전부»를 센다** | 모달·풀은 **게으르게 만들어져** 화면에 없다. 프리팹·표를 전수로 본다 |
| 화면을 봐야 하면 **«가라앉기»를 기다린다** | 창들이 차례로 붙는다 — 첫 프레임에 재면 절반만 잡힌다 |

| 규칙 | 내용 |
|---|---|
| **분모** | 확정표의 이관 범위(모드·월드·「한 판」)에 드는 원본 요소 전수. 갈래는 화면 · 시스템 축 · 무기/행동 · 진행 체인 · 월드 개체 · HUD · 연출 · **UI 연출(펄스·호버·디머·트윈)** · 지형 · **아트(재제작이면 «퀄리티 동일» 판정 행)** 처럼 **세기 쉬운 단위**로. ⚠ 갈래가 하나 빠지면 그 갈래 0건인 채 100% 가 나온다 |
| **원본 개수** | 소스가 있으면 **소스 정의**로, 없으면 관측 + 「관측 범위」 명시. 관측으로 센 개수는 하한이다 |
| **의도된 차이** | 원본과 다르게 «두기로 한» 것 전부 — 재제작 아트 · 사운드 · 플랫폼 요소 · 광고 · 이관 밖 화면. **근거 칸에 확정표 행 또는 판정 절**을 적는다 |
| **증명** | 갈래마다 **「화면에 나옴/동작함」을 보인 근거**를 적는다 — 재생 검사 이름 · 사건 프레임 덤프의 그 줄 · A/B 개체 수. **비면 분자에 안 넣는다** |
| **판정** | 이 표에 없는 차이는 전부 **미흡**이다. 표 자체가 없으면 100% 를 말할 수 없다 (PD 「QA 체크 순서」 9) |

#### 리스트업

| 규칙 | 내용 |
|---|---|
| 항목 단위 | **화면·시스템 단위**로 자른다. 「UI 이관」 같은 덩어리는 달성률이 영원히 70% 에서 안 움직인다 |
| 완료 정의 | **분모가 있는 문장.** **[예시]** 「9요소 중 6개 이식」·「정답지 230행 중 통과 수」·「팝업 9곳」 — 문장의 모양이다. 분모는 그 프로젝트에서 센다 |
| 달성률 | 완료 정의에서 **역산**한다. 분모를 못 적으면 전수 대조표(PD 「화면 하나를 전수 대조표로 여는 법」)를 안 만든 것 — 그것부터 한다 |
| 회차 | 그 항목을 **몇 번 손댔나.** 3회차인데 60% 면 접근이 틀린 것이다 (PD 「회차 카운터를 원장에 남긴다」) |
| 100% | **PD QA 통과 후에만** 붙는다. 담당자가 스스로 붙이지 않는다 |
| **미측정** | **0% 로 계산한다.** 통과가 아니라 미달이다 (아래 「재측정 대기」) |

#### 학습 내용

- 한 줄에 **한 사실**. 「배운 것」에 두 가지를 넣지 않는다.
- **근거 열이 빈 줄은 적지 않는다.** 근거 없는 줄은 다음 회차에 오염이 된다.
- 이전 회차 줄을 지우지 않는다. 바뀌었으면 새 줄을 추가하고 「전 회차 정정」이라고 적는다.

#### 오염된 내용 — **갈래를 반드시 적는다**

| 갈래 | 무엇 |
|---|---|
| **캡처를 사양으로 삼음** | 픽셀로 읽은 것을 사양으로 적었다. 판정은 ①원본 코드 → ②규약 → ③캡처 |
| **문서·라인 번호를 믿음** | 인용 라인이 현재 빌드와 어긋났다 |
| **애니메이션 프레임을 정색으로 오인** | 점멸·페이드 중 한 프레임이 찍힌 캡처를 정색으로 봤다 |
| **이름이 비슷해 다른 물건을 가져옴** | 파일명·클래스명이 그럴듯해 다른 용도의 것을 썼다 |
| **추측을 결론으로 적음** | 「대략 이 정도」가 다음 회차에 원본 수치처럼 인용됐다 |

**고치기 전에 먼저 적는다.** 조용히 고치면 왜 틀렸는지가 사라져 재발한다.

#### 패스 ①②③ 수행 내용

- **한 항목을 끝낼 때마다** 적는다. 몰아서 적지 않는다 — 문맥이 날아가면 복구할 수 없다.
- **판정 열에 숫자를 적는다.** 「됨」이 아니라 **[예시]** 「팝업 9/9」·「정답지 120/230」·「A/B 개체 수 통과」
  같은 분모 있는 문장 — 모양의 예시다. 분모는 그 항목에서 센다.
- 미착수는 **회차를 `—`** 로 두고 남긴다. 지우지 않는다 — 다음 회차의 입력이다.
- 패스 ③은 **배선 대상 6종**(UI · 게임 플로우 · 연출 파라미터 · 게임오브젝트 ·
  데이터 종속 아트 · 지연 로드 아트) 중 무엇인지를 적는다 (PD 「패스 ③이 하는 일」).

#### 회고록 — **세 칸이 다 차야 끝난다**

```
무엇을 놓쳤나 | 왜 안 보였나 | 무엇으로 막나
```

**「주의하겠다」는 대책이 아니다.** 세 번째 칸은 반드시 셋 중 하나로 끝난다:

| 형태 | 예 |
|---|---|
| **도구** | 양방향 에셋 감사기를 만들어 화면 완료 전에 돌린다 |
| **체크리스트** | 담당자 md 완료 체크리스트에 한 줄 추가 |
| **게이트** | 플로우 diff 를 프리팹 대조보다 먼저 돌리게 순서를 고정 |

#### ★ 재측정 대기 — **미측정을 통과로 넘기지 않는 장치**

「못 쟀다」를 그냥 넘어가면 그 자리는 영원히 안 채워진다. 네 가지로 닫는다.

**① 판정 칸에 숫자를 못 넣으면 `미측정(사유)` 로 적는다.** 빈칸·「됨」·「확인함」 금지.

**② 사유를 3갈래 중 하나로 적는다 — 해소 방법이 각각 다르다.**

| 갈래 | 무엇 | 해소하려면 |
|---|---|---|
| **① 도구 없음** | 브라우저·Unity 제어·이미지 비교 등이 없다 | 사람에게 도구 또는 **대체 자료**(캡처·로그·DOM 덤프)를 요청 |
| **② 상태를 못 맞춤** | A/B 정합 실패 — 진행도·재화·선택 상태가 캡처와 다르다 | 치트/디버그 명령을 이식해 **한 줄로 같은 상태**를 만든다 (공통절차 「A/B 측정」) |
| **③ 하네스 없음** | 재는 도구 자체가 아직 없다 (채점기·프리뷰·감사기) | **그 하네스를 만드는 것**을 리스트업 항목으로 올린다 (PD 「재는 도구를 먼저 만든다」) |

**③ 달성률에 0% 로 계산한다.** 미측정은 통과가 아니라 **미달**이다 —
못 잰 만큼 달성률이 안 오르고, 도구 결핍이 숫자로 드러난다.

**④ 재측정 대기 표에 남기고 다음 회차에 먼저 처리한다.**

| 규칙 | 내용 |
|---|---|
| 등록 | 미측정이 생기면 **그 즉시** 재측정 대기 표에 한 줄 |
| 우선순위 | 다음 회차 착수 시 **재측정 대기가 신규 작업보다 먼저**다 |
| 대기 회차 | 회차가 돌 때마다 +1. **3 이상이면 PD 가 사람에게 도구·데이터를 직접 요청**한다 |
| 해소 | 실측값이 들어오면 대기 표에서 지우고 해당 패스 표의 판정 칸을 숫자로 덮는다 |

**PD 는 QA(PD 「QA 체크 순서」 8번)에서 이 표를 읽어 미흡 목록에 자동 편입한다.** 담당자가 안 올려도 집힌다.

#### PD QA 미흡 목록

- **[무엇이 · 어디가 · 기대 · 실측]** 네 칸. 「어색하다」는 QA 결과가 아니다.
- 이 목록이 **그대로 다음 회차의 리스트업**이 된다. 해당 항목의 달성률을 내리고 회차를 +1 한다.

### 갱신 시점

| 시점 | 누가 | 무엇을 |
|---|---|---|
| 착수 **전** | 전원 | 이번 회차에 손댈 범위를 리스트업에 먼저 적는다 |
| 학습 중 | 지식 담당자 | 학습 내용 · 오염된 내용 |
| 한 항목 완료마다 | 이관 담당자 | 해당 패스 수행 내용 |
| 패스 ③ 완료 | Transfer_Programmer | 회고록 · 회차 +1 |
| 미측정 발생 즉시 | 담당자 | **재측정 대기** 표에 한 줄 |
| QA 후 | PD | 미흡 목록 · 달성률 조정 · **재측정 대기 편입** |
| 회차 시작 | PD | 재측정 대기의 **대기 회차 +1**. 3 이상이면 사람에게 요청 |

### 닫힌 회차는 원장에서 뺀다 — **원장은 아카이브가 아니다**

원장은 **다음 회차가 읽고 판단하는 문서**다. 닫힌 회차의 상세가 쌓이면 살아 있는 상태가
그 안에 묻혀 「착수 전 3단계」가 형식만 남는다. 닫힌 것은 **지우지 말고 옮긴다.**

| 판정 | 기준 |
|---|---|
| 언제 빼나 | **닫힌 기록이 원장의 절반을 넘으면** 그 회차에 뺀다. 재는 것은 줄 수 하나다 |
| 어디로 | 원장과 **같은 폴더**의 `HtmlToUnity_작업내역_아카이브.md`. 분량이 계속 늘면 회차별 파일로 가른다 |
| 원장에 남기는 것 | **한 줄 요약 + 아카이브 링크.** 「무엇이 닫혔나」는 원장, 「어떻게 닫혔나」는 아카이브 |
| 헤딩 | 아카이브로 옮길 때 레벨을 **다시 잡는다.** 원장에서 잘라 붙이면 `##` 와 `###` 가 섞여 목차가 무너진다 |

**빼지 않는 것 셋** — 닫혀도 원장에 남는다. 다음 회차가 **판단에 쓰는 것**이기 때문이다.

| 남기는 것 | 왜 |
|---|---|
| **오염된 내용** | 같은 오염이 재발했는지 매 회차 대조한다 |
| **회고록** | 대책이 도구·체크리스트·게이트로 살아 있는지 확인한다 |
| **재측정 대기** | 대기 회차가 계속 도는 표다 |

⚠ **「대조해서 문제 없었던 곳」도 아카이브가 아니라 원장에 남긴다.** 같은 자리를 다시 파는 것을
막는 게 목적이라 **착수 전에 읽혀야** 한다. 다만 **근거(원본 위치·실측값)가 없는 줄은 남기지 않는다** —
근거 없는 「문제 없었다」는 다음 회차의 확인을 막기만 한다.

## 안티패턴 — 이렇게 적으면 그 문서는 다음 회차에 쓸모가 없다

| 안티패턴 | 왜 나쁜가 | 대신 |
|---|---|---|
| 「거의 다 됐다」 | 판정이 불가능하다 | 분수로 적는다 |
| 근거 없는 수치 | 다음 회차에 원본 수치처럼 인용된다 | 원본 위치를 같이 적거나 「미확인」 |
| 이전 회차 덮어쓰기 | 무엇이 바뀌었는지가 사라진다 | 새 줄 추가 + 「전 회차 정정」 |
| 오염을 조용히 수정 | 같은 실수가 재발한다 | 오염 표에 먼저 적고 고친다 |
| 산문으로 요약 | 빠진 것이 숨는다 | 표 + 빈 칸 |
| 회고에 「주의하겠다」 | 아무것도 안 바뀐다 | 도구·체크리스트·게이트 중 하나 |
| 담당자가 100% 선언 | 검증 단계를 건너뛴다 | PD QA 통과 후에만 |
| **못 잰 것을 「됨」으로** | 미측정이 통과로 둔갑해 영원히 안 채워진다 | `미측정(사유)` + 재측정 대기 등록 |
| **역할을 바꾸고 기억으로 이어감** | 「우리 코드가 심판」으로 뒤집힌다 | 이전 역할의 결론은 **md 에 적힌 것만** 인정 (PD 「역할 기동 규약」) |
| 리스트업 항목이 덩어리 | 달성률이 안 움직인다 | 화면·시스템 단위로 자른다 |
| **원장이 아카이브를 겸함** | 닫힌 기록이 대부분이 되면 살아 있는 상태가 묻힌다 | 「닫힌 회차는 원장에서 뺀다」 |
| **PNG 만 쌓고 대장이 없다** | 상태를 모르는 캡처는 A/B 에 못 쓰고, 다음 회차가 **사양으로 인용**한다 | `_대장.md` 에 상태·원본 근거를 같이 적는다 |
| **본문에 「(추정)」을 달아 적는다** | 다음 회차는 괄호를 안 읽는다 — **사실로 인용된다** | 추정은 본문이 아니라 **재측정 대기**에. 본문에는 등급이 붙은 것만 (PD 「근거 등급」) |
| **관측 최솟값·최댓값을 값으로** | 가려진 마지막 타격 · 무적 간격은 **하한**이다 | `≥ N [관측 하한]` 으로 적고 소스·후킹으로 닫는다 (재발방지 `#134`) |
| **「없다」** | 그때 화면에 없었을 뿐이다 — 조건부로 꺼지는 것은 영원히 안 보인다 | 「그 조건에서 안 나왔다」 + 개수는 **원본 정의**로 (재발방지 `#130`) |
| **남은 일이 있는 채로 「완료」** | 다음 회차가 완료로 읽고 남은 것을 잊는다 | PD 「«완료»는 마지막에 한 번」 — 조건이 다 찼을 때만 |
