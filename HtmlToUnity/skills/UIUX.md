# UI/UX 파트 — HTML5 → Unity 이관

상위: [PD](PD.md) (PD)

**담당** — 프리팹 · 레이아웃 · 좌표계 · 폰트/글리프 · 컴포넌트 재사용 · 입력 판정.
**한 줄 원칙** — 원본 DOM 구조를 그대로 옮긴다. **절대 y를 박기보다 원본 flex를 옮기는 게 낫다.**

**역할** — 나는 **지식 담당자**다. 이관에 직접 참여하지 않는다.
[Transfer_Artist](Transfer_Artist.md) 가 100% 이관할 수 있도록 **정확한 정보를 제공**하는 것이 산출물이다.
**판정은 항상 ①원본 코드 → ②규약 문서 → ③캡처 순이다.** 캡처에서 「읽어낸」 것을 사양으로 삼지 않는다.

**역할 선언** — 이 역할로 들어갈 때 다음을 **출력한다** (PD 「역할 기동 규약」).

```
  할 수 있는 것 : 원본 읽기·실행 · 04_UIUX규칙.md / 06_리소스.md 작성
  하지 않는 것  : 프리팹·아트 생성 (그건 Transfer_Artist 가 한다)
```

**이전 역할의 결론은 md 에 적힌 것만 인정한다.** 기억으로 이어가지 않는다.

## 좌표계

### 환산 상수는 한 곳에서만

| 항목 | 무엇을 적나 |
|---|---|
| 원본 논리 해상도 | 원본이 캔버스를 잡는 논리 크기. **실측한다** — CSS 가 아니라 JS 가 잡는 값일 수 있다 |
| Unity Canvas Scaler | `Scale With Screen Size` / Reference 해상도 / Screen Match |
| 환산 배율 | 원본 → Reference. **코드에 직접 곱하지 말고 팩토리의 `Px()` 하나만 통과시킨다** |

**착수 후 캔버스 설정은 바꾸지 않는다.** 한 번 굽기 시작하면 프리팹 전부가 그 기준으로 잡힌다 —
바꾸려면 프리팹을 전부 다시 잡아야 한다.

### y축이 반대다

캔버스는 **아래가 +y**, UGUI는 **위가 +y**.

```js
shipY = winH * 0.84          // 원본
```
```csharp
ship.y = area.height * 0.16  // 유니티
```
원본의 `shipY - 18` 같은 오프셋은 유니티에서 **`+18`** 이 된다. 부호를 빼먹으면 조용히 위아래가 바뀐다.

### 창 안 상대 배율은 따로 있다

전체 화면 환산과 **패널 안 환산은 별개다.**
원본이 패널 안에서 자체 기준 폭을 쓰면 (`_unit = area.width / 기준폭`) 반지름·속도·오프셋이 전부 그 단위다.
원본 좌표를 그대로 넣으면 창 크기가 달라질 때 어긋난다.

### 분수로 정의된 배치를 픽셀로 굽지 않는다

원본이 `min(W*0.195, bandH*0.40)` 처럼 **부모 크기의 분수**로 정의한 값은 그대로 분수로 옮긴다.
고정 픽셀로 구우면 접힘/펼침처럼 부모가 바뀌는 상태에서 전부 어긋난다.

### ★ 원본 좌표값이 「위치」인지 「순서」인지 먼저 가른다

**이게 좌표 이관에서 가장 크게 새는 자리다.** 원본 필드가 숫자라고 위치가 아니다.
그리는 코드를 열어 **그 값이 식에 어떻게 들어가는지** 본다.

```js
// 스킬트리 — x 는 위치가 아니라 순서표였다
const _cols = [...new Set(페이지의 x들)].sort();
lx = 8 + (_cols.indexOf(x) / (_cols.length - 1)) * 84;   // indexOf ← 순위만 쓴다
top = Math.round(y * 3.2);                                // y ← 값을 그대로 쓴다
```

같은 노드 객체 안에서 **`x` 는 순위, `y` 는 실제값**이다. 둘을 같은 규칙으로 옮기면 한쪽이 깨진다.

| 원본이 값을 쓰는 방식 | 옮기는 법 |
|---|---|
| `indexOf(x)` · `sort()` 후 순위 | **정수 인덱스**로 옮긴다. 원래 숫자(2.9 / 8.6 …)는 버려도 결과가 같다 |
| `y * 배율` 처럼 값을 직접 곱함 | **실수로 옮긴다.** 정수 행으로 접으면 반 칸 오프셋이 사라진다 |
| 화면 폭 대비 퍼센트 | 칸 수로 나눈 격자로 옮긴다 — 픽셀로 굽지 않는다 (「분수로 정의된 배치를 픽셀로 굽지 않는다」) |

**[사고]** 순위와 실제값 두 개를 `Cell = row*N + col` 한 컬럼으로 접었다가 **노드 70% 의 열이 어긋났다.**
원본은 페이지마다 열 개수가 달랐는데 고정 열 수로 눌렀고,
`y = 300`(280행 + 20) 같은 **반 칸 오프셋**이 통째로 한 행씩 밀렸다.
`X`(int 순위) · `Y`(double 실제값) **두 컬럼으로 풀어야** 한다.

**검산은 원본 렌더 결과와 좌표로 대조한다.** 캡처 위에서 노드 중심 픽셀을 재고,
원본 식(`8% ~ 92% 균등 분배`)이 내는 값과 맞는지 본다 — 「비슷해 보인다」로 닫지 않는다.

### renderMode 는 상황마다 다르다

| 언제 | renderMode | worldCamera |
|---|---|---|
| 프리팹을 굽는 시점 | `ScreenSpaceOverlay` | 없음 |
| **런타임(실기)** | **`ScreenSpaceCamera`** | **`UICamera`** |
| 프리뷰 하네스 | `WorldSpace` | 프리뷰 카메라 |

프리팹 인스펙터 값은 셋 중 하나일 뿐이다 — **런타임에서 확인한다.**
`EventSystem.RaycastAll` 은 `RectTransformUtility.WorldToScreenPoint(rootCanvas.worldCamera, …)` 를 거쳐야 한다.
안 그러면 전부 `NONE` 이 나와 「다 막혔다」고 오판한다.

## 계층 — Window → Panel 두 단계까지만

**원본 DOM 구조를 그대로 옮긴다.** 원본이 `.screen > .body > 블록들` 이면 우리도 그렇게 만든다.

```
XxxWindow            Canvas + Scaler + Raycaster + XxxWindow.cs
├ BG                 anchor 0,0~1,1 / sizeDelta 0
├ TopBarPanel        상단 고정
├ BodyPanel          원본 flex 컨테이너 → VerticalLayoutGroup
│  ├ AaaPanel        늘어나는 블록은 LayoutElement.flexibleHeight = 1
│  └ BbbPanel        나머지는 preferredHeight (캡처 실측값)
└ NavPanel
```

- Window 최상위 자식은 **무조건 `XxxPanel` 단위**로 자른다. 낱개 위젯을 루트에 직접 붙이지 않는다.
- Window 스크립트는 패널을 물고 프로퍼티로 노출만 한다. 로직 없음.
- **블록 높이만 실측해 넣으면 접힘/펼침 같은 상태 변화가 자동으로 맞는다.**

### 앵커 패턴

| 용도 | anchorMin/Max | pivot | 비고 |
|---|---|---|---|
| 전체 배경 | (0,0)~(1,1) | (0.5,0.5) | sizeDelta 0 |
| 상단 고정 바 | (0,1)~(1,1) | (0.5,1) | `sizeDelta.x`=음수(좌우 인셋) |
| 세로 스택 블록 | (0,1)~(1,1) | (0.5,1) | `anchoredPosition.y` = **-y** |
| 하단 버튼 바 | (0,0)~(1,0) | (0.5,0) | |
| 중앙 카드 | (0.5,0.5) | (0.5,0.5) | 팝업 기본 |

- **「중심 좌표」와 「왼쪽 변 좌표」 헬퍼를 구분한다.** 캡처에서는 왼쪽 변을 재게 되니 변 기준이 기본이다.
- **회전시킬 rect는 앵커·피벗을 직접 잡는다.** 상단 피벗 헬퍼로 만들면 그 축으로 돌아 엉뚱한 데 간다.
- **부모 변에 붙이는 아이콘은 앵커까지 옮긴다.** 기본 앵커(0.5,0.5)면 가운데에서 이동한 자리에 앉는다.

## 레이아웃 함정 — 실제로 걸렸던 것들

- **행 폭 헬퍼를 세로 스택 안에서 쓰면 안 된다.** 빌드 시점의 `rect.width` 를 보는데 레이아웃 전이라
  기본값 100이 잡혀 비율이 어긋난다. 절대 폭을 `LayoutElement.preferredWidth` 로 주고
  `childForceExpandWidth = false` 로 고정한다.
- **세로 레이아웃 헬퍼는 `childControlHeight` 를 건드리지 않는다** (가로판은 켜준다).
  코드로 붙이면 false로 남아 자식이 `preferredHeight` 대신 기본 100으로 앉는다. 쓰는 자리에서 명시한다.
- **`HorizontalLayoutGroup` 은 `childForceExpandWidth` 가 기본 true다.** `preferredWidth` 를 줘도
  무시되고, 합이 부모 폭을 넘으면 0폭까지 눌려 버튼 판이 안 보인다(라벨만 남는다).
- ⚠ **레이아웃 그룹 아래의 낱개 아이콘에는 `LayoutElement` 를 반드시 준다.**
  가로 레이아웃은 `childControlWidth/Height` 를 켜므로, 없으면 **점 하나가 행 전체로 늘어나 타원이 된다.**
  ```csharp
  var le = dot.gameObject.AddComponent<LayoutElement>();
  le.preferredWidth = size; le.preferredHeight = size; le.flexibleWidth = 0f;
  ```
- **`childControlHeight=true` 아래 버튼은 높이를 명시한다.** `preferredHeight` 가 -1이면
  0 높이로 수축해 클릭 영역이 사라질 수 있다.
- **`ContentSizeFitter` 를 레이아웃 그룹의 자식에 붙이지 않는다.** 부모와 높이를 두고 싸운다.
- **레이아웃 그룹 안의 테두리·코너 틱은 `ignoreLayout` 을 준다.** 없으면 한 행으로 취급된다.
- **행 수가 상황마다 다른 카드는 `ContentSizeFitter` 로 늘린다.** 중앙 앵커면 위아래로 같이 자란다.

### ★★ 원본의 **좌표 계산**은 옮기는 게 아니라 **버리는** 것이다

HTML5 는 코드가 좌표를 계산해 요소마다 박는다 (`left:36%` · `top:rowY(y)px`).
UGUI 는 **컨테이너가 배치를 소유한다** — 셀 크기·열 수·간격만 주면 자식 위치는 유니티가 만든다.
그래서 원본의 배치 계산을 그대로 이식하면 **배치를 정하는 주체가 둘이 되고**,
프리팹 값을 바꿔도 안 먹거나 스크롤 길이가 어긋난다.

**판단 기준 한 줄 — 격자·리스트로 표현되는 것은 전부 프리팹, 진짜 좌표 그래프만 데이터.**

| 원본이 코드로 하던 것 | 이식하면 |
|---|---|
| `x:36` → `left:%` 환산 | **버린다.** 데이터는 **행 안 순위**만, 위치는 LayoutGroup |
| `rowY(y)=y*ROWH + GAP*band` | **프리팹 필드** (`_rowPitch` · `_bandGap`) |
| `SA={3:[22,50,78]}` 배치표 | **프리팹 필드** (직렬화 배열) |
| 그리드를 「행 래퍼 컴포넌트」로 흉내 | 스크롤 뷰에 **열 수 필드** 하나 |
| 노드 그래프 좌표 (스킬 트리) | **남긴다** — 원본이 좌표로 정의한 것이고 격자가 아니다 |

**DB 에도 코드 상수에도 UI 픽셀을 두지 않는다.** 둘 다 「내려야 할 곳」이 아니다 —
기획자가 인스펙터에서 잡을 값을 코드 상수로 되돌리는 것은 문제를 옮긴 것이지 푼 것이 아니다.

> **[사고]** 한 회차에 같은 판단을 **네 번** 틀렸다. 원본 하드코딩을 없앤다는 명분으로 유령 노드
> 띄움값을 **DB 컬럼**으로 넣었고, 행 간격·밴드 여백을 **C# 상수**로 되돌렸고,
> 유닛 트리 x(0~100)를 **두 번** 데이터에 남겨 뒀다.
> 전부 「원본이 계산하니 우리도 계산값을 들고 있어야 한다」는 착각이었다.

⚠ **중간 판정이 갈린다고 결과가 갈리는 건 아니다.** **[사고]** 트리 x 를 순위로 바꾸면
중앙 승격 판정이 156행 중 26행에서 달라진다 — 그런데 승격 뒤 그 행의 x 를 배치표가 통째로
다시 깔아서 **최종 좌표는 전 트리 전 노드가 동일**했다. 「깨진다」고 두 번 보고했는데
중간만 보고 결과를 안 돌려본 탓이다. **바꾸기 전에 최종 산출물로 대조한다.**

### ★ CSS 레이아웃 프리미티브는 Unity 와 1:1이 아니다

**「비슷한 걸로 대체」하면 줄바꿈이 생기는 순간 어긋난다.** 대응표를 먼저 보고, 없으면 만든다.

| CSS | Unity 대응 | 주의 |
|---|---|---|
| `display:flex; flex-direction:row` | `HorizontalLayoutGroup` | `childForceExpandWidth` 기본 true — 끄고 시작한다 |
| `display:flex; flex-direction:column` | `VerticalLayoutGroup` | `childControlHeight` 를 쓰는 자리에서 명시 |
| `flex:1` | `LayoutElement.flexibleWidth/Height = 1` | |
| `display:grid` (칸 크기 고정) | `GridLayoutGroup` | 칸 크기가 고정일 때만 |
| **`flex-wrap:wrap` + `justify-content:center`** | **없다** | 줄마다 중앙 정렬 — `GridLayoutGroup` 은 마지막 줄을 왼쪽에 붙인다 |
| `gap` | `spacing` | |
| `align-items:center` | `childAlignment` | |
| `overflow:hidden` / `clip()` | `RectMask2D` | 빠뜨리면 창 밖으로 나가야 할 것이 그대로 보인다 |
| `border-radius` | 둥근 채움 스프라이트 + `Image.Type.Sliced` | 채움과 테두리를 **같은 반경**으로 |

> **[사고]** 픽업 칩이 `flex-wrap + justify-content:center` 였다. `GridLayoutGroup` 으로는
> **줄마다 중앙 정렬**이 안 나와 마지막 줄이 왼쪽으로 쏠렸다. `UIFlowLayout` 최소 컴포넌트를 새로 만들었다.

**없으면 최소 컴포넌트를 하나 만든다.** 범용 레이아웃 시스템을 새로 짜지 않는다 —
그 CSS 속성 하나가 하는 일만 하는 것을 만들고, 이름에 무엇을 흉내 내는지 적는다.

### ★★ **CSS 흐름을 고정 박스로 옮기면 「길이가 변하는 순간」 전부 깨진다**

**[사고]** 같은 병을 한 회차에 **세 화면에서** 만났다. 증상은 제각각인데 원인은 하나다 —
원본이 **내용 길이만큼 늘어나는 흐름**인데 이식본이 **고정 y·고정 높이**로 박았다.

| 화면 | 원본 | 이식본 | 증상 |
|---|---|---|---|
| 뽑기 상자 설명 | `.gx-desc{line-height:1.45; margin:6px 0 14px}` — flex 흐름 | 고정 높이 104 + **가운데 정렬** | 3줄짜리가 **위아래로** 넘쳐 제목과 겹침 |
| 컬렉션 단계 행 | `<span>라벨</span> <span>조건</span>` — 인라인 흐름 | 라벨 **고정 폭 120px** | 조건 없이 라벨만 긴 행이 접혀 효과와 겹침 |
| 설정 단계 버튼 | `.set-step{padding:16px 0; font-size:41px}` | 행 높이 46 · 버튼 높이 미지정 | `childControlHeight` 아래 **0으로 수축**, 라벨만 겹침 |

**세 가지 처방이 다르다. 증상만 보고 y를 밀지 마라.**

| 원본이 | 옮기는 법 |
|---|---|
| 세로로 흐른다 (블록이 쌓임) | 세로 레이아웃 + `preferredHeight`. 고정 y 를 쓸 거면 **가장 긴 경우**를 담을 높이로 |
| 가로로 흐른다 (인라인) | 가로 레이아웃 + **내용 폭**(`NoWrap` + `flexibleWidth=0`). 고정 폭 칸으로 자르지 않는다 |
| `padding` 으로 높이가 정해진다 | 높이 = `padding×2 + fontSize×lineHeight`. 계산하고 **캡처로 검증**한다 (「CSS 수치는 계산 → 캡처로 검증 2단계」) |

**넘칠 때 어디로 넘치는지가 중요하다.** 가운데 정렬은 위아래 **양쪽**으로 넘쳐 위 요소를 친다.
고정 박스를 쓸 수밖에 없으면 **위 기준(Top)으로 두어 아래로만 넘치게** 한다 — 그래야 피해가 한 방향이다.

⚠ 그리고 **한 요소의 높이를 늘리면 그 아래 전부를 같이 민다.** 카드 높이도 함께 키운다.
고정 y 로 박아둔 화면에서는 이게 자동으로 안 된다 — 원본이 flex 라서 공짜로 되던 일이다.

### ★ CSS 수치는 「계산 → 캡처로 검증」 2단계다. 한쪽만 하면 반드시 틀린다

**양방향으로 틀린다.** 한쪽 방향만 조심하면 반대쪽에서 당한다.
**[예시]** 실측 사례 — 수치는 프로젝트마다 다시 잰다:

| 방향 | 사례 | 원인 |
|---|---|---|
| CSS 값이 **크게** 나온다 | 폰트 — CSS `font-size` 를 그대로 넣으면 브라우저보다 25% 크다 | TMP 가 같은 숫자를 더 크게 그린다 → 잉크 높이 역산 |
| CSS 값이 **작게** 나온다 | 궤도 카드·그리드 칸 — 눈대중 값이 원본보다 20% 작았다 | 애초에 CSS 를 안 읽고 캡처 눈대중으로 넣었다 |

**절차**
1. **CSS 에서 계산한다.** 해당 규칙을 grep 해 `width`/`height`/`padding`/`font-size` 를 그대로 뽑는다.
   상속·우선순위까지 본다 (`#id .class` 가 `#id` 를 이긴다).
2. **캡처로 검증한다.** 그 요소의 픽셀 bbox 를 재서 1번 값과 맞는지 본다.
   글리프처럼 렌더가 개입하는 것은 **캡처가 이긴다** (역산해서 넣는다).
3. 둘이 다르면 **왜 다른지 밝히기 전에는 어느 쪽도 넣지 않는다.**

## ★ 장식과 내용물을 한 필드에 겸하지 않는다

> **[사고]** 카드의 아이콘 필드 하나가 **육각 테두리 이미지**를 물고 있었다.
> 런타임에 데이터 아이콘을 주입하는 순간 `sprite` 가 교체돼 **육각 테두리가 사라졌다.**
> 프리팹 인스펙터로는 정상이라 런타임에서만 드러난다.

원본을 보면 애초에 둘이다:

```css
.awep-frame{width:126px;height:126px}          /* 테두리 (등급색 stroke) */
.awep-frame .aug-ic{width:52px;height:52px}    /* 그 안에 든 아이콘 */
```

**규칙**

| 구분 | 예 | 처리 |
|---|---|---|
| **정적 장식** | 프레임, 패널 테두리, 탭 아이콘 | 프리팹에 직접 물린다. 런타임이 건드리지 않는다 |
| **데이터 종속** | 초상·유닛·아이템 아이콘·**구역별 배경** | 프리팹에 박지 않는다. 런타임 `SetXxx` 주입 |

- **둘이 겹치는 자리는 부모/자식으로 나눈다.** 원본 비율(52/126)을 그대로 쓴다.
- 등급색처럼 **여러 요소가 같이 물드는 것**은 전용 setter 하나로 묶는다
  (원본은 `.rk-*` 클래스 하나로 테두리·태그·아이콘·프레임이 동시에 바뀐다).
- ⚠ **등급색을 「테두리」가 아니라 「본문 배경」에 물리지 않는다.** 원본 CSS가 `border-color` 면
  테두리만이다. 배경 Image에 물리면 카드 전체가 등급색으로 칠해진다.
- 등급별 프레임처럼 **후보가 유한한** 경우는 배열 필드에 전부 물려두고 인덱스로 고른다 — 정적 취급.

### ★ CSS 클래스 하나가 만드는 요소를 낱개로 옮기면 반드시 하나가 빠진다

한 클래스가 **본체 + `::before` + `::after`** 를 동시에 그린다. 눈에 띄는 것부터 옮기다 보면
안 띄는 하나가 남고, 그 클래스를 쓰는 **모든 화면에서 똑같이** 빠진다.

> **[사고]** `.hud-frame` 은 세 요소다.
> ```css
> .hud-frame{ border:1px solid var(--line); ... }                       /* ① 외곽선 */
> .hud-frame::before,::after{ width:32px;height:32px;
>                             border:4px solid var(--cyan); opacity:.8; } /* ② 좌상·우하 ㄱ자 */
> ```
> 이식본은 **② 만** 옮겼다. ① 1px 외곽선이 **팝업 아홉 곳에서 통째로** 빠져 카드가 배경에 녹아 있었다.
> 코너 브래킷이 워낙 눈에 띄어서 「hud-frame 은 했다」고 넘어간 것이다.

**처방 — 클래스 하나 = 헬퍼 하나.** `AddCornerTicks` 처럼 조각 함수를 노출하면 조각만 불린다.
`AddHudFrame()` 처럼 **한 벌을 통째로 붙이는 함수**를 만들고, 조각 함수 주석에
「이것만 부르면 ○○이 빠진다」를 적는다.

**옮기기 전에 그 클래스의 규칙을 전부 센다.** 셋이면 셋을 옮겼는지 세고 넘어간다
(**[예시]** — `hud-frame` 은 위 사고 원본의 공용 프레임 클래스명이다. 클래스명은 원본마다 다르다):

```bash
# 클래스 본체 + 의사요소 + 다른 규칙의 오버라이드까지 한 번에
grep -no "\.hud-frame[^}]*}" 원본.html
grep -no "[^{}]*hud-frame::before[^}]*}" 원본.html   # 카드별 크기 오버라이드가 있다
```

### ★ 「테두리」는 대개 카드마다 색이 다르다 — 한 값으로 굽지 않는다

원본의 공용 프레임 클래스가 기본 테두리색을 주더라도 개별 카드가 덮는다.
**[예시]** 한 게임의 실측 — 네 값이 있었다. 클래스명·색은 원본마다 다르다:

| 카드 | 원본 CSS | 값 |
|---|---|---|
| `.shop-card` · `.sk-card` | `--ac:var(--cyan); border-color:var(--ac);` | 시안 |
| `.lucky-card` | `border:1px solid #2a3a58` | 자체 값 |
| `.anom-card` | `border:1.5px solid #b23a3a` | 자체 값 · **굵기도 다르다** |
| 나머지 | `.hud-frame` 상속 | `--line` |

헬퍼에 **색을 인자로 뺀다.** 기본값은 기본 테두리색, 덮는 카드만 넘긴다.
그리고 **테두리는 있는데 공용 프레임 클래스가 아닌** 카드가 있다 (**[예시]** `.lucky-card`·`.lko-card`) —
「테두리 = 코너 브래킷」으로 묶어 버리면 이쪽이 통째로 빠진다. 두 조건을 따로 받는다.

### ⚠ 애니메이션의 어두운 구간이 찍힌 캡처를 「정색」으로 오인하지 않는다

정적 캡처는 애니메이션의 **한 프레임**이다. 그 프레임이 어두운 구간이면 색을 어둡게 굽게 된다.

> **[사고]** 경고 헤더의 아이콘을 `#8a3a35` 로 구웠다. 원본은 `#ff5a4d` 이고,
> `anHdBlink` 가 주기의 40% 를 `opacity:.25` 로 보낸다. 캡처가 그 구간을 잡았을 뿐이다.
> **밝기를 색에 구우면 애니메이션을 붙여도 영영 어둡다.**

**색은 CSS 에서, 밝기 변화는 컴포넌트에서.** 캡처로 색을 정하기 전에
그 요소에 `animation` / `transition` 이 걸려 있는지부터 본다:

```bash
grep -no "\.anom-head \.wic{[^}]*}" 원본.html      # color:#ff5a4d + animation:anHdBlink
grep -no "@keyframes anHdBlink{[^}]*}" 원본.html   # 0%,60%{opacity:1} 61%,100%{opacity:.25}
```

### ★ 캡처에 절대 안 찍히는 것 둘 — `animation` 과 `:hover`

캡처만 보고 만들면 이 둘은 **존재 자체를 모른다.** 화면을 열 때 원본 CSS 에서 먼저 훑는다.

```bash
grep -no "animation:[^;]*;" 원본.html | sort -u -t: -k3
grep -no "[^{]*:hover{[^}]*}" 원본.html
```

| 원본 | 성질 | 이식 |
|---|---|---|
| `animation: anHdBlink 1.05s steps(1,end)` | **계단** — 한 주기에 두 값뿐 | `UIBlink` (듀티 0.6) |
| `transition: transform .25s` + `:hover{rotate(40deg)}` | 상태 전이 | `UIHoverRotate` |

- **`steps()` 를 사인파 맥동으로 대체하지 않는다.** 경고등의 성질이 계단에서 나온다.
  듀티도 절반이 아니라 원본 값(60%)을 쓴다 — 0.5 로 넣으면 눈에 띄게 급해진다.
- **`:hover` 는 무엇이 도는지 확인한다.** `.set-gear:hover{transform:rotate(40deg)}` 는
  아이콘이 아니라 **버튼 판 전체**가 돈다 (그래서 캡처에서 판이 마름모로 기울어 보인다).
- `:hover` 는 각도만 바꾸지 않는다. 같은 규칙의 `border-color`·`color` 까지 한 컴포넌트가 쥔다.

### ★★ 원본의 표기 **분기 개수**를 세고 그대로 옮긴다

원본은 한 자리에 삼항을 겹쳐 쓴다. 그 자리를 「값 있으면 찍고 없으면 비움」 2갈래로 접으면
**나머지 상태가 통째로 사라진다.** 화면에는 빈칸으로 나오니 아무도 에러를 못 본다.

```js
// 노드 비용 한 자리에 네 갈래가 들어 있다
let costTxt = root  ? '<span class="cost no">시스템</span>'
            : maxed ? '<span class="cost max">MAX</span>'
            : !reach? '<span class="cost no">잠김</span>'
            :         '<span class="cost">◆' + fmtCost(cost) + '</span>';
```

> **[사고]** `cost.HasValue ? 숫자 : null` 로 옮겨 `시스템`·`MAX`·`잠김` **세 갈래가 빈칸**이 됐다.

**규칙**

- 원본 한 자리의 **삼항·분기 수를 세고**, 옮긴 코드의 분기 수와 맞춘다. 수가 다르면 이관이 덜 된 것이다.
- **분기의 순서까지 옮긴다.** 위 예에서 `maxed` 가 `!reach` 보다 먼저라 **MAX 이면서 잠긴** 노드는
  `MAX` 로 뜬다. 순서를 바꾸면 다른 화면이 된다.
- 갈래마다 **색이 다른지** 본다 (`.cost` amber / `.cost.max` green / `.cost.no` muted).
  텍스트만 옮기고 색을 한 값으로 두면 상태 구분이 사라진다.

#### CSS 의 「기본 + .on 오버라이드」는 「숨김 + 표시」가 아니다

```css
.pip     { background:#2a3650; }   /* 미획득도 자리를 보여준다 */
.pip.on  { background:var(--nc); box-shadow:0 0 5px var(--nc); }
```

`enabled=false` 나 `SetActive(false)` 로 옮기면 **미획득 칸이 사라져** `1/8` 이 점 하나로 보인다.
원본은 **둘 다 보이고 색만 다르다** — 색을 바꿔야 한다.

#### `Infinity` 는 표기 분기를 같이 옮긴다

원본 `nodeMax` 가 `Infinity` 를 돌리면 표기는 pips 가 아니라 `Lv N` 으로 **갈라진다.**

```js
function nodeScaling(k){ const mx=nodeMax(k); return mx===Infinity || mx>12; }
```

> **[사고]** `Infinity` 를 `int.MaxValue` 로만 옮기고 분기를 안 옮겨서
> 노드에 **`1/2147483647`** 이 찍혔다. pips 12개도 같이 켜져 겹쳤다.

C# 에 `Infinity` 정수가 없으므로 **경계값(`> 12`)이 곧 계약**이다. 그 수가 UI 에서 오는 값
(pip 슬롯 개수 등)이면 상수로 박지 말고 **그 배열 길이에서 뽑는다.**

## ★ 화면 하나를 전수 대조표로 연다

**정적 캡처 점수만 보면 「배치는 맞는데 알맹이가 빠진」 상태를 못 잡는다.**
원본에서 그 화면을 만드는 함수를 찾아 요소를 빠짐없이 표로 펴고, 표를 만들기 전에 코드를 고치지 않는다 — **빈 칸이 곧 작업 목록이다.**
표 형식·절차·실제 사고는 [PD](PD.md) 「화면 하나를 「전수 대조표」로 여는 법」 이 정본이다.

UI/UX 가 추가로 보는 것 — **DOM과 캔버스 둘 다** 훑는다. `draw*` 호출 트리는 재귀적으로 끝까지 편다.

|---|---|
| **엔티티마다 모양이 다른가** | 원본 탄환·미사일·드론·적은 전부 다른 도형이다. 전부 점 하나로 찍어 「색만 있는 도형」이 됐다 |
| **표기 크기가 원본 수치인가** | 원본 반지름을 그대로 통과시킨다. 임의값을 넣어 2~3배 작았다 |
| **지연 로드 아트를 다시 묻는가** | 열릴 때 한 번만 물어 전부 null → 평생 폴백 도형으로 남았다 |
| **데이터가 바뀌면 그 자리에서 갈리는가** | 배경은 매 프레임 고른다. 구역을 바꿔도 그대로였다 |
| **눌러야 하는 것이 다 버튼인가** | 썸네일이 그림일 뿐이었다. 원본은 전부 탭 가능하다 |
| **전면 히트 영역에 가려지지 않는가** | 전체가 히트 영역이라 그 위 버튼이 전부 먹혔다 |
| **애니메이션 위상·속도가 원본 값인가** | 드리프트를 11px/s 로 넣었는데 원본은 **1.1** |
| **상태가 바뀌면 같이 바뀌는 것까지 옮겼나** | 펼침 상태에서 원본이 숨기거나 줄이는 형제 요소가 그대로 남아 있었다 |
| **분수 배치를 픽셀로 박지 않았나** | 고정 픽셀로 구워 펼침 상태에서 다 어긋났다 |

## 폰트 · 글리프 — 「원본 폰트를 가져오면 된다」가 아니다

원본이 CSS에 폰트를 적어도 **그 폰트가 모든 글리프를 그리는 게 아니다.**

> **[사고]** 원본은 Google Fonts로 `Chakra Petch` + `Share Tech Mono` 를 싣는다.
> 그런데 **둘 다 한글이 0자다**(cmap 실측). 원본에서도 한글은 OS 폴백이 그린다.
> 즉 **원본 폰트는 이 게임의 주폰트가 될 수 없다.**

### ★ 주폰트는 「가장 넓은 글리프 집합」이 가져간다

폰트를 고르는 순서가 거꾸로 되기 쉽다. 자형(원본과 닮았는가)부터 보면 반드시 폴백이 붙는다.

**순서는 이렇다.**

1. **화면에 실제로 나오는 문자 집합을 센다** — 본문 언어 + 기호 + 이모지.
2. **후보 폰트의 cmap 을 실측해 표로 만든다.** 「있을 것 같다」로 고르지 않는다.
3. **본문 언어를 100% 덮는 폰트를 주폰트로 정한다.** 여기서 자형은 2순위다.
4. 남는 구멍만 스프라이트로 내린다.

> **[예시]** 실측표 — 프로젝트마다 값이 다르다. 다시 잰다:
>
> | 폰트 | 글리프 | 한글 | ★ ✓ ▼ ● ◆ ▲ ⚠ ∞ → ₩ | ✕ ◈ ⚙ | 이모지 |
> |---|---|---|---|---|---|
> | **Noto Sans KR** | 23,174 | **11172/11172** | 전부 O | ✕◈⚙ 없음 | 없음 |
> | Chakra Petch | 725 | **0** | 일부 | 없음 | 없음 |
> | Share Tech Mono | 267 | **0** | ∞ 만 | 없음 | 없음 |
>
> 한글을 쥔 것이 하나뿐이므로 **선택의 여지가 없다.** 자형 차이는 허용 오차로 못박고 넘어간다.

**자형을 살리겠다고 「원본 폰트 주 + 본문언어 폴백」으로 가면 안 된다.**
그러면 거의 모든 문자열이 폴백을 타고, 폴백을 없앤 것과 자원 소모가 같아진다.

### 폴백 폰트는 쓰지 않는다 — 「폰트는 하나」가 기본값이다

폴백 폰트는 한 글자를 살리자고 **폰트를 하나 더 들이는 일**이다.

- 빌드에 폰트 파일이 하나 더 실린다 (다이내믹이면 TTF 원본이 통째로).
- **폴백이 조용히 메워준다.** 폰트에 없는 글자를 새로 써도 그 자리에서 안 드러나고,
  나중에 떼는 순간 어디가 깨질지 아무도 모르는 상태가 된다.
- 자형이 두 종류로 섞인다.

**먼저 주폰트에 정말 없는지 cmap 을 실측한다.** 「없을 것 같다」로 폴백을 얹지 않는다.

```bash
# TTF 의 cmap 을 직접 파싱해 대상 코드포인트 유무를 찍는다 (fontTools 없어도 된다)
python cmap.py *.ttf
```

**폴백은 두 곳에 따로 있다. 둘 다 세야 「0」이라고 말할 수 있다.**

| 자리 | 확인 |
|---|---|
| 엔진 전역 설정 | `TMP_Settings.fallbackFontAssets` |
| **폰트 에셋마다** | `TMP_FontAsset.fallbackFontAssetTable` — 안 쓰는 기본 에셋에도 붙어 있다 |

점검을 **메뉴로 만들어 둔다**(`Verify No Font Fallback`). 눈으로 확인하는 규칙은 반드시 새어 나간다.

### ⚠ 폰트를 바꾸면 「참조가 끊긴 프리팹」이 남는다 — 화면에서만 멀쩡해 보인다

옛 폰트 에셋을 지우면 그것을 물고 있던 프리팹은 죽은 GUID 를 가리킨 채 남는다.
**그런데 에디터에서 열어 보면 멀쩡하다** — TMP 가 로드할 때 기본 폰트로 자동 대체하기 때문이다.

> ⚠ 그래서 「모든 TMP 를 새 폰트로 바꾸는」 도구가 **0개 변경**을 보고했다.
> 메모리 값(`text.font`)은 이미 새 폰트였고, 직렬화 파일만 깨져 있었다.

**판정은 파일에서 한다.**

```bash
grep -rl "<옛 폰트 GUID>" Assets/ | wc -l      # 0 이어야 한다
```

고치는 순서:

1. **스크립트로 굽는 프리팹이 있으면 다시 굽는다** — 코드가 새 폰트를 물린다.
2. 남는 것은 스크립트가 소유하지 않는 것들이다(손으로 만든 공용 프리팹·머티리얼).
   `m_fontAsset` 만이 아니라 **`m_sharedMaterial`·머티리얼의 `_MainTex` 까지** 옛 폰트의
   서브에셋을 가리킨다 — 셋을 같이 갈아야 한다.
3. 끝나고 **프리팹 전수로 `font == null` 을 센다**(`Verify TMP Font References`).

### Dynamic 폰트는 에디터에서 계속 자란다

한글처럼 글리프가 수천 자면 Dynamic(런타임 래스터화)이 맞다 — 쓰는 글자만 아틀라스에 채운다.
대신 **에디터에서 화면을 열 때마다 에셋이 커진다.** 2MB 넘는 텍스트 에셋이 세션마다 diff 에 잡힌다.

**커밋 전에 아틀라스를 비우는 메뉴를 둔다**(`ClearFontAssetData`). 런타임 동작에는 영향이 없다.

### 스프라이트가 활자와 같은 크기로 앉게 만드는 법

TMP 는 스프라이트 에셋의 `faceInfo.pointSize` 가 0 이면 **`ascentLine / metrics.height` 로 정규화**한다.
그래서 `metrics.height` 는 최종 크기에 영향이 없고, 실제 높이는 이렇게 정해진다:

```
렌더 높이   = ascentLine / pointSize * fontSize * spriteCharacter.scale
렌더 폭     = 렌더 높이 * metrics.width / metrics.height     ← 종횡비는 metrics 가 정한다
advance     = 렌더 높이 * metrics.horizontalAdvance / metrics.height
baseline까지 = 렌더 높이 * metrics.horizontalBearingY / metrics.height
```

따라서 **`metrics` 는 글리프 바운딩박스를 그대로**(단위 무관·비율만 맞으면 된다) 넣고,
크기는 `scale` 하나로 잡는다:

```
scale = 목표높이(em) / (ascentLine / pointSize)
```

목표 높이는 **눈대중이 아니라 폴백이 그리던 값을 실측해서** 쓴다. 바꾸기 **전에** 재 둔다:

```csharp
tmp.text = "A★∞H"; tmp.ForceMeshUpdate(true, true);
var ci = tmp.textInfo.characterInfo[i];
// 높이 = topLeft.y - bottomRight.y,  yMax = topLeft.y - baseLine,  advance = xAdvance - origin
// ⚠ 월드스페이스 TMP 는 0.1 배수가 끼어 있다 — fontSize 가 아니라 fontSize/10 으로 나눠야 em 이 된다
// ⚠ 활자 쪽 실측값에는 SDF 패딩이 포함된다. 스프라이트에도 같은 여유를 주면 그만큼 상쇄된다
```

**[예시]** 실측 — `∞` 를 폴백 폰트에서 스프라이트로 내린 결과. 프로젝트마다 값이 다르다. 다시 잰다:

| | 높이 | yMax | advance |
|---|---|---|---|
| 폴백 폰트(LiberationSans) | 0.4090em | 0.4940 | 0.7130 |
| 스프라이트 | 0.4141em | 0.4961 | 0.7148 |
| 차이 | +1.2% | +0.4% | +0.25% |

### 아트는 손으로 그리지 않는다

- `∞` 는 **폴백이 그리던 그 폰트의 글리프를 래스터라이즈**해 구웠다
  (PIL `ImageFont.truetype` → `anchor="ls"` 로 베이스라인 기준 렌더 → 알파 bbox 크롭).
- `★`·`✓` 는 게임이 이미 쓰는 아트를 **픽셀 그대로** 가져왔다.
  인라인 별과 별 표시 컴포넌트의 별이 다른 모양이면 그게 더 어색하다.

### ★ 치환 Helper 를 안 타는 경로가 남는다 — 그게 진짜 버그다

폴백이 있을 때는 폴백이 메워주니 안 보인다. 폴백을 떼면 드러난다.
**데이터에서 그 글자가 든 컬럼을 세고, 그 컬럼의 표시 경로를 전부 훑는다.**

```bash
# 어느 테이블 · 어느 컬럼에 들어 있는지부터 센다
python -c "...json 순회해서 컬럼별 카운트..."   # → Name 12 · Description 164 · Script 1
# 그 다음 그 컬럼을 읽는 코드를 전부 찾는다
grep -rn "row\.Name\|node\.Name\|\.Description\b" Assets/Scripts/UI
```

트리 노드 **이름**(★ 12개)이 치환을 안 타고 있었다 — 폴백에도 `★` 는 없었으니
**원래부터 공백으로 나오고 있던** 것을 이때 발견했다.
치환 함수는 결과에 원래 글자가 남지 않으므로 **두 번 호출해도 안전하게** 만들어 둔다.

### TMP 일반

- 폰트에 없는 기호를 텍스트로 적지 않는다. 도형은 Image/스프라이트로 얹는다.
- **TMP는 같은 숫자를 브라우저보다 크게 그린다** (**[예시]** 실측 25%쯤). 원본 CSS `font-size` 를
  그대로 넣지 말고 캡처의 글리프 높이를 재서 역산한다.
- 폰트 자형·자간 차이는 허용 오차다. 맞추지 않는다.

## 렌더링 함정

- **한 GameObject에 Graphic 하나.** TMP 오브젝트에 `AddComponent<Image>()` 는 **null 반환** → NRE.
- **`Image.type = Filled` 은 sprite가 없으면 무시된다.**
- **`Image.Type.Tiled` 는 원본 픽셀 크기로 가로·세로 **양쪽** 반복한다.**
- **9-slice 보더는 원본 픽셀 크기 그대로 그려진다.** 좌우 보더 합이 배치 크기를 넘으면 가운데가 사라진다.
  **그 아트를 쓰는 가장 작은 자리를 기준으로** 보더를 잡는다.
  원본이 `background-size:100% 100%` 면 9-slice가 아니라 **통짜 스트레치**다.
- **세로로 크게 눌리는 장식 아트는 속이 뭉개진다.** 캡처 색을 뽑아 단색 판을 깔고 아트는 테두리로만.
- **원본 카드·버튼은 거의 전부 `border-radius` 가 있다.** 채움과 테두리를 같은 반경으로 맞춘다.
- **9-slice 는 스트레치 존이 심판이다.** 보더를 장식 두께에 「딱 맞게」 자르지 않는다 —
  경계의 안티앨리어스·압축 노이즈 픽셀 한 줄이 스트레치 존에 걸리면 배치 폭 전체로 늘어나
  뿌연 베일·띠가 된다. 4방향 모두 장식이 **완전히 끝난 균일(투명) 지점 너머까지** 보더를 잡아
  코너 조각이 장식 전부를 삼키게 한다. 스트레치 존(중앙·엣지 띠 4개)에는 완전 투명 또는
  완전 균일 픽셀만 남아야 한다.
  > **[사고]** 프레임 링 스프라이트의 보더를 라인 두께(3px)에 딱 맞게 잘랐더니 선택 카드 전체가
  > 흰 베일로 덮였다 — 경계 픽셀이 엣지 띠에 걸려 카드 전폭으로 스트레치된 것. 보더를 장식 밖
  > 투명 지점(7px)까지 늘려 해결했다.
  - 검증은 눈이 아니라 스크립트로 — 보더 기준 5개 존을 잘라 알파·색 분산이 0인지 잰다
    (알파 `std > 2` 또는 스트레치 축 방향 인접 차 `> 8` 이면 오염).
  > **[사고]** 반경별 9-slice 채움·테두리 프리미티브를 만들어 두고도, 프리팹을 만들 때
  > Image 의 Source Image 를 비우고 색만 채웠다 — 한 저장소 실측으로 원본 `border-radius` 220곳에
  > 색-판 Image 390개가 대응돼 전 UI 가 각진 사각형이 됐다. **색을 옮겼다고 모양이 옮겨진 게 아니다.**
- **중첩 Canvas는 세트를 완성한다.** `overrideSorting` + `sortingOrder` + `GraphicRaycaster` +
  루트와 같은 `renderMode`/`worldCamera`. **`worldCamera` 가 비면 WorldSpace 렌더에서 하위가 통째로 안 그려진다.**
  형제 순서로 해결되면 **중첩 Canvas를 아예 쓰지 않는다.**
- **중첩 Canvas의 order를 프리팹에 굽지 마라.** 루트 `sortingOrder` 는 창이 열릴 때 프레임워크가
  나중에 넣는다. `OnEnable` 에서 한 번만 읽으면 order가 굳어 뒤에 깔린 히트 영역에 계속 먹힌다.
- **투명 히트 판에는 `raycastTarget` 을 명시적으로 켠다.**
- **클리핑을 빼먹지 않는다.** 원본이 `clip()`/`overflow:hidden` 이면 마스크가 필요하다.
- ★ **원본의 그리기 순서를 계층 순서로 옮긴다.** 원본은 한 컨테이너에 SVG 를 먼저 쓰고
  노드 `div` 를 나중에 붙여 **선이 노드 뒤로 지나간다.** Unity 는 형제 순서가 그리기 순서라,
  같은 부모에 섞어 `Instantiate` 하면 **먼저 만든 것만 뒤로 간다** — 풀링으로 셀이 나중에 생기면
  순서가 뒤집힌다. **전용 부모를 하나 만들어 `SetAsFirstSibling` 으로 고정한다.**
- ★ **선이 붙는 점은 「셀 사각형 중심」이 아니다.** 원본은 노드 상단에서 잰 고정 오프셋
  (`y = node.y*YS + 42`) 으로 **아이콘 원 중심**에 붙인다. 우리 셀은 이름·레벨·비용까지 포함해
  더 길므로 셀 중심을 쓰면 선이 라벨 한가운데서 나온다. **아이콘 rect 를 기준으로 비율을 뽑는다** —
  칸 크기가 해상도마다 달라지므로 픽셀로 박으면 안 된다.

### ★ 비율이 안 맞는 rect 에서 스틸(contain)과 영상(cover)이 갈린다

같은 자리에 **스틸 폴백과 영상**을 겹쳐 두면, rect 비율이 소스와 다를 때 둘이 다르게 앉는다.

| | 맞추는 방식 | 비율이 다르면 |
|---|---|---|
| `Image.preserveAspect` | contain | **레터박스** — 남는 쪽에 여백 |
| `VideoPlayer` 기본 (`aspectRatio`) | cover | **잘라 채움** — 넘치는 쪽이 잘린다 |

> **[사고]** 확대뷰 rect 가 0.6555 인데 소스는 0.6806 이었다. 스틸은 여백이 생기고 영상은 잘려
> **같은 화면인데 그림 크기가 달랐다.**

**해법은 fit 모드를 맞추는 게 아니라 컨테이너 rect 를 소스 비율에 맞추는 것이다.**
비율이 같아지면 contain 과 cover 가 같은 결과를 낸다 — 코드로 분기할 게 없어진다.
원본 CSS 에 크기가 적혀 있으면 그 값이 곧 소스 비율이다 (**[예시]** 882×1296).

## 재사용 · 생성

- **새로 그리기 전에 기성 공용 프리팹을 먼저 뒤진다.** 순서: 기존 컴포넌트 재사용 → 프리팹 변형 추가
  → 그래도 안 되면 새 클래스.
- **무조건 동적 생성.** 리스트성 UI는 인스펙터에 미리 박아두지 않는다.
  단, **개수가 작고 상한이 고정인 것**(스택 점 5칸 등)은 프리팹에 미리 만들고 켜고 끄는 편이
  풀 개체를 매번 만드는 것보다 낫다.
- **UI는 표기만 한다.** DB id를 인스펙터에 적어두지 않는다. 외부가 런타임 주입한다.
- 프리팹은 **코드로 생성한다.** 손으로 클릭한 건 다음 실행에 날아간다.
- `[SerializeField]` private 참조는 리플렉션 주입 헬퍼로 넣는다.
  **UnityEngine.Object 가 아닌 직렬화 클래스 배열**은 리스트 헬퍼로 못 넣는다 — `SerializedProperty` 로 원소마다 채운다.

### ★ 「재사용 우선」에는 단서가 붙는다 — **원본 구조가 같을 때만**

이름이 같다고 같은 물건이 아니다. **원본에서 두 화면의 DOM/CSS 를 나란히 놓고 구조가 같은지 먼저 본다.**

> **[사고]** 모집 확률표를 상점 `OddsPopup` 으로 돌려 썼다. 「확률표니까 확률표 팝업」이었다.
> 원본은 설계가 아예 달랐다 — **좌정렬 2열 · 행 밑줄 · `hud-frame` · 전체폭 닫기 버튼**.
> 결국 `RecruitRatesPopup` 을 새로 만들어 분리했다. 억지로 돌려 쓰는 동안 두 화면 다 틀렸다.

**판단 기준** — 아래 중 하나라도 다르면 **새로 만든다**:
정렬(좌/중앙) · 열 수 · 행 구분 방식(밑줄/카드) · 프레임 종류 · 버튼 배치.
공용으로 남길 것은 **그보다 작은 단위**(행 컴포넌트, 프레임)다.

### ⚠ 구운 뒤 **임포트 설정을 안 걸면 굽는 의미가 없다**

절차 생성 텍스처는 저장이 끝이 아니다. 프로젝트 기본값이 `Multiple` 이면 유니티가 새 텍스처를
**자동 슬라이스**해 버리고, `Tight` 메시면 투명 여백을 **잘라낸다.**
둘 다 `sprite.rect` 를 바꾸므로 「캔버스 좌표를 그대로 옮긴다」는 전제가 무너진다.

> **[사고]** 홀로그램 5층을 464² 로 구웠는데 스프라이트가 이렇게 잡혔다:
> `base 414²` · `alt 284×176` · **`reticle 8×13`** (눈금 하나!). 이름도 전부 `_0` 접미였다.
> 다섯 층을 같은 rect 에 늘려 그리니 **층마다 배율이 달라져** 항성이 썸네일을 꽉 채웠다.
> 그림은 정확히 구워져 있었다 — 틀린 건 임포터다.

**생성기가 저장 직후 설정을 강제한다.** 최소 네 가지:

```csharp
importer.textureType      = TextureImporterType.Sprite;
importer.spriteImportMode = SpriteImportMode.Single;      // ← 자동 슬라이스 차단
importer.alphaIsTransparency = true;
settings.spriteMeshType   = SpriteMeshType.FullRect;      // ← 여백 트리밍 차단
```

**판별법은 한 줄이다.** 스프라이트 이름에 `_0` 이 붙었거나 `sprite.rect != 텍스처 크기` 면 잘린 것이다:

```csharp
var sp = AssetDatabase.LoadAssetAtPath<Sprite>(path);
var tx = AssetDatabase.LoadAssetAtPath<Texture2D>(path);
Debug.Log(sp.name + " " + sp.rect.size + " vs " + tx.width + "x" + tx.height);
```

### ★ 캔버스 한 장을 옮길 때는 **색과 움직임**으로 층을 가른다

원본이 `<canvas>` 하나에 매 프레임 여러 겹을 그리면, 그걸 **한 장으로 구우면 안 된다.**
데이터로 갈리는 색도, 층마다 다른 회전도 줄 수 없기 때문이다.

> 선택 카드의 홀로그램 연출은 원본이 9층인데 이식본은 배경 한 장이었다
> (빌더 주석: 「아트 없음 — 색 박스로 대체」).

가르는 기준:

| 기준 | 처리 |
|---|---|
| **색이 다르다** (`ac` / `ac2`) | 층을 나눠 굽고 **흰색+알파**로만 저장 · 런타임 tint |
| **회전 속도가 다르다** | 층마다 따로 굽고 `UISpin` 에 **원본 rad/s 를 환산해** 넣는다 |
| **회전이 아니라 폭 변조다** | 스핀으로 못 만든다. 정지 프레임을 굽고 과제로 남긴다 |
| 정적이고 색이 같다 | 한 장으로 합친다 |

**알파는 텍스처에 굽는다.** 원본 `globalAlpha` 가 층마다 다르면(0.16 / 0.55 / 0.6 / 0.06)
런타임에서 하나로 통일할 수 없다. tint 는 RGB 만 갈아끼우고 알파는 1로 둔다.

### ★ 절차 생성 도형은 **구운 PNG의 알파를 직접 찍어** 확인한다

화면에서 「좀 뿌옇다」로 보이는 것은 대개 **도형이 아니라 알파 프로파일**이 틀린 것이다.
눈으로는 판별이 안 된다.

> **[사고]** 카드 내곽 발광을 `RoundRectSdf` 깊이로 그렸는데, SDF 는 **직선 구간에서 `qx=qy=0` 이라
> `-radius` 로 포화**한다. 그래서 깊이가 상수가 되고 **카드 전체에 균일 알파**(blur 48 → 112/255)가
> 깔렸다. 「발광이 세다」로 몇 번 조정했지만 원인은 SDF 포화였다.

```bash
# 구운 뒤 중앙 가로선의 알파를 그대로 찍는다 — 계단이 없으면 포화다
python -c "
from PIL import Image; im=Image.open('out.png').convert('RGBA'); w,h=im.size
print([im.getpixel((x,h//2))[3] for x in range(0,w,4)])"
```

**볼 것** — ① 가장자리에서 0으로 떨어지는가 ② 안쪽이 상수로 굳지 않았는가
③ 의도한 띠(테두리·간격)가 실제로 계단으로 나오는가.

### ★ 공용 팩토리 헬퍼는 **입력 조합별 degenerate 케이스를 스캔**한다

파라미터 몇 개를 받는 헬퍼는 특정 조합에서 조용히 다른 그림을 낸다.

> **[사고]** `EnsureSlicedSprite` 가 텍스처 크기를 `radius` 만 보고 잡았다.
> `thickness ≥ half` 인 조합에서 **안쪽 사각형이 음수**가 되어 테두리가 통째 채움으로 바뀌었다
> (LR 등급 카드가 노란 판때기가 됐다). 다른 등급에서는 정상이라 한참 안 보였다.

헬퍼를 고치거나 새로 만들면 **호출부에서 실제로 쓰는 인자 조합을 전부 뽑아 한 번씩 굽고**
결과를 몽타주로 붙여 본다. 조합 수가 많지 않다 — 안 하면 한 조합만 틀린 채로 남는다.

## UI/UX 파트 완료 체크리스트

- [ ] **미측정 항목 0** — 못 잰 것은 `미측정(사유)` 로 적고 **재측정 대기**에 등록했다
- [ ] **내 권한 밖 파일을 건드리지 않았다** (PD 「역할 기동 규약」 권한표)

1. 원본 함수를 **전수 대조표**로 펴고 빈 칸이 0인가 (「화면 하나를 전수 대조표로 연다」)
2. 장식과 데이터 종속 아트가 **다른 필드**인가 (「장식과 내용물을 한 필드에 겸하지 않는다」)
3. 등급색 같은 공통 강조가 **테두리에** 걸리나 (배경이 아니라) (「장식과 내용물을 한 필드에 겸하지 않는다」)
4. 레이아웃 그룹 아래 낱개 아이콘에 `LayoutElement` 가 있나 (「레이아웃 함정」)
5. 폰트가 못 그리는 글리프를 텍스트로 넣지 않았나 (「폰트 · 글리프」)
6. 치환 Helper 를 **모든 표시 경로**가 타나 (「치환 Helper 를 안 타는 경로가 남는다」)
7. 분수 배치를 픽셀로 박지 않았나 (「분수로 정의된 배치를 픽셀로 굽지 않는다」)
8. Play Mode에서 눌러야 할 것이 실제로 눌리나 (`RaycastAll` 첫 결과가 자기 자신)
9. 지연 로드 아트를 다시 묻는가
10. 상태 전이(접힘↔펼침, 정지↔재개)를 실제로 눌러 확인했나
11. CSS 레이아웃을 **대응표**로 옮겼나 — 없는 프리미티브를 비슷한 걸로 때우지 않았나 (「CSS 레이아웃 프리미티브는 Unity 와」)
12. 수치를 **CSS 계산 → 캡처 검증** 2단계로 넣었나 (「CSS 수치는 계산 → 캡처로 검증 2단계」)
13. 스틸과 영상이 겹치는 자리의 **rect 비율을 소스에 맞췄나** (「비율이 안 맞는 rect 에서 스틸(contain)과 영상(cover)이 갈린다」)
14. 재사용한 공용 창이 **원본에서도 같은 구조**인가 (「재사용 우선에는 단서가 붙는다」)
15. 새로 구운 절차 도형의 **알파 프로파일을 찍어 봤나** (「절차 생성 도형은 구운 PNG의 알파를 직」)
16. 팩토리 헬퍼를 고쳤으면 **호출부 인자 조합을 전부 굽어 봤나** (「공용 팩토리 헬퍼는 입력 조합별 degen」)


## ★★ 문구는 «상자에 맞춘다» — 크기만 옮기면 서체가 바뀔 때 넘친다

원본이 문구를 <b>상자에 줄여 넣는</b>(`배율 = min(상자폭/글자폭, 상자높이/글자높이, 1)`) 것이 흔하다.
크기만 옮기면 **그 서체로는 마침 맞는** 상태가 되고, 서체를 갈면 바로 넘친다.

| 옮길 것 | 어디서 오나 |
|---|---|
| 글자 크기 | 덤프의 `font` |
| **상자** | **소스** — 표시 개체의 속성이 아니라 «호출 인자»라 덤프에 없다 |
| 줄이기만(키우지 않음) | 소스 식 그대로 |

⚠ **맞추기를 «한 번 재고 캐시»하면 안 된다** — 캔버스가 자리를 잡기 전에 재면 0 이 나오고,
그걸 캐시하면 영영 안 줄어든다. **0 은 «잰 것»으로 치지 않는다.**

## ★★ 화면 «층»은 덤프의 부모·형제 순서로 정한다 — 그림으로 못 읽는다

반투명 디머 아래의 밝은 UI 는 「덮였다」인지 「위에 있다」인지 **눈으로 안 갈린다.**
실측 사례로 시작 화면 대역을 스크린샷으로 정했다가 **원본과 반대**로 두었다 (`재발방지` #165).

⚠ **대역을 옮기면 그리는 순서와 «입력 순서»가 같이 바뀐다** — 옮긴 뒤 「그 버튼이 아직 눌리나」를 잰다.


## ★★ 9슬라이스는 «인셋 값»이 아니라 **«그려지는 두께»**로 검사한다

인셋은 **스프라이트 px** 단위다. 엔진은 모서리를 그 크기 «그대로» 그리는데,
캔버스가 원본을 배율만큼 키우면 **가운데만 늘어나고 모서리는 남는다** —
테두리가 원본의 `1/배율` 두께가 되고 모서리 곡률이 조여 보인다.

```
그려지는 두께 = 인셋 ÷ (스프라이트 PPU × 배수) × 캔버스 기준 PPU
목표          = 인셋 × 화면 배율
⇒ 배수 = 1 / 화면 배율
```

⚠ **「소스와 같은 인셋」은 입력이 맞다는 뜻일 뿐이다** — 물어야 할 것은 **화면에 몇 px 로 나오나**다
(`재발방지` #166).

## ★ «차오르는» 바는 자르는 것이 아니라 **폭이 자라는 것**일 수 있다

원본이 같은 9슬라이스 판의 **폭**을 바꾸면, 폭이 줄어도 **양끝 둥근 마감이 남는다.**
그림을 «자르는» 방식으로 만들면 **가득 찼을 때만 같아 보이고** 차오르는 동안 끝이 싹둑 잘린다.
⇒ 원본이 «자르나 늘리나»를 소스에서 확인하고 같은 쪽을 쓴다.
