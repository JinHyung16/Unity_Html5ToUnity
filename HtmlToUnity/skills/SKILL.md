# HtmlToUnity — HTML5 → Unity 이관 오케스트레이션

## 이 폴더가 무엇인가

**HTML5 게임을 Unity로 이관하는 범용 오케스트레이션 문서 세트**다.
특정 타이틀에 종속되지 않는다 — **어떤 HTML5 게임에도 그대로 쓴다.**

만족시켜야 하는 목적은 둘이다.

1. **HTML5 게임을 Unity 엔진으로 100% 이관한다** — 화면·그래픽·시스템·콘텐츠 전부
2. **이관한 Unity 빌드가 원본과 100% 똑같이 플레이된다** — 「돌아간다」가 아니라 「원본과 같다」가 완료 조건
3. **이관 과정이 사람의 유니티 조작을 요구하지 않는다** — 원본을 만든 사람은 **코딩도 유니티도 모를 수 있다**

**원본이 심판이다. 다르면 유니티가 틀린 것이다.**

### ★★ 세 번째 목적이 나머지 둘의 완료 기준을 바꾼다

이관을 의뢰하는 사람은 대개 **HTML5 게임을 만든 사람**이지 유니티 사용자가 아니다.
그 사람에게 「에디터를 열고 이 메뉴를 누르세요」·「인스펙터에서 이 값을 넣으세요」라고 하는 순간
**그 절차는 거기서 멈춘다.** 무엇을 누르는지도, 잘못 눌렀는지도 모르기 때문이다.

| ✗ 절차가 아니다 | ✓ 이렇게 한다 |
|---|---|
| 「`Tools > …` 메뉴를 눌러 주세요」 | **배치모드로 직접 실행한다** (아래) |
| 「인스펙터에서 라벨을 지정해 주세요」 | 에디터 API 로 **코드가 지정한다** |
| 「프리팹을 만들어 주세요」 | **빌더 스크립트가 굽는다** (확정표 10-b) |
| 「패키지를 설치해 주세요」 | `Packages/manifest.json` 을 **직접 고친다** |

**사람에게 남기는 것은 둘뿐이다** — ① 원본 게임을 건네주는 것 ② 마지막에 열어서 **보는 것**.

⚠ **그리고 결과물은 「돌아가는 수준」이 아니라 프로 수준이어야 한다.**
비개발자가 의뢰했다는 사실이 품질을 낮출 이유가 되지 않는다 —
오히려 **그 사람은 결과물을 검수할 수 없으므로** 기준을 우리가 지켜야 한다.

### 유니티 에디터는 **배치모드로 돌린다**

MCP 에디터 제어가 없어도 **에디터 코드를 실행할 수 있다.** 셸과 유니티만 있으면 된다.

```bash
# [예시] 정적 메서드 하나를 헤드리스로 실행한다
<Unity실행파일> -batchmode -quit -nographics -silent-crashes \
  -projectPath <프로젝트> -executeMethod <Namespace.Class.Method> -logFile <로그>
```

| 되는 것 | 조건 |
|---|---|
| 메뉴 항목·에디터 툴 실행 | 대상이 **인자 없는 `static` 메서드** |
| 에셋 임포트·설정 에셋 생성·프리팹 굽기 | — |
| 테스트 실행 | `-runTests` |

⚠ **에디터가 그 프로젝트를 열어 두면 실패한다** (같은 프로젝트를 두 인스턴스가 못 연다).
**이관 중에는 에디터를 닫아 둔다.** 열려 있으면 **닫고 → 돌리고 → 다시 연다.**
사람에게 닫아 달라고 하기 전에 **저장 안 된 작업이 날아갈 수 있다는 것을 먼저 알린다.**

## 언제 여나

**이 스킬이 열렸다는 것은 이관 작업이라는 뜻이다.** 아래대로 움직인다.

| 언제 | 무엇부터 |
|---|---|
| HTML5 게임을 Unity 로 **새로 이관** | [PD.md](PD.md). 착수 질문(확정표 전 행)의 답을 받기 전에 **아무것도 만들지 않는다** |
| 이관한 것이 **원본과 같은지 검증** | 같은 문서. PD 를 QA/게이트 역할로 연다 |
| 원본에서 **아직 안 옮긴 것**을 옮긴다 (누락 필드·미구현 화면) | 해당 파트 문서만 (`UIUX.md` · `ResourceRule.md` · `Transfer_Programmer.md` …) |

### ★★ 사람은 「이관」이라는 말을 쓰지 않는다

**어휘로 판정하지 않는다.** 같은 요청이 사람마다 다르게 나온다 —

> 「이거 유니티로 **환원**해줘」 · 「유니티로 **옮겨**줘」 · 「유니티로 **만들어**줘」
> 「이 게임 **유니티 버전** 뽑아줘」 · 「**포팅**해줘」 · 「유니티로 **바꿔**줘」
> 「이거 유니티에서 **돌아가게** 해줘」 · 「**컨버팅**」 · 「**마이그레이션**」

**공통점은 「HTML5/웹 게임」과 「Unity」가 한 문장에 있다는 것**이다. 그러면 이 스킬이다.

### 애매하면 **한 줄로 묻고 Y/N 을 받는다**

용어가 애매하거나(「환원」이 무엇을 되돌리는 것인지 불분명), 대상이 웹 게임인지 확실하지 않으면
**만들기 전에** 이렇게 묻는다.

> **「HTML5 게임을 Unity 로 제작(이관)하는 것을 원하십니까?  Y / N」**

| 답 | 무엇 |
|---|---|
| **Y** | 이 스킬대로 간다 — `PD.md` 착수 질문부터 |
| **N** | 스킬을 닫고 `CLAUDE.md` 로 돌아간다. **평소 작업에는 이 문서 세트를 열지 않는다** |

⚠ **되묻는 것은 한 번뿐이다.** 「예」를 받으면 그다음부터는 묻지 않는다 —
회차마다 되물으면 사람이 같은 답을 계속 하게 된다.

⚠ **어느 줄인지는 원장이 가른다.** `.claude/HtmlToUnity_작업내역.md` 가 **없으면** 신규 착수(첫 줄)다.
**있으면** 신규가 아니다 — 확정표의 빈 행·「미확인」 행만 다시 묻고, 원장의 최신 회차 → 미흡 목록 →
**최하위 미통과 게이트**로 간다 (PD 「첫 턴에 하는 일」의 갈림길 판정).
프로젝트 규칙과 어긋나면 **`CLAUDE.md` 가 우선한다.**

## 구성

```
PD            오케스트레이터 — 확정 · 배분 · 게이트 · 최종 QA
├── 지식 (이관에 직접 참여하지 않는다. 정보를 제공한다)
│    ├── Design    기획 — 상수·테이블·문구·밸런스
│    ├── Client    클라 — 시뮬 루프·계산·수치 정밀도
│    ├── Fx    연출 — 렌더 패리티·합성·색공간
│    └── UIUX      UI/UX — 레이아웃·좌표계·폰트/글리프
├── 이관 (지식을 합쳐 실제로 옮긴다 — 3패스)
│    ├── Transfer_Programmer   ① 코드/데이터   ③ 배선
│    └── Transfer_Artist       ② 프리팹/연출
├── 규약 — {DataFramework · GameFramework · UIFramework · PrefabRule · ResourceRule}
├── 공통절차     전 파트가 매번 쓰는 것 — 측정 · 캡처 · 감사 · 원본에서 답 찾는 법
├── 재발방지     게임을 넘어 반복되는 사고와 막는 장치 (착수 전에 훑는다)
└── 분석로직     프로젝트마다 새로 만드는 문서의 생성 규격
```

**프로젝트마다 새로 만드는 것은 셋뿐이다** — 확정표(착수 질문 전부의 답 · PD 소관) · `.claude/HtmlToUnity_작업내역.md`(원장) ·
`<원본폴더>/HtmlToUnityLogic/` 8종(실측 기록). **나머지 문서는 프로젝트가 바뀌어도 그대로 쓴다.**

원본을 돌려 보며 캡처를 남기면 같은 층에 `<원본폴더>/Html_Screenshot/` 이 넷째로 생긴다 — **없으면 만든다.**
게이트가 아니라 필요할 때만 생기는 것이고, 생기면 `_대장.md` 가 반드시 같이 생긴다
(규격은 [공통절차.md](공통절차.md) 「캡처는 어디에 쌓나」).

**빈 템플릿을 들고 다니지 않는다.** 채우지 않은 칸이 「해당 없음」으로 읽히기 때문이다 —
규격만 들고 다니고 실물은 그 프로젝트를 보고 만든다.

## 원본을 여는 규칙

이관이 끝난 뒤에도 **로직·수치·연출의 진실 소스는 원본 HTML5** 다.

- **화면이 이상하다** → 프리팹을 연다. 원본을 보지 않는다.
- **수치·확률·상태 전이가 이상하다** → 원본을 연다. 프리팹을 고쳐 덮지 않는다.
- **원본에 있는데 우리에게 없다** → 옮기다 만 것이다. 아래 표로 간다.

## 옮기다 만 것을 만났을 때

가장 자주 새는 셋이다. 고치기 전에 해당 규칙을 먼저 편다.

| 증상 | 규칙 |
|---|---|
| 원본에 있는 필드가 우리 데이터에 없다 | `Transfer_Programmer.md` — **안 옮긴 필드는 어떤 검증에도 안 걸린다.** 원본 필드 전수표부터 만든다 |
| 원본의 기호(`✹ ⚔ ▸` …)가 두부로 뜨거나 안 보인다 | `ResourceRule.md` 「원본의 기호는 셋 중 하나로 갈린다」 — 자리 판정 후 cmap 실측 |
| 좌표가 원본과 어긋난다 | `UIUX.md` 「원본 좌표값이 「위치」인지 「순서」인지 먼저 가른다」 |

## 잘못 옮긴 것을 만났을 때 — **「옮기다 만 것」의 반대편**

「옮기다 만 것」만 찾으면 절반만 본다. **다 옮겼는데 엉뚱한 곳에 옮긴 것**이 나머지 절반이고,
이쪽은 **화면이 정상으로 보여서 파리티 검증에도 안 걸린다.**

원본 HTML5 는 캔버스에 좌표를 넘겨 그리므로 JS 에 배치 좌표·프레임 번호·트림 박스·프레임 개수가
상수로 들어 있다. 그걸 **전부 시트로 옮기면 유니티에서 프리팹·AnimationClip·스프라이트 임포터·
앵커가 담당하는 몫을 표가 덮는다.**

| 증상 | 규칙 |
|---|---|
| 시트에 좌표·오프셋·크기 컬럼이 있다 | `PrefabRule.md` 「원본의 배치 상수는 프리팹으로 온다」 — **정규화 −1~1 좌표는 앵커다** |
| 시트에 프레임 접두어·개수·fps·loop 가 있다 | `DataFramework.md` 「시트를 만들기 전에」 — **재생 계층**이 가질 값이다 |
| 개수 컬럼이 실제 파일 수와 정확히 같다 | 합격이 아니라 **중복**이다. 같은 문서 |
| 같은 거동 값이 프리팹과 시트 양쪽에 있다 | 같은 문서. 화면마다 읽는 쪽이 갈린다 |
| 판별 어휘가 `string` 컬럼이다 | 같은 문서 — **enum 이다.** 전환 전 세이브 키인지 확인 |
| 조회 실패에 폴백을 깔았다 | **없으면 오류다.** 폴백은 어서트를 무력화한다 — 조회 실패는 터뜨린다 |
| 아트 주소를 코드가 조립한다 (`"<폴더>/" + code`) | 1장이면 `~Path` 컬럼 + `Validate` 존재 검사 |
| **연출 상수가 코드 `const` 로 남아 있다** (크기 배율·fps·알파·오프셋) | **아래 「옮기지 않고 코드에 남은 것」** — 시트로 잘못 옮긴 것보다 찾기 어렵다 |
| **원본과 크기·속도가 어긋나는 것을 뷰에서 보정했다** | 같은 절 — **단위 문제를 뷰로 덮으면 판정과 그림이 갈린다** |

**가르는 질문은 셋이다 — 「이 값을 누가 눈으로 맞추나」.**
아트가 보면서 맞추면 **프리팹·클립**, 기획이 표로 정하면 **시트**,
**아무도 눈으로 안 맞추는 것**(좌표계 단위 기준 등)만 코드다.
원본이 JS 상수였다는 사실은 답이 아니다 — **그대로 코드에 두는 것도 이관이 아니다.**

### 옮기지 않고 코드에 남은 것 — 「잘못 옮긴 것」보다 안 보인다

시트로 잘못 옮긴 것은 시트를 열면 보인다. **코드에 남은 것은 아무 데서도 안 보인다** —
화면은 정상이고, 시트 검사도 프리팹 검사도 통과한다. 기획·아트가 만질 수 없다는 사실만 남는다.

**착수 시 한 번 센다.** 이관한 파일에서 숫자를 든 상수를 전부 뽑아 행선지를 적는다.

```bash
# [예시] — 경로·언어는 프로젝트마다 다르다. 「세어서 표로 만든다」가 규칙이다
grep -rn "const .*= *[0-9]" <이관한 코드 폴더> | grep -v "<단위 기준 파일>"
```

| 남아 있는 상수 | 가야 할 곳 |
|---|---|
| 크기·오프셋 배율, 색·알파 | **프리팹** (`[SerializeField]`) |
| 프레임 fps·재생 길이·loop | **재생 계층** — 아래 「재생 계층은 개체 수가 고른다」 |
| 밸런스·확률·문구·쿨다운 | **시트** |
| 좌표계 단위 기준 · 원본 알고리즘의 고정 계수 | **코드에 남긴다** — 다만 「튜너블이 아니다」를 주석으로 못박는다 |

**마지막 줄이 면죄부가 아니다.** 「이건 단위라서 코드」라고 적기 전에
**그 값을 바꾸고 싶어질 사람이 있는지** 묻는다. 있으면 코드 자리가 아니다.

### 재생 계층은 개체 수가 고른다 — 「애니메이션이니까 AnimationClip」이 아니다

프레임 값(fps·loop·프레임 목록)이 **시트도 코드 `const` 도 아니라는 것**까지는 같다.
그 다음 「무엇이 재생하느냐」는 **동시에 몇 개가 도느냐**가 정한다.

| 언제 | 재생 계층 |
|---|---|
| **동시 수십~수백 개** (풀링되는 전투 개체·이펙트·투사체) | **중앙 틱** — 프레임 인덱스를 **데이터에 두고** 렌더러가 배열을 한 번에 진행시킨다 |
| 단발·소수 · 이벤트/커브를 여러 트랙으로 동기해야 함 | **AnimationClip / Timeline** |

⚠ **다수 풀링 개체에 개체당 재생 컴포넌트(Animator 포함)를 붙이지 않는다.**
개체마다 업데이트와 재생 그래프가 생겨 **개체 수에 비례해 비용이 붙는다** — 스프라이트
한 장 바꾸는 일에 그 값을 치를 이유가 없다. 중앙 틱은 `frame += dt * fps` 한 줄이고
풀링·리셋과도 맞물린다 (프레임 인덱스가 개체 데이터라 반환 시 같이 초기화된다).

**그래서 fps·배율·알파는 어디 가나** — **에디터에서 눈으로 다루는 자산**으로 간다.
연출 값은 아트가 맞추는 값이라 1순위가 **에셋(ScriptableObject)** 이다. 밸런스로 갈리는 값만 시트다.
어느 쪽이든 **코드 `const` 는 아니다.**

**경량 런타임과 에디터 저작은 배타적이지 않다.** 「개체당 컴포넌트를 안 붙인다」는 런타임 얘기고,
**값을 어디서 만드느냐**는 별개다. 중앙 틱이 **에셋을 읽게** 하면 둘 다 만족한다 —
런타임 비용은 그대로 0 이고, 아트는 인스펙터에서 프리뷰하며 맞춘다.
**「경량이라 코드에 박았다」는 성립하지 않는다.**

**착수 전에 세 가지를 센다.** ① 새 표의 행 수가 상위 표와 같은가(→컬럼으로 접는다)
② 같은 값이 프리팹에도 있는가 ③ 개수 컬럼이 파일 개수와 같은가.

## 표기 규약 — **예시를 지우지 말고, 예시라고 표시한다**

구체적인 예시가 없는 규칙은 적용이 안 된다. 그래서 **예시는 남긴다.**
문제는 예시가 **사실로 오독되는 것**이라서, 마커 두 개로 경계를 기계적으로 만든다.

| 마커 | 뜻 | 읽는 쪽이 할 일 |
|---|---|---|
| **`[예시]`** | 이렇게 생기면 된다는 **모양**. 값은 프로젝트마다 다르다 | **모양만 베끼고 값은 갈아끼운다.** 그대로 쓰지 않는다 |
| **`[사고]`** | 실제로 났던 실패. 재발 조건이 그대로 남아 있다 | **같은 자리를 먼저 확인한다.** 안 겪었다고 넘기지 않는다 |

`[사고]` 안의 수치·이름은 **그 사고의 증거**라 남긴다 — 단 본문은 「무엇을 확인하라」는
재발 조건이고, 수치는 그 프로젝트의 실측이지 사양이 아니다. `[사고]` 밖의 실측 표·수치는
전부 `[예시]` 를 달거나 재는 방법으로 바꾼다.
| 마커 없음 | 프로젝트 불변 규칙 | **그대로 지킨다** |

**코드 블록·경로·클래스명은 전부 `[예시]` 취급이다.**
`Assets/Scripts/UI/` · `GameRoot.Instance.XxxDataContainer` 같은 것은 **모양을 보이는 용도**이고,
**프로젝트에 이미 규약이 있으면 그쪽이 우선한다** — 「이름이 아니라 역할이 규약이다」.

**수치가 붙은 문장은 둘 중 하나여야 한다** — `[예시]` 로 표시된 남의 실측이거나, **재는 방법**이거나.
표시 없는 수치는 다음 회차에 **원본 사양처럼 인용된다.** 그게 오염이다.

## 다른 프로젝트에 붙이는 법

**스킬로 붙인다.** 문서 세트를 `.claude/skills/<이름>/` 에 두고 `SKILL.md` 를 진입점으로,
나머지를 `` 에 넣는다. `SKILL.md` 프론트매터의 `description` 이 **발화 조건**이다 —
사용자가 실제로 쓸 문구를 넣는다: 「원본과 대조」·「파리티 검증」·「옮기다 만 것」,
그리고 되물어 「예」를 받은 경우.

**진입 파일(`CLAUDE.md`·`AGENTS.md`)에 포인터만 적는 방식은 쓰지 않는다.**

> **[사고]** 자동 로드되는 `CLAUDE.md` 에 「이관 작업일 때만 다른 문서를 연다」는 세 줄을 넣어 뒀는데,
> **한 세션 내내 이관 검증 작업을 하면서 그 문서를 한 번도 열지 않았다.** 원본 줄번호까지 파고
> 값을 대조하고 파리티 결함을 찾는, 이 세트가 정의한 바로 그 작업이었다.
> **조건문에 트리거가 없었던 것**이다 — 긴 문서 중간의 「~일 때만」은 아무것도 강제하지 못한다.
> `description` 은 작업 문구와 매칭되어 발화하므로 이 실패를 막는다.

**진입 파일에는 스킬을 열라는 한 줄만 남긴다.**

**진입 파일에는 절차를 적지 않는다.** 절차가 두 곳에 있으면 한쪽이 반드시 낡고,
그때 어느 쪽이 맞는지 아무도 모른다. **진입 파일은 여기로 보내는 역할만 한다.**

## 이 문서 세트에 적을 때의 금칙

**특정 타이틀의 고유명사·실측치를 적지 않는다.** 세트의 수명을 깎는 가장 흔한 오염이다.

| 금지 | 대신 |
|---|---|
| 게임 고유명사 (유닛명·화면명·스킬명) | 역할 이름 (`선택 카드` · `유닛` · `상점 창`) |
| 특정 프로젝트의 실측치 (`노드 564개`) | 재는 **방법**. 수치는 그 프로젝트의 원장에 |
| 그 프로젝트에서만 있던 도구 경로 | 도구가 **무엇을 재는지**. 이름은 프로젝트가 정한다 |
| 「이 저장소는 …」 | **`[예시]`** 로 표시한다 |

**프로젝트 사정에 맞춰 이 문서들을 고치고 싶어지면,**
그건 대개 프로젝트 사정이 아니라 **원장에 적을 회고**다.
