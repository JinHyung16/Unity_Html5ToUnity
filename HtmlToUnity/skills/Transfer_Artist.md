# 이관 담당 · 프리팹/리소스 — HtmlToUnity_Transfer_Artist

상위: [PD](PD.md) (PD)
지식 출처: [FX](Fx.md) + [UI/UX](UIUX.md)
규약: [PrefabRule](PrefabRule.md) · [ResourceRule](ResourceRule.md) · [UIFramework](UIFramework.md)
원장: `HtmlToUnity_작업내역_<게임명>.md` (착수 시 PD 가 생성한다)

지식을 만들지 않고, FX 와 UI/UX 의 지식을 합쳐 프리팹 구성과 연출을 옮긴다. 목표는 퀄리티까지 100% 다.

## 나는 한 단위 안의 ②다

```
작업 분해표의 단위 하나 :
  ① 코드 / 데이터 이관      ← Transfer_Programmer
  ② 프리팹 / 연출 생성      ← 나
  ③ 게임 플로우에 따라 배선  ← Transfer_Programmer
  → 그 단위의 완료 조건 검사 → 완료 → 다음 단위
```

분해표에서 내 차례인 단위만 만든다. 다른 단위의 것을 같이 만들지 않는다 (`재발방지` #123).

- ①이 끝난 뒤에 착수한다. 이유: 주입 API(`SetData`) 시그니처와 넘어올 필드의 의미가 있어야 프리팹 모양이 정해진다.
- 배선은 ③이 한다. 나는 실물과 주입받을 자리까지 만든다. ② 시점에 눌러도 반응이 없는 것은 정상이지만 자리는 다 있어야 한다.
- ③에서 온 프리팹 수정 요청은 내가 받는다. 확정표 10-b 가 「프리팹이 주인」(기본)이면 기존 프리팹을 열어 고치고, 「빌더가 주인」이면 빌더를 고쳐 다시 굽는다. Programmer 는 프리팹을 만지지 않는다.

역할 선언 — 이 역할로 들어갈 때 다음을 출력한다 (PD 「역할 기동 규약」).

```
[역할 전환] 지금부터 나는 Transfer_Artist(패스 ②)다.
  할 수 있는 것 : 프리팹 · 리소스 · 연출 (굽는 방식은 확정표 10-b)
  하지 않는 것  : 게임 로직 · 데이터 컨테이너 · 배선 (그건 패스 ③이다)
```

이전 역할의 결론은 md 에 적힌 것만 인정한다. 기억으로 이어가지 않는다.

## 작업 순서 (패스 ②)

### 원본이 호출하는 리소스를 파악한다

원본이 부르는 리소스 폴더를 훑어 제작되어 있는 리소스 목록을 만든다.

```bash
grep -oE "(assets|img|res)/[A-Za-z0-9_./-]+\.(png|jpg|webp|mp4|webm|mp3|ogg)" 원본.html scripts/**/*.js | sort -u
```

### 출력되는데 파일이 없는 것을 찾는다 — 그릴 목록

화면에 나오는데 파일이 없으면 CSS 나 canvas 로 그린 것이다. Client 지식으로 그리는 코드를 짚어 그릴 목록으로 정리한다.

```bash
grep -n "background:linear-gradient\|box-shadow\|clip-path" 원본.html   # CSS 로 그리는 것
grep -n "fillRect\|arc(\|createLinearGradient\|shadowBlur" 원본.html     # canvas 로 그리는 것
```

**이 목록의 전 항목을 굽혀야 끝난다.** 단색 박스로 남기면 미완성이다.

### 아트를 재제작한다면 — 손으로 그리지 말고 규격에 맞춘다

원본 에셋을 못 쓰는 게임(상용·저작권)에서도 원본 스프라이트의 규격은 잴 수 있다. 손으로 다시 그리면 결과가 회차마다 흔들리고, 크기·주소·컷 수만 세는 채점기는 전부 통과시킨다.
사례: 「실루엣·팔레트를 맞춘 재제작」으로 통과시켰으나 실측 IoU 평균 50.6%, 색 수 19색 → 7색이었다.

먼저 몇 단까지 뜰지 확정한다: 존재 → 규격 → 형태·색 → 픽셀 배치.
사다리와 각 단이 닫는 것은 `공통절차.md` 「자산은 네 단으로 뜬다」가 정본이고, 어디까지 갈지는 사람이 정한다(아래 「어디까지 맞추나」).

| 단계 | 무엇 | 어떻게 |
|---|---|---|
| 1 | 규격을 잰다 | 아틀라스 이미지 파일을 내려받아 컷마다 실루엣 마스크(불투명/투명) · 팔레트(색 + 비중) · 알파 단계(색과 별개의 축) · 채움률 · 고유색 수 · (4단이면) 픽셀·알파 인덱스맵을 뽑는다. 캔버스로 뽑지 않는다 — 저알파 RGB 가 왜곡된다 (`#169`) |
| 2 | 규격을 데이터로 둔다 | 굽는 입력이므로 에디터 전용 자리에 둔다(빌드에 안 들어간다). 학습 산출물 `06` 에 출처와 재는 방법을 적는다 |
| 3 | 규격을 목표로 굽는다 | 마스크대로 채우고 팔레트 비중대로 면적을 나눈다 |
| 4 | 채점기가 기계로 잰다 | 픽셀 일치율(주 지표) · 실루엣 IoU · 팔레트 거리 · 색 수 비 |
| 5 | 합격선을 확정표에 숫자로 | 「픽셀 일치 ≥ N%」 형태로 |

### 「어디까지 맞추나」는 담당자가 정하지 않는다

| 무엇 | 누가 정하나 |
|---|---|
| 실루엣·팔레트·컷 수·fps 를 실측해 맞춘다 | 담당자 — 어느 경우에나 한다 |
| 픽셀 배치까지 맞추나 | 사람 — 저작권·정책 문제다. 착수 질문으로 묻고 확정표에 적는다 |

- 「형태는 맞추되 픽셀은 우리 것」은 작은 스프라이트에서 성립하지 않는다. 16×16 에서는 픽셀 배치가 곧 형태라, 실루엣·팔레트가 맞아도 픽셀 일치가 13~34% 에 머문다.
- 사례: 담당자가 임의로 선을 긋고 자기 지표(IoU·팔레트) 100% 로 완료를 보고했다.
- 사람이 「픽셀까지」로 정하면 규격에 픽셀 인덱스맵을 넣고 그대로 굽는다. 그때는 재제작이 아니므로 의도된 차이 목록에서 그 줄을 지운다.
- 사람 확정은 측정보다 위다. 측정이 확정과 다르면 알리고 확정을 따른다. 결과물(프리팹) 또는 굽는 입력 데이터(규격)에 반영하고 회귀 검사가 지킨다 (`#184`).
- 그 예외를 굽는 코드에 에셋 이름 목록으로 넣지 않는다 (PD 「속 품질 — 이어서 다듬을 수 있어야 한다」). 사례: 버튼 둘레 반투명 띠를 빌더의 이름 목록(`NoOuterHalo`)으로 걷어, 되돌리거나 다른 에셋에 적용하려면 코드를 고쳐야 했다.
- 규격 파일을 정적 변수로 캐시하지 않는다. 이유: 다시 재서 넣어도 옛 값으로 굽는다.
- 컷 크기가 아트 표와 다르면 표가 틀린 것이다. 굽지 말고 알린다.

### 두 목록을 플랫폼에 맞게 담는다

제작된 것과 제작할 것 모두 텍스처 사이즈를 플랫폼에 맞춘다 (ResourceRule 「해상도 정책」).
임포트 설정(Pivot·PPU·압축·mip)은 생성기 안에서 건다. 이유: 구운 뒤 손으로 걸면 빠진다.

### 프리팹을 굽는다

- 화면 하나를 열기 전에 전수 대조표(UIUX 「화면 하나를 전수 대조표로 연다」)를 만든다. 표 없이 코드를 고치지 않는다.
- 원본 DOM 구조를 그대로 옮긴다. 절대 y 대신 flex 를 옮긴다 (PrefabRule 「계층」).
- 굽는 방식은 확정표 10-b 를 따른다. 「프리팹이 주인」(기본)이면 빌더는 없는 프리팹만 초안으로 굽고 있는 것은 건너뛴다. 이후 수정은 프리팹을 열어 고친다 (PrefabRule 「프리팹이 주인일 때」). 「빌더가 주인」이면 빌더를 고쳐 다시 굽는다.
- 보이는 조정값(위치·크기·색·알파·연출 속도·타이밍)은 프리팹 직렬화 필드에 둔다. 기본값은 원본 값, 출처는 `[Tooltip]` 이나 주석. 코드 상수로 두지 않는다.
- 색은 원본 `:root` 변수를 그대로 쓴다. 하드코딩 금지.

### 연출을 붙인다

정적 캡처에는 `animation` 과 `:hover` 가 안 찍힌다. 화면을 열 때 원본 CSS 에서 먼저 훑는다.

| 원본 | 우리 |
|---|---|
| 등속 회전 | 회전 컴포넌트 (`degreesPerSecond`, 음수 = 시계 방향) |
| 사인파 맥동 | 맥동 컴포넌트 |
| `animation: … steps(1,end)` | 계단 점멸 — 사인파로 대체하면 다른 연출이다 |
| `:hover{transform:rotate()}` | 호버 회전 + 색 전이 |
| 등속 이동 | 드리프트 (`unitsPerSecond` · `range` · `pingPong`) |
| `grid-template-rows: 0fr↔1fr` | 높이 접기 — 자식을 끄지 않는다 |
| `cubic-bezier()` | 같은 이징. `SmoothStep` 으로 대충 맞추면 궤적이 다르다 |

- 방향·속도를 원본에서 확인한다. 드리프트 배율·타일링 방향·왕복 여부까지.
- 접기 연출에서 자식을 `SetActive(false)` 로 끄지 않는다. 이유: 내용 높이를 못 재서 한 프레임 튀고 형제 패널도 같이 튄다.
- 시간축은 `Time.unscaledDeltaTime` 을 쓴다 (전투가 멈춘 동안에도 돌아야 한다).

### 유니티를 돌려 확인한다 (PD 「유니티는 스스로 돌린다」)

직접 실행하고 직접 멈춘다. 에디터 작업은 기본으로 에디터 다리(`Tools/unity-batch.sh`)로 시키고, 재생 확인도 `PLAYMODE=1` 로 다리에서 돌린다.

```
재생 멈춤 → 굽기(초안 빌더 또는 기존 프리팹 수정 저장) → 로그 읽기(경고 0 확인)
→ Preview 하네스로 캡처와 같은 해상도로 굽는다 → 픽셀 측정
→ PLAYMODE=1 Tools/unity-batch.sh … → 거동 확인 → 재생 멈춤
```

- 재생 검사기는 `Application.runInBackground = true` 를 켠다 (재발방지 #156).
- 정지 프리뷰는 `Update` 가 안 돈다. 애니메이션이 붙은 상태는 끝 상태를 강제한다. 이유: t=0 이 찍혀 기능이 없다고 오판한다.

### 패스 ③이 배선할 자리를 비워 둔다

③이 값을 넣을 수 있게 자리와 통로를 만드는 것이 ②의 절반이다. 자리가 없으면 ③에서 프리팹을 다시 뜯는다.

| 비워 둘 자리 | 어떻게 |
|---|---|
| 데이터 종속 아트 | 프리팹에 굽지 않는다. `[SerializeField] Image` 만 두고 프리팹 값은 폴백으로만 |
| 주입 API | ①에서 받은 `SetData(...)` 시그니처대로 필드를 다 만든다. 안 쓰는 필드가 있으면 계약이 틀린 것 |
| 연출 파라미터 | 속도·위상·색·범위를 `[SerializeField]` 로 노출하고 런타임 재설정 메서드를 둔다. 상수로 굽지 않는다 |
| 상태 전이 | 접힘/펼침·활성/비활성을 메서드 하나로 바꿀 수 있게 (`SetExpanded(bool, instant)`) |
| 장식과 내용물 | 반드시 별개 필드. 하나로 두면 ③의 런타임 주입이 장식을 덮는다 |
| 월드 프리팹의 스프라이트 | 프리팹에 박지 않는다. 계층·`SpriteRenderer`·정렬 순서·머티리얼까지만 |

②를 닫을 때 ③에게 무엇을 어디에 넣으면 되는지 원장에 적어 넘긴다.

// 살아 움직이는 것들의 스프라이트 이름을 찍는다 — 같은 이름만 나오면 모양을 안 옮긴 것이다
foreach (Transform t in entityRoot) Log(t.GetComponentInChildren<Image>().sprite.name);

## 점수를 믿기 전에

- 헤드리스 캡처는 색 프로파일 때문에 더 밝게 나올 수 있다. 점수가 낮으면 원본 에셋과 직접 대조한다.
- 글자·숫자·라벨은 DOM/JS 문자열에서 확인한다. 픽셀로 읽지 않는다.
- 애니메이션의 어두운 구간이 찍힌 캡처를 정색으로 오인하지 않는다.
- 폰트 차이는 허용 오차다. 폰트에 없는 글리프를 쓰는 것은 버그다.
- 영상 프레임·보유 재화·선택 상태가 다르면 그 구간 점수는 무의미하다. 결함을 찾기 전에 상태 정합 체크리스트(공통절차 「A/B 측정」)부터 채운다.
