# HTML5 → Unity 이관 · PD 문서

이 문서 세트는 타이틀에 종속되지 않는다. 특정 게임의 고유명사·실측치·도구 경로는 확정표와 원장(`HtmlToUnity_작업내역_<게임명>.md`)에 적는다 (금칙은 [SKILL.md](SKILL.md) 「이 문서 세트에 적을 때의 금칙」).

이 문서는 오케스트레이터다. 무엇을 확정하고, 누구에게 넘기고, 무엇을 증명해야 다음으로 가는지 정한다. 작업 규칙은 하위 문서에 있다.

**목적: 장르와 무관하게 HTML5 게임을 시스템·데이터·리소스·퀄리티까지 100% 이관한다. 완료 조건은 둘이다 — 겉은 「원본과 같다」, 속은 「이어서 다듬을 수 있다」.**

---

## 이 문서를 연 순간 당신은 PD다

- 이 문서는 지시서다. 역할은 PD다 — 확정 · 배분 · 게이트 · 최종 QA.
- PD는 직접 만들지 않는다. 코드·프리팹·아트에 손대면 역할 이탈이다 (「역할 기동 규약」).
- `## 진입` 의 첫 턴 프로토콜 1번부터 시작한다.

## 담당자를 어떻게 실행하나 — 능력만 규정한다

격리 실행 수단(서브에이전트 등)이 있으면 아래가 기본이다. 없으면 역할 전환으로 순차 수행하고 「문서 로딩 규칙」이 격리를 대신한다.

| 단계 | 컨텍스트 |
|---|---|
| 학습 (지식 4) | 격리 컨텍스트로 병렬. 산출물이 md 라 서로 독립이다 |
| 이관 (단위 안의 3패스) | 패스마다 새 컨텍스트, 순차. 병렬 금지 (같은 프로젝트에 쓴다) |
| PD | 메인 컨텍스트. 위임하고 게이트를 검증한다. 담당자로 내려가지 않는다 |

담당자에게 넘기는 것은 문서(허리 산출물 — SKILL.md 「뼈대」)뿐이다. 문서에 없는 지식을 전제한 지시는 인수인계 계약 위반이다.
격리 실행 가능 여부는 확정표 13 점검 때 찔러 보고 적는다.

## 진입 — 이 문서가 시작점이다

이관 요청을 받으면 이 문서를 먼저 연다. 별도 시작 문서를 두지 않는다.

### 첫 턴에 하는 일 — PD 프로토콜

```
원장(HtmlToUnity_작업내역_<게임명>.md)이 있나?
├─ 없다 + 「분석만 해줘」·이관 의사 미확정 → 사전 분석 모드 (아래 절).
│         끝에 이관 Y 를 받으면 그때 신규 착수로 내려온다.
├─ 없다 → 신규 착수. 아래 절차를 1번부터.
├─ 있다 → 확정표부터 검증한다. 빈 행·「미확인」 행만 다시 묻는다.
│         그다음 원장의 미흡 목록에서 최하위 미통과 게이트로 간다.
└─ 검증·누락 보충 요청 → 원장 최신 회차 → 해당 게이트의 통과 증명을 다시 잰다.
```

신규 착수 절차. 착수 질문에 답을 받기 전에 아무것도 만들지 않는다.

```
1. 전제 도구를 점검한다 — 못 하는 단계가 있으면 만들기 전에 알린다
   (브라우저가 없으면 해상도 실측(3-d)을 사람에게 요청하고, 못 받으면 확정표에 미측정(① 도구 없음))
2. 원본 HTML5 위치를 확인한다 (모르면 묻는다) — 원본 형태를 가른다 (「원본 형태 판정」)
3. 「착수 전 확정」 착수 질문 전부를 묻는다      ← 답을 다 받기 전에 다음으로 안 간다
4. 답을 「확정표」에 채우고 각 담당자 md 의 [Unity 프로젝트 세팅] 절로 복사한다
5. HtmlToUnity_작업내역_<게임명>.md 를 만든다                ← 분석로직 「HtmlToUnity_작업내역_<게임명>.md」
6. <원본폴더>/HtmlToUnityLogic/ 골격 껍데기를 만든다 ← 분석로직 「HtmlToUnityLogic/」
7. 템플릿 프로젝트면 잔재를 걷는다                  ← GameFramework 「신규 프로젝트를 청소한다」
8. 확정값을 프로젝트 설정에 반영한다                ← GameFramework 「확정표를 프로젝트 설정에 반영한다」
9. 학습 단계를 연다
```

프로젝트마다 새로 만드는 것은 셋뿐이다: 「확정표」(행 수는 문장에 적지 않고 표를 센다) · `HtmlToUnity_작업내역_<게임명>.md` · `HtmlToUnityLogic/` 골격 전부.
빈 템플릿 파일을 들고 다니지 않는다. 규격만 들고 다니고 실물은 그 프로젝트를 보고 만든다 (분석로직 「왜 미리 만들어 두지 않고 매번 생성하나」).
다른 문서를 프로젝트 사정에 맞춰 고치고 싶어지면 그것은 대개 원장에 적을 회고다.

### 사전 분석 모드 — 이관을 결정하기 전에 원본만 본다

게임만 주고 「분석해줘」라고 하면 이관 의사 미확정이다. 착수 질문을 던지지 않는다.

- 한다: 원본 형태 판정 · 원본 폴더 준비 · `00_원본정보.md` · 실측(조작·구조·메커니즘·미측정 목록).
- 하지 않는다: 확정표·원장 생성, `HtmlToUnityLogic/` 골격, Unity 쪽 산출물 일절.
- 산출물은 md 뿐이다. 선제작 금지 규칙과 충돌하지 않는다.

끝나면 결과를 보고하고 「이 게임을 Unity 로 제작(이관)할까요? Y / N」을 묻는다. Y 면 첫 턴 프로토콜 1번부터 가고 산출물은 이월한다. N 이면 멈추고 산출물은 남긴다.

### 원본 형태 판정 — 코드로 오나, URL 로만 오나

| 형태 | 무엇 | 학습 방법 |
|---|---|---|
| 코드 제공형 | 원본 폴더에 HTML/JS/CSS 가 있다 | 코드 정독 + 실행 실측 |
| URL 제공형 | 서비스 링크만 있다 | 런타임 직독 → 번들 소스 수신 → 실측. 「블랙박스」라고 적지 않는다 |

#### URL 제공형이라고 블랙박스로 단정하지 않는다 — 런타임을 먼저 찔러라

엔진 런타임은 대개 전역으로 노출돼 있어 오브젝트·좌표·프레임 수를 직접 읽을 수 있다. 착수 실측 첫 순서로 아래를 한 묶음으로 찔러 본다.

| 찌를 자리 | 나오는 것 |
|---|---|
| 프레임 전수 순회 (먼저) | 게임은 첫 iframe 이 아니라 더 안쪽 프레임(대개 다른 출처)에 있을 수 있다 |
| 콘솔 로그 | 엔진 종류 · 진행 이벤트 |
| 엔진 런타임 전역 — 예시: `window.c3_runtimeInterface._localRuntime` (Construct) · `window.game`/`Phaser` · `unityInstance` | 오브젝트 클래스 전수 · 인스턴스 좌표·크기 · 애니메이션 프레임 수 · 레이어 |
| 게임 프레임의 `canvas` | 논리 해상도 · 스케일 방식 |
| 저장소 (`localStorage` 등) | 진행 저장 여부와 키 |

사례: 프레임 전수 순회를 안 해 블랙박스로 오판했다. 못 찾으면 「안 뒤진 곳이 있다」를 먼저 의심한다.

런타임 조회의 함정:

| 함정 | 대응 |
|---|---|
| 화면 밖 대기 개체 (좌표가 음수이거나 터무니없이 큼) | 그대로 옮기지 않는다 |
| 한 화면에 배율이 둘 이상 (레이어별 스케일·시차) | 한 배율로 환산하지 않는다 |
| 충돌 칸과 그림 스프라이트의 크기가 다름 | 분리해서 옮긴다 |
| 매 프레임 갱신 연출(흔들림·위상차) | 캡처로 안 보인다. 런타임 속성명을 단서로 쓴다 |
| 첫 인스턴스가 미끼·대기·비활성 | 전 인스턴스를 열거한다 |
| 연달아 조작한 상태는 첫 상태와 다름 | 판정용 실측은 시행마다 새 컨텍스트(또는 재시작)에서 잰다 |

런타임이 읽혀도 규칙은 그대로다. [실측]+재현 방법을 붙이고, 읽은 값은 사양이 아니라 원본에서 온 값이다.

#### 그리고 번들 소스를 받아 읽는다 — 여기서 판이 바뀐다

웹 게임 코드는 브라우저로 내려온다. 난독화돼도 저작 상수·식·클래스 구조는 문자열로 남는다.

| 단계 | 무엇 |
|---|---|
| ① 스크립트 URL 수집 | 게임 프레임이 로드하는 `*.js` 를 네트워크에서 모은다 |
| ② 게임 프레임 안에서 받는다 | 그 프레임 origin 으로 받아 교차 출처를 피하고, 로컬 파일로 저장한다 |
| ③ 앵커로 찾는다 | 관측한 값(목표 배열 · 간격 · 개체 이름)을 정규식으로 찾아 근처를 읽는다 |
| ④ 우리 구조로 다시 구현 | 베끼지 않고 상수·식·순서를 우리 표·시뮬로 옮긴다 |

앵커 없이 그럴듯한 숫자를 줍지 않는다. 관측치와 맞물리는 것만 인정한다.
사례: 실측만 8회차로 상수는 2% 안으로 맞췄으나 규칙(스폰·조준·업그레이드·레벨 목표·카메라)은 전부 틀렸고, 소스를 받은 9회차에 한 번에 닫혔다.

심화(후킹 · 자산의 원래 색·모양 · 도달 불가 입력 · 무작위 경계 · 저작값 찾기)는 `공통절차.md` 「런타임에서 직접 캐내는 법」이 정본이다.

#### URL 제공형이면 먼저 묻는다 — 한 번에

「이 게임의 정확한 게임명은 무엇입니까? 【기본값: 서비스 페이지의 표기】
제공하신 URL 이 원본의 전부입니까 — 따로 받을 수 있는 코드·에셋이 있습니까?
이관 대상은 어느 범위까지입니까 (모드·월드 등)?」

게임명이 폴더명·원장명이 된다.

#### 원본 폴더가 없다 — 만든다

URL 제공형은 착수 시 원본 폴더를 만든다. 위치는 저장소 진입 파일(CLAUDE.md 등)이 정하고, 코드 제공형 풀과 다른 루트에 둔다.
이유: 폴더 이름에서 「코드가 없다」가 읽혀야 다음 회차가 없는 코드를 찾지 않는다.

```
[예시]
<URL 원본 풀>/<NN>-<게임명>/     ← 이 폴더가 <원본폴더> 역할이다
├─ 00_원본정보.md               ← 코드 대신 원본 포인터
└─ HtmlToUnityLogic/            ← 골격 전부(덤프 포함). 규격 동일 (분석로직)
                                   캡처 폴더는 없다 — 공통절차 「캡처는 쌓지 않는다」
```

`00_원본정보.md` 최소 행: 게임명 · 원본 URL · 제작사/서비스 · 실측 엔진(콘솔 로그로 확인) · 조작 방법 [실측] · 접속·재현 방법(입력 자동화 포함) · 플랫폼 소속 목록.
원본이 내려가면 이 문서와 기대값 표가 2차 심판이다. 실측마다 재현 방법을 남긴다.

#### 서비스 플랫폼이 그리는 것은 원본이 아니다

포털의 홈 버튼·광고·로그인·SDK 연출은 게임이 아니다. 실측 첫 회차에 화면 요소를 게임 소속 / 플랫폼 소속으로 가르고, 플랫폼 소속 목록을 `00_원본정보.md` 에 적어 이관 범위에서 뺀다.
이유: 섞으면 플로우 diff 가 오탐한다.

#### 실측이 막히는 구간 — 사람에게 영상을 요청한다

자동 입력으로 재현이 안 되는 구간(정밀 타이밍·제스처, 후반 구간, 결제·계정 뒤)은 사람에게 플레이 영상을 한 묶음으로 요청하고 스틸(ffmpeg 등)로 실측한다. 못 받으면 미측정이다.

#### 코드 인용 게이트는 실측 재현 방법으로 대체한다 — 면제가 아니다

| 코드 제공형의 증거 | URL 제공형의 동등 증거 |
|---|---|
| 원본 파일:줄 인용 | [실측] + 재현 방법 — URL · 진입 경로 · 입력 시퀀스 · 캡처 파일명 |
| 상수·테이블 발췌 | 반복 실측값 + 측정 횟수. 못 재면 `미측정` |
| 정답지를 코드 로직으로 산출 | 입력 시퀀스 → 화면 결과를 표로 채록 |
| 캡처 `_대장.md` 의 「근거(원본 코드 위치)」 컬럼 | 재현 방법 컬럼 |

「이런 게임은 보통 이렇다」로 채우지 않는다. 장르 지식은 가설까지만 쓴다.

##### 실측으로 채록한 정답지는 성공 1점으로 만들지 않는다

연속 입력값(누르는 시간·거리·각도)이 있으면 레벨·상황마다 「실패-성공-실패」 3점을 담아 성공 구간의 양쪽 경계를 고정한다.
이유: 성공 1점만 담으면 곡선이 어긋나도 통과한다.
사례: 성긴 격자로 한 발도 성공하지 못해 「깰 수 없는 구간」으로 오판할 뻔했다. 성공을 못 찾으면 격자를 촘촘히 한다.

원본 에셋(스프라이트·사운드)을 뜯어 오지 않는다. 런타임·번들로 읽을 수 있어도 마찬가지다(저작권). 리소스는 재제작하고 합격 기준(확정표 12)은 퀄리티 동일로 잡는다. 수치·규칙은 실측해 재현한다.

### 전제 도구 — 없으면 못 하는 단계를 먼저 알린다

착수 시 실제로 찔러 보고 확정표 13번에 적는다.

| 도구 | 없으면 | 대체 판정 |
|---|---|---|
| 브라우저 (원본 실행 · DOM · 콘솔) | 순서·타이밍·게이트 조건이 안 잡힌다 | 코드 정독 + 사람에게 캡처·영상·DOM 덤프 요청. 돌려 봐야 아는 것은 미측정 |
| Unity 에디터 제어 | 대화형 조작이 안 된다 | 에디터가 열려 있으면 끄지 않고 에디터 다리로 시킨다. 재생 검사도 다리로 한다 (예시: `Tools/unity-batch.sh` · `PLAYMODE=1`). 에디터가 꺼져 있을 때만 배치모드(`-batchmode -executeMethod`) (공통절차 「에디터가 열려 있으면」 · 「에디터 툴은 배치모드로 직접 실행한다」). 둘 다 없으면 사람에게 한 묶음으로 요청 |
| 파일 검색 · grep | 원본 인용이 성립하지 않는다 | 없으면 착수하지 않는다 |
| 이미지 비교 | 「글자 제외 95%」를 못 잰다 | 요소 수 대조 (원본 N개 중 M개). 점수는 미측정 |
| 셸 (빌드 · ffmpeg 등) | 컴파일 판정(공통절차 「컴파일·툴 실행 순서」 ⓪-b)·영상 스틸 불가 | 사람에게 빌드 로그 요청. 「에디터가 안 먹는다」 판별식은 미측정 |

### 근거 등급 — 네 단계로 적는다

값마다 출처 등급을 붙인다. 이유: 없으면 가설이 실측처럼 인용된다.

| 등급 | 무엇 | 표기 |
|---|---|---|
| ① 소스 직독 | 원본 코드의 저작 상수·식 | `[소스]` · 표에서는 표본 수 `-1` |
| ② 실측 | 원본을 돌려 잰 값 (n ≥ 3) | `[실측 n=…]` |
| ③ 관측 | 한두 번 본 것 | `[관측]` — 실측 승격 전까지 값으로 쓰지 않는다 |
| ④ 미측정 / 가설 | 안 쟀거나 추론한 것 | `[미측정]` — 달성률 0% |

①이 오면 ①이 정본이다(실측 169.3 → 저작 170 이면 170). 실측치는 식의 확인 근거로 남긴다.
값의 등급과 규칙의 등급은 따로 매긴다 (재발방지 #128).

### 미측정 ≠ 통과

| 장치 | 규칙 |
|---|---|
| 어휘 | 숫자를 못 넣으면 `미측정(사유)`. 빈칸·「됨」 금지 |
| 사유 3갈래 | ① 도구 없음 ② 상태를 못 맞춤(A/B 정합 실패) ③ 하네스 없음. 해소법이 달라 뭉뚱그리지 않는다 |
| 달성률 | 미측정은 0% |
| 재측정 대기 | 원장 재측정 대기 표에 남기고 다음 회차에 신규 작업보다 먼저 처리한다 |
| 에스컬레이션 | 대기 회차 3 이상이면 PD 가 사람에게 도구·데이터를 요청한다 |
| 소스 우선 | 미측정 3건 이상이면 관측 회차보다 번들 소스 수신(「번들 소스를 받아 읽는다」)이 먼저다 |

규격은 [분석로직 「섹션별 기입 규칙」](분석로직.md).

### 전제 — 특정 라이브러리를 강요하지 않는다. 능력만 규정한다

아래 둘의 충족 방법을 확정표 14번에 적는다. 이미 쓰던 것이 있으면 그것을 쓴다.

| 필요한 능력 | 용도 | 못 채우면 |
|---|---|---|
| JSON 역직렬화 — 최상위 배열 · 임의 키 맵 · `null` 구분 · 중첩 제네릭 | 데이터 컨테이너 · 정답지 파싱 | 데이터 로드·수치 판정이 막힌다. `JsonUtility` 는 넷 다 안 된다 |
| 아트 로드/해제 단위 (번들 시스템 등) | 카테고리 단위 로드 · 양방향 감사(공통절차 「에셋 등록은 양방향으로 감사한다」) | 전부 `Resources` 로 물어 빌드가 부푼다 |

- 선택지와 접점 격리는 [DataFramework 「전제」](DataFramework.md). 라이브러리 이름이 나오는 파일이 한두 개를 넘으면 설계가 틀렸다.
- 확인은 `dotnet build` 로 한다. 이유: 에디터 콘솔은 변경을 아직 안 집어갔을 수 있다 (공통절차 「컴파일·툴 실행 순서」 ⓪-b).

### 문서 로딩 규칙 — 단계마다 여는 것만 연다

| 단계 | 여는 문서 |

## 이 오케스트레이션이 존재하는 이유

결함 대부분은 파트 경계에서 난다. 그래서 이 문서의 핵심은 「인수인계 계약」이다.

| 경계 | 사고 |
|---|---|
| 기획 → 클라 | 표기 테이블 110행이 컨테이너가 없어 아무도 안 읽었다 |
| 클라 → UI | 계통명 자리에 내부 분류값(`parent`)이 들어갔다 (둘 다 문자열이라 통과) |
| UI → 연출 | 아이콘 필드 하나가 테두리와 글리프를 겸해 런타임 주입이 테두리를 덮었다 |
| 클라 → 연출 | 렌더 컴포넌트 기본값이 가산 합성이라 안 건드린 전부가 가산이었다 |
| 기획 → UI | `+42/Lv` 같은 파생 표기에 표시 직전 계산이 없었다 |

## 대원칙 — 값과 규칙을 옮기고, 구조는 다시 설계한다

**이관은 번역이 아니라 재구현이다.** 원본은 「무엇을 하는가」의 출처이고 「어떻게 만드는가」는 Unity 가 정한다.

| 원본에서 가져오는 것 | 원본에서 버리는 것 |
|---|---|
| 수치 · 확률 · 계수 · 문구 | DOM 계층 · CSS 셀렉터 |
| 계산식 · 상태 전이 · 조건 분기와 그 순서 | `flex` · `absolute` · `%` 같은 배치 수단 |
| 무엇이 보이고 무엇이 눌리는가 | `innerHTML` 재생성 · SVG · canvas 호출 순서 |
| 개체 수 · 층 수 · 등장 조건 | 유니코드·폰트·색을 공짜로 쓰던 전제 |

| 원본이 그 일을 하던 방법 | Unity 구조 |
|---|---|
| DOM 계층 | Window / Panel / Component ([UIFramework](UIFramework.md)) |
| `display:flex` · `position:absolute` | LayoutGroup · 앵커 · 재활용 스크롤 ([PrefabRule](PrefabRule.md)) |
| `innerHTML` 로 매번 재생성 | 프리팹 풀링 + 값 주입 (「엔진 패러다임 차이」 ①) |
| 컨테이너 1개 + `closest()` 이벤트 위임 | 개체가 적으면 Button, 많으면 뷰 하나가 좌표로 (「엔진 패러다임 차이」 ④) |
| 유니코드 기호 · 임의 폰트 | 아틀라스 아이콘 · `TMP_SpriteAsset` ([ResourceRule](ResourceRule.md) 「원본의 기호는 셋 중 하나로 갈린다」) |
| 전역 상수 · 하드코딩 테이블 | 시트 → JSON → Container ([DataFramework](DataFramework.md)) |

### 판정 기준 — 이 문장으로 스스로 검사한다

근거는 「원본이 이렇게 생겼으니」가 아니라 「원본이 무엇을 하니 우리는 이 구조로 한다」여야 한다.

- 원본 좌표식을 그대로 옮기고 있으면 멈추고 위치인지 순위인지 가른다 (UI/UX 「renderMode 는 상황마다 다르다」).
- 원본 DOM 을 1:1 로 대응시키고 있으면 멈추고 프레임워크 3계층에 앉힌다.
- 값·분기·순서는 한 줄도 바꾸지 않는다. 「더 나은 공식」을 넣지 않는다.

### 속 품질 — 이어서 다듬을 수 있어야 한다

겉이 원본과 같아도 속이 엉망이면 결과물을 이어서 다듬을 수 없다.
**사람이 디테일을 올릴 때 프리팹이나 데이터를 조금 고쳐서 끝나야 한다.** 보이는 값을 바꾸는데 코드를 고쳐야 하면 결함이다.

적용 범위: 이 기준을 정한 뒤 새로 착수하는 게임부터다. 이미 이관한 게임은 소급해서 고치지 않는다 [사람 확정].

| 값 | 사는 곳 | 이유 |
|---|---|---|
| 보이는 조정값 — 위치 · 크기 · 색 · 알파 · 연출 속도 · 타이밍 · 이징 | 프리팹 직렬화 필드. 기본값은 원본 값, 출처는 `[Tooltip]` 이나 주석 | 사람이 에디터에서 바로 고친다 |
| 굽는 아트의 입력 (규격 · 색 · 예외) | 굽는 입력 데이터 (에디터 전용 JSON 등) | 다시 구워도 유지된다 |
| 밸런스 — HP · 확률 · 비용 · 레벨 표 | 데이터 시트 ([DataFramework](DataFramework.md)) | 표로 한꺼번에 조정한다 |
| 원본 규칙 · 계산식 · 폴백 계수 | 코드 상수 + 원본 행 인용 | 다듬을 대상이 아니라 사양이다 |

- 프리팹이 주인이다 (확정표 10-b 기본값). 빌더는 첫 초안만 굽고 이미 있는 프리팹을 덮어쓰지 않는다 ([PrefabRule](PrefabRule.md) 「프리팹 생성 방식은 확정표 10-b 가 가른다 — 이 문서가 정하지 않는다」).
- 런타임이 프리팹 값을 코드 상수로 다시 덮어쓰지 않는다. 런타임이 바꾸는 것은 데이터·상태로 갈리는 값뿐이다.
- 원본과 다르게 가기로 한 것(의도된 차이 · 사람 확정)은 결과물(프리팹 · 데이터 · 굽는 입력)에 반영한다. 생성기·런타임 코드에 에셋 이름 목록으로 분기를 넣지 않는다.
- 사례: 버튼 둘레 띠 제거를 빌더 코드의 이름 목록(`NoOuterHalo`)으로 넣어, 되돌리거나 다른 에셋에 적용하려면 코드를 고쳐야 했다.
- 에셋 이름·게임 이름으로 갈리는 `if` 를 코드에 두지 않는다. 갈리는 것은 데이터 행이나 프리팹 필드로 표현한다.
- 검사가 겉만 재면 속이 엉망이어도 전부 통과한다. 속은 G8 로 판정한다 (「게이트」).

### 원본의 이상 거동 — 고치는 것도 이관이 아니다

**모자란 루프 상한, `0` 의 falsy 판정, 빠진 가드도 사양이다.** 고쳐서 옮기지 않는다.

1. 원본을 돌려 실측으로 확증한다.
2. 학습 문서에 [실측] 표시와 재현 방법을 적는다.
3. 원장 「원본 이상 목록」에 올린다.
4. PD 가 재현/수정을 확정한다. 확정 전에는 이관하지 않는다.

기본값은 재현이다. 고치려면 확정표 12번에 「의도된 차이」로 등재한다. 등재 없이 고친 것은 결함이다.
사례: 매치 루프 상한이 하나 모자라 특정 자리 4연속이 3점이 됐다. 무매치 기저 보드에서 점수 증분을 재서 확증했다.
찾은 건수를 원장에 숫자로 적는다. 0건이면 「아직 안 찾았다」를 먼저 의심한다.

### 「이상」과 「직관과 다른 것」을 가른다 — 처리가 다르다

| | 원본 이상 | 직관과 다른 것 |
|---|---|---|
| 무엇 | 저자가 의도하지 않았을 수 있는 것 (모자란 상한, falsy, 빠진 가드) | 구현 방식의 필연적 결과 (순회 방향, 판정 순서, 즉시 수정) |
| PD 확정 | 필요 (재현/수정) | 불필요. 무조건 재현 |
| 고칠 수 있나 | 「의도된 차이」 등재 시 | 없다. 고치면 다른 게임이다 |
| 놓치면 | 특정 자리만 어긋난다 | 전 구간이 조용히 어긋난다 |

둘 다 실측으로 확증하고 정답지로 못 박는다.
가르는 질문: 「원본을 그대로 옮겼는데도 이 값이 나오나?」 나오면 직관과 다른 것, 특정 한 줄을 그대로 옮겨야만 나오면 이상이다.
주의: 직관과 다른 것은 「교과서대로」 구현하고 맞다고 믿기 쉽다. 겹치는 입력·연속 입력을 반드시 벡터에 넣는다.
원장에 「원본 이상 목록」(확정 대기)과 「직관과 다른 것」(벡터만)을 따로 둔다.

## 엔진 패러다임 차이 — 그래도 새는 일곱 자리

대원칙을 지켜도 새는 자리다. 착수 전에 읽고 각 행의 점검을 회차마다 한 번 돌린다 (G7).

| # | HTML5 | Unity | 파생 결함 |
|---|---|---|---|
| 1 | 즉시 모드 — `innerHTML=` 로 매번 다시 그린다 | 유지 모드 — 오브젝트를 살려 두고 값만 바꾼다 | 이전 상태 잔존 · 이벤트 중복 구독 · 캐시 무효화 누락 |
| 2 | 문서 순서 — 나중에 쓴 것이 위 | 형제 순서 — 풀링이 순서를 뒤집는다 | 선이 노드 위로 · 딤이 대상 아래로 |
| 3 | 캐스케이드 — `var(--nc)` 하나로 자식 전부 | 개별 대입 — Graphic 마다 따로 | 한 요소만 기본색 · 상태색 누락 |
| 4 | 이벤트 위임 — 컨테이너 1개 + `closest()` | 개별 리스너 — 노드마다 Button | 노드 2000개 = GameObject 2000개 |
| 5 | 흐름 배치 — 내용이 자리를 만든다 | 고정 rect — 자리가 내용을 자른다 | 넘침·잘림 |
| 6 | 공짜 자원 — 아무 글리프·아무 색 | 선언된 것만 — 폰트 cmap · Linear | 두부 · 빈칸 · 알파 과다 |
| 7 | 느슨한 수치 — 전부 double, `Infinity` | 엄격 — float 혼입, `int.MaxValue` | 정밀도 손실 · `2147483647` 노출 |

### 즉시 모드 → 유지 모드 : 「안 그림」과 「안 끔」은 다르다

원본에 `else` 가 없어도 우리에겐 `else`(끄기·구독 해제·캐시 무효화)가 필요하다. 정본은 UIFramework 「「안 그림」과 「안 끔」은 다르다」, 점검은 G7.

### 문서 순서 → 형제 순서 : 풀링이 순서를 뒤집는다

같은 부모에 섞어 `Instantiate` 하면 먼저 만든 것만 뒤로 간다. 먼저 그린 것은 전용 부모를 만들어 `SetAsFirstSibling` 으로 고정한다.

### 캐스케이드 → 개별 대입 : 색은 한 곳에서 받아 뿌린다

상태색 컴포넌트는 색을 받는 진입점을 하나만 두고 거기서 전부 뿌린다.

```bash
# 점검 — 원본이 한 요소에 몇 개의 상태 클래스를 거는지 센다
grep -o "\.tnode\.[a-z-]*" 원본.html | sort -u
```

### 이벤트 위임 → 개별 리스너 : 개수를 먼저 센다

`closest()` 는 개체 수 상한이 없다는 뜻이다. 최대 개수를 세고, 수백을 넘으면 Button 대신 뷰 하나가 좌표로 찾는다.

### 흐름 → 고정 rect

길이가 변하는 순간(번역·큰 수치·긴 이름) 전부 깨진다 (UI/UX 「CSS 흐름을 고정 박스로 옮기면 길이가」).

### 공짜 자원 → 선언된 것만

| 원본이 공짜로 쓰는 것 | Unity 에서 필요한 선언 | 점검 |
|---|---|---|
| 유니코드 기호 | 폰트 cmap 에 있거나 `TMP_SpriteAsset` 등록 | 기호 전수 → cmap 대조 (`ResourceRule` 「원본의 기호는 셋 중 하나로 갈린다」 · G7 #4) |
| 반투명 합성 | Linear 면 브라우저와 다르게 합성된다 | 알파 역산. 밝은 것과 어두운 것은 방향이 반대다 (`Fx` 「색공간」 · 재발방지 #183) |
| 임의 폰트 | 폰트 하나 · 폴백 없음 | UIUX 「주폰트는 가장 넓은 글리프 집합이 가져간다」 |

### 느슨한 수치 → 엄격

- JS 숫자는 전부 double 이다. `float` 를 섞지 않는다.
- `Infinity` 는 표기 분기를 같이 옮긴다 (UI/UX 「`Infinity` 는 표기 분기를 같이 옮긴다」).
- 가중 추첨을 `float` 로 누적하지 않는다.

## 작업 사이클 — 학습 → 실행 → 검증

```
[학습] PD 확정 → 지식 담당자 4인이 원본을 돌려 보며 HtmlToUnityLogic/ 을 채운다
   │        (Unity 코드를 건드리지 않는다)
   ↓
[실행] 지식 담당자 갱신(Design → Client → FX → UI/UX)
   │   → 이관 담당자 수행(Programmer ① → Artist ② → Programmer ③)
   ↓
[검증] 이관 담당자가 PD 에게 콜 → PD 가 QA → 미흡 항목 나열 → 다음 회차로
   │
   ├─ 리스트업 전 항목 100% 가 될 때까지 [실행]↔[검증] 을 N회 반복
   └─ 미흡의 원인이 「원본을 덜 봤다」면 [학습]으로 되돌린다 (「회차 카운터를 원장에 남긴다」)
```

### 담당자는 착수 전에 반드시 3단계를 밟는다

1. 작업 내역 확인 — 원장에서 자기 항목 + 오염된 내용 + 회고록을 읽는다.
2. 최신화 — 이번 회차에 손댈 범위를 착수 전에 원장에 적는다.
3. 확인 — 다른 담당자와 겹치는지, 선행 게이트(「게이트」)가 열렸는지 본다. 안 열렸으면 착수하지 않는다.

### 「학습 단계」와 「실행 단계」를 섞지 않는다

학습 단계 산출물은 md 뿐이다. 이유: 학습 중 코드를 고치면 그 결과물이 다음 학습 대상이 되어 오염이 고착된다.

### 회차 카운터를 원장에 남긴다

학습·실행 단계 수행 횟수를 숫자로 적는다. 3회차에도 같은 항목이 60% 면 반복하지 말고 방법을 바꾸거나 원본을 다시 연다.

## 학습이 끝나면 「작업 분해표」를 만든다 — 이관은 그 순서대로만 돈다

**단위는 학습 산출물에서 기계적으로 뽑는다.** 이유: 분해 없이 돌면 뒤 결함이 앞으로 되돌아가고 진행이 안 보인다.

| 단위가 나오는 자리 | 한 단위 |
|---|---|
| `02_시스템_<이름>.md` | 문서 한 장 |
| `01_게임플로우.md` 의 화면 전이 그래프 | 화면 하나 |
| `03_데이터.md` 의 테이블 전수 | 테이블 묶음 |
| `05_연출.md` 의 연출 목록 | 연출 덩어리 (클리어 연출 · 피격 연출 …) |
| `06_리소스.md` 의 두 목록 | 리소스군 (배경 · UI · 이펙트) |

문서에 없는 단위가 필요하면 분석이 덜 된 것이다. 학습으로 돌아간다.

### 분해표 — 원장에 만든다 (규격은 `분석로직.md`)

| # | 단위 | 무엇을 만드나 | 근거 문서 | 선행 | 완료 조건 (검사·항수) | 상태 |
|---|---|---|---|---|---|---|
| 1 | 데이터 적재 | 테이블 N개 → 컨테이너 | `03` | — | 행 수 어설션 N/N | |
| 2 | <핵심 시스템> | 계산·판정 | `02_<이름>` | 1 | 정답지 N/N | |
| 3 | <화면> | Window/Panel | `01`·`04` | 1 | 전수 대조표 빈칸 0 | |
| … | | | | | | |

빈칸이 있는 단위, 특히 완료 조건에 숫자가 없는 단위는 시작하지 않는다.

### 순서를 매기는 규칙 — 네 개, 위에서부터 적용

1. 의존이 먼저 — 데이터 → 로직 → 화면 → 연출 → 배선.
2. 한 판이 돌아가는 최소 경로(입력 → 판정 → 결과)가 먼저. 장식·연출은 뒤.
3. 그 안에서 못 잰 것이 많은 단위가 먼저. 이유: 불확실을 미루면 마지막에 터진다.
4. 같은 순위면 작은 것부터.

2 와 3 이 부딪히면 3 이 이긴다.

### 3패스는 한 단위 안에서 도는 순서다

게임 전체에 ①을 다 하고 ②를 다 하지 않는다.

```
단위 1 : ① 코드·데이터 → ② 프리팹·연출 → ③ 배선 → 검사 → 완료
단위 2 : ① → ② → ③ → 검사 → 완료
…
```

- 한 단위는 검사까지 끝내고 다음으로 간다.
- 끝난 단위를 다시 열어야 하면 그 단위의 완료 조건을 고쳐 분해표에 반영한다.
- 공용 토대(프레임워크 최소 세트 · 로더 · 확정표 반영)는 단위가 아니라 0번 전제로 먼저 세운다.

### 시작과 완료를 말한다

```
<단위 이름> 작업 들어갑니다.      ← 무엇을 · 왜 (한 줄)
<단위 이름> 완료 — <검사> N/N.    ← 무엇이 바뀌었나 · 숫자 (한 줄)
```

| 하지 않는다 | 한다 |
|---|---|
| 「패스 ①-g 완료. 정답지 459 → 461」 | 「발사 물리 완료 — 정답지 461/465」 |
| 여러 단위를 한 보고에 섞기 | 단위마다 시작·완료를 따로 |
| 「됐습니다」 | 어느 검사가 몇 항 통과했나 |

제목은 게임을 아는 사람이 알아듣는 말로 쓰고 패스 번호·파일명을 넣지 않는다.

### 완료는 마지막에 한 번, 조건이 다 찼을 때만 말한다

**이관 완료는 아래가 전부 참일 때만 말한다. 하나라도 비면 남은 것의 목록을 낸다.** 「거의 완료」는 쓰지 않는다.

| 조건 | 확인 위치 |
|---|---|
| 재측정 대기 표가 비어 있다 (해소 또는 이관 밖 판정) | 원장 |
| PD QA 미흡 목록이 비어 있다 | 원장 |
| 이관율 대조표 분모가 확정표 범위와 같고 「의도된 차이」 밖 차이가 0 | 원장 (분석로직 「이관율 대조표」) |
| 검사 전부가 마지막 코드로 다시 돌아 N/N | 검사 로그 |
| 빌드가 그 게임 확정표로 구워졌다 | `GameFramework.md` 「저장소에 게임이 여럿이면」 |
| 재는 도구 정리 — 회차용 검사기는 각 회차 끝에, 게임별 하네스·회귀 검사는 이관이 끝날 때 지운다(`out/` 은 회차마다 비운다) · 게임 전용 도구가 공용 자리에 없다 | `Transfer_Programmer.md` 「재는 도구는 이관이 끝나면 지운다」 |
| 오케스트레이션 문서를 고쳤으면 두 곳이 같다 | 진입 파일의 동기화 절차 |
| 사람이 열어서 볼 상태로 되돌려 놓았다 (닫았던 에디터 재실행 등) | 도구 제약 표 |

**이 답이 모든 파트의 분기를 결정한다. 답이 없으면 그 아래를 짜지 않는다.**

|---|---|---|

### 질문 문안 — 파생 문항까지 전부 묻는다. 일부만 묻고 넘어가지 않는다

화면·해상도 계열(2·3·7)은 한 덩어리로 먼저 묻는다. 이유: 미정이면 좌표 단위를 모르고 아트를 두 번 굽는다.
기본값 있는 질문은 「이대로 갈까요?」로 묻고, 답이 무엇을 바꾸는지 한 줄을 붙인다.
다른 답을 받으면 그 답이 이긴다. 사람이 정한 값은 실측으로 뒤집지 않는다. 실측은 보고하고 확정을 따른다 (재발방지 #184).

[화면 · 해상도]
- 1. 타깃 플랫폼은? 【기본값: 모바일】 → 세이프에어리어·터치 입력·텍스처 압축이 갈린다. 원본이 데스크톱 전용 흐름 배치면 모바일 레이아웃은 원본에 없으므로 기준을 12번에서 따로 정한다.
- 1-b. 구체 플랫폼은? (Android / iOS / Windows / WebGL …) 【기본값: Android】 → 패키지 이름·최소 OS·텍스처 압축 포맷·스크립팅 백엔드·그래픽 API 가 갈린다. 답이 없으면 빌드 설정이 끝까지 기본값으로 남는다.
- 1-c. 제품명과 패키지 식별자는? 【기본값: 게임명 그대로 · `com.<회사>.<게임명>`】 사례: 행이 없어 첫 게임의 제품명·패키지가 두 번째 게임에 남았다.
- 2. 화면 방향은? 【기본값: Portrait】 주의: 자동 회전을 끄지 않으면 기기를 돌렸을 때 원본에 없는 레이아웃이 나온다.
- 3. Canvas Reference Resolution 은? 【기본값: Landscape 1920×1080 · Portrait 1080×1920】
- 3-b. Canvas Screen Match Mode 는? 【기본값: Match Width or Height · Match = 0 (Width 기준)】 → 세로 게임의 판정 대상이 대개 폭이다.
- 3-c. Canvas Render Mode 는? 【기본값: ScreenSpace-Camera + 전용 UICamera】 → UI 사이에 파티클·스프라이트·셰이더를 끼울 수 있다. Overlay 는 나중에 통째로 갈아야 한다.
- 3-d. (알림) 원본 논리 해상도는 PD 가 원본을 띄워 실측하고(CSS 가 아니라 JS 가 잡는 경우가 많다) 환산 배율을 계산해 확인만 받는다. 배율은 한 곳만 통과시킨다. 프로젝트에 스케일·레이아웃 규약이 있으면 그쪽이 우선이다.

2. 고르면 무엇이 달라지나(비용·품질·나중에 바꾸기 어려운가)를 쓴다.

### 합격 기준을 숫자로 못 박는다

완료 조건은 「정답지 36/36 통과」 · 「글자 제외 95%」 · 「같은 상태에서 개체 수가 원본 범위」처럼 판정 가능한 문장만 된다.
**픽셀 95%는 정적 화면의 하한이고, 실제 기준은 「같은 상태에서 같은 것이 같은 밀도로 움직이는가」다.**
사례: 배치·아트·좌표는 맞는데 적이 안 죽어 화면이 어색했다. 정적 캡처로는 안 잡힌다.

### 재는 도구를 먼저 만든다 — 기준만 정해 놓으면 아무도 안 잰다

채점기가 없으면 합격선을 적어도 한 번도 수치로 판정되지 않는다.
사례: 「거의 다 됐다」던 코드에 채점기를 붙이자 첫 실행에서 수백 건 결함이 나왔다.

1. 출처 대조 — 정답지가 전제한 원본과 지금 데이터가 같은가.
2. 측정 — 실패를 갈래로 나눠 찍는다 (자료형 한계 / 진짜 차이 / 정답지 결함).
3. 수정 — 갈래별로 처방한다.

자세한 절차는 `Client.md` 「순서를 지킨다 — 출처 대조가 채점보다 먼저다」.

### 원장은 오케스트레이션이 아니다 — 배포물에 끼워 넣지 않는다

| 무엇 | 어디 | 성격 |

| 원장 (확정표·게이트 판정 숫자·회고) | 개인 작업 공간 | 그 회차의 기록 |
| 학습 산출물 · 정답지 | 원본 게임 폴더 | 그 게임의 것 |

재사용되는 것과 그 회차의 것을 같은 자리에 두지 않는다.

### 학습은 「읽기」가 아니라 「돌려 보기」다

- HTML5 를 실제로 실행해 놀아 본다.
- 덮어쓰지 말고 「전 회차: … / 이번 회차:」로 남긴다.
- 자기가 지난 회차에 쓴 문장을 의심한다.

### 오염된 내용의 정의 — 이것들이 원장에 기록되어야 하는 것이다

**오염 = 사실이 아닌데 사실로 기록되어 다음 회차의 전제가 된 것.**

| 갈래 | 예 |
|---|---|
| 캡처를 사양으로 삼음 | 두 줄로 보여 `LR` / `LEGEND RARE` 두 요소로 적었는데 DOM 은 한 덩어리였다 |
| 문서·라인 번호를 믿음 | 기획서 라인 번호가 구간마다 어긋났다 (공통절차 「문서의 라인 번호를 믿지 마라」) |
| 애니메이션 한 프레임을 정색으로 오인 | 점멸 중 캡처로 `#8a3a35` 를 구웠다. 원본은 `#ff5a4d` |
| 이름이 비슷한 다른 물건 | `XXX_button.png` 를 행 배경으로 깔았는데 장착 버튼용이었다 |
| 추측을 결론으로 적음 | 「대략 이 정도 배율」이 원본 수치처럼 인용됐다 |

오염을 발견하면 고치기 전에 원장에 먼저 적는다.

## 작업 원장 — `HtmlToUnity_작업내역_<게임명>.md`

PD 가 학습 단계 착수 직후에 만들고, 모든 담당자가 이 파일 하나에 적는다. 골격은 [분석로직 「HtmlToUnity_작업내역_<게임명>.md」](분석로직.md)이고 카테고리는 고정이다.
내용: 회차 · 리스트업(달성률) · 학습 내용 · 오염된 내용 · 패스 ①②③ 수행 내용 · 회고록 · PD QA 미흡 목록.

### 리스트업 규칙

- 항목은 화면·시스템 단위로 자른다.
- 항목마다 회차와 달성률(%)을 적는다.
- 달성률은 분모가 있어야 한다(「9요소 중 6개 → 67%」). 분모가 없으면 「화면 하나를 전수 대조표로 여는 법」의 대조표부터 만든다.
- 100% 는 PD QA(「검증 단계」) 통과로만 붙는다.

### 원장에 쓰지 않는 것 — 표준 선언

「확정된 이름 · 앞으로 이걸 쓴다」 같은 표준 선언은 규칙 문서(`CLAUDE.md` · 파트 문서)에 적고, 원장에는 「어디에 적었다」만 남긴다.
사례: 원장의 표준 선언 블록이 개편 뒤 9곳 어긋났고 하나는 정반대였다 (「셀을 꺼서 저장하면 안 보인다」 → 지금은 `CreateCell` 이 `SetActive(true)` 를 부른다).

| 원장에 쓴다 | 규칙 문서에 쓴다 |
|---|---|
| 무엇을 했나 · 몇 개를 셌나 · 무엇을 놓쳤나 | 이름 규약 · 값 기준 · 금지 사항 |
| 그 회차의 판단과 근거 | 앞으로 지켜야 할 것 |

이미 적힌 표준 선언은 지우지 말고 취소선 + 「지금은 이렇다」 대조표를 붙인다.

### 회고록 규칙

회차마다 「무엇을 · 왜 놓쳤나 · 다음에 무엇으로 막나」를 채운다. 대책은 도구·체크리스트·게이트 중 하나여야 한다. 「주의하겠다」는 대책이 아니다.
예: 「없어야 할 창이 떴다 / 프리뷰가 창을 격리해 구워서 / 「플로우 diff 를 프리팹 대조보다 먼저」를 게이트에 넣음」

## 실행 단계 — 순서와 운영

### 역할 기동 규약 — 한 명이 7개 역할을 연기한다

한 AI 가 7개 역할을 순차로 연기하므로 역할 이탈이 가장 흔한 실패다.

#### ① 전환할 때마다 선언문을 출력한다

사용자에게 보이게 출력한다.

```
[역할 전환] 지금부터 나는 <역할>다.
  할 수 있는 것 : <산출물>
  하지 않는 것  : <권한 밖>
```

```
[역할 전환] 지금부터 나는 Client(지식 담당)다.
  할 수 있는 것 : 원본 읽기 · 01_게임플로우.md / 99_원본지도.md 작성
  하지 않는 것  : Unity 코드·프리팹 수정 (그건 Transfer_Programmer 가 한다)
```

#### ② 역할별 권한표 — 이 표 밖을 건드리면 이탈이다

| 역할 | 만드는 것 | 손대지 않는 것 |
|---|---|---|
| PD | 확정표 · 원장 껍데기 · QA 미흡 목록 | 코드 · 프리팹 · 아트 전부 |
| Design / Client / FX / UI/UX (지식) | `HtmlToUnityLogic/` 문서만 | Assets 아래 전부 |
| Transfer_Programmer ① | 데이터·Manager·Management·Window 스크립트 · 검증 하네스·정답지 덤프·채점기 (G1·G2 를 열기 전에) | 프리팹 · 아트 파일 · 빌더 스크립트 |
| Transfer_Artist ② | 프리팹 · 리소스 · 연출 (굽는 방식은 확정표 10-b) | 게임 로직 · 데이터 컨테이너 · 배선 |
| Transfer_Programmer ③ | 배선 (등록 · 호출 · 파라미터 주입) | 프리팹 수정 — Artist 에게 되돌린다 |

#### ③ 역할을 바꾸면 기억을 이어가지 않는다

**이전 역할의 결론은 md 에 적힌 것만 인정한다.** 필요하면 원본을 다시 연다.
이유: 방금 본 Unity 코드가 「원본도 이렇겠지」로 판단을 오염시킨다.

#### ④ 서브에이전트를 쓸 수 있으면 써도 된다

권한표(②)를 도구 화이트리스트로 강제하면 이탈이 원천 차단된다. ①~③은 환경과 무관하게 항상 지킨다.

### 순서는 고정이다

```
지식 담당자 갱신 :  Design → Client → FX → UI/UX

이관 담당자 수행 :  Transfer_Programmer ①  코드 / 데이터 이관
                    Transfer_Artist     ②  프리팹 / 연출 생성
                    Transfer_Programmer ③  게임 플로우에 따라 배선
                                            (UI · 연출 · 게임오브젝트)
```

| 패스 | 담당 | 다음으로 가는 조건 | 이유 |
|---|---|---|---|
| ① | Programmer | 데이터 조회·로직·화면 전이가 돈다. 주입 API(`SetData`)가 선언돼 있다 | 주입 API 가 있어야 프리팹을 구울 의미가 있다 |
| ② | Artist | 프리팹·리소스·연출이 존재하고 정적 상태로 원본과 같아 보인다 | 배선할 실물이 있어야 ③이 가능하다 |
| ③ | Programmer | 게임 플로우 위에서 실제로 돈다 | 어디에 물리는지는 실물이 나온 뒤 정해진다 |

### 패스 ③이 하는 일 — 「만들어졌다」와 「돈다」 사이

| 배선 대상 | 하는 일 | 빠지면 |
|---|---|---|
| UI 배선 | Management 등록 · 버튼 → event → Manager 연결 · `SetData` 호출 | 창이 안 열리거나 값이 비었다 |
| 게임 플로우 배선 | `GameFlow` 전이표대로 열고 닫기 · 원본에 없는 창 차단 | 없어야 할 창이 뜬다 (「플로우 diff 를 프리팹 대조보다 먼저」) |
| 연출 배선 | 런타임 파라미터(속도·위상·색·상태) 주입 · 상태 전이와 동기 | 프리팹 기본값으로만 돈다 |
| 게임오브젝트 배선 | 프리팹 로드 경로 · 풀 등록 · 스프라이트 런타임 주입 · 정렬 기준값 | 폴백 도형으로 남거나 풀에서 샌다 |
| 데이터 종속 아트 | 배경·초상·아이콘을 데이터로 조회 | 1번 값이 전 구역에 나온다 |
| 지연 로드 아트 | 로드 완료 후 다시 조회 | 평생 폴백 |

**③의 완료 판정은 Play Mode 다.**
재생 검사는 사람에게 넘기지 않고 에디터 다리로 돌린다. 에디터를 껐다 켜지 않는다 (예시: `PLAYMODE=1`). 검사기는 시작할 때 `Application.runInBackground = true` 를 켠다 (재발방지 #156). 절차는 `공통절차.md` 「에디터가 열려 있으면」 · 「입력 판정은 재생 안에서만 잰다」.
주의: 편집 모드 레이캐스트는 원리적으로 비므로 「안 맞았다」를 결함으로 읽지 않는다.

### 공통

- Design 이 먼저다. 데이터가 없으면 배선할 대상이 없다.
- 이관 담당자는 `HtmlToUnityLogic/` 을 근거로 작업하되, 최종 판정은 지식 담당자 요약이 아니라 원본 코드다.
- ③에서 프리팹을 다시 뜯어야 하면 Artist 에게 되돌린다. 확정표 10-b 가 「프리팹이 주인」(기본)이면 프리팹을 직접 고치고 빌더를 다시 돌리지 않는다. 「빌더가 주인」이면 빌더를 고쳐 다시 굽는다.

### 유니티는 스스로 돌린다 — 사람에게 묻지 않는다

도메인 리로드·재생·정지는 담당자가 직접 실행하고 멈춘다. 에디터가 열려 있으면 다리로 시킨다.

```
[재생 멈춤]      ← 작업 착수 전 무조건 (공통절차 「컴파일·툴 실행 순서」 ⓪)
dotnet build …                    ← 컴파일 판정은 여기서 (공통절차 「컴파일·툴 실행 순서」 ⓪-b)
[에셋 새로고침] → 컴파일 완료 확인 → [에디터 코드 실행] → [콘솔 읽기]
[재생 시작] → 거동 확인 → [재생 멈춤]
```

재생 멈춤은 파괴적 행위가 아니다. 재생 중에 이관 작업을 하지 않는다. 이유: 컴파일 보류·프리팹 미반영·세이브 훼손이 섞인다.

### 이관 담당자는 한 항목을 끝낼 때마다 원장을 갱신한다

몰아서 적지 않는다. 문맥이 날아가면 복구할 수 없다.

### 완료되면 PD 에게 콜한다

패스 ③까지 끝나야 콜한다. 콜을 받은 PD 는 「검증 단계」 QA 를 돌린다. 담당자가 100% 를 선언하지 않는다.

## 검증 단계 — PD QA

PD 는 만들지 않고 안 된 것을 찾아 나열한다.

### QA 체크 순서

| # | 보는 것 | 판정 |
|---|---|---|
| 0 | 역할 경계 위반 | 학습 회차 Assets 변경 · ②에서 배선 · PD 직접 제작 (「역할 기동 규약」) |
| 1 | 게이트(「게이트」) G0~G8 순서대로 닫혔나 | 아래층이 안 닫혔으면 위층 점수는 무효 |
| 2 | 플로우 diff(「플로우 diff 를 프리팹 대조보다 먼저」) | 없어야 할 창 · 있어야 할 창 · 순서 |
| 3 | 전수 대조표(「화면 하나를 전수 대조표로 여는 법」) 빈 칸 | 빈 칸 = 미이관 |
| 4 | 수치 판정 — 정답지 또는 A/B 개체 수(공통절차 「A/B 측정」) | 상태를 맞춘 뒤에 잰다 |
| 5 | 렌더 판정 — 글자 제외 점수, 그리기 파라미터 표 | 점수가 낮으면 공통절차 「점수를 믿기 전에」부터 |
| 6 | 리소스 감사(공통절차 「에셋 등록은 양방향으로 감사한다」) | 코드가 요구하는 주소가 있는가 (양방향) |
| 7 | 거동 판정 — Play Mode 에서 눌러 본다 | 클릭 가능성·상태 전이·지연 로드 아트 |
| 8 | 재측정 대기 표 | 미측정 항목을 그대로 미흡 목록에 편입. 담당자가 안 올려도 PD 가 집는다 |
| 9 | 이관율 대조표 (분석로직 「이관율 대조표」) | 분모 = 확정표 범위. 「의도된 차이」 밖 차이는 전부 미흡. 표가 없으면 100% 선언 불가 |
| 10 | 「증명」 열이 채워졌나 | 갈래마다 화면에 나옴/동작함의 근거. 「프리팹에 있다」·「표에 행이 있다」는 증명이 아니다. 빈 줄은 분자에서 뺀다 (재발방지 #159) |
| 11 | 개체마다 행동이 분모에 들어갔나 | 소스 개체 클래스 `update()` 분기 수 = 우리 갈래 수. 사례: 공격 못 하는 동료가 100% 였다 (재발방지 #160) |
| 12 | 검사가 결과물을 재나 | 여러 패스·캐시 제자리 수정·좌표 변환은 중간값이 맞아도 결과가 갈린다. 골든은 산출물 전 칸 대조 (재발방지 #162) |
| 13 | 세는 검사가 개수를 못 박았나 | 「0개 실패」는 분모 0 이어도 통과로 보인다. 최소 개수를 박고 만들어 둔 것 전부(프리팹·표)를 센다 (재발방지 #163) |
| 14 | 그림으로 못 읽는 것을 그림으로 정하지 않았나 | 층(겹침) · 늘리는 방식(9슬라이스/확대) · 「0인가 못 읽었나」는 덤프의 부모·형제 순서와 소스로 판정 (재발방지 #161 · #165) |
| 15 | 원본과 우리의 화면 단면을 숫자로 댔나 | 값이 다 맞아도 알파·색공간·블렌딩·늘리기로 화면이 다를 수 있다. 같은 자리 한 줄을 색이 바뀌는 구간으로 뽑아 나란히 둔다 (재발방지 #168) |
| 16 | 속을 이어서 다듬을 수 있나 — G8 | 네 수가 원장에 있다. 겉 점수가 100% 여도 G8 이 안 닫히면 미흡이다 (「속 품질 — 이어서 다듬을 수 있어야 한다」) |

### QA 결과는 「미흡 목록」으로 낸다

- 항목마다 [무엇이 · 어디가 · 기대 · 실측] 네 칸. 「어색하다」는 결과가 아니다.
- 미흡 목록이 다음 회차 리스트업이 된다. 달성률을 내리고 회차를 +1 한다.
- 미측정은 「미측정 ≠ 통과」를 따른다.
- 전 항목 100% 전에는 사이클을 닫지 않는다.

### PD 가 가장 많이 속는 세 가지

| 함정 | 실제 |
|---|---|
| 「화면 점수가 높다」 | 없어야 할 창이 떠 있어도 높다 (「플로우 diff 를 프리팹 대조보다 먼저」) |
| 「경고 0 이다」 | 빌드 중 NRE 를 노이즈로 방치하면 기준으로 못 쓴다 (공통절차 「컴파일·툴 실행 순서」) |
| 「구간 점수가 낮으니 결함이다」 | 영상 프레임·재화 보유량 차이일 수 있다 (공통절차 「A/B 측정」 상태 정합표) |

## 인수인계 계약 — 파트 사이에서 무엇을 넘기고 무엇을 증명하나

```
원본(심판)
   │
   ├─ 기획 ──[테이블 + 문구 + 파생규칙]──▶ 클라
   │                                        │
   │                                        ├─[계산 결과 스냅샷 + 표기 계약]──▶ UI/UX
   │                                        │
   │                                        └─[엔티티 상태 + 그리기 파라미터]──▶ 연출
   │
   └─ (모든 파트가 원본을 직접 읽는다. 전달받은 요약을 믿지 않는다)
```

### 지식 담당자 → 이관 담당자

md 는 컴파일되지 않아 가장 조용히 새는 경계다.

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| `HtmlToUnityLogic/` 골격 전부 | 항목이 코드·프리팹에 1:1로 도달했다. 안 쓰인 항목은 미이관 |
| 원본 라인 인용 | 직접 열어 grep 으로 재확정했다 (공통절차 「문서의 라인 번호를 믿지 마라」) |
| 「제작 필요 리소스」 목록(`06_리소스.md`) | 전 항목을 굽고 어드레서블 등록까지 했다 (공통절차 「에셋 등록은 양방향으로 감사한다」) |
| 「오염된 내용」 목록 | 다시 밟지 않았다. 대책이 도구로 남아 있다 |

점검: 문서 항목 수 대비 이관 수를 분수로 적는다. 이것이 「리스트업 규칙」 달성률의 분모다.

### 기획 → 클라

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 테이블 (스키마 + 행 수) | 컨테이너가 존재하고 조회가 성공한다 |
| 원본 계산식 인용 (라인 번호 포함) | 같은 입력에 같은 출력. 정답지 또는 A/B |
| 폴백 계수 (원본 `\|\|` 뒤의 값) | 코드 상수로 두고 원본 행을 주석에 인용 |

점검: 새 테이블마다 `AllValues.Count` 를 찍는다.

### 클라 → UI/UX

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 표기용 스냅샷 구조체 (`XxxEntry`) | 모든 필드가 화면에 도달한다. 안 쓰는 필드는 계약 오류 |
| 필드의 의미(내부 코드인가 표기명인가) | 화면에 내부 코드가 뜨지 않는다 |
| 파생 표기 필요 여부 | 표시 직전 변환을 태웠다 |

점검: 원본 UI 함수(예: `augCardHTML`) 하나를 「원본 / 우리 / 출처」 3열 요소표로 편다 (「화면 하나를 전수 대조표로 여는 법」).

### 클라 → 연출

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 엔티티 상태 (위치·속도·반지름·종류) | 원본 반지름을 그대로 쓴다 |
| 원본 그리기 파라미터 (선 굵기·blur·색·알파) | 상수로 두고 원본 행을 인용 |
| 프레임 단위 시각(`t`)·`dt` | `t`/`dt` 를 받는 원본 함수는 반드시 움직인다 |

점검: 원본 draw 함수의 `lineWidth` / `shadowBlur` / `globalAlpha` / `globalCompositeOperation` 을 전부 grep 해 표로 만든다.

### UI/UX ↔ 연출

분담: 텍스트·레이아웃·입력은 UI, 그림 자체는 연출.

- 아이콘 프레임(장식)과 글리프(데이터 종속)는 별개 필드로 나눈다.
- 절차 생성 아이콘·이펙트 텍스처는 연출이 굽고 UI는 경로만 참조한다.

### 화면 하나를 「전수 대조표」로 여는 법 (모든 파트 공통)

원본에서 그 화면을 그리는 함수의 요소를 빠짐없이 표로 나열한 뒤에 코드를 고친다.

| 요소 | 원본 | 우리 | 출처 | 상태 |

| 태그 | 등급 사전 + 접미어 (`고급 등급 무기`) | `고급` | 등급명만 넘김 | 실패 |

| … | | | | |

### 플로우 diff 를 프리팹 대조보다 먼저 돌린다

**프리뷰 하네스는 창을 격리해 구우므로 원본에 없는 창이 한 겹 더 뜨는 결함은 프리팹 검증으로 안 잡힌다.**
사례: 뽑기 후 원본에 없는 `RewardResultPopup` 이 떴는데 창마다 점수가 높아 몇 턴 동안 못 봤다.

화면을 완료로 올리기 전에 Play Mode 에서:

1. 원본에서 그 화면의 버튼 전수와 각각이 여는 것을 나열한다 (`addEventListener` · `data-*` · `onclick` 을 grep).
2. 유니티에서 같은 순서로 눌러 열린 창 목록을 적는다.
3. 두 목록을 diff 한다 — 없어야 할 창 · 있어야 할 창 · 순서.

배치 대조는 그다음이다.

### 검증 하네스에 없던 화면을 만나면 먼저 하네스를 만든다

캡처가 들어오면 먼저 「이 화면을 굽는 프리뷰가 있나」를 묻고, 없으면 그것부터 만든다. 없으면 그 화면 지적은 전부 미측정으로 쌓인다.
주의: 정지 프리뷰는 `Update` 가 안 돌므로 애니메이션 상태는 끝 상태를 강제한다. 안 그러면 t=0 이 찍혀 「기능이 없다」로 오판한다.
