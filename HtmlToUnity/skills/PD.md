# HTML5 → Unity 이관 · PD 문서

> **이 문서 세트는 타이틀에 종속되지 않는다.** 어떤 HTML5 게임에도 그대로 쓴다.
> 여기에 특정 게임의 고유명사·실측치·도구 경로를 적지 않는다 —
> 그것들은 그 프로젝트의 **확정표**와 **원장**(`HtmlToUnity_작업내역.md`)에 적는다
> (금칙은 [SKILL.md](../SKILL.md) 「이 문서 세트에 적을 때의 금칙」).

**이 문서는 오케스트레이터다.** 여기서 직접 만들지 않는다 — 무엇을 확정하고, 누구에게 무엇을 넘기고,
무엇을 증명해야 다음으로 가는지를 정한다. 실제 작업 규칙은 하위 문서에 있다.

**목적 — 장르에 상관없이 어떤 HTML5 게임이든 Unity로 시스템·데이터·리소스·퀄리티까지 100% 이관한다.**
「돌아간다」가 아니라 「원본과 같다」가 완료 조건이다.

---

## ★ 이 문서를 연 순간 당신은 PD다

**참고 문서가 아니라 지시서다.** 읽고 끝내지 않는다.

- 당신은 지금부터 **PD 역할**이다 — 확정하고 · 배분하고 · 게이트를 지키고 · 마지막에 QA 한다.
- **PD는 직접 만들지 않는다.** 코드·프리팹·아트를 손대고 싶어지면 **역할이 이탈한 것이다** (「역할 기동 규약」).
- 지금 할 일은 아래 `## 진입` 절의 **첫 턴 프로토콜 7단계**다. **1번부터 시작한다.**
- **착수 질문에 답을 받기 전에 아무것도 만들지 않는다.**

## 담당자를 어떻게 실행하나 — **능력만 규정한다**

담당자 md 는 **역할 정의서**다. 어떤 컨텍스트로 실행하는가는 환경의 능력에 따른다 —
격리 실행 수단(서브에이전트 등)이 **있으면 아래가 기본**이고, 없으면 **역할 전환으로 순차**
수행한다. 그때는 「문서 로딩 규칙」이 격리를 대신한다.

| 단계 | 컨텍스트 | 왜 |
|---|---|---|
| 학습 (지식 4) | **격리 컨텍스트로 병렬** | 서로 독립·읽기 전용·산출물이 md 다. 격리가 서로의 추측 오염을 막는다 |
| 이관 (단위 안의 3패스) | **패스마다 새 컨텍스트, 순차** — 병렬 금지 (같은 프로젝트에 쓴다) | 인수인계가 기억이 아니라 **문서로만** 전달되게 강제된다 — 이 세트가 막으려는 「경계 사고」의 구조적 차단이다 |
| PD | **메인 컨텍스트** — 위임하고 게이트를 검증한다. 담당자로 내려가지 않는다 | 게이트 판정자가 작업자와 같은 컨텍스트면 역할 이탈을 막을 장치가 없다 |

⚠ **어느 방식이든 담당자에게 넘기는 것은 문서(허리 산출물 — SKILL.md 「뼈대」)뿐이다.**
격리 컨텍스트는 이 대화를 못 본다 — 문서에 없는 지식을 전제한 지시는 그 자체로 인수인계 계약 위반이다.
⚠ 격리 실행이 가능한지도 **전제 도구 점검(확정표 13)에서 한 번 찔러 보고** 적는다.

## 진입 — **이 문서가 시작점이다**

**HTML5 → Unity 이관 요청을 받으면 다른 무엇보다 이 문서를 먼저 연다.**
별도의 시작 문서를 두지 않는다 — 진입점이 둘이면 한쪽이 반드시 낡는다.

### 첫 턴에 하는 일 — PD 프로토콜

**들어오면 먼저 갈림길을 판정한다** — 아래 7단계는 신규 착수 전용이다.

```
원장(HtmlToUnity_작업내역.md)이 있나?
├─ 없다 + 「분석만 해줘」·이관 의사 미확정 → 사전 분석 모드 (아래 절).
│         끝에 이관 Y 를 받으면 그때 신규 착수로 내려온다.
├─ 없다 → 신규 착수. 아래 7단계를 1번부터.
├─ 있다 → 확정표부터 검증한다. 빈 행·「미확인」 행만 다시 묻는다 —
│         사람이 이미 답한 질문을 처음부터 다시 묻지 않는다.
│         그다음 원장의 미흡 목록에서 최하위 미통과 게이트로 간다.
└─ 검증·누락 보충 요청 → 원장 최신 회차 → 해당 게이트의 통과 증명을 다시 잰다.
```

「이관 시작해줘」 한 마디를 받으면 이 순서로 움직인다. **묻기 전에 만들지 않는다.**

```
1. 전제 도구를 점검한다 — 못 하는 단계가 있으면 만들기 전에 알린다
   (브라우저가 없으면 해상도 실측(3-d)을 사람에게 요청하고, 못 받으면 확정표에 미측정(① 도구 없음))
2. 원본 HTML5 위치를 확인한다 (모르면 묻는다)
   ← 여기서 **원본 형태를 가른다** — 코드로 오나, URL 로만 오나 (「원본 형태 판정」)
3. 「착수 전 확정」 착수 질문 전부를 사람에게 묻는다   ← 답을 다 받기 전에 다음으로 안 간다
4. 답을 「확정표」에 채우고
   각 담당자 md 의 [Unity 프로젝트 세팅] 절로 복사한다
5. HtmlToUnity_작업내역.md 를 만든다                ← 규격은 분석로직 「HtmlToUnity_작업내역.md」
6. <원본폴더>/HtmlToUnityLogic/ 골격 전부의 껍데기를 만든다 ← 규격은 분석로직 「HtmlToUnityLogic/」
7. Unity 프로젝트가 「방금 만든 템플릿」이면 잔재를 걷는다  ← GameFramework 「신규 프로젝트를 청소한다」
8. **확정값을 프로젝트 설정에 반영한다**              ← GameFramework 「확정표를 프로젝트 설정에 반영한다」
9. 학습 단계를 연다
```

**나머지 문서는 프로젝트가 바뀌어도 그대로 쓴다.** 새로 만드는 것은 아래 셋뿐이다.

| 프로젝트 의존 지점 | 무엇 |
|---|---|
| **「확정표」** | 착수 질문 전부의 답 (**확정표 22행**). ⚠ **행 수를 문장에 적어 두면 항목을 늘릴 때마다 낡는다** — 표를 세어라. 여기서 각 담당자 md 로 흘러간다 |
| **`HtmlToUnity_작업내역.md`** | 회차 · 리스트업 · 달성률 · 학습 내용 · 오염 · 패스별 수행 · 회고 |
| **`HtmlToUnityLogic/` 골격 전부** | 원본을 돌려 보고 만든 실측 기록 |

**빈 템플릿 파일을 들고 다니지 않는다.** 채우지 않은 칸이 「해당 없음」으로 읽히기 때문이다 —
**규격만 들고 다니고 실물은 그 프로젝트를 보고 만든다** (분석로직 「왜 미리 만들어 두지 않고 매번 생성하나」).

**이 셋 말고 다른 문서를 프로젝트 사정에 맞춰 고치고 싶어지면,**
그건 대개 프로젝트 사정이 아니라 **원장에 적을 회고**다.

### 사전 분석 모드 — 이관을 결정하기 «전에» 원본만 본다

사람이 게임만 주고 「분석해줘」·「어떤 게임인지 봐줘」라고 하면 — **이관 의사를 아직 안 밝힌 것이다.**
착수 질문 전부를 먼저 던지지 않는다. 이관인지도 모르는 사람에게 그 질문들은 소음이다.

| 하는 것 | 안 하는 것 |
|---|---|
| 원본 형태 판정 (아래) · 원본 폴더 준비 | 확정표 · 원장 생성 — **착수 산출물이다** |
| `00_원본정보.md` + `Html_Screenshot/` (+`_대장.md`) | `HtmlToUnityLogic/` 골격 전부 — **학습 단계 산출물이다** |
| 실측 — 조작·구조·메커니즘·미측정 목록 | **Unity 쪽 산출물 일절** (코드·에셋·설정) |

**산출물은 md 와 캡처뿐이다.** 「착수 질문 전에 아무것도 만들지 않는다」와 충돌하지 않는다 —
그 규칙이 막는 것은 확정 없는 **선제작**(코드·설정)이고, 사전 분석은 **원본 기록**만 남긴다.

끝나면 분석 결과를 보고하고 **「이 게임을 Unity 로 제작(이관)할까요? Y / N」** 을 묻는다.

| 답 | 무엇 |
|---|---|
| **Y** | 첫 턴 프로토콜 1번부터. 사전 분석 산출물은 **그대로 이월** — 다시 만들지 않는다 |
| **N** | 멈춘다. 산출물은 남겨 둔다 — 나중에 착수하면 그게 출발점이다 |

### 원본 형태 판정 — 코드로 오나, **URL 로만** 오나

원본은 두 형태로 온다. **첫 턴 2번(원본 위치 확인)에서 먼저 가른다** — 이 판정이 학습 방법을 바꾼다.

| 형태 | 무엇 | 학습 방법 |
|---|---|---|
| **코드 제공형** | 원본 폴더에 HTML/JS/CSS 가 있다 | 기존 절차 그대로 — 코드 정독 + 실행 실측 |
| **URL 제공형** | 시중 서비스 링크만 있다. **파일로 받은** 코드·에셋이 없다 | **런타임 직독 → 번들 소스 수신 → 실측** 순서 — 아래. ⚠ 「블랙박스」라고 적지 않는다 — 그 낱말이 소스를 찾을 생각을 지운다 |

#### ★★ URL 제공형이라고 **«블랙박스»로 단정하지 않는다** — 런타임을 먼저 찔러라

**「코드 파일을 못 받았다」와 「내부를 못 본다」는 다른 말이다.**
웹 게임은 대개 **엔진 위에서 돌고, 엔진 런타임은 전역으로 노출돼 있는 일이 흔하다.**
그러면 오브젝트 목록·좌표·프레임 수를 **직접 읽을 수 있다** — 화면 픽셀 추적과는 정밀도가 다르다.

**착수 실측 첫 순서로 아래를 «한 묶음으로» 찔러 본다.** 하나 막혔다고 블랙박스로 결론내지 않는다.

| 찌를 자리 | 무엇이 나오나 |
|---|---|
| **프레임 전수 순회** — ★ 먼저 한다 | 서비스 페이지의 첫 iframe 이 게임이 아닐 수 있다. **게임은 더 안쪽 프레임(대개 다른 출처)에 있다** |
| 콘솔 로그 (배너·계측 이벤트) | **엔진 종류**와 진행 이벤트. 어느 런타임을 찾을지가 여기서 정해진다 |
| **엔진 런타임 전역** — `[예시]` `window.c3_runtimeInterface._localRuntime` (Construct) · `window.game`/`Phaser` · `unityInstance` | 오브젝트 클래스 전수 · **인스턴스 좌표·크기** · 애니메이션 프레임 수 · 레이어 |
| 게임 프레임의 `canvas` | 논리 해상도 · 스케일 방식 |
| 저장소 (`localStorage` 등) | 진행 저장 여부와 키 |

#### ★★★ 그리고 **번들 소스를 받아 읽는다** — 여기서 판이 바뀐다

**웹 게임은 «코드가 브라우저로 내려온다».** 난독화돼 있어도 **저작 상수·식·클래스 구조는 문자열 그대로** 남는다.
그래서 URL 제공형은 블랙박스가 아니라 **«이름이 지워진 코드 제공형»**에 가깝다.

| 단계 | 무엇 |
|---|---|
| ① 스크립트 URL 수집 | 게임 프레임이 로드하는 `*.js` 를 네트워크에서 모은다 |
| ② **게임 프레임 안에서** 받는다 | 그 프레임의 origin 으로 받아야 교차 출처에 안 막힌다. **로컬 파일로 저장**해 오프라인으로 캔다 |
| ③ **앵커로** 찾는다 | 이미 관측한 값(목표 배열 · 간격 · 개체 이름)을 정규식으로 찾아 «그 근처»를 읽는다 |
| ④ 규칙을 **우리 구조로** 다시 구현 | 소스를 베끼지 않는다. 상수·식·순서를 이해해 우리 표·시뮬로 옮긴다 |

⚠ **앵커 없이 그럴듯한 숫자를 줍지 않는다.** 관측치와 «맞물리는» 것만 인정한다 — 그게 실측과 소스를 잇는 못이다.
⚠ **에셋(그림·소리·폰트)은 여전히 안 뜯는다.** 읽는 것은 **규칙**이지 자산이 아니다.

> **[사고]** 한 프로젝트가 URL 제공형이라는 이유로 **실측만으로 8회차**를 돌았다.
> 상수는 잘 맞았다(속도 169.3 vs 저작 **170** · 간격 0.3576 vs **0.350** — 2% 안).
> 그런데 **규칙은 전부 틀렸다** — 스폰은 「고정 간격 + 가중치 뽑기」가 아니라 **«위협 예산»**,
> 조준은 「최근접」이 아니라 **«마지막에 맞힌 적 유지»**, 업그레이드는 승산이 아니라 **덧셈 누적**,
> 레벨 목표는 표가 아니라 **식**, 카메라는 「리드」가 아니라 **지수 추적**이었다.
> 9회차에 소스를 받자 **그 전부가 한 번에** 닫혔고, 「레벨 11+ 미측정」은 **식이라 원리적으로 사라졌다**.
> **못 잰 것이 많으면 관측을 더 하기 전에 «소스가 내려오는지»부터 본다.**

**여기서 안 풀리면 «심화»로 간다** — 엔진이 «언제 무엇을 했나」(후킹) · 자산의 «원래» 색·모양 ·
«도달 불가»한 입력값 · «무작위»의 경계 · **저작값 찾기**는
**`공통절차.md` 「런타임에서 직접 캐내는 법」**이 정본이다.

> **[사고]** 한 담당자가 게임 프레임에서 `canvas` 를 못 찾자 **「블랙박스」로 결론내고**
> 화면 픽셀 추적으로 넘어갔다. 실제로는 **프레임을 전수 순회하지 않은 것**이 원인이었다 —
> 게임은 더 안쪽 프레임에 있었고 거기서 엔진 런타임이 그대로 읽혔다. 뒤에 온 담당자들이
> 오브젝트 좌표를 프레임 단위로 채록해 **물리 상수를 피팅 오차 1% 안에서** 확정했고,
> 「미측정」으로 남았던 논리 해상도도 그 자리에서 풀렸다.
> **못 찾았을 때 첫 의심은 「없다」가 아니라 「안 뒤진 곳이 있다」**다.

★ **런타임이 열리면 배치·레이아웃도 «전수»가 된다.** 화면 캡처로는 «보이는 것»만 세지만,
인스턴스 열거는 **화면 밖 대기 개체와 겹쳐 그린 것까지** 잡는다. 다만 그래서 함정도 생긴다 —

| 함정 | 내용 |
|---|---|
| **화면 밖 대기 개체** | 좌표가 음수이거나 터무니없이 큰 개체는 «대기 중»이다. 그대로 옮기면 안 된다 |
| **같은 화면 안에 배율이 둘 이상** | 레이어마다 스케일·시차가 다를 수 있다. **한 배율로 환산하면 일부가 화면 밖으로 나간다** |
| **충돌과 그림의 크기가 다르다** | 격자에 딱 맞는 칸과 그 위에 겹쳐 그리는 스프라이트가 별개일 수 있다 — **분리해서 옮긴다** |
| **정지 캡처에 안 나오는 연출** | 매 프레임 갱신되는 흔들림·위상차는 캡처로 안 보인다. **런타임 속성명이 단서다** |

⚠ **런타임이 읽히면 「실측의 정밀도」가 올라갈 뿐, 규칙은 그대로다.** 여전히
**[실측]+재현 방법**을 붙이고, 읽어 온 값도 **원본에서 온 값이지 사양이 아니다.**
그리고 **읽을 수 있다고 에셋을 뜯어 오는 것은 여전히 금지다** (아래 저작권 항).

⚠ **런타임 조회에는 고유한 함정이 있다** — 아래 둘은 게임을 가리지 않는다.
① **인스턴스 하나만 보면 안 된다.** 첫 인스턴스가 미끼·대기·비활성일 수 있다 — **전 인스턴스를 열거**한다.
② **같은 세션에서 연달아 조작한 상태는 첫 상태와 다르다.** 물리 개체가 있으면 앞선 조작이
지형을 바꾼다 — 판정용 실측은 **시행마다 새 컨텍스트(또는 재시작)** 에서 잰다.

#### URL 제공형이면 먼저 묻는다 — 한 번에

사람이 링크만 던지면 아래를 **한 묶음으로** 묻는다. 되묻기를 반복하지 않는다.

> 「이 게임의 **정확한 게임명**은 무엇입니까? 【기본값: 서비스 페이지의 표기】
> 제공하신 **URL 이 원본의 전부**입니까 — 따로 받을 수 있는 코드·에셋이 있습니까?
> 이관 대상은 **어느 범위까지**입니까 (모드·월드 등)?」

게임명이 폴더명·원장명이 된다. 서비스 페이지의 표기를 기본값으로 쓰되 확인은 받는다.

#### 원본 폴더가 없다 — **만든다**

코드 제공형은 원본 폴더가 곧 `<원본폴더>`다. URL 제공형은 그 폴더가 없으므로 **착수 시 만든다.**
위치는 저장소 진입 파일(CLAUDE.md 등)의 규약이 정한다 — 코드 제공형 풀과 **다른 루트**에 두어
**「여기엔 코드가 없다」가 폴더 이름에서 읽히게 한다.** 같은 루트에 섞으면 다음 회차가
있지도 않은 코드를 찾아 헤맨다 — 이 세트의 여러 절차가 「원본 코드를 열어라」로 시작하기 때문이다.

```
[예시]
<URL 원본 풀>/<NN>-<게임명>/     ← 이 폴더가 <원본폴더> 역할이다. 문서의 <원본폴더>는 전부 여기로 읽는다
├─ 00_원본정보.md               ← 코드 대신 «원본 포인터»
├─ HtmlToUnityLogic/            ← 골격 전부. 규격 동일 (분석로직)
└─ Html_Screenshot/             ← 캡처 + _대장.md. 규격 동일 (공통절차)
```

`00_원본정보.md` 의 최소 행 — **게임명 · 원본 URL · 제작사/서비스 · 실측 엔진(콘솔 로그로 확인) ·
조작 방법 [실측] · 접속·재현 방법(입력 자동화 방법 포함) · 플랫폼 소속 목록(아래)**.
원본이 서비스에서 내려가면 이 문서와 캡처·기대값 표가 2차 심판이 된다 —
그래서 **실측마다 재현 방법을 같이 남긴다.**

#### 서비스 플랫폼이 그리는 것은 원본이 아니다

상용 게임은 대개 포털(서비스 사이트) 안에서 돈다 — 포털의 홈 버튼·광고·로그인·SDK 연출이
게임 화면에 섞여 보인다. **이걸 게임 본체로 오인하면 플로우 diff 가 「원본에 있는데 우리에게
없다」로 오탐한다.** 실측 첫 회차에 화면 요소를 **«게임 소속 / 플랫폼 소속»** 으로 가르고,
플랫폼 소속 목록을 `00_원본정보.md` 에 적는다 — **이관 범위에서 뺀다.**

#### 실측이 막히는 구간 — 사람에게 «영상»을 요청한다

자동 입력으로 도달·재현이 안 되는 구간이 나온다 — 정밀 타이밍·제스처 조작, 실력이 필요한
후반 구간, 결제·계정 뒤의 콘텐츠. 코드형은 코드를 읽으면 되지만 블랙박스는 대체가 없다.
**막힌 구간은 사람에게 플레이 영상을 요청하고, 영상 스틸(ffmpeg 등)로 실측한다.**
그것도 못 받으면 **미측정**으로 남긴다. 전제 도구 표의 「사람에게 요청」과 같은 패턴이고,
요청은 **한 묶음으로** 한다 — 막힐 때마다 한 번씩 부르면 사이클이 죽는다.

#### 코드 인용 게이트는 **실측 재현 방법**으로 대체한다 — 면제가 아니다

이 세트의 여러 게이트가 「원본 파일:줄」을 증거로 요구한다. 블랙박스에는 그 증거가
원리적으로 없다 — **동등 증거로 바꾼다. 게이트 자체를 면제하는 것이 아니다.**

| 코드 제공형의 증거 | URL 제공형의 동등 증거 |
|---|---|
| 원본 파일:줄 인용 | **[실측] + 재현 방법** — URL · 진입 경로 · 입력 시퀀스 · 캡처 파일명 |
| 상수·테이블을 코드에서 발췌 | **반복 실측으로 얻은 값 + 측정 횟수.** 못 재면 `미측정` — 「대충 비슷하게」 금지 |
| 정답지를 코드 로직으로 산출 | **화면 실측으로 채록** — 입력 시퀀스 → 화면 결과를 표로 |
| 캡처 `_대장.md` 의 「근거(원본 코드 위치)」 컬럼 | **재현 방법** 컬럼으로 대체 |

⚠ **실측 없이 「이런 게임은 보통 이렇다」로 채우는 것이 이 형태의 최대 오염이다.**
장르 지식은 가설을 세우는 데까지만 쓴다. 확정값은 전부 **[실측]** 이거나 **미측정**이다.

##### 실측으로 채록한 정답지는 **성공 1점으로 만들지 않는다**

코드에서 산출한 정답지는 계산식 자체가 정답이지만, **화면 실측 정답지는 「이 입력이 통했다」뿐**이다.
성공 1점만 담으면 **우리 쪽 곡선이 어긋나 있어도 그 점만 지나가면 통과한다.**

**연속 입력값(누르는 시간·거리·각도)이 있는 게임은 레벨·상황마다 「실패-성공-실패」 3점**을 담는다 —
성공 구간의 **양쪽 경계**가 곡선을 고정한다.

> **[사고]** 어떤 구간은 성공 폭이 매우 좁았다 — 성긴 격자로 전 구간을 훑고도 **한 발도 성공하지 못해**
> 「깰 수 없는 구간」으로 오판할 뻔했다. 격자를 촘촘히 하자 바로 잡혔다.
> **성공을 못 찾았을 때 첫 의심은 「불가능」이 아니라 「격자가 성기다」**다.

⚠ **원본 에셋을 뜯어 오지 않는다.** 상용 게임의 스프라이트·사운드 추출은 저작권 침해다.
리소스는 **전부 재제작**하고, 합격 기준(확정표 12)도 픽셀 동일이 아니라 **«퀄리티 동일»** 로 잡는다.
수치·규칙(레벨 배치·물리 거동·판정)은 실측해 재현하되, **아트 파일 자체는 원본에서 가져올 수 없다.**

### 전제 도구 — 없으면 **못 하는 단계를 먼저 알린다**

착수 시 **실제로 한 번씩 찔러 보고** 결과를 「확정표」 13번 행에 적는다. 「있을 것이다」로 적지 않는다.

| 도구 | 없으면 | **대체 판정** |
|---|---|---|
| **브라우저** (원본 실행 · DOM 조회 · 콘솔) | **학습 단계가 반쪽이 된다.** 정적 코드 읽기로는 순서·타이밍·게이트 조건이 안 잡힌다 | 원본 코드 정독 + **사람에게 캡처·영상·DOM 덤프를 요청**한다. 「돌려 봐야 아는 것」은 전부 **미측정** |
| **Unity 에디터 제어** (재생·정지·메뉴·콘솔) | 대화형 조작이 안 된다 | ★ **배치모드가 먼저다.** 셸과 유니티가 있으면 `-batchmode -executeMethod` 로 **에디터 코드를 직접 실행**할 수 있다 (SKILL.md 「유니티 에디터는 배치모드로 돌린다」). 배치모드도 없으면 그때 사람에게 **한 묶음으로** 요청한다 — 매 턴 요청하면 사이클이 죽는다 |
| **파일 검색 · grep** | 전 단계 불가. **원본 인용이 성립하지 않는다** | **없으면 착수하지 않는다.** 이건 대체가 없다 |
| **이미지 비교** (픽셀 측정) | 렌더 판정이 눈대중이 된다. 「글자 제외 95%」를 못 잰다 | **요소 수 대조**로 내린다 (원본 요소 N개 중 M개 존재). 점수는 **미측정** |
| **셸** (빌드 · ffmpeg 등) | 컴파일 판정(공통절차 「컴파일·툴 실행 순서」 ⓪-b)과 영상 스틸 추출이 안 된다 | 사람에게 빌드 로그를 요청한다. 「에디터가 안 먹는다」 판별식은 **미측정** |

### ★★ 근거 등급 — **네 단계로 적는다**

값 하나하나에 «어디서 왔는지»를 붙인다. 등급이 없으면 **가설이 실측처럼 인용된다**.

| 등급 | 무엇 | 표기 |
|---|---|---|
| **① 소스 직독** | 원본 코드에서 읽은 **저작 상수·식** | `[소스]` · 표에서는 표본 수 `-1` |
| **② 실측** | 원본을 돌려 잰 값 (**n ≥ 3**) | `[실측 n=…]` |
| **③ 관측** | 한두 번 본 것 · 표본이 모자란 것 | `[관측]` — **실측으로 승격 전까지 값으로 쓰지 않는다** |
| **④ 미측정 / 가설** | 안 쟀거나 추론한 것 | `[미측정]` — **달성률 0%** |

⚠ **①이 오면 ②를 «되돌리지» 않는다.** 실측 169.3 이 저작 170 으로 확인되면 **정본은 170**이고,
실측치는 「식이 맞는지 확인한 근거」로 남긴다.
⚠ **값의 등급과 «규칙»의 등급은 따로 매긴다** — 값이 ②여도 규칙이 ④일 수 있다(재발방지 `#128`).

### ★ 미측정 ≠ 통과

**못 잰 것을 넘어가면 그 자리는 영원히 안 채워진다.** 아래 장치를 전부 같이 건다.

| 장치 | 규칙 |
|---|---|
| **어휘** | 판정 칸에 숫자를 못 넣으면 `미측정(사유)` 로 적는다. **빈칸·「됨」 금지** |
| **사유 3갈래** | ① 도구 없음 ② 상태를 못 맞춤(A/B 정합 실패) ③ 하네스 없음 — **해소 방법이 각각 다르다.** 뭉뚱그리면 안 풀린다 |
| **달성률** | 미측정은 **0% 로 계산**한다. 통과가 아니라 미달이다 — 못 잰 만큼 달성률이 안 오른다 |
| **재측정 대기** | 원장의 **재측정 대기 표**에 남는다. **다음 회차에 신규 작업보다 먼저** 처리한다 |
| **에스컬레이션** | 대기 회차가 **3 이상**이면 PD 가 사람에게 도구·데이터를 직접 요청한다 |
| **소스 우선** | 미측정이 **3건 이상** 쌓이면 관측 회차를 더 돌기 전에 **번들 소스 수신**(「번들 소스를 받아 읽는다」)부터 시도한다 — 관측 8회차가 못 닫은 것을 소스 1회차가 닫았다 |

규격은 [분석로직 「섹션별 기입 규칙」](분석로직.md).

### 전제 — **특정 라이브러리를 강요하지 않는다. 능력만 규정한다**

착수 시 아래 둘을 어떻게 충족할지 정해 「확정표」 14번 행에 적는다.
**무엇을 쓸지는 프로젝트가 고른다** — 이미 쓰던 게 있으면 그걸 쓴다.

| 필요한 능력 | 왜 | 못 채우면 |
|---|---|---|
| **JSON 역직렬화** — 최상위 배열 · 임의 키 맵 · `null` 구분 · 중첩 제네릭 | 데이터 컨테이너 · **정답지 파싱** | 데이터 로드와 수치 판정이 둘 다 막힌다. ⚠ Unity 내장 `JsonUtility` 는 넷 다 안 된다 |
| **아트 로드/해제 단위** (번들 시스템 등) | 카테고리 단위 로드 · 양방향 감사(공통절차 「에셋 등록은 양방향으로 감사한다」) | 아트를 전부 `Resources` 로 물게 되고 빌드가 부푼다. **막히지는 않는다** |

- **선택지와 접점 격리는 [DataFramework 「전제」](DataFramework.md).**
  라이브러리 이름이 나오는 파일이 **한두 개를 넘으면 설계가 잘못된 것**이다.
- **확인은 `dotnet build` 로 한다.** 에디터 콘솔은 아직 변경을 안 집어갔을 수 있다 (공통절차 「컴파일·툴 실행 순서」 ⓪-b).

### 문서 로딩 규칙 — 단계마다 **여는 것만** 연다

전부 합치면 한 컨텍스트에 안 들어간다. **필요한 절만 뽑아 읽는다.**

| 단계 | 여는 문서 |
|---|---|
| 착수 확정 | 이 문서 「착수 전 확정」 |
| 원장 · 학습 산출물 생성 | 분석로직 |
| 학습 (지식 담당자) | **자기 파트 문서 1개** + 분석로직 「HtmlToUnityLogic/」 + **공통절차 「원본 코드에서 답 찾는 법」** |
| 패스 ① 코드 / 데이터 | Transfer_Programmer + DataFramework + GameFramework |
| 패스 ② 프리팹 / 연출 | Transfer_Artist + PrefabRule + ResourceRule + UIFramework |
| 패스 ③ 배선 | Transfer_Programmer 「패스 ③」 + UIFramework |
| **재거나 캡처할 때 (전 단계 공통)** | **공통절차** — PD 문서를 열지 않는다 |
| 검증 (PD QA) | 이 문서 「검증 단계」 · 「게이트」 + **공통절차** |

**단계와 무관하게 착수 전에 항상 읽는 것 둘** —
[재발방지](재발방지.md) 전체, 그리고
`HtmlToUnity_작업내역.md` 의 **오염된 내용 · 회고록**.

## 이 오케스트레이션이 존재하는 이유

**결함의 대부분은 파트 안이 아니라 파트 경계에서 난다.** 각자 자기 몫은 다 했는데
넘기는 지점에서 값이 증발하거나 계약이 어긋난다. 실제로 겪은 것들이다:

| 경계 | 사고 | 왜 안 보였나 |
|---|---|---|
| 기획 → 클라 | 스탯 표기 테이블 110행을 만들어 뒀는데 **컨테이너가 없어 아무도 안 읽었다** | 엑셀에는 있으니 기획은 「했다」, 코드에 없으니 클라는 「없다」 |
| 클라 → UI | 카드에 계통명 자리에 내부 분류값(`parent`)을 넣었다 | 둘 다 문자열이라 컴파일도 통과하고 화면에도 뜬다 |
| UI → 연출 | 아이콘 필드 하나가 **육각 테두리와 글리프를 겸했다** → 런타임 주입이 테두리를 덮었다 | 프리팹만 보면 정상, 런타임에만 사라진다 |
| 클라 → 연출 | 렌더 컴포넌트 기본값이 **가산 합성**이라 아무도 안 건드린 전부가 가산이었다 | 원본에 없는 기능이 기본값으로 켜져 있었다 |
| 기획 → UI | 문구에 `+42/Lv` 같은 파생 표기가 있는데 표시 직전 계산이 없었다 | 원문 그대로 화면에 나오니 「데이터가 그런가 보다」 |

**그래서 이 문서의 핵심은 「인수인계 계약」의 인수인계 계약이다.** 각 경계마다 「무엇을 넘기고, 받는 쪽이 무엇을 증명하는가」를 못 박는다.

## ★★★ 대원칙 — **값과 규칙을 옮기고, 구조는 다시 설계한다**

이관은 **번역이 아니라 재구현**이다. 원본은 「무엇을 하는가」의 출처이고,
「어떻게 만드는가」는 **Unity 가 정한다.** 이 하나가 지켜지면 「엔진 패러다임 차이」 의 결함 대부분이 애초에 안 생긴다.

| 원본에서 **가져오는 것** | 원본에서 **버리는 것** |
|---|---|
| 수치 · 확률 · 계수 · 문구 | DOM 계층 · CSS 셀렉터 |
| 계산식 · 상태 전이 · 조건 분기와 **그 순서** | `flex` · `absolute` · `%` 같은 배치 수단 |
| 무엇이 보이고 무엇이 눌리는가 | `innerHTML` 재생성 · SVG · canvas 호출 순서 |
| 개체 수 · 층 수 · 등장 조건 | 유니코드·폰트·색을 공짜로 쓰던 전제 |

버린 것은 **엔진의 제 구조로 다시 세운다.**

| 원본이 그 일을 하던 방법 | Unity 에서 그 일을 하는 구조 |
|---|---|
| DOM 계층 | Window / Panel / Component ([UIFramework](UIFramework.md)) |
| `display:flex` · `position:absolute` | LayoutGroup · 앵커 · 재활용 스크롤 ([PrefabRule](PrefabRule.md)) |
| `innerHTML` 로 매번 재생성 | 프리팹 풀링 + 값 주입 (「엔진 패러다임 차이」 ①) |
| 컨테이너 1개 + `closest()` 이벤트 위임 | 개체가 적으면 Button, 많으면 **뷰 하나가 좌표로** (「엔진 패러다임 차이」 ④) |
| 유니코드 기호 · 임의 폰트 | 아틀라스 아이콘 · `TMP_SpriteAsset` ([ResourceRule](ResourceRule.md) 「리스트업 규칙」) |
| 전역 상수 · 하드코딩 테이블 | 시트 → JSON → Container ([DataFramework](DataFramework.md)) |

### 판정 기준 — 이 문장으로 스스로 검사한다

> **「원본이 이렇게 생겼으니 우리도 이렇게」는 근거가 아니다.**
> 근거는 **「원본이 무엇을 하니 우리는 이 구조로 그것을 한다」** 여야 한다.

- 원본 좌표식을 그대로 옮기고 있으면 멈춘다 — 그 값이 위치인지 순위인지부터 가른다 (UI/UX 「renderMode 는 상황마다 다르다」).
- 원본 DOM 을 1:1 로 대응시키고 있으면 멈춘다 — 프레임워크 3계층에 다시 앉힌다.
- **반대로, 값·분기·순서는 한 줄도 바꾸지 않는다.** 구조를 새로 짜는 것과
  규칙을 임의로 고치는 것은 다르다. 「더 나은 공식」을 넣지 않는다.

### ★★ 원본의 이상 거동 — **고치는 것도 이관이 아니다**

원본을 읽다 보면 **명백히 잘못된 것처럼 보이는 줄**을 만난다. 루프 상한이 하나 모자라거나,
`0` 을 falsy 로 판정하거나, 경계 가드가 빠져 있거나. 여기서 가장 흔한 사고는
**「이건 버그니까 고쳐서 옮기자」로 조용히 넘어가는 것**이다.

> **그 줄은 버그가 아니라 사양이다.** 사용자는 그 거동을 겪어 왔고, 우리 합격 기준은
> 「원본과 같다」다. 고치는 순간 **그 지점에서 파리티 판정이 무너지고**, 무엇이 원본이었는지가 사라진다.

**절차 — 이관 담당자가 판단하지 않는다.**

| # | 하는 일 |
|---|---|
| 1 | **실측으로 확증한다.** 코드를 읽은 추측이 아니라 원본을 돌려서 그 거동이 실제로 나오는지 본다 |
| 2 | 학습 문서에 **[실측] 표시와 재현 방법**을 같이 적는다 (「어떻게 쟀나」가 없으면 다음 회차가 못 믿는다) |
| 3 | 원장의 **「원본 이상 목록」**에 올린다 |
| 4 | **PD 가 재현/수정을 확정한다.** 확정 전에는 이관하지 않는다 |

**기본값은 「그대로 재현」이다.** 고치려면 PD 가 확정표 12번(합격 기준)에
**그 항목을 「의도된 차이」로 명시 등재**해야 한다 — 등재 없이 고친 것은 결함이다.

> **[예시]** 매치 판정 루프의 상한이 하나 모자라 특정 자리의 4연속이 3점으로 처리되는 원본이 있었다.
> 무매치 기저 보드를 깔고 점수 증분을 재서 확증했다 — **읽어서 안 것이 아니라 재서 안 것**이다.

**세는 법** — 학습 단계에서 원본 이상을 **몇 건 찾았는지 숫자로** 원장에 적는다.
0건이면 「없었다」가 아니라 **「아직 안 찾았다」**일 가능성을 먼저 본다.

### ★ 「이상」과 「직관과 다른 것」을 가른다 — **처리가 다르다**

둘 다 「그냥 짜면 다르게 나오는 자리」지만 **PD 가 할 일이 다르다.**
섞어 두면 확정이 필요 없는 것에 확정을 기다리거나, 확정이 필요한 것을 그냥 넘긴다.

| | **원본 이상** | **직관과 다른 것** |
|---|---|---|
| 무엇 | 원본 저자가 **의도하지 않았을 수 있는** 것 (경계 하나 모자란 상한, falsy 판정, 빠진 가드) | 원본 **구현 방식의 필연적 결과** (순회 방향, 판정 순서, 즉시 수정) |
| 사용자가 겪나 | **겪는다.** 다만 「버그」로 인식할 수 있다 | **겪는다.** 그게 그 게임의 손맛이다 |
| **PD 확정** | **필요하다** — 재현할지 고칠지 정한다 | **필요 없다.** 무조건 재현이다 |
| 고칠 수 있나 | 확정표 12번에 **「의도된 차이」로 등재하면** 가능 | 고친다는 개념이 없다 — 고치면 **다른 게임**이 된다 |
| 놓치면 | 점수·상태가 특정 자리에서만 어긋난다 | **전 구간이 조용히 어긋난다** |
| **공통** | **둘 다 실측으로 확증하고 정답지로 못 박는다** | |

**가르는 질문** — 「원본을 그대로 옮겼는데도 이 값이 나오나?」

- **나온다** → 직관과 다른 것이다. 확정 없이 재현한다.
- **원본 코드의 특정 한 줄을 그대로 옮겨야만 나온다** → 이상이다. PD 확정 대상이다.

⚠ **「직관과 다른 것」이 더 위험하다.** 이상은 눈에 띄어 목록에 오르지만,
이쪽은 **「판정을 «교과서대로» 정확히 구현」했다는 이유로 다르게 짜고도 맞다고 믿게** 된다.
그래서 **벡터가 유일한 방어선**이다 — 겹치는 입력·연속 입력처럼
**구현 방식이 갈리는 입력**을 반드시 벡터에 넣는다.

**원장에 표를 따로 둔다.** 「원본 이상 목록」(확정 대기가 붙는다)과
「직관과 다른 것」(확정 없이 벡터만 붙는다)을 섞지 않는다.

## ★★ 엔진 패러다임 차이 — 그래도 새는 일곱 자리

「대원칙」 을 지켜도 **경계에서 새는 자리가 일곱 개** 있다. 구조를 다시 설계했더라도
원본에 **대응 코드가 아예 없어서** 옮길 것이 없거나, 엔진이 조용히 다르게 처리하는 곳들이다.
[재발방지](재발방지.md) 에 등재되는 사고 대부분이 서로 다른 실수가 아니라 여기서 나온다.

**착수 전에 이 표를 읽고, 각 행의 점검을 그 회차에 반드시 한 번 돌린다 (G7).**

| # | HTML5 | Unity | 여기서 파생되는 결함 |
|---|---|---|---|
| 1 | **즉시 모드** — `innerHTML=` 로 매번 통째로 다시 그린다 | **유지 모드** — 오브젝트를 살려 두고 값만 바꾼다 | 재사용 시 이전 상태 잔존 · 이벤트 중복 구독 · 캐시 무효화 누락 |
| 2 | **문서 순서** — 나중에 쓴 것이 위 | **형제 순서** — 풀링이 순서를 뒤집는다 | 선이 노드 위로 · 딤이 대상 아래로 |
| 3 | **캐스케이드** — `var(--nc)` 하나로 자식 전부 | **개별 대입** — Graphic 마다 따로 | 한 요소만 기본색 · 상태색 누락 |
| 4 | **이벤트 위임** — 컨테이너 1개 + `closest()` | **개별 리스너** — 노드마다 Button | 노드 2000개 = GameObject 2000개 |
| 5 | **흐름 배치** — 내용이 자리를 만든다 | **고정 rect** — 자리가 내용을 자른다 | 글자 길어지면 넘침·잘림 |
| 6 | **공짜 자원** — 아무 글리프·아무 색 | **선언된 것만** — 폰트 cmap · Linear | 두부 · 빈칸 · 알파 과다 |
| 7 | **느슨한 수치** — 전부 double, `Infinity` | **엄격** — float 혼입, `int.MaxValue` | 정밀도 손실 · `2147483647` 노출 |

### 즉시 모드 → 유지 모드 : **「안 그림」과 「안 끔」은 다르다**

원본은 조건이 거짓이면 요소가 **아예 안 만들어지고**, 우리는 **꺼야 사라진다** —
원본에 `else` 가 없어도 우리에겐 `else`(끄기·구독 해제·캐시 무효화)가 필요하다.
규칙 전문과 예시는 **UIFramework 「「안 그림」과 「안 끔」은 다르다」** 절이 정본이다.
점검 grep 은 아래 G7 표에 있다 — 여기 사본을 두지 않는다.

### 문서 순서 → 형제 순서 : **풀링이 순서를 뒤집는다**

같은 부모에 섞어 `Instantiate` 하면 **먼저 만든 것만 뒤로 간다.**
원본에서 「먼저 그린 것」은 **전용 부모를 만들어 `SetAsFirstSibling`** 으로 고정한다.

### 캐스케이드 → 개별 대입 : **색은 한 곳에서 받아 뿌린다**

CSS 는 부모에 `--nc` 하나만 주면 끝난다. 우리는 자식마다 대입해야 하고, **한 군데 빠지면 그것만 남는다.**
→ 상태색을 쓰는 컴포넌트는 **색을 받는 진입점을 하나만** 두고 거기서 전부 뿌린다.

```bash
# 점검 — 원본이 한 요소에 몇 개의 상태 클래스를 거는지 센다
grep -o "\.tnode\.[a-z-]*" 원본.html | sort -u
```

### 이벤트 위임 → 개별 리스너 : **개수를 먼저 센다**

원본이 `closest()` 로 받고 있으면 **개체 수 상한이 없다는 뜻**이다. 몇 개까지 늘어나는지 세고,
수백을 넘으면 Button 을 달지 말고 **뷰 하나가 좌표로 찾는다.**

### 흐름 → 고정 rect

CSS 흐름을 고정 박스로 옮기면 **「길이가 변하는 순간」 전부 깨진다** (UI/UX 「CSS 흐름을 고정 박스로 옮기면 길이가」).
번역·큰 수치·긴 이름에서만 드러나므로 초기 화면에서는 정상으로 보인다.

### 공짜 자원 → 선언된 것만

| 원본이 공짜로 쓰는 것 | Unity 에서 필요한 선언 | 점검 |
|---|---|---|
| 유니코드 기호 | 폰트 cmap 에 있거나 `TMP_SpriteAsset` 등록 | 원본 기호 전수 → cmap 파싱 대조 (`ResourceRule` 「리스트업 규칙」) |
| 반투명 합성 | 색공간이 Linear 면 브라우저보다 밝다 | 알파 역산 (`Fx` 「작업 사이클」) |
| 임의 폰트 | 폰트 하나 · 폴백 없음 | UIUX 「주폰트는 가장 넓은 글리프 집합이 가져간다」 |

```bash
# 점검 — 원본이 쓰는 비ASCII 기호 전수
grep -oP "[^\x00-\x7F]" 원본.html | sort -u   # 비ASCII 전수 (-P 없으면 python 한 줄로)
```

### 느슨한 수치 → 엄격

- JS 숫자는 **전부 double**. `float` 를 섞으면 큰 값에서 조용히 어긋난다.
- `Infinity` 는 값만 옮기면 안 된다 — **표기 분기를 같이 옮긴다** (UI/UX 「원본의 표기 분기 개수를 세고 그대로」).
- 가중 추첨을 `float` 로 누적하면 확률이 미세하게 틀어진다.

## 작업 사이클 — 학습 → 실행 → 검증

**한 사이클은 세 단계다. 단계를 건너뛰지 않는다.**

```
[학습] PD 확정 → 지식 담당자 4인이 원본을 돌려 보며 HtmlToUnityLogic/ 을 채운다
   │        (여기서 끝낸다. 학습 단계에서는 Unity 코드를 건드리지 않는다)
   ↓
[실행] 지식 담당자 갱신(Design → Client → FX → UI/UX)
   │   → 이관 담당자 수행(Programmer ① → Artist ② → Programmer ③)
   ↓
[검증] 이관 담당자가 PD 에게 콜 → PD 가 QA → 미흡 항목 나열 → 다음 회차로
   │
   ├─ 리스트업 전 항목 100% 가 될 때까지 [실행]↔[검증] 을 N회 반복
   └─ 미흡의 원인이 「원본을 덜 봤다」면 [실행]이 아니라 [학습]으로 되돌린다
      (3회차에도 같은 항목이 60% 면 반복이 아니라 학습 부족이다 — 원본을 다시 연다)
```

### 담당자는 착수 전에 반드시 3단계를 밟는다

**작업 내역 확인 → 최신화 → 확인.** 이걸 건너뛰면 같은 실수를 회차마다 반복한다.

| 단계 | 하는 일 |
|---|---|
| **① 작업 내역 확인** | `HtmlToUnity_작업내역.md` 에서 **자기 항목 + 오염된 내용 + 회고록**을 읽는다. 이전 회차가 무엇을 틀렸는지 모르면 그대로 다시 틀린다 |
| **② 최신화** | 이번 회차에 자기가 손댈 범위를 원장에 먼저 적는다. 착수 후가 아니라 **착수 전**이다 |
| **③ 확인** | 그 범위가 다른 담당자와 겹치는지, 선행 게이트(「게이트」)가 열렸는지 본다. 안 열렸으면 착수하지 않는다 |

### 「학습 단계」와 「실행 단계」를 섞지 않는다

학습 중에 코드를 고치기 시작하면 **원본을 덜 본 채로 옮기게 되고**, 그 결과물이 다음 회차의
학습 대상이 되어 오염이 고착된다. 학습 단계의 산출물은 md 뿐이다.

### 회차 카운터를 원장에 남긴다

「학습 단계 수행 횟수」·「실행 단계 수행 횟수」를 숫자로 적는다.
**3회차인데 같은 항목이 여전히 60% 면 그건 접근이 틀린 것이다** — 반복이 아니라 방법을 바꾼다.

## ★★★ 학습이 끝나면 **「작업 분해표」를 만든다** — 이관은 그 순서대로만 돈다

**학습(분석)과 이관 사이에 «분해»가 빠져 있으면 이관이 뒤죽박죽이 된다.**
게임 전체를 한 덩어리로 놓고 패스만 반복하면, 뒤에서 나온 결함이 앞으로 되돌아가고
밖에서 보는 사람은 **「지금 무엇을 만들고 있나」를 알 수 없다.**

**학습 산출물이 이미 나눠 놓았다.** 상상해서 나누지 말고 **거기서 기계적으로 뽑는다.**

| 단위가 나오는 자리 | 무엇이 한 단위가 되나 |
|---|---|
| `02_시스템_<이름>.md` | **문서 한 장 = 한 시스템 단위** |
| `01_게임플로우.md` 의 화면 전이 그래프 | **화면 하나 = 한 단위** |
| `03_데이터.md` 의 테이블 전수 | **테이블 묶음 = 한 단위** |
| `05_연출.md` 의 연출 목록 | **연출 덩어리 = 한 단위** (클리어 연출 · 피격 연출 …) |
| `06_리소스.md` 의 두 목록 | **리소스군 = 한 단위** (배경 · UI · 이펙트) |

⚠ **문서에 없는 단위를 만들지 않는다.** 만들어야 한다면 **분석이 덜 된 것**이다 — 학습으로 돌아간다.

### 분해표 — **원장에 만든다** (규격은 `분석로직.md`)

| # | 단위 | 무엇을 만드나 | 근거 문서 | **선행** | **완료 조건 (검사·항수)** | 상태 |
|---|---|---|---|---|---|---|
| 1 | 데이터 적재 | 테이블 N개 → 컨테이너 | `03` | — | 행 수 어설션 N/N | |
| 2 | <핵심 시스템> | 계산·판정 | `02_<이름>` | 1 | 정답지 N/N | |
| 3 | <화면> | Window/Panel | `01`·`04` | 1 | 전수 대조표 빈칸 0 | |
| … | | | | | | |

**빈칸이 있으면 그 단위는 시작하지 않는다.** 특히 **완료 조건** — 숫자가 없으면 완료를 판정할 수 없다.

### ★★ 순서를 매기는 규칙 — **네 개, 위에서부터 적용**

| 순위 | 규칙 | 왜 |
|---|---|---|
| **1** | **의존이 먼저** | B 가 A 없이 못 서면 A 가 앞이다. 데이터 → 로직 → 화면 → 연출 → 배선 |
| **2** | **«한 판이 돌아가는» 최소 경로가 먼저** | 입력 → 판정 → 결과. 장식·연출은 그 뒤다. 뼈대가 서야 나머지를 «붙여» 볼 수 있다 |
| **3** | 그 안에서 **못 잰 것이 많은 단위가 먼저** | 불확실을 뒤로 미루면 **마지막에 터진다.** 앞에서 터지면 계획을 고칠 시간이 있다 |
| **4** | 같은 순위면 **작은 것부터** | 완료가 빨리 쌓여야 흐름이 보인다 |

⚠ **2 와 3 이 부딪히면 3 이 이긴다** — 뼈대 중에서도 **아직 모르는 곳**부터다.

### ★★★ 3패스는 **«한 단위 안에서» 도는 순서**다

**게임 전체에 ①을 다 하고 ②를 다 하는 것이 아니다.**
그렇게 하면 ② 에서 나온 결함이 ① 로 되돌아가고, 그 되돌아감이 **뒤죽박죽의 정체**다.

```
단위 1 : ① 코드·데이터 → ② 프리팹·연출 → ③ 배선 → 검사 → ✔ 완료
단위 2 : ① → ② → ③ → 검사 → ✔ 완료
…
```

- **한 단위는 «검사까지» 끝내고 다음으로 간다.**
- ⚠ **끝난 단위를 다시 열어야 하면, 그건 «완료 조건이 약했다»는 뜻이다** —
  단위를 다시 여는 것으로 끝내지 말고 **그 단위의 완료 조건을 고쳐 분해표에 반영**한다.
- **공용 토대(프레임워크 최소 세트 · 로더 · 확정표 반영)는 단위가 아니라 «전제»**다. 0번으로 먼저 세운다.

### 시작과 완료를 **말한다**

번호(`①-a` · `2회차`)는 **우리의 순서지 그 사람의 관심사가 아니다.**
사람이 알고 싶은 것은 **「지금 무엇을 만들고 있나」**와 **「그건 끝났나」**다.

```
▶ <단위 이름> 작업 들어갑니다.      ← 무엇을 · 왜 (한 줄)
✔ <단위 이름> 완료 — <검사> N/N.    ← 무엇이 바뀌었나 · «숫자» (한 줄)
```

| ✗ | ✓ |
|---|---|
| 「패스 ①-g 완료. 정답지 459 → 461」 | 「**발사 물리 완료** — 정답지 461/465」 |
| 여러 단위를 한 보고에 섞기 | **단위마다** 시작·완료를 따로 |
| 「됐습니다」 | **「어느 검사가 몇 항 통과했나」** |

⚠ **제목은 «그 게임을 아는 사람이 알아듣는 말»로.** 패스 번호·파일명을 제목에 넣지 않는다.

### ★ «완료»는 **마지막에 한 번, 조건이 다 찼을 때만** 말한다

단위마다의 「✔ 완료 — N/N」과 **이관 전체의 «완료»**는 다른 말이다. 후자는 아래가 **전부** 참일 때만 쓴다.
하나라도 비면 「완료」 대신 **남은 것의 목록**을 낸다 — 「거의 완료」·「핵심은 완료」는 없는 말이다.

| 조건 | 어디서 확인 |
|---|---|
| 재측정 대기 표가 **비어 있다** (해소 또는 «이관 밖 판정») | 원장 |
| PD QA 미흡 목록이 **비어 있다** | 원장 |
| **이관율 대조표**의 분모가 확정표 범위와 같고, 「의도된 차이」 표 밖의 차이가 **0** | 원장 (분석로직 「이관율 대조표」) |
| 검사 전부가 **마지막 코드로** 다시 돌아 N/N 이다 — 고친 뒤 안 돌린 검사는 통과가 아니다 | 검사 로그 |
| 빌드가 **그 게임 확정표로** 구워졌다 | `GameFramework.md` 「저장소에 게임이 여럿이면」 |
| 재는 도구를 **지웠고** 게임 전용 도구가 공용 자리에 없다 | `Transfer_Programmer.md` 「재는 도구는 지운다」 |
| 오케스트레이션 문서를 고쳤으면 **두 곳이 같다** | 진입 파일의 동기화 절차 |
| 사람이 「열어서 볼」 상태로 되돌려 놓았다 (닫았던 에디터를 다시 열었다 등) | 도구 제약 표 |

> **[사고]** 「핵심 파리티는 닫혔고 셋이 남았다」고 보고한 뒤 사람이 **「완료라고 말할 때는 남은 것이 없어야 한다」**고
> 못 박았다. 남은 것이 있는 «완료»는 다음 회차가 그 셋을 잊게 만든다.

## 착수 전 확정 — PD가 사람에게 물어 확정한다

**이 답이 아래 모든 파트의 분기를 결정한다. 답을 못 하면 그 아래를 짜지 마라.**

| # | 질문 | 왜 중요한가 | 영향받는 파트 |
|---|---|---|---|
| 1 | **타깃 플랫폼** — PC / 모바일 / 콘솔 | 코덱·세이프에어리어·입력·빌드 체인·텍스처 압축 | 전부 |
| 2 | **화면 방향** — Landscape / Portrait | 캔버스·레이아웃·조작 배치의 대전제 | UI · 연출 |
| 3 | **화면 비율 (Width × Height)** | Canvas Reference Resolution 이 여기서 나온다 | UI · 연출 |
| 4 | **2D / 3D** | 카메라·정렬·물리 정책 | 클라 · 연출 |
| 5 | **렌더 파이프라인** | 셰이더·블렌딩·후처리 | 연출 |
| 6 | **색공간 (Linear / Gamma)** | 캔버스는 감마 합성이라 Linear면 반투명이 전부 밝게 뜬다 | 연출 · UI |
| 7 | **리소스 해상도 정책** — 원본 크기 그대로 / 플랫폼에 맞춰 리사이즈 | 굽기 전에 정해야 두 번 굽지 않는다 | 연출 · UI |
| 8 | **원본 위치와 접근 방법** | 「기억으로 구현」을 막는 유일한 수단 | 전부 |
| 9 | **데이터 소스** — 엑셀 / 스프레드시트 | 원본 JS 상수를 어디에 둘 것인가 | 기획 · 클라 |
| 10 | **UI 프레임워크** | Window/Panel/Component 규약 | UI |
| 11 | **수치 정답지(정답지) 유무** | 있으면 기계 증명, 없으면 A/B 개체 수 판정뿐 | 클라 |
| **11-b** | **밸런싱 채록 범위** — 레벨·스테이지·웨이브가 있으면 **몇 번째까지 원본과 같게 맞추나** | **전수는 비용이 폭발하고, 안 물으면 「1레벨만」이 된다.** 앞쪽 N개를 채록해 **규칙을 뽑고** 나머지는 그 규칙으로 세운다 | 기획 · 클라 |
| 12 | **합격 기준** | 픽셀 동일인가, 「퀄리티 동일」인가 | 전부 |

### 질문 문안 — **파생 문항까지 전부 묻는다. 일부만 묻고 넘어가지 않는다**

**화면·해상도 계열(2·3·7)이 가장 많이 새는 자리다.** 이 셋이 안 정해지면
지식 담당자는 원본 좌표를 어느 단위로 적을지 모르고, 이관 담당자는 **아트를 두 번 굽는다.**
그래서 화면 계열은 한 덩어리로 묶어 먼저 묻는다.

**기본값이 붙은 질문은 「이대로 갈까요?」로 묻는다.** 비개발자에게 열린 질문을 던지면
답이 안 나오거나 되묻기만 반복된다. **기본값 + 그 답이 무엇을 바꾸는지 한 줄**이 있어야 판단이 선다.
**다른 답을 받으면 그 답이 이긴다** — 기본값은 강요가 아니라 출발점이다.

> **[화면 · 해상도]**
### ★★ 두 번째 게임부터 — **이월되는 것과 «다시 묻는» 것을 가른다**

같은 저장소에서 두 번째 게임을 이관할 때, 첫 게임의 확정을 **전부 이월하면 안 된다.**
확정에는 두 종류가 있다.

| 종류 | 무엇 | 두 번째 게임에서 |
|---|---|---|
| **저장소 규약** — 게임과 무관한 배관 | 구체 플랫폼 · 렌더 파이프라인 · 색공간 · 데이터 소스 · UI 프레임워크 · 프리팹 생성 방식 · 로드 방식 | **이월한다.** 다시 묻지 않는다 |
| **게임의 결정** — 그 게임의 모양에 걸린 것 | **화면 방향 · 해상도(몇×몇)** · 입력 대체 · 사운드 · 렌더 방식(어떻게 그릴까) · 리소스 정책 · 합격 기준 · 정답지 유무 · 원본 위치 | **게임마다 다시 묻는다** |

⚠ **화면 방향과 해상도가 가장 잘 이월돼 버리는 자리다.** 첫 게임이 세로였다고
두 번째 게임도 세로인 것이 아니다 — 가로 슈팅·와이드 퍼즐이면 가로가 맞을 수 있다.

> **[사고]** 두 번째 게임에서 화면 방향·해상도를 「프로젝트 규약」으로 이월해
> **묻지 않고** 세로 1080×1920 으로 만들었다. 그 게임엔 맞았지만 **우연**이었다 —
> 절차대로면 착수 때 「무슨 뷰입니까? 해상도는 몇×몇입니까?」를 물었어야 했다.

**묻는 문구는 간단하다** — 「이 게임은 **세로(Portrait)로 갈까요, 가로(Landscape)로 갈까요?**
해상도는 **몇×몇**으로 잡을까요? 【기본값: 세로 1080×1920 / 가로 1920×1080】」

### ★★ 묻는 법 — **비개발자가 고를 수 있게 묻는다**

이관을 의뢰한 사람은 **유니티 용어를 모른다.** 「Tilemap 으로 할까요?」는 질문이 아니라
**아는 사람만 답할 수 있는 시험**이다. 모르면 아무 답이나 고르고, 그 답이 확정표에 박힌다.

| ✗ | ✓ |
|---|---|
| 「Tilemap 으로 할까요?」 | 「① UI 로 그릴까요 ② **2D 게임에서 많이 쓰는 «타일맵»** 으로 그릴까요 ③ 통째로 그림 한 장으로 구울까요」 |
| 선택지 2개 | **가능한 방식을 최대한 다 편다** — 고를 것이 없으면 고른 것이 아니다 |
| 용어만 | **용어 + 한 줄 설명 + 그래서 무엇이 달라지나** |
| 「권장」만 적고 끝 | 권장을 **맨 앞**에 두되, **나머지도 왜 있는지** 적는다 |

**규칙 셋**

1. **선택지에 유니티 용어가 들어가면 그 옆에 「무엇인지」를 한 줄 붙인다**
2. **「이걸 고르면 무엇이 달라지나」를 쓴다** — 비용·품질·나중에 바꾸기 어려운가
3. **「나중에 정해도 되는 것」은 그렇게 말한다** — 지금 안 정해도 되는 것을 지금 강요하지 않는다

> **[사고]** 렌더 방식을 「Tilemap / 스프라이트 개체 / 절차적 텍스처」 셋으로 물었다.
> 셋 다 유니티 용어라 **비개발자에게는 고를 근거가 없는 질문**이었다.
> 「UI 로 그릴까요 / 타일맵으로 그릴까요」처럼 **무엇인지부터** 말했어야 했다.

> 1. **타깃 플랫폼**은 PC · 모바일 · 콘솔 중 무엇입니까?
>    【기본값: **모바일**】 → 세이프에어리어 · 터치 입력 · 텍스처 압축이 여기서 갈립니다.
>    ⚠ 원본이 데스크톱 전용 흐름 배치면 **모바일 레이아웃은 원본에 없는 것을 우리가 만드는 것**입니다 —
>    그 부분은 「원본과 같다」로 판정할 수 없으니 아래 12번에서 기준을 따로 정합니다.
> 1-b. **구체적으로 어느 플랫폼**입니까? (Android / iOS / Windows / WebGL …)
> 1-c. **제품명과 패키지 식별자**를 무엇으로 할까요? 【기본값: 게임명 그대로 · `com.<회사>.<게임명>`】
>     ⚠ **이 행이 없으면 코드에 «누가 정했는지 모를 이름»이 남는다.** 실제로 두 게임을 이관하는
>     동안 첫 게임의 제품명·패키지가 그대로 남아 있었고, **확정표에 행이 없어 아무도 못 잡았다.**
>    【기본값: **Android**】 → 「모바일」만으로는 정할 수 없는 것이 많습니다 —
>    패키지 이름 · 최소 OS 버전 · 텍스처 압축 포맷 · 스크립팅 백엔드 · 그래픽 API 가 전부 여기서 갈립니다.
>    ⚠ **이 답이 없으면 빌드 설정을 못 만듭니다.** 「모바일」에서 멈추면 그 설정은 끝까지 기본값으로 남습니다.
> 2. **화면 방향**은 Landscape 입니까 Portrait 입니까?
>    【기본값: **Portrait**】 → 캔버스·레이아웃·조작 배치의 대전제입니다.
>    ⚠ 기본 방향만 바꾸고 **자동 회전을 안 끄면** 기기를 돌렸을 때 원본에 없는 레이아웃이 나옵니다.
> 3. **Canvas Reference Resolution** 은?
>    【기본값: Landscape **1920×1080** · Portrait **1080×1920**】 → 「화면을 몇 픽셀짜리로 치고 만들 것인가」입니다.
> 3-b. **Canvas Screen Match Mode** 는?
>    【기본값: **Match Width or Height · Match = 0 (Width 기준)**】 →
>    기기 비율이 달라져도 **가로 폭 기준**으로 맞춥니다. 세로 게임에서 판정 대상이 대개 폭이라서입니다.
> 3-c. **Canvas Render Mode** 는?
>    【기본값: **ScreenSpace-Camera + 전용 UICamera**】 →
>    UI 사이에 파티클·스프라이트·셰이더 효과를 끼울 수 있습니다. Overlay 는 나중에 그게 필요해지면 통째로 갈아야 합니다.
> 3-d. 원본의 **논리 해상도는 제가 실측해서 환산 배율을 계산**하겠습니다.
>    그 배율은 **한 곳만 통과**시키는 규칙으로 갑니다 — 괜찮습니까?
>    (프로젝트에 이미 스케일·레이아웃 규약이 있으면 **그쪽이 우선**입니다)
> **7-b. 원본에 «소리»가 있으면** 어떻게 하시겠습니까?
>    【기본값: **① 오디오 없이 간다**】 — 넷 중에 고릅니다. **지금 안 정해도 되는 것**입니다.
>
>    | # | 무엇 | 무슨 뜻인가 |
>    |---|---|---|
>    | **①** | **오디오 없이 진행** | 소리를 빼고 나머지를 완성합니다. **나중에 「오디오 넣어줘」라고 하시면** 그때 원본과 대조해 **어느 장면에서 어떤 소리가 나는지 맞춰 배치**하고, 주신 오디오 클립을 **유니티에 맞게 최적화**해 넣습니다 |
>    | ② | **오디오 파일을 주신다** | 가지고 계신 클립을 주시면 원본과 대조해 배치·최적화합니다 |
>    | ③ | **직접 구워서 원본과 같게** | 원본이 코드로 «합성»하는 소리면 같은 파형·주파수로 구워 넣고, **구운 것이 원본과 같은지 숫자로 증명**합니다 |
>    | ④ | 런타임에 원본과 같은 방식으로 합성 | 원본이 코드로 소리를 만들면 우리도 코드로 만듭니다. 오디오 파일이 0개가 됩니다 |
>
>    ⚠ **①을 골라도 「없는 것」이 되지 않습니다** — 원본에 소리가 있으면
>    **「의도된 차이」로 등재**해 두고, 나중에 채울 자리를 남겨 둡니다.
>
> 7. 리소스는 **원본 크기 그대로** 쓰시겠습니까, **타깃에 맞춰 재제작**하시겠습니까?
>    【기본값: **재제작** · 크기는 **4의 배수**】 →
>    ⚠ 먼저 **원본 아트의 실제 해상도를 재서 알려 드립니다.** 원본이 작으면 키울 때 흐려지고,
>    다시 굽는 순간 **「그림이 원본과 같다」 판정은 그 아트에 대해 포기**하는 것입니다.

**3-d 는 묻는 게 아니라 알리는 항목이다.** 원본 논리 해상도는 사람이 아는 값이 아니라
**PD 가 원본을 띄워 실측할 값**이다 (CSS 가 아니라 JS 가 잡는 경우가 많다).
실측 → 환산 배율 계산 → **사람에게 확인만 받는다.**

**답이 나오면 PD 가 세 곳에 박는다.**

| 어디에 | 무엇을 |
|---|---|
| 각 담당자 md 의 **`[Unity 프로젝트 세팅]`** 절 | 확정표 전 행의 확정값. **담당자는 이 절만 보고 작업한다** |
| ~~규약 문서(`PrefabRule.md` 등)~~ | **적지 않는다.** 규약 문서는 프로젝트를 넘어 재사용된다 — 확정값의 자리는 원장과 담당자 md 뿐이다 |
| 그 프로젝트의 **원장** | 확정표 전체. 나중에 「왜 이 값이었나」를 여기서 되짚는다 |

**답을 못 받은 항목이 하나라도 있으면 학습 단계를 열지 않는다.** 뒤에서 전부 다시 뜯게 된다.
특히 **화면 계열을 미정으로 두고 아트를 굽기 시작하면 그 회차는 통째로 버린다.**

### 회차를 버릴 때와 끊긴 뒤 다시 시작할 때

「통째로 버린다」의 실행 절차다 — 선언만 하고 산출물을 남겨 두면 다음 회차가 그걸 전제로 쌓는다.

**폐기**
1. 폐기 대상을 나열한다 — 그 회차에 구운 아트·프리팹·코드 변경과 원장의 해당 행 전부.
2. 파일은 지우거나 되돌린다 (커밋은 사람 몫이므로 작업 트리에서 제거하고 목록을 사람에게 넘긴다).
3. 원장의 그 회차에 **「폐기」와 사유**를 적는다 — 행을 지우지 않는다. 폐기된 사실 자체가 다음 회차의 정보다.
4. 폐기 원인이 확정표의 빈 행이면 그 행부터 다시 확정한다.

**재개 (컨텍스트가 끊긴 뒤)**
읽는 순서 세 줄: ① 원장의 최신 회차 → ② 미흡 목록 → ③ 최하위 미통과 게이트.
기억으로 이어가지 않는다 — md 에 적힌 것만 인정한다 (「역할을 바꾸면 기억을 이어가지 않는다」와 같은 원리다).

### 확정표 — **착수 시 PD 가 채운다**

### 합격 기준을 숫자로 못 박는다

「이식했다」가 아니라 **「정답지 36/36 통과」 · 「글자 제외 95%」 · 「같은 상태에서 개체 수가 원본 범위」**
처럼 판정 가능한 문장만 완료 조건이 된다.

**픽셀 95%는 정적 화면의 하한이고, 실제 기준은 「같은 상태에서 같은 것이 같은 밀도로 움직이는가」다.**

> **[사고]** 배경에서 전투가 도는 화면이 「어색하다」고 지적됐을 때 배치·아트·좌표는 전부 맞았다.
> 틀린 건 **적이 안 죽는 것**이었다. 정적 캡처로는 절대 안 잡힌다.

### ★ 재는 도구를 먼저 만든다 — 기준만 정해 놓으면 아무도 안 잰다

「글자 제외 95%」를 문서에 적어 놓고도 **재는 도구가 없으면 아무도 재지 않는다.**
합격선을 문서에 적는 것과 그 값이 실제로 측정되는 것은 별개다 —
채점기가 없으면 그 계통은 **한 번도 수치로 판정되지 않은 채** 회차만 쌓인다.

실제로 겪는 전형 — 채점기를 붙이자마자 **첫 실행에서 미이식 필드와 수백 건 단위 결함**이 나온다.
그 전까지 그 코드는 「거의 다 됐다」고 보고돼 있다.

**순서를 이렇게 잡는다.**

1. **출처 대조** — 정답지가 전제한 원본과 지금 데이터가 같은가. 여기가 어긋나면 그 뒤 전부 무의미하다.
2. **측정** — 값을 재고 **실패를 갈래로 나눠** 찍는다 (자료형 한계 / 진짜 차이 / 정답지 결함).
3. **수정** — 갈래별로 처방이 다르다. 섞어 놓으면 큰 쪽에 작은 쪽이 묻힌다.

자세한 절차와 함정은 `Client.md` 「순서를 지킨다 — 출처 대조가 채점보다 먼저다」.

### ⚠ 원장은 **오케스트레이션이 아니다** — 배포물에 끼워 넣지 않는다

원장은 **그 사람이 그 게임을 돌린 기록**이다. 사람마다·회차마다 다르다.
오케스트레이션 폴더에 넣으면 받는 사람에게는 **남의 작업 기록**일 뿐이고,
「이게 템플릿인가」로 헷갈린다.

| 무엇 | 어디 | 성격 |
|---|---|---|
| 스킬 문서 (규칙·절차·게이트) | 오케스트레이션 폴더 | **게임을 넘어 재사용된다** |
| 원장 (확정표·게이트 판정 숫자·회고) | 개인 작업 공간 | **그 회차의 기록** |
| 학습 산출물 · 정답지 | 원본 게임 폴더 | **그 게임의 것** |

> 재사용되는 것과 그 회차의 것을 **같은 자리에 두지 않는다** — 섞이면 둘 다 못 믿는다.


## 학습 단계 — 지식 담당자가 원본을 돌려 보고 `HtmlToUnityLogic/` 을 채운다

**PD 확정(「착수 전 확정」) → 지식 담당자 수행. 여기까지가 학습 단계다.** Unity 코드는 건드리지 않는다.

### 산출물 위치

원본 HTML5 게임 폴더의 **최상위 바로 아래**에 `HtmlToUnityLogic/` 을 만들고 그 안에 넣는다.
(확정표 8번의 원본 위치가 `<원본폴더>/` 면 `<원본폴더>/HtmlToUnityLogic/`.)

**Assets 안이 아니다.** 원본 옆에 두어야 원본과 같이 갱신되고, 유니티 임포트에 섞이지 않는다.

원본을 돌려 보며 남긴 캡처는 **같은 층의 `Html_Screenshot/`** 에 쌓는다 — 없으면 만든다.
**PNG 만 쌓지 않는다** — `_대장.md` 에 상태와 원본 근거를 같이 적는다
(공통절차 「캡처는 어디에 쌓나」). 상태가 안 적힌 캡처는 A/B 에 못 쓴다.

> **파일별 골격·기입 규칙은 [분석로직 「HtmlToUnityLogic/」](분석로직.md) 에 있다.**
> 여기 「학습 단계」 은 「무엇을 왜 만드나」, 분석로직 「HtmlToUnityLogic/」 는 「어떤 표를 어떻게 채우나」다.

### 산출물 목록 — 이 골격이 «전부» 있어야 학습 단계가 끝난다

두 역할이 같은 표에 다른 값을 적으면 **최종 기입자가 원본을 다시 열어 판정**하고, 진 값은
지우지 말고 「전 회차: …」로 남긴다.

### 학습은 「읽기」가 아니라 「돌려 보기」다

- **HTML5 를 실제로 실행해 놀아 본다.** 정적 코드 읽기로는 순서·타이밍·게이트 조건이 안 잡힌다.
- 이해가 안 되는 부분은 **반복 학습**한다. 이전 회차에 적은 것과 새로 안 것을 **같이** 놓고 본다 —
  덮어쓰지 말고 「전 회차: … / 이번 회차:」로 남긴다. 무엇이 바뀌었는지가 정보다.
- **내용에 거짓이 없는지 항상 의심한다.** 특히 자기가 지난 회차에 쓴 문장을 의심한다.

### ★ 「오염된 내용」의 정의 — 이것들이 원장에 기록되어야 하는 것이다

**오염 = 사실이 아닌데 사실로 기록되어 다음 회차의 전제가 된 것.** 다섯 갈래다.

| 갈래 | 예 |
|---|---|
| **캡처를 사양으로 삼음** | 셀이 두 줄로 보여 `LR` / `LEGEND RARE` 두 요소로 적었는데 DOM 은 한 덩어리였다 |
| **문서·라인 번호를 믿음** | 기획서 라인 번호가 작성 시점 빌드 기준이라 현재와 구간마다 다르게 어긋났다 (공통절차 「문서의 라인 번호를 믿지 마라」) |
| **애니메이션의 한 프레임을 정색으로 오인** | 점멸 중 어두운 구간이 찍힌 캡처를 보고 색을 `#8a3a35` 로 구웠다. 원본은 `#ff5a4d` |
| **이름이 비슷해 다른 물건을 가져옴** | `XXX_button.png` 를 행 배경으로 깔았는데 그건 장착 버튼용 아트였다 |
| **추측을 결론으로 적음** | 「대략 이 정도 배율」로 적은 값이 다음 회차에 원본 수치처럼 인용됐다 |

**오염을 발견하면 고치기 전에 원장에 먼저 적는다.** 조용히 고치면 왜 틀렸는지가 사라져 재발한다.

## 작업 원장 — `HtmlToUnity_작업내역.md`

**PD 가 학습 단계 착수 직후에 만든다.** 이후 모든 담당자가 같은 파일 하나에 적는다.

> **골격과 섹션별 기입 규칙은 [분석로직 「HtmlToUnity_작업내역.md」](분석로직.md) 에 있다.**
> 카테고리는 고정이다 — 임의로 늘리거나 줄이지 않는다.

원장이 갖는 것 — 회차 · 리스트업(달성률) · 학습 내용 · **오염된 내용** ·
패스 ①②③ 수행 내용 · **회고록** · PD QA 미흡 목록.

### 리스트업 규칙

- **항목은 화면·시스템 단위**로 자른다. 「UI 이관」 같은 덩어리는 달성률이 영원히 70% 에서 안 움직인다.
- 항목마다 **회차(몇 번 손댔나)** 와 **달성률(%)** 을 적는다.
- **달성률은 완료 정의에서 역산한다.** 「9요소 중 6개 이식 → 67%」처럼 분모가 있어야 한다.
  분모를 못 적는 항목은 「화면 하나를 전수 대조표로 여는 법」 전수 대조표를 아직 안 만든 것이다 — 그것부터 한다.
- **100% 는 PD QA(「검증 단계」)를 통과해야 붙는다.** 담당자가 스스로 붙이지 않는다.

### ⚠ 원장에 쓰지 않는 것 — **표준 선언**

원장은 **회차별 기록**이다. 「확정된 이름 · 앞으로 이걸 쓴다 · 이 값을 기준으로 한다」 같은
**표준 선언을 원장에 적지 않는다.** 표준은 규칙 문서(`CLAUDE.md` · 파트 문서)에 적고,
원장에는 **「어디에 적었다」만** 남긴다.

원장의 표준 선언은 **시간이 지나면 거짓 규칙이 된다.** 기록이라 아무도 안 고치는데
후속 담당자는 규칙으로 읽는다. 실측 사고 — 한 회차 원장의 「확정된 컬럼 이름」·「부품 프리팹
저장 규칙」 블록이 이후 개편으로 **9곳이 현재와 어긋났고, 그중 하나는 지시가 정반대**였다
(「셀을 꺼서 저장하면 안 보인다」 → 지금은 `CreateCell` 이 `SetActive(true)` 를 부른다).

| 원장에 쓴다 | 규칙 문서에 쓴다 |
|---|---|
| 무엇을 했나 · 몇 개를 셌나 · 무엇을 놓쳤나 | 이름 규약 · 값 기준 · 금지 사항 |
| 그 회차의 판단과 근거 | 앞으로 지켜야 할 것 |

**이미 적힌 표준 선언을 발견하면** 지우지 말고 취소선 + 「지금은 이렇다」 대조표를 붙인다 —
그 회차에 무슨 판단을 했는지가 회고의 재료다.

### 회고록 규칙

회차마다 **「무엇을 · 왜 놓쳤나 · 다음에 무엇으로 막나」** 세 칸을 채운다.
「주의하겠다」는 대책이 아니다. **도구·체크리스트·게이트 중 하나로 바뀌어야** 회고가 끝난다.

> 예 — 「없어야 할 창이 한 겹 더 떴다 / 프리뷰가 창을 격리해 구워서 / **플로우 diff 를 프리팹 대조보다
> 먼저 돌리는 절차(「플로우 diff 를 프리팹 대조보다 먼저)를 게이트에 넣음**」

## 실행 단계 — 순서와 운영

### ★ 역할 기동 규약 — 한 명이 7개 역할을 연기한다

이 오케스트레이션의 역할 7종은 **사람 7명이 아니라 한 AI 가 순차로 연기하는 것**이다.
그래서 **역할 이탈이 가장 흔한 실패**다 — 지식 담당자가 코드를 고치고, Artist 가 배선을 하고,
PD 가 직접 만들기 시작한다. 이걸 막는 장치는 셋이다.

#### ① 전환할 때마다 **선언문을 출력한다**

역할을 바꿀 때 반드시 이 형식을 **사용자에게 보이게** 출력한다. 속으로만 생각하지 않는다.

```
[역할 전환] 지금부터 나는 <역할>다.
  할 수 있는 것 : <산출물>
  하지 않는 것  : <권한 밖>
```

예:

```
[역할 전환] 지금부터 나는 Client(지식 담당)다.
  할 수 있는 것 : 원본 읽기 · 01_게임플로우.md / 99_원본지도.md 작성
  하지 않는 것  : Unity 코드·프리팹 수정 (그건 Transfer_Programmer 가 한다)
```

**선언이 출력에 남으면 이탈이 눈에 보인다.** 이게 이 장치의 전부이자 목적이다.

#### ② 역할별 권한표 — 이 표 밖을 건드리면 이탈이다

| 역할 | 만드는 것 | **손대지 않는 것** |
|---|---|---|
| **PD** | 확정표 · 원장 껍데기 · QA 미흡 목록 | **코드 · 프리팹 · 아트 전부.** PD 가 만들기 시작하면 검수자가 사라진다 |
| **Design / Client / FX / UI/UX** (지식) | `HtmlToUnityLogic/` 문서만 | **Assets 아래 전부.** 학습 회차에 Assets 변경이 있으면 이탈이다 |
| **Transfer_Programmer** ① | 데이터·Manager·Management·Window 스크립트 · **검증 하네스·정답지 덤프·채점기** (G1·G2 를 열기 전에) | 프리팹 · 아트 파일 · 빌더 스크립트 |
| **Transfer_Artist** ② | 프리팹 · 리소스 · 연출 (굽는 방식은 확정표 10-b) | 게임 로직 · 데이터 컨테이너 · 배선 |
| **Transfer_Programmer** ③ | 배선 (등록 · 호출 · 파라미터 주입) | **프리팹을 손으로 고치지 않는다** — Artist 에게 되돌린다 |

#### ③ ⚠ 역할을 바꾸면 **기억을 이어가지 않는다**

한 AI 가 연기하므로 **앞 역할에서 본 것이 그대로 남아 있다.** 그게 판단을 오염시킨다 —
Unity 코드를 방금 읽고 지식 담당자로 넘어가면 「우리 코드가 이러니 원본도 이렇겠지」가 된다.

> **역할을 바꾸면 이전 역할의 결론은 md 에 적힌 것만 인정한다.** 기억으로 이어가지 않는다.
> 필요하면 **원본을 다시 연다.**

이게 없으면 「원본이 심판이다」가 조용히 「우리 코드가 심판이다」로 뒤집힌다.

#### ④ 서브에이전트를 쓸 수 있으면 써도 된다

역할별로 격리된 컨텍스트를 띄울 수 있는 환경이면 그렇게 해도 좋다 — 권한표(②)가
**도구 화이트리스트로 강제**되면 이탈이 원천 차단된다.
다만 **①~③은 환경과 무관하게 항상 지킨다.** 그게 이 규약의 기준선이다.

### 순서는 고정이다

```
지식 담당자 갱신 :  Design → Client → FX → UI/UX

이관 담당자 수행 :  Transfer_Programmer ①  코드 / 데이터 이관
                    Transfer_Artist     ②  프리팹 / 연출 생성
                    Transfer_Programmer ③  게임 플로우에 따라 배선
                                            (UI · 연출 · 게임오브젝트)
```

**한 «단위»의 이관은 2단계가 아니라 3패스다.** ③이 없으면 「만들어졌지만 아무것도 안 물린」 상태로 끝난다.

| 패스 | 담당 | 무엇이 끝나야 다음으로 | 왜 이 순서인가 |
|---|---|---|---|
| **①** | Programmer | 데이터가 조회되고 로직·화면 전이가 돈다. **주입 API(`SetData`)가 선언돼 있다** | 프리팹은 **주입받을 API 가 있어야** 굽는 의미가 있다. 뒤집으면 Artist 가 만든 것을 Programmer 가 다시 뜯는다 |
| **②** | Artist | 프리팹·리소스·연출이 존재한다. **정적 상태로 원본과 같아 보인다** | 배선할 **대상이 실물로 있어야** ③이 붙일 곳이 생긴다 |
| **③** | Programmer | 만들어진 것이 **게임 플로우 위에서 실제로 돈다** | 프리팹은 굽는 시점에는 어느 흐름에 붙을지 모른다. 실물이 나온 뒤에야 **어디에 어떻게 물리는지**가 결정된다 |

### ★ 패스 ③이 하는 일 — 「만들어졌다」와 「돈다」 사이

**②까지만 하면 정적 캡처 점수는 높은데 눌러도 아무 일이 없다.**
③은 실물이 나온 뒤에만 할 수 있는 일들을 한다.

| 배선 대상 | 하는 일 | ③ 없이 끝내면 |
|---|---|---|
| **UI 배선** | 창을 Management 에 등록 · 버튼 → event → Manager 경로 연결 · `SetData` 실제 호출 | 창은 예쁜데 열리지 않거나, 열려도 값이 안 들어간다 |
| **게임 플로우 배선** | `GameFlow` 전이표대로 열고 닫기 · 원본에 없는 창이 안 뜨게 | **없어야 할 창**이 한 겹 더 뜬다 (「플로우 diff 를 프리팹 대조보다 먼저」) |
| **연출 배선** | 연출 컴포넌트에 **런타임 파라미터**(속도·위상·색·상태) 주입 · 상태 전이와 동기 | 애니메이션이 프리팹 기본값으로만 돌아 상태가 바뀌어도 안 변한다 |
| **게임오브젝트 배선** | 프리팹 로드 경로 · 풀 등록 · 스프라이트 **런타임 주입** · 정렬 기준값 | 폴백 도형으로 남거나 풀에 안 돌아와 샌다 |
| **데이터 종속 아트** | 배경·초상·아이콘을 데이터로 갈리게 조회 | 프리팹에 구운 1번 값이 전 구역에 나온다 |
| **지연 로드 아트** | 로드 완료 후 다시 조회 | 열 때 null 이라 평생 폴백 |

**③의 완료 판정은 Play Mode 다.** 정적 캡처로는 위 여섯 중 하나도 못 잡는다.

⚠ **「재생은 사람이 해야 한다」로 넘기지 않는다.** 배치에서 `-quit` 을 빼면 재생에 들어간다 —
절차는 `공통절차.md` 「입력 판정은 재생 안에서만 잰다」에 있다.
**편집 모드 레이캐스트는 원리적으로 비므로**, 거기서 나온 「안 맞았다」를 결함으로 읽으면 안 된다.

### 공통

- **Design 이 먼저인 이유** — 데이터가 없으면 Client 가 배선할 대상이 없다.
- 이관 담당자는 **`HtmlToUnityLogic/` 을 근거로** 작업한다. 필요하면 원본을 다시 돌려 본다.
  **지식 담당자의 요약을 최종 근거로 쓰지 않는다** — 최종 판정은 언제나 원본 코드다.
- **③에서 프리팹을 다시 뜯어야 하면 Artist 에게 되돌린다.** 고칠 곳은 **확정표 10-b** 가 가른다 —
  「빌더 스크립트」면 손으로 고친 것이 다음 실행에 날아가므로 스크립트를 고치고,
  「에디터 직접 편집」이면 **프리팹이 진실 소스라 코드가 프리팹을 다시 굽지 않는다.**

### 유니티는 스스로 돌린다 — 사람에게 묻지 않는다

**도메인 리로드·재생·정지를 기다려야 하면 담당자가 직접 실행하고 직접 멈춘다.**
「확인 부탁드립니다」로 멈추면 사이클이 끊긴다.

```
[재생 멈춤]      ← 작업 착수 전 무조건 (공통절차 「컴파일·툴 실행 순서」 ⓪)
dotnet build …                    ← 컴파일 판정은 여기서 (공통절차 「컴파일·툴 실행 순서」 ⓪-b)
[에셋 새로고침] → 컴파일 완료 확인 → [에디터 코드 실행] → [콘솔 읽기]
[재생 시작] → 거동 확인 → [재생 멈춤]
```

**재생을 멈추는 것은 파괴적 행위가 아니다.** 재생 상태는 원래 휘발이다.
반대로 재생 중에 이관 작업을 하면 컴파일 보류·프리팹 미반영·세이브 훼손이 조용히 섞인다.

### 이관 담당자는 한 항목을 끝낼 때마다 원장을 갱신한다

「다 끝내고 몰아서」가 아니다. 회차 중간에 문맥이 날아가면 **무엇을 했는지 복구할 수 없다.**

### 완료되면 PD 에게 콜한다

**패스 ③(배선)까지 끝나야 콜이다.** ②에서 콜하지 않는다 — 그 상태는 「보이기만 하는」 상태다.
콜을 받은 PD 는 「검증 단계」 QA 를 돌린다. **담당자가 스스로 100% 를 선언하지 않는다.**

## 검증 단계 — PD QA

**PD 는 만들지 않는다. 안 된 것을 찾아 나열한다.**

### QA 체크 순서

| # | 보는 것 | 판정 |
|---|---|---|
| **0** | **역할 경계 위반** | 학습 회차에 Assets 변경이 있었나 · ②에서 배선을 했나 · PD 가 직접 만들었나 (「역할 기동 규약」) |
| 1 | **게이트(「게이트」)** G0~G7 이 순서대로 닫혔나 | 아래층이 안 닫혔으면 위층 점수는 무효다 |
| 2 | **플로우 diff(「플로우 diff 를 프리팹 대조보다 먼저」)** | 없어야 할 창 · 있어야 할 창 · 순서 |
| 3 | **전수 대조표(「화면 하나를 전수 대조표로 여는 법」)** 의 빈 칸 | 빈 칸 = 미이관. 「배치는 맞는데 알맹이가 빠진」 것을 여기서 잡는다 |
| 4 | **수치 판정** — 정답지 또는 A/B 개체 수(공통절차 「A/B 측정」) | 상태를 맞춘 뒤에 잰다 |
| 5 | **렌더 판정** — 글자 제외 점수, 그리기 파라미터 표 | 점수가 낮으면 공통절차 「점수를 믿기 전에」 부터 확인 |
| 6 | **리소스 감사(공통절차 「에셋 등록은 양방향으로 감사한다」)** | 코드가 요구하는 주소가 실제로 있는가 (양방향) |
| 7 | **거동 판정** — Play Mode 에서 실제로 눌러 본다 | 클릭 가능성·상태 전이·지연 로드 아트 |
| **8** | **재측정 대기 표** | 원장의 미측정 항목을 **그대로 미흡 목록에 편입**한다. 담당자가 안 올려도 PD 가 집는다 |
| **9** | **이관율 대조표** (분석로직 「이관율 대조표」) | 분모 = 확정표 범위. 「의도된 차이」 표에 없는 차이는 전부 미흡이다. **표 자체가 없으면 100% 를 선언할 수 없다** |
| **10** | **★ 「증명」 열이 채워졌나** | 갈래마다 «화면에 나옴/동작함»을 보인 근거가 있어야 한다. **「프리팹에 있다」·「표에 행이 있다」는 증명이 아니다** — 그건 만든 것이다. 빈 줄은 분자에서 뺀다 (`재발방지` #159) |

### QA 결과는 「미흡 목록」으로 낸다

- 항목마다 **[무엇이 · 어디가 · 기대 · 실측]** 네 칸. 「어색하다」는 QA 결과가 아니다.
- 미흡 목록은 그대로 **다음 회차의 리스트업**이 된다. 달성률을 내리고 회차를 +1 한다.
- **미측정은 통과가 아니다.** 재측정 대기 표의 항목은 달성률 0% 이고,
  **다음 회차에 신규 작업보다 먼저** 처리한다. 대기 회차 3 이상이면 **사람에게 도구·데이터를 요청**한다.
- **전 항목 100% 가 되기 전에는 사이클을 닫지 않는다.**

### ⚠ PD 가 가장 많이 속는 세 가지

| 함정 | 실제 |
|---|---|
| 「화면 점수가 높다」 | 원본에 **없어야 할 창**이 떠 있어도 점수는 높다 (「플로우 diff 를 프리팹 대조보다 먼저」) |
| 「경고 0 이다」 | 빌드 중 NRE 를 노이즈로 방치하면 「경고 0」이 완료 기준으로 못 쓰인다 (공통절차 「컴파일·툴 실행 순서」) |
| 「구간 점수가 낮으니 결함이다」 | 영상 프레임·재화 보유량 차이일 수 있다 (공통절차 「A/B 측정」 상태 정합표) |

## 인수인계 계약 — 파트 사이에서 무엇을 넘기고 무엇을 증명하나

```
원본(심판)
   │
   ├─ 기획 ──[테이블 + 문구 + 파생규칙]──▶ 클라
   │                                        │
   │                                        ├─[계산 결과 스냅샷 + 표기 계약]──▶ UI/UX
   │                                        │
   │                                        └─[엔티티 상태 + 그리기 파라미터]──▶ 연출
   │
   └─ (모든 파트가 원본을 직접 읽는다. 전달받은 요약을 믿지 않는다)
```

### 지식 담당자 → 이관 담당자

**가장 새로 생긴 경계이고, 가장 조용히 새는 곳이다.** 지식은 md 로 넘어가고 md 는 컴파일되지 않는다.

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| `HtmlToUnityLogic/` 골격 전부 | **문서에 적힌 항목이 코드·프리팹에 1:1로 도달했다.** 안 쓰인 항목은 미이관이다 |
| 원본 라인 인용 | 인용 라인을 **직접 열어 확인**했다. 라인 번호는 어긋난다(공통절차 「문서의 라인 번호를 믿지 마라」) — grep 으로 재확정한다 |
| 「제작 필요 리소스」 목록(`06_리소스.md`) | 목록의 전 항목이 굽혔고 **어드레서블 등록까지 끝났다**(공통절차 「에셋 등록은 양방향으로 감사한다」) |
| 「오염된 내용」 목록 | 오염 항목을 **다시 밟지 않았다.** 회고록에 대책이 도구로 남아 있다 |

> **점검 한 줄** — `HtmlToUnityLogic/` 문서의 항목 수와 실제 이관 수를 세어 분수로 적는다.
> 이 분수가 「리스트업 규칙」 달성률의 분모다. 세지 않으면 달성률은 언제나 「대충 80%」가 된다.

### 기획 → 클라

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 테이블 (스키마 + 행 수) | **컨테이너가 실제로 존재하고 조회가 성공한다.** 「엑셀에 있다」는 증명이 아니다 |
| 원본 계산식 인용 (라인 번호 포함) | 같은 입력에 같은 출력. 정답지 있으면 기계 판정, 없으면 A/B |
| 폴백 계수 (원본 `\|\|` 뒤의 값) | 코드 상수로 두되 **원본 행을 주석에 인용** |

> **점검 한 줄** — 새 테이블을 추가하면 반드시 `AllValues.Count` 를 찍어 본다.
> 수백 행짜리 표기 테이블이 **컨테이너 없이 몇 달 방치**된 사례가 있다.

### 클라 → UI/UX

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 표기용 스냅샷 구조체 (`XxxEntry`) | **모든 필드가 화면 어딘가에 도달한다.** 안 쓰는 필드가 있으면 계약이 틀린 것이다 |
| 필드의 **의미**(내부 코드인가 표기명인가) | 화면에 내부 코드가 뜨지 않는다 |
| 파생 표기가 필요한 문자열인지 여부 | 표시 직전 변환을 태웠다 |

> **점검 한 줄** — 원본 UI 함수(예: `augCardHTML`) 하나를 **요소별 표**로 펴고
> 「원본 / 우리 / 출처」 3열로 채운다. 빈 칸이 곧 결함 목록이다. 「화면 하나를 전수 대조표로 여는 법」 참고.

### 클라 → 연출

| 넘기는 것 | 받는 쪽이 증명할 것 |
|---|---|
| 엔티티 상태 (위치·속도·반지름·종류) | **원본 반지름을 그대로** 쓴다. 눈대중 배율 금지 |
| 원본 그리기 파라미터 (선 굵기·blur·색·알파) | 상수로 코드에 남기고 **원본 행을 인용** |
| 프레임 단위 시각(`t`)·`dt` | `t`/`dt` 를 받는 원본 함수는 반드시 움직인다 |

> **점검 한 줄** — 원본 draw 함수에서 `lineWidth` / `shadowBlur` / `globalAlpha` /
> `globalCompositeOperation` 을 **전부 grep** 해 표로 만든다. 하나라도 눈대중이면 실패다.

### UI/UX ↔ 연출

경계가 흐린 지점이다. **분담 기준: 텍스트·레이아웃·입력은 UI, 그림 자체는 연출.**

- 아이콘 **프레임**(장식)과 **글리프**(데이터 종속)는 **반드시 별개 필드**로 나눈다.
  하나로 두면 런타임 주입이 장식을 덮어 버린다.
- 절차 생성 아이콘·이펙트 텍스처는 연출이 굽고, UI는 경로만 참조한다.

### 화면 하나를 「전수 대조표」로 여는 법 (모든 파트 공통)

원본에서 그 화면을 그리는 함수를 찾아 **요소를 빠짐없이 나열**한 표를 먼저 만든다.
표를 만들기 전에 코드를 고치지 않는다.

| 요소 | 원본 | 우리 | 출처 | 상태 |
|---|---|---|---|---|
| 상단 띠 | 계통 사전으로 변환한 표기명 | 내부 코드가 그대로 뜸 | 클라가 분류값을 넘김 | ✗ |
| 태그 | 등급 사전 + 접미어 (`고급 등급 무기`) | `고급` | 등급명만 넘김 | ✗ |
| 설명 | `descLvResolve(augDescT(k), L[k])` | (없음) | 트리 노드 설명 미조회 + 파생 미적용 | ✗ |
| 효과표 | `augEffectHTML(k)` 최대 6줄 | (빈 박스) | 미이식 | ✗ |
| … | | | | |

**이 표가 없으면 「배치는 맞는데 알맹이가 빠진」 상태를 못 잡는다.**
실제로 한 선택 카드는 9개 요소 중 **6개가 비어 있었는데** 화면상으론 그럴듯했다.

### ★★ G7 — 패러다임 스윕은 「안 틀렸다」가 아니라 「전수를 셌다」로 닫는다

「엔진 패러다임 차이」 의 일곱 차이는 **읽고 넘어가면 반드시 재발한다.** 회차마다 아래를 돌리고
**센 수를 원장에 적는다.** 숫자가 없으면 그 항목은 미통과다 (「작업 사이클」 「미측정 ≠ 통과」).

| # | 무엇을 세나 | 통과 조건 |
|---|---|---|
| 1 | 재사용 컴포넌트의 **해제 없는 이벤트 구독** | 0 |
| 2 | 원본 객체의 **키 합집합** vs 시트 컬럼 | 개수 일치 · 뺀 것은 이유를 적었다 |
| 3 | 원본 한 자리의 **표기 분기 수** vs 우리 분기 수 | 자리마다 일치 |
| 4 | 원본의 **비ASCII 기호 전수** vs 폰트 cmap | 없는 것은 전부 아이콘/스프라이트로 처리됨 |
| 5 | 원본 노드/셀의 **좌표 필드가 위치인지 순위인지** | 필드마다 판정이 적혀 있다 |
| 6 | 원본 **draw 호출 층 수** vs 우리 자식 수 | 개체 종류마다 일치 |
| 7 | 화면별 **요소 전수 대조표**(「화면 하나를 전수 대조표로 여는 법」) | 빈 칸 0 |

```bash
# 1 — 해제 없는 구독
# 구독 ↔ 해제 짝 검사 — 명령은 `UIFramework.md` 「구독은 짝으로」가 정본

# 2 — 원본 객체 키 합집합 (배열/맵 형태에 맞게 경로만 바꾼다)
node -e "const M=require('./원본모듈.js'); const k=new Set();
  Object.values(M).flat().forEach(o=>Object.keys(o).forEach(x=>k.add(x)));
  console.log([...k].sort().join(' '),'|',k.size)"

# 3 — 한 자리의 삼항 개수
grep -o "costTxt *= *[^;]*" 원본.html | grep -o "?" | wc -l

# 4 — 비ASCII 기호 전수 → cmap 대조
grep -oP "[^\x00-\x7F]" 원본.html | sort -u   # 비ASCII 전수 (-P 없으면 python 한 줄로)

# 6 — draw 호출 층
grep -c "ctx.fill()\|ctx.stroke()\|drawImage" 원본.html
```

**[재발방지](재발방지.md) 와 역할이 다르다 — 둘 다 돈다.** 그쪽은 지난 사고의 사후 기록이고,
이쪽은 **처음 보는 게임에서도 돌아가는 절차**다.

### ★ 플로우 diff 를 프리팹 대조보다 **먼저** 돌린다

**플로우 차원의 결함은 프리팹 검증으로 절대 안 잡힌다.** 프리뷰 하네스는 창을 하나씩 격리해 굽기
때문에, **원본에 없는 창이 한 겹 더 뜨는 것**은 어느 캡처에도 안 나온다.

> **[사고]** 뽑기를 돌리면 원본에 없는 `RewardResultPopup` 이 한 겹 더 떴다.
> 창마다 프리팹 점수는 전부 높았고 **몇 턴 동안 아무도 못 봤다.**
> 정적 캡처를 아무리 비교해도 「없어야 할 창」은 안 보인다.

**절차** — 화면 하나를 완료로 올리기 전에 Play Mode 에서 이걸 먼저 한다:

1. 원본에서 그 화면의 **버튼 전수**와 각각이 여는 것을 나열한다
   (`addEventListener` · `data-*` · `onclick` 을 grep).
2. 유니티에서 같은 순서로 눌러 **열린 창 목록**을 적는다.
3. 두 목록을 diff 한다 — **없어야 할 창 · 있어야 할 창 · 순서** 세 가지를 본다.

「배치가 맞는지」는 그 다음이다. 순서를 바꾸면 프리팹을 다 맞춰 놓고 플로우 때문에 다시 뜯게 된다.

## 진행 현황 · 대조 결과 · 캡처 대응은 **원장에 적는다**

회차별 달성률 · 정답지 통과 수 · 지적 캡처 처리 내역 · 폰트 교체 상태는
**전부 `HtmlToUnity_작업내역.md`(원장)의 소관**이다. 이 문서에 적으면 다음 프로젝트에서 낡은 채로 남는다.

여기서는 그 기록에서 반복해 확인된 **운영 규칙 하나만** 남긴다.

### 검증 하네스에 없던 화면을 만나면 먼저 하네스를 만든다

지적 캡처가 있는데 **재는 도구가 없으면** 대조를 못 한다.
프리뷰가 일부 화면만 굽고 있으면, 나머지 화면의 지적은 전부 미측정으로 쌓인다.

**캡처가 들어오면 먼저 물을 것은 「이 화면을 굽는 프리뷰가 있나」다.** 없으면 그것부터 만든다.
정지 프리뷰는 `Update` 가 안 도니 애니메이션이 붙은 상태는 **끝 상태를 강제**해야 한다 —
안 그러면 t=0 이 찍혀 「기능이 없다」로 오판한다.
