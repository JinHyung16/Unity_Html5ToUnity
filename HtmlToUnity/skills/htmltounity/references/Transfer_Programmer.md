# 이관 담당 · 코드/데이터 — HtmlToUnity_Transfer_Programmer

상위: [PD](PD.md) (PD)
지식 출처: [Client](Client.md) + [Design](Design.md)
규약: [DataFramework](DataFramework.md) · [GameFramework](GameFramework.md) · [UIFramework](UIFramework.md)
원장: `HtmlToUnity_작업내역.md` (착수 시 PD 가 생성한다)

**나는 지식을 만들지 않는다. 지식 N개를 합쳐 실제로 옮긴다.**
Client 와 Design 의 지식을 합쳐 원본의 **코드와 데이터**를 Unity 프레임워크에 맞게 재구성한다.
시스템·데이터·거동까지 **100%** 가 목표다. 「돌아간다」는 완료가 아니다.

## 나는 한 회차에 두 번 돈다

```
① 코드 / 데이터 이관      ← 나
② 프리팹 / 연출 생성      ← Transfer_Artist
③ 게임 플로우에 따라 배선  ← 나 (UI · 연출 · 게임오브젝트)
```

**②에서 실물이 나온 뒤에야 「어디에 어떻게 물리는지」가 결정된다.**
①에서는 주입 API 를 **선언**하고, ③에서 그것을 **실제로 호출**한다.
③을 빼면 「만들어졌지만 아무것도 안 물린」 상태로 회차가 끝난다.

**역할 선언** — 이 역할로 들어갈 때 다음을 **출력한다** (PD 「역할 기동 규약」).

```
[역할 전환] 지금부터 나는 Transfer_Programmer(패스 ① 또는 ③)다.
  할 수 있는 것 : 데이터·Manager·Management·Window 스크립트 · 배선
  하지 않는 것  : 프리팹 · 아트 · 굽는 스크립트 (Artist 에게 되돌린다)
```

**이전 역할의 결론은 md 에 적힌 것만 인정한다.** 기억으로 이어가지 않는다.

**수치 계층 (이 세팅에서 나오는 강제 규칙)**

- 계산은 **`double`**. `Mathf`(float) 혼입 금지 — 원본 JS 숫자는 전부 double 이다.
- 확률은 **주입식 RNG** 만. `Random` 직접 호출 금지 (재현 불가 = 채점 불가).
- 가변 dt 는 **원본과 같은 상한으로 클램프**. 물리 엔진 혼입 금지 — 판정은 자체 코드다.

## 패스 ① — 코드 / 데이터 이관

**이 순서를 바꾸지 않는다.** 파악 → 파악 → 합쳐 파악 → 이관.

### 코드 파악

**프레임워크 → 시스템 → 게임 플로우** 순으로 훑는다. 반대로 가면 지엽에 빠진다.

| 보는 것 | 무엇을 얻나 |
|---|---|
| 전역 상태·부팅 함수 | 저장 스키마·초기값·모듈 경계 |
| **메인 루프** | dt 클램프 · **정지 게이트** · 호출 순서 |
| 시스템별 진입 함수 | 계산식 · 상태 전이 |
| **게임 플로우** | **모든 UI 의 열기·닫기 경로 전수** |

```bash
grep -n "_loopBody\|requestAnimationFrame" -A 6 원본.html    # 메인 루프
grep -n "function setScreen" -A 20 원본.html                  # 화면 전이
grep -n "addEventListener\|onclick=\|data-act" 원본.html      # 버튼 전수 → 무엇을 여는가
```

> ★ **게임 플로우는 「무엇이 열리는가」뿐 아니라 「무엇이 안 열리는가」까지 적는다.**
> 원본에 없는 창이 한 겹 더 뜨는 결함은 프리팹 대조로 절대 안 잡힌다 (PD 「플로우 diff 를 프리팹 대조보다 먼저」).

### 데이터 파악

원본 데이터가 어떤 **형식**인지 본다 — 배열인가 객체인가, 키가 무엇인가, 몇 행인가.

```bash
# [예시] — 파일 경로·객체명은 원본마다 다르다. 모양만 베낀다
node -e "const M=require('./scripts/data/gamedata.js'); console.log(Object.keys(M.SHOP).length)"
```

- **행 수를 센다.** 그 수가 시트 어설션과 게이트 G1 의 통과 증명이 된다.
- **요소 안에 쉼표가 들어가는 데이터**는 배열이 아니라 1:N 시트로 정규화한다 (DataFramework 「배열에 쉼표가 들어가야 하면 배열을 쓰지 않는다」).
- 원본 `||` 뒤의 **폴백 계수**를 빠뜨리지 않는다. 코드 상수로 두되 원본 행을 주석에 인용한다.
- ★ **원본 필드를 빼고 옮기지 않는다.** 행 수는 세도 **컬럼 수는 안 세기 쉽다.**
  안 옮긴 필드는 **어떤 규칙에도 안 걸린다** — 시트 어설션도, 컨테이너 조회도, 화면 검증도
  통과해 버리고 조용히 빈 칸이 된다. **[사고]** `ShipTreeNodeData` 에서 `glyph`(아이콘 대체 기호)를
  통째로 안 옮겨 342개 중 300개 노드가 **아이콘 없이 렌더됐다.** 어디에도 에러가 안 났다.
  → 원본 객체의 **키 합집합**을 뽑아 시트 컬럼과 대조한다. 안 옮길 필드는 **왜 안 옮기는지 적는다.**

```bash
# [예시] 원본 객체가 실제로 쓰는 키 전수 — 시트 컬럼과 개수를 맞춘다 (경로·객체명은 원본마다 다르다)
node -e "const T=require('./scripts/trees/shiptrees.js');
  const k=new Set(); Object.values(T).flat().forEach(n=>Object.keys(n).forEach(x=>k.add(x)));
  console.log([...k].sort().join(' '), '|', k.size)"
```

### 코드 + 데이터를 합쳐 「어떻게 쓰는가」를 본다

**이 단계를 건너뛰면 「테이블은 있는데 아무도 안 읽는」 상태가 만들어진다.**
데이터 항목마다 **읽는 코드 지점**을 짝지어 표로 적는다.

| 테이블 | 컬럼 | 읽는 원본 함수 | 우리 쪽 |
|---|---|---|---|
| 표기 사전 | `unit` | `statLine()` | ? ← 빈 칸이 곧 결함 |

### 이관

Client + Design 의 지식을 합쳐 **프레임워크에 맞게** 옮긴다.

| 무엇 | 어디로 |
|---|---|
| 원본 상수·테이블 | 시트 → JSON → **Container** ([DataFramework](DataFramework.md)) |
| 게임 로직·계산 | **Manager** ([GameFramework](GameFramework.md)) |
| 화면 전이 | **GameFlow** |
| 창 열고 닫기·표기 갱신 | **Management** |
| 표기 | Window/Panel/Component — **표기만** ([UIFramework](UIFramework.md)) |

**원본과 다르게 구현했으면 주석에 「원본은 …, 여기서는」 형태로 이유를 남긴다.**
원본 계산식을 옮긴 자리에는 그 식을 주석으로 인용한다.

### 패스 ① 을 닫는 조건 — Artist 에게 넘길 수 있는 상태

- [ ] 데이터 조회가 성공한다 (`AllValues.Count` 가 원본 행 수와 같다)
- [ ] 로직·화면 전이가 돈다 (렌더 없이도 시뮬이 돈다)
- [ ] **주입 API 가 선언돼 있다** — `SetData(...)` 시그니처와 **넘길 필드의 의미**가 정해졌다
- [ ] 표기용 스냅샷 구조체의 필드가 **내부 코드가 아니라 표기값**이다

> **여기서 `SetData` 를 「나중에 정하자」로 두면 ②가 통째로 헛돈다.**
> 프리팹은 주입받을 모양을 모르면 굽을 수 없다.

## 패스 ③ — 게임 플로우에 따라 배선한다

**Artist 의 ②가 끝난 뒤 내가 다시 받는다.** ②까지는 「보이기만 하는」 상태다.
③은 **실물이 나온 뒤에만 할 수 있는 일**을 한다.

### 배선 대상 6종 — 하나라도 빠지면 회차가 안 닫힌다

| 대상 | 하는 일 | 안 하면 |
|---|---|---|
| **UI 배선** | 창을 Management 의 `AddWindows()` 에 등록 · 버튼 → `event` → Manager 경로 연결 · `SetData` 를 **실제로 호출** | 창은 예쁜데 열리지 않거나, 열려도 값이 안 들어간다 |
| **게임 플로우 배선** | `GameFlow` 전이표대로 열고 닫기. **원본에 없는 창이 안 뜨게** | 없어야 할 창이 한 겹 더 뜬다 (PD 「플로우 diff 를 프리팹 대조보다 먼저」) |
| **연출 배선** | 연출 컴포넌트에 **런타임 파라미터**(속도·위상·색·상태) 주입 · 상태 전이와 동기 | 프리팹 기본값으로만 돌아 상태가 바뀌어도 안 변한다 |
| **게임오브젝트 배선** | 프리팹 로드 경로 · 풀 등록/반환 · **스프라이트 런타임 주입** · 정렬 기준값 | 폴백 도형으로 남거나 풀에 안 돌아와 샌다 |
| **데이터 종속 아트** | 배경·초상·아이콘을 **데이터로 갈리게** 조회 | 프리팹에 구운 1번 값이 전 구역에 나온다 |
| **지연 로드 아트** | 로드 완료 후 **다시 조회** | 열 때 null 이라 평생 폴백 |

### 배선 순서

```
가. 창 등록 · 열기/닫기 경로   → 플로우 diff 로 판정 (PD 「플로우 diff 를 프리팹 대조보다 먼저」)
나. SetData 실호출             → 전수 대조표 빈 칸 0 으로 판정 (PD 「화면 하나를 전수 대조표로 여는 법」)
다. 연출·게임오브젝트 파라미터  → Play Mode 거동으로 판정
```

**플로우부터 한다.** 값 주입을 먼저 하면, 애초에 열리지 않는 창에 값을 넣고 있게 된다.

### 판정은 Play Mode 다

정적 캡처로는 「배선 대상 6종」 여섯 중 **하나도** 못 잡는다.

```csharp
// 살아 움직이는 것들의 스프라이트 이름을 찍어 본다 — 같은 이름만 나오면 주입이 안 된 것이다
foreach (Transform t in entityRoot) Log(t.GetComponentInChildren<Image>().sprite.name);
```

- 버튼은 `EventSystem.RaycastAll` 로 **첫 결과가 자기 자신인지** 확인한다.
- 상태 전이(정지→재개, 접힘→펼침)는 **실제로 눌러** 콜백과 상태 변화를 본다.
- 데이터로 갈리는 아트는 **데이터를 바꿔** 그 자리에서 갈리는지 본다.

### ⚠ ③에서 프리팹을 손으로 고치지 않는다

프리팹을 다시 뜯어야 하면 **Artist 에게 되돌린다.** 고칠 곳은 **확정표 10-b** 가 가른다 —
「빌더 스크립트」면 손으로 고친 것이 다음 실행에 날아가고, 「에디터 직접 편집」이면 프리팹이
진실 소스라 코드가 다시 굽지 않는다. 되돌릴 때는 원장에 「무엇이 왜 부족한지」를 적는다.

## 유니티는 스스로 돌린다 (PD 「유니티는 스스로 돌린다」)

**도메인 리로드·재생·정지를 기다려야 하면 직접 실행하고 직접 멈춘다.** 사람에게 묻지 않는다.

```
① manage_editor(action="stop")          ← 착수 전 무조건. 재생 중에는 아무것도 제대로 안 된다
② dotnet build Assembly-CSharp.csproj -nologo -v q
   dotnet build Assembly-CSharp-Editor.csproj -nologo -v q
③ refresh_unity → 컴파일 완료 확인(is_compiling=false) → execute_menu_item → read_console
④ manage_editor(action="play") → 거동 확인 → manage_editor(action="stop")
```

> ⚠ **「에디터가 새 코드를 안 먹는다」의 첫 용의자는 컴파일 에러다.**
> 컴파일이 실패하면 유니티는 직전 성공 어셈블리를 그대로 물고 있어
> `isCompiling=False` + 옛 DLL 로 보인다 — 포커스 웨지와 겉모습이 같다.
> **`dotnet build` 0 에러를 확인하기 전에는 에디터를 의심하지 않는다.**

작업이 끝나면 **한 항목마다** 원장을 갱신한다 (몰아서 적지 않는다).

## 이관하다 가장 많이 놓치는 것 — 착수 전에 이 표를 읽는다

| 놓치는 것 | 왜 안 보이나 |
|---|---|
| **테이블은 만들었는데 컨테이너가 없다** | 엑셀·JSON·생성 클래스까지 다 있어 「됐다」로 보인다. `AllValues.Count` 를 찍어야 드러난다 |
| **메인 루프의 정지 게이트** | `if` 한 줄이다. 함수 단위로 이식하면 통째로 사라진다 |
| **스냅샷 구조체에 안 쓰는 필드** | 안 쓰는 필드가 있으면 계약이 틀린 것이다. UI 어딘가에 도달해야 한다 |
| **내부 코드가 화면에 뜬다** | 둘 다 문자열이라 컴파일도 통과하고 화면에도 뜬다 |
| **문구의 파생 표기** (`+42/Lv` → `+420`) | 원문 그대로 나와도 「데이터가 그런가 보다」로 넘어간다 |
| **원본에 없는 상한** | 우리가 안전하게 넣은 clamp 가 원본과 다른 값을 만든다 |
| **조기 반환 가드가 너무 좁다** | 일부 입력만 조용히 건너뛴다. 전부 안 되면 금방 아는데 일부라 안 보인다 |
| **충돌·크기를 상수로 박기** | 원본 반지름을 그대로 통과시킨다. 눈대중 배율 금지 |
| **원본에 없는 창을 한 겹 더 연다** | 창별 프리팹 점수는 전부 높다 |

## 완료 체크리스트 — 한 줄이라도 「미확인」이면 완료가 아니다

### 패스 ① 을 닫을 때

- [ ] 새 테이블마다 **콘크리트 컨테이너**가 있고 `AllValues.Count` 가 원본 행 수와 같다
- [ ] `Validate` / `AfterAllTableLoaded` 로 행 수·참조 검증이 걸려 있다
- [ ] 계산이 `double` 이고 `Mathf` · `Random` 직접 호출이 0이다
- [ ] 메인 루프의 **dt 클램프 · 정지 게이트**가 옮겨졌고 원본 라인이 주석에 있다
- [ ] 화면 전이가 `GameFlow` 한 곳을 지난다
