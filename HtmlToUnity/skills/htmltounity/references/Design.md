# 기획 파트 — HTML5 → Unity 이관

상위: [PD](PD.md) (PD)

**담당** — 원본 상수·테이블·문구를 데이터로 옮기기 · 파생 규칙 · 밸런스 수치 · 스키마.
**한 줄 원칙** — **문구는 원본과 바이트 단위로 같아야 한다.** 안 보이면 폰트나 배선을 의심하지, 문구를 고치지 않는다.

**역할** — 나는 **지식 담당자**다. 이관에 직접 참여하지 않는다.
[Transfer_Programmer](Transfer_Programmer.md) 가 100% 이관할 수 있도록 **정확한 정보를 제공**하는 것이 산출물이다.
**내용에 거짓이 없는지 항상 의심한다** — 특히 내가 지난 회차에 쓴 문장을.

**역할 선언** — 이 역할로 들어갈 때 다음을 **출력한다** (PD 「역할 기동 규약」).

```
[역할 전환] 지금부터 나는 Design(지식 담당)다.
  할 수 있는 것 : 원본 읽기 · 00_게임개요.md / 03_데이터.md 작성
  하지 않는 것  : Assets 아래 전부 (데이터 이관은 Transfer_Programmer 가 한다)
```

**이전 역할의 결론은 md 에 적힌 것만 인정한다.** 기억으로 이어가지 않는다.

## ★ 테이블을 만들었다 ≠ 게임이 읽는다

**기획 파트의 완료는 「엑셀에 있다」가 아니라 「런타임 조회가 성공한다」다.**

> **[사고]** 스탯 표기 테이블 수백 행을 원본 표기 사전에서 그대로 옮겨 뒀는데,
> 콘크리트 컨테이너가 없어 **아무도 읽지 못했다.** 엑셀·JSON·생성 클래스까지 다 있어서
> 파일만 보면 완료로 보였고, 그동안 그 표를 쓰는 화면(스탯 변화표)은 **빈 박스**였다.

**인수인계 체크 (기획 → 클라)**

```
① 행 수 어설션      원본 N행 = JSON N행 = 컨테이너 AllValues.Count
② 조회 성공         Get(대표코드) 가 null 이 아니다
③ 소비처 존재       그 테이블을 읽는 코드가 실제로 있다  ← 여기서 대부분 끊긴다
```

세 번째가 핵심이다. **`grep` 으로 소비처를 확인하고, 없으면 「미배선」으로 보고한다.**

```bash
grep -rn "XxxDataContainer" Assets/Scripts --include=*.cs | grep -v Generated
# 결과가 비면 아무도 안 쓴다
```

## 어디까지 데이터로 뺄 것인가

| 종류 | 처리 |
|---|---|
| 밸런스 수치 (HP·확률·비용·계수 테이블) | **데이터로 뺀다** |
| 표기 순서·서식표 (원본의 표시용 배열) | **데이터로 뺀다.** 순서가 곧 우선순위다 |
| 원본 코드의 `\|\|` 폴백 계수 | **코드 상수 + 원본 행 인용 주석.** 데이터로 빼면 원본과의 대응이 끊긴다 |
| 그리기 파라미터 (선 굵기·blur·색) | **코드 상수 + 원본 행 인용.** 연출 파트 소관 |
| 문구·설명 텍스트 | 데이터. **원본과 바이트 단위로 같아야 한다** |

> **[사고]** 배경 연출의 무기 위력을 데이터로 빼려 했으나, 필요한 값이 이미 계산 스냅샷에 전부 있었다.
> **새 시트가 필요한 게 아니라 배선이 빠진 것이었다.**
> 「값이 화면에 안 나온다 → 시트를 만든다」는 대개 오진이다. **먼저 배선을 의심한다.**

## ★ 문구의 파생 규칙을 같이 옮긴다

원본은 문구를 **원문 그대로 저장하고 표시 직전에 계산**하는 경우가 많다.

```js
// [예시] 원본.html — 문구 파생 규칙. 단위 사전(%p·/s·단계 …)과 함수명은 원본마다 다르다.
//        인용할 때 라인 번호를 grep 으로 재확정한다
const _DLV_RE=/([+\-−])(\d+(?:\.\d+)?)((?:\s?(?:%p|%\/s|%|\/s|s|시간|단계|기|척|회복))?)(\s*\/\s*Lv)/g;
descLvResolve("최대 내구도 +42/Lv", 10)   →   "최대 내구도 +420"
```

> **[사고]** 이 규칙이 안 옮겨져서 카드에 `+4% / Lv.` 가 **원문 그대로** 떴다.
> 데이터가 그런 줄 알고 넘어가기 쉽다.

**규칙**

- 원본에서 **문구를 가공하는 함수**를 전부 찾아 목록화한다.
  ```bash
  grep -n "function .*desc\|replace(.*RegExp\|\.replace(/" 원본.html
  ```
- 데이터에는 **원문**을 넣고, 변환은 표시 직전에 한 번만 한다.
- 변환 함수는 **결과에 원래 패턴이 남지 않게** 만들어 두 번 호출해도 안전하게 한다.
- 반올림·꼬리 0 제거까지 원본 그대로 옮긴다 (`Math.round(v*100)/100` 후 `0` 제거).

## 엑셀 스키마 컨벤션

- 컬럼명은 **PascalCase**.
- 필수 컬럼은 자료형 뒤에 `!`. 비어 있으면 익스포터가 에러를 낸다.
- 배열은 `기본자료형 + Array` (**쉼표 구분 셀만**). 요소 안에 쉼표가 들어가야 하는 데이터는
  배열이 아니라 **1:N 시트로 정규화**한다.
- enum 컬럼은 먼저 enum 시트에 추가하고 컬럼 자료형에 그 이름을 적는다.
- **`Id` 는 무조건 `int!`** — 1부터의 순번이고 테이블 키다.
- 문자열 논리 식별자는 **`Code` 컬럼(`string!`)**. 같은 `Code` 가 여러 행에 걸쳐도 `Id` 는 유일하다.
- 다른 테이블을 가리키는 참조 컬럼은 `Code` 값을 담고 이름에 `~Code`/`~Codes` 를 쓴다.
  `~Id` 는 int로 오해되니 금지.
- enum 이름 규칙은 **프로젝트 컨벤션이 우선한다** (`DataFramework` 「Enum 은 `_Enum` 시트에서 나온다」).
- 엑셀 파일은 **도메인 단위**로 나눈다. 잡탕 시트 금지.
- **데이터 작성이 끝나면 항상 익스포터를 실행**해 JSON/C#을 재생성한다.

## 스키마 카운트 어설션

「조용히 비어 들어온 데이터」가 뒤늦게 계산 실패로 둔갑하기 전에, **셀 수 있는 모든 것을 센다.**

**무엇을 세나** — 트리/스킬 노드 총합과 계열별 내역 · 유닛 수 · 뽑기 가중치 합 ·
표기 규칙 행 수 · 아이콘 수. 원본과 우리 쪽 수를 나란히 적고 **다르면 그 자리가 결함**이다.
수치는 그 프로젝트의 원장에 적는다.

원본에서도 같은 방법으로 센다:

```bash
# [예시] — 파일 경로·전역 객체명은 원본마다 다르다. 모양만 베낀다
# 원본 JS 객체의 키 수
grep -c "^\s*\w\+:" 원본/trees/combat.js
# 브라우저에서 직접
Object.keys(window.SkillIcons).length
```

## 원본 문구·수치를 뽑는 법

```bash
# 특정 글리프가 어느 테이블 · 어느 컬럼에 들어 있는지
python -c "json 순회해서 컬럼별 카운트"
# 원본의 표시용 배열 (표기 순서 = 우선순위)
grep -n "const .*_DISP\|const .*_NAME\|const .*_NM" -A 30 원본.html
# 등급·분류 표기명 사전
grep -n "const .*RKNAME\|const .*_LINE\|const .*THEME" 원본.html
```

**표기 사전을 빠뜨리지 않는다.** 원본은 내부 코드(`parent`, `deployRoot`)와
표기명(`무기 계통`, `전개 통제`)을 **별도 사전**으로 들고 있다.
사전을 안 옮기면 화면에 내부 코드가 그대로 뜬다 — 실제로 카드 상단에 `parent` 가 떴다.

**[예시]** — 사전의 갈래 모양이다. 코드·표기명 값은 그 원본의 것이다:

| 사전 종류 | 역할 |
|---|---|
| 등급 사전 | 등급 코드 → 표기명 (`uncommon` → `고급`) |
| 계통 사전 | 분류 코드 → 표기명 (`deployRoot` → `전개 통제`) |
| 테마 사전 | 테마 코드 → 표기명 |

**이름은 프로젝트마다 다르다.** 「코드 → 사람이 읽는 이름」 매핑이 있으면 전부 사전이다.

## 밸런스 수치는 원본에서 실측한다

- 원본을 브라우저에서 띄우고 **전역 상태를 직접 읽는다.** 문서에 적힌 수치보다 우선한다.
- 치트/디버그 명령이 있으면 그대로 이식해 **같은 한 줄로 양쪽을 같은 상태**로 만든다 (공통절차 「A/B 측정」).
- **직관과 반대인 값이 나와도 원본과 같으면 맞다.** 강화를 받는데 사거리가 줄어드는 것처럼
  이상해 보이는 결과가 원본 계산식의 정답일 수 있다. 원본에서 같은 상태를 만들어 확인한 뒤 판단한다.

## 기획 파트 완료 체크리스트

- [ ] **미측정 항목 0** — 못 잰 것은 `미측정(사유)` 로 적고 **재측정 대기**에 등록했다
- [ ] **내 권한 밖 파일을 건드리지 않았다** (PD 「역할 기동 규약」 권한표)

1. 원본 테이블의 **행 수**가 JSON·컨테이너와 일치하나 (「테이블을 만들었다 ≠ 게임이 읽는다」)
2. 그 테이블을 **읽는 코드가 실제로 존재**하나 (「테이블을 만들었다 ≠ 게임이 읽는다」) — 여기서 대부분 끊긴다
3. 문구가 원본과 **바이트 단위로** 같나
4. 문구의 **파생 규칙**(레벨 비례 등)을 함께 옮겼나 (「문구의 파생 규칙을 같이 옮긴다」)
5. 내부 코드 → 표기명 **사전**을 전부 옮겼나 (「원본 문구·수치를 뽑는 법」)
6. `Id`/`Code`/`~Code` 컨벤션을 지켰나 (「엑셀 스키마 컨벤션」)
7. 셀 수 있는 것을 전부 세어 어설션으로 남겼나 (「스키마 카운트 어설션」)
8. 폴백 계수를 데이터로 빼지 않고 코드 상수 + 원본 인용으로 뒀나 (「어디까지 데이터로 뺄 것인가」)
