# Resource Rule — `_Art` 폴더링 · 해상도 · 어드레서블

상위: [PD](PD.md) (PD) · 사용자: [Transfer_Artist](Transfer_Artist.md)

**HTML5 게임의 리소스는 두 갈래다** — 파일로 존재하는 것, 그리고 **코드(CSS·canvas)로 그리는 것**.
후자를 못 세면 이관은 반드시 미완으로 끝난다.

---

## 폴더

```
Assets/_Art/               (없으면 만든다)
├─ UI/
│   ├─ Icons/   Frames/   Bars/   Cards/   …   (기존 폴더의 대소문자를 따른다)
├─ Game/
│   ├─ BG/<theme>/         bg · stars · planets · meteors  레이어 분리
│   ├─ Adjutants/  Enemies/  Ships/  Parts/  Weapons/
│   ├─ Fx/       Video/     Audio/
├─ Atlas/                  스프라이트 아틀라스 (아이콘 계열은 여기 묶인다)
├─ Materials/  Shaders/
```

- **경로는 빌더·로더 상단에 `const` 로 모은다.** 인라인 문자열로 흩뿌리지 않는다.
- **각 폴더만 어드레서블에 등록**하고, 개별 파일 주소는 **DB(시트)에서 가져와 쓴다.**
  코드에 파일명을 박으면 아트가 늘 때마다 코드를 고치게 된다.

---

## 착수 — 두 목록을 먼저 만든다 (`06_리소스.md`)

학습 단계 산출물이다 (PD 「산출물 목록」). **이 목록이 없으면 무엇이 빠졌는지 영원히 모른다.**

| # | 목록 | 만드는 법 |
|---|---|---|
| ① | **존재하는 리소스** | 원본이 리소스를 호출하는 폴더를 훑는다 (`assets/` 등). 파일명·크기·사용처 |
| ② | **제작해야 하는 리소스** | 화면에는 나오는데 파일이 없는 것. **CSS·canvas 로 그리고 있다.** Client 지식 담당자의 도움을 받아 원본 draw/CSS 를 짚는다 |

```bash
# ① 원본이 실제로 부르는 파일 전수
grep -oE "(assets|img|res)/[A-Za-z0-9_./-]+\.(png|jpg|webp|mp4|webm|mp3|ogg)" 원본.html scripts/**/*.js | sort -u
# ② 코드로 그리는 것 — 그리기 호출을 전수로 뽑는다
grep -n "fillRect\|arc(\|drawImage\|createLinearGradient\|shadowBlur" 원본.html | wc -l
# ② CSS 로 그리는 것 — 배경·그라디언트·테두리
grep -n "background:linear-gradient\|box-shadow\|border-radius\|clip-path" 원본.html
```

**②를 「나중에」로 미루면 단색 박스가 남는다.** 단색 박스는 미완성이다 — 그 자리에서 굽는다.

## 해상도 정책 — PD 착수 질문 7번의 답으로 갈린다

### 원본 크기 그대로

원본 HTML5 의 픽셀 크기를 유지한다. 픽셀 대조가 쉬운 대신 모바일 메모리가 커진다.

### 플랫폼에 맞춰 리사이즈 (기본 권장)

**모바일이 타깃이면 텍스처가 4의 배수여야 압축이 걸린다.** 아니면 압축이 통째로 풀려 용량이 튄다.

| 종류 | 권장 크기 |
|---|---|
| BG | 512 ~ 1024 |
| Icon | 64 ~ 512 |
| FX | 64 ~ 256 |
| 폰트 | 임시 생성해 사용 (「폰트」) |

공통 임포트 규격:

| 항목 | 값 |
|---|---|
| Pivot | **Center** |
| Pixels Per Unit | **100** |
| Max Size / 압축 | 플랫폼별로 명시 (모바일 압축 포맷) |
| Mip | UI 는 끈다 |

> ⚠ **구운 뒤 임포트 설정을 안 걸면 굽는 의미가 없다.** 생성기가 PNG 를 쓰고 끝내면
> 기본 임포트(압축·mip·PPU)가 걸려 화면에서 흐려지거나 크기가 어긋난다.
> **생성기가 임포트 설정까지 책임진다.**

## 없는 리소스는 만들어서 채운다

### 절차 생성 규칙

- **흰색 + 알파만 굽는다.** 색은 런타임 `Image.color` tint 로 준다.
  단, **색이 데이터로 갈리지 않는 것**(위험 사선·금속 그라디언트·리벳)은 색까지 구워야 원본과 같아진다.
- 얇은 선이 있는 큰 도형은 **고해상 + 슈퍼샘플**로 굽는다. 저해상 알파는 선이 사라진다.
- **원본이 이모지면 그 이모지의 실제 형태를 옮긴다.** 단순 도형으로 대체하면 다른 물건으로 읽힌다.
  (`💎` 브릴리언트 컷 · `🎲` 아이소메트릭 큐브 · `🍀` 하트 잎 4장 + 줄기)
- **컬러 이모지는 tint 가 안 먹는다.** 원본 CSS `color` 가 컬러 이모지에 안 걸리듯,
  우리도 흰색 실루엣 + tint 로 내면 다른 색이 된다 → **컬러 그대로 베이크**한다.
- 영상만 있는 배경은 첫 프레임을 떠서 **스틸 폴백**을 만든다 (`ffmpeg -frames:v 1`).

### ★ 절차 이펙트는 재구현하지 말고 원본에서 베이크한다

손으로 다시 그리면 크게 어긋난다. **원본 드로잉 코드를 줄 단위로 옮겨 굽는다.**
`shadowBlur` 글로우도 베이크에 함께 구워지므로 별도 셰이더가 필요 없다.

### ★★ 반투명을 구울 때 — **모양 마스크가 원본 알파를 덮어쓴다**

둥근 모서리를 «마스크로 씌우는» 코드는 대개 알파를 **통째로 갈아 끼운다.**
그러면 원본이 반투명이어도 **불투명하게 구워진다** — 모양은 맞으니 눈으로는 잘 안 보이고,
「배경이 안 비친다」는 것도 원본을 나란히 놓아야 알아챈다.

> **[사고]** 반투명 판(원본 알파 0.5)이 불투명하게 구워져 원본보다 어둡고 납작했다.
> 요소 대조에서 사탕까지 19~39% 로 떨어져 **엉뚱한 곳(사탕 리사이즈)을 의심**했다.

**모양 마스크와 원본 알파는 «곱한다».** 덮어쓰지 않는다.

### ★★ Linear 프로젝트에서 반투명은 **원본 값 그대로는 안 맞는다**

원본(브라우저)은 **감마 공간**에서 섞고 우리는 **Linear** 에서 섞는다.
같은 알파를 줘도 **결과 색이 다르다** — 반투명 면은 원본보다 밝게 나온다.

| 하지 않는 것 | 하는 것 |
|---|---|
| 코드·데이터의 원본 알파를 고쳐 적기 | 원본 값은 **그대로 적어 둔다** |
| 눈대중으로 「좀 진하게」 | **계산해서** 굽는다 (아래) |

**보정값은 계산으로 낸다.**

1. 대표 배경색 하나를 고른다 (원본 캡처에서 그 요소 뒤에 실제로 있는 색)
2. **감마 합성 결과**를 구한다 = 원본이 내는 정답
3. 알파를 바꿔 가며 **Linear 합성 결과**를 구해 ②에 가장 가까운 값을 고른다
4. 그 값을 **굽는 스크립트에 주석과 함께** 박는다 — 「왜 원본 값이 아닌지」가 거기 있어야 한다

⚠ **한 알파로 모든 배경에서 맞지는 않는다.** 감마 합성은 Linear 알파로 정확히 표현되지 않는다.
그래서 «대표 배경 기준»이라고 적고, 최대 채널차를 같이 남긴다.

⚠ **그림자·글로우처럼 그 위에 겹치는 것도 같은 보정이 필요하다.** 하나만 고치면 나머지가 어긋난다.

### ⚠ 블러는 **여백을 두고 걸어야** 가장자리에 생긴다

이미지 경계에 딱 붙은 도형을 블러하면 라이브러리가 **바깥도 같은 값으로 늘려 잡아**
그 변에는 그라디언트가 **아예 안 생긴다.** 안쪽 그림자를 구울 때 **옆면만 통째로 빠진다.**

→ **여백을 준 큰 캔버스에서 블러하고 잘라낸다.**

### ⚠ 스프라이트 PPU 는 **캔버스 기준 PPU 와 짝이다**

9-slice 경계는 두 값의 «비»로 환산된다. 어긋나면 경계가 그만큼 줄어
**둥근 사각형이 타원으로 늘어난다** — 「스프라이트가 있다」 검사는 전부 통과한다.

→ 두 값이 같은지를 **검사로 박는다.** (`재발방지.md` #12 「짝이 맞다」로 쓴다)

### ⚠ 생성기가 조용히 죽을 수 있다

유니티가 텍스처를 메모리 매핑 중이면 IO 예외가 나고 **그 뒤 전부가 안 구워진다.**
→ 내용이 같으면 건너뛰고, 실패하면 핸들 해제 후 재시도하고, 그래도 안 되면 경고를 남긴다.

## 폰트

- **폰트는 하나로 간다. 폴백을 추가하지 않는다** — 폰트가 둘이 되는 순간 방침이 깨지고,
  폴백이 조용히 메워 주면 **없는 글리프가 영원히 안 드러난다.**
- 영어 · 한국어 · 특수문자 대응이 되게 **임시로 구워** 쓴다 (Dynamic · 1024² 등).
- **원본 문구를 고쳐 적지 않는다.** 폰트에 있는 글자는 그대로 쓴다
  (치환은 그 자체로 원본과의 차이다).
- **폰트에 없는 글자만** 스프라이트로 그린다. 무엇이 없는지는 TTF 의 cmap 을 파싱해 확인한다.
- 커밋 전에 **Dynamic 아틀라스를 비운다** — 에디터에서 쌓인 글리프가 diff 를 부풀린다.

### ★ 원본의 기호는 셋 중 하나로 갈린다 — 그대로 옮기지 않는다

브라우저는 아무 글리프나 그린다. `<div>✹</div>` 한 줄이면 끝난다.
**Unity 는 폰트 cmap 에 있는 것만 그린다.** 없으면 두부(tofu)다. 그래서 원본에 기호가 보이면
**먼저 자리를 판정하고, 그다음 cmap 을 잰다.**

| 그 기호가 있는 자리 | 처리 |
|---|---|
| **아이콘 칸** — 노드·슬롯·버튼의 그림 자리 | **아틀라스 아이콘.** 데이터에 `IconCode` 를 넣는다 |
| **글자 흐름 안** — 문장에 섞여 나오는 기호 | cmap 에 있으면 텍스트 그대로, 없으면 `TMP_SpriteAsset` 에 등록 |
| 장식 | 프리팹에 이미지로 물린다 |

**「원본이 텍스트로 그렸으니 우리도 텍스트」가 아니다.** 원본이 아이콘 칸을 유니코드 기호로
때운 것뿐일 수 있다 — 그때는 **이미지가 맞다.** **[사고]** 스킬 수백 개가
아이콘 칸을 `✹ ⚔ ❤ ➤ ⚡ ✦ ✧ ➶` 같은 기호 글리프로 그렸는데, 그것들이 **전부 폰트에 없었다.**
글리프를 그대로 옮겼으면 대부분이 두부가 됐을 자리다. 아틀라스 아이콘으로 매핑해 해결했다.

```bash
# 판정 전에 반드시 잰다 — 눈으로 보고 「있겠지」 하지 않는다
python - <<'EOF'
# TTF cmap(format 12) 파싱 → 원본에서 뽑은 코드포인트 전수를 대조
EOF
```

## 정적 아트 vs 데이터 종속 아트 — 섞지 않는다

| 구분 | 예 | 처리 |
|---|---|---|
| **정적 장식** | 패널 테두리, 탭 아이콘, 인트로 이미지 | 프리팹에 직접 물린다 |
| **데이터 종속** | 초상·유닛·아이템 아이콘·**구역별 배경** | 프리팹에 박지 않는다. 런타임 `SetData/SetXxx` 로 주입 |

**「배경」은 대개 데이터 종속이다.** 원본이 매 프레임 `bgIdFor(모드, 구역)` 로 고른다면
프리팹에 1구역 배경을 구워두면 5구역에서도 그게 나온다. **프리팹 값은 로드 실패 시 폴백으로만.**

등급별 프레임처럼 **후보가 유한한** 것은 `Sprite[]` 에 전부 물려두고 런타임에 인덱스로 고른다 — 정적 취급.

### 프리팹에 스프라이트를 박지 않는다 (월드 오브젝트)

아트를 어드레서블이 카테고리 단위로 로드/해제하는데 `Resources` 프리팹이 물면
그 생명주기를 우회하고 **빌드에 중복 편입**된다.
프리팹은 계층·`SpriteRenderer`·정렬 순서·머티리얼까지만 담고, 스프라이트는 각 Visual 이 주입한다.

### ⚠ 지연 로드 아트는 **다시 물어야** 한다

첫 화면을 띄운 뒤에 로드되는 아트가 있으면, 창이 열릴 때 한 번만 물어서는 전부 null 이다.
→ 평생 폴백 도형으로 남는다. **로드 완료 이벤트를 구독하거나 표시 시점에 다시 조회한다.**

## ★ 어드레서블 등록은 **양방향**으로 감사한다

동기화 도구는 보통 **「파일 → 주소」 한 방향만** 보장한다.
반대 방향 — **코드·데이터가 요구하는 주소가 실제로 있는가** — 는 아무도 안 본다.

> ⚠ 사고 — 영상 파일명이 복사본 접미로 `Intro_start 1.mp4` 가 되어 주소가 어긋났고
> 시작 시네마틱이 `InvalidKeyException` 으로 죽었다. 동기화 도구는 「제거 0 · 건너뜀 0」 이라 보고했다.

**감사 3종 — 도구로 만들어 두고 화면 완료 전에 돌린다.**

| 항목 | 잡는 것 |
|---|---|
| 코드·데이터에 박힌 주소 리터럴 전수 → 등록 여부 | 이름이 어긋난 것 |
| 아트 파일명의 **공백 · 복사본 접미** | 「이름 1.png」 는 조용한 시한폭탄이다 |
| 등록됐는데 파일이 없는 **고아** | 지운 뒤 남은 것 |

주의 — 감사기는 **폴더 엔트리**와 **폴더 접두어**를 오탐한다.
데이터의 아트 경로 중에는 파일이 아니라 폴더인 것이 섞여 있다.
파일 존재 검사에 디렉터리 예외를 넣고, 폴더 접두어는 Play Mode 로딩으로 확인한다.

**파일을 만드는 생성기가 등록까지 책임지게 한다.** 사람이 기억해서 등록하면 반드시 빠진다.

## ⚠ 아트를 물리기 전에 캡처의 그 영역을 실제로 확인한다

**파일명이 그럴듯하다고 붙이지 않는다.** 크롭해서 그 그림이 정말 거기 있는지 본다.

> **[사고]** `XXX_button.png`(금색 장식 프레임)를 어느 행 배경으로 깔았는데,
> 캡처는 **평면 남색 패널 + 좌측 시안 바**였다. 그 아트는 다른 화면의 장착 버튼용이었다.

크롭·픽셀 샘플링은 python + PIL 로 한다 (`cap.getpixel((x, y))`).
