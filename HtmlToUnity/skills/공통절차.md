# 공통 절차 — 전 파트가 매번 쓰는 것

상위: [PD](PD.md) (PD)

역할이 없는 문서다. 지식·이관·PD 누구든 측정·캡처·감사·컴파일 판정을 하거나 원본에서 사양을 캐낼 때 연다.
사고 사례와 막는 장치는 [재발방지](재발방지.md) 에 있다.

---

## 검수 절차 — 재기 전에 상태부터 맞춘다

### 세이브를 먼저 백업한다

Play Mode 중 자동 저장이 돌아 상태 조작이 실제 세이브를 덮는다. 백업 → 측정 → 반드시 복원한다.

### 원본을 재기 전에 — 폰트가 뜬 뒤에 잰다

웹폰트 원본의 첫 페인트는 폴백 폰트다. 글자가 크기를 정하는 요소(`width:auto` 컨테이너·버튼·라벨)는 로드 전후 값이 다르다.

```js
await document.fonts.ready;          // 이 줄 없이 잰 값은 사양이 아니다
el.getBoundingClientRect();
```

두 번 재서 다르면 나중 값이 사양이고, 먼저 잰 값은 오염으로 원장에 적는다(분석로직 「오염된 내용」, `재발방지.md` #1).

### 「그 기능이 없다」는 정확한 패턴으로 증명한다

```bash
grep -c "play" 원본.js                          # 하지 않는다: display · scoreDisplay 가 걸린다
grep -nE "new Audio|<audio|\.play\(\)" 원본.js   # 한다: 경계가 있는 패턴 + 줄을 눈으로 본다
```

개수만 보지 않고 매칭된 줄을 출력해 확인한다(`재발방지.md` #2).

### A/B 측정 — 상태를 맞추고 개체를 센다

스크린샷을 믿지 않는다. 캔버스는 픽셀로 셀 수 없고, 상태가 다르면 결함을 가를 수 없다.

① 상태를 맞춘다. 원본의 치트/디버그 명령을 이식해 같은 한 줄로 양쪽을 올리고, 그 상태를 기준 캡처의 상태로 못박는다. 아래 중 하나라도 다르면 그 구간 점수는 의미가 없다.

| 맞출 것 | 안 맞추면 |
|---|---|
| 진행도 (스킬·유닛·등급·장비·동료) | 계산이 수십 % 어긋난다 |
| 보유 재화 | 자릿수가 달라 상단바 구간이 깎인다 |
| 스크롤 위치 · 선택 대상 · 활성 탭 | 다른 화면을 비교한다 |
| 배경이 영상인가 | 그 구간은 40~60%가 정상이다 |

점수가 낮으면 결함을 찾기 전에 이 표부터 채운다.

② 픽셀이 아니라 개체를 센다. 원본은 JS 전역 상태, 유니티는 리플렉션으로 private 리스트를 같은 항목·같은 이름으로 센다. 종류 분포까지 센다(총량이 비슷해도 `Elite:5` 가 살아 있으면 무언가 안 죽는다).

③ 판정 표를 만든다. 실시간 시뮬은 2~3회 샘플링해 같은 대인지 본다.

| 항목 | 원본 | 고치기 전 | 고친 후 |
|---|---|---|---|
| 살아있는 적 (예시) | 1 / 6 / 2 | 11 / 28 | 2~4 |

### 재기 전에 노이즈가 0인 기저 상태를 만든다

재려는 변화 외의 변화가 0인 판을 먼저 설계한다.

| 원본에 있는 것 | 기저 상태 설계 |
|---|---|
| 자동 진행 (자동 매치·전투·낙하) | 자동 진행이 원천적으로 불가능한 배치를 만든다 (예: 값이 `(열 + 2×행) % 3` 인 판) |
| 무작위 생성 | 생성이 안 일어나는 상태로 두거나 생성 자리를 대조에서 제외한다 |
| 타이머 | 타이머 없는 모드나 정지 상태에서 잰다 |

- 깔고 방치해 변화가 0인지로 기저 상태를 먼저 증명한다. 그 위에 원본이 안 쓰는 값을 심어 델타의 출처를 확정한다.
- 제외할 자리는 벡터에 `RANDOM` 으로 미리 적는다. 안 적으면 다음 회차가 「값이 틀렸다」로 읽는다.

### 하네스에 `requestAnimationFrame` 을 쓰지 않는다

창·패널이 안 보이면 rAF 가 멈춘다. `setInterval`·`setTimeout` 은 계속 돈다.

```js
// 하지 않는다: 패널이 숨겨지면 여기서 멈춘다
await new Promise(r => requestAnimationFrame(r));

// 한다: 숨겨져 있어도 돈다
await new Promise(r => setTimeout(r, 10));
```

막힌 것 같으면 `document.hidden` 을 먼저 찍고, 원본이 정말 멈췄는지 타이머 한 번으로 확인한다.

### 교전 중 프레임을 얼려서 본다 (게임 코드 무수정)

도구 왕복(10~30초)이 전투보다 길면 에디터 쪽 `EditorApplication.update` 훅으로 조건에서 얼린다.

```csharp
EditorApplication.CallbackFunction hook = null;
hook = () => {
  var ctx = GameManager.Instance?.Combat?.Context;
  if (ctx == null || GameManager.Instance.Combat.IsRunning == false) return;
  ctx.Player.Hp = ctx.Player.MaxHp;        // 조사 중 격침 방지
  if (/* 보고 싶은 조건 */) {
    EditorApplication.isPaused = true;
    EditorApplication.update -= hook;      // 한 번만 잡고 스스로 제거
  }
};
EditorApplication.update += hook;
```

- `Time.timeScale` 낮추기는 안 통한다(출격 전이가 안 걸린다).
- 일시정지는 원격 도구의 틱으로 풀린다. 결과는 파일로 덤프한다.
- 원본에 「선택창이 뜨면 시뮬 정지」가 있으면 그 모달 상태가 곧 정지 프레임이다. 캡처·측정을 여기서 한다.

### 원본을 결정적으로 찍는 법 — G4 대조의 정본을 만든다

렌더 대조는 두 그림이 같은 상태일 때만 뜻이 있다. 원본 복사본에 다음을 적용한다(원본 폴더는 건드리지 않는다).

- 난수를 시드 LCG 로 고정한다.
- 주기 호출을 빈 함수로 덮어 주기 진행을 막는다.
- 원격 리소스를 로컬 경로로 바꾼다.
- 웹폰트를 뺀다(글자는 대조 제외 항목).
- 레이아웃 크기를 못 박는다(아래).

#### `file://` 은 정적 스냅샷이 될 수 있다

브라우저 패널이 프로젝트 밖 파일을 스크립트가 안 도는 스냅샷으로 열 수 있고, 화면은 멀쩡해 보인다. 로컬 HTTP 서버로 연다.

#### 「좌표를 재는 실행」과 「그림을 찍는 실행」의 배치가 다를 수 있다

헤드리스 브라우저는 두 실행의 창 크기가 다를 수 있다(스크롤바·페이지 높이).
캡처용 페이지에 `html, body { width: …px; height: …px; overflow: hidden; }` 로 크기를 못 박는다. 좌표는 숨은 요소의 텍스트로 DOM 에 심어 덤프로 꺼낸다.

### 요소 대조는 요소가 실제로 칠하는 자리만 센다

배경 배치가 달라, 통째로 겹치면 투명한 자리로 새어든 배경이 점수를 먹는다.

| 요소 종류 | 재는 법 |
|---|---|
| 불투명한 그림 | 원본 알파에서 심만 남긴 마스크로 센다. 가장자리 몇 px 는 깎는다 |
| 반투명한 면 | 뒷배경이 같은 색인 자리에서 앞색을 대조하거나 실효 알파를 역산한다 |
| 모서리·모양 | 반지름을 잰다 |
| 크기가 의도된 차이인 요소 | 색만 본다. 크기 차이는 확정표 등재로 갈음한다 |

- 알파 역산은 `Fx.md` 「색공간」을 따른다. 어두운 덮개는 역산 방향이 반대다(재발방지 #183).
- 원본 PNG 와 우리 PNG 를 먼저 대조해 자산 문제와 렌더 문제를 가른다.

### 화면 캡처는 비동기다

`ScreenCapture.CaptureScreenshot` 은 프레임 끝에 기록되어 같은 호출 안에서는 파일이 없다. 그 사이 Play Mode 가 리셋될 수 있으니 모달로 시뮬을 얼린 뒤 찍는다(「교전 중 프레임을 얼려서 본다」).

### 캡처는 쌓지 않는다 — 남기는 것은 덤프다

**캡처는 세션 안에서 눈으로 한 번 보는 데까지만 쓰고 저장소에 쌓지 않는다.**
이유: 캡처는 눈으로 맞춘 값을 근거 없이 사양으로 만든다. 덤프는 값마다 개체·열이 남아 다음 회차가 다시 재서 숫자로 대조한다(재발방지 #144 · #161 · #165).

- 판정 순서는 ①원본 코드 → ②규약 문서 → ③덤프다. 캡처는 그 뒤 마지막 눈 확인 한 장이고 스크래치패드에 둔다.
- 그림으로 원리적으로 안 읽히는 것(겹침·늘리는 방식(9슬라이스 vs 확대)·「0인가 못 읽었나」)은 덤프와 소스로 본다.

#### 그래도 캡처를 남겨야 한다면 — 상태를 같이 적는다

| 컬럼 | 무엇 / 비었을 때 |
|---|---|
| 파일명 | 공백·복사본 접미 금지 (「이름 1.png」) — 주소가 깨진다 |
| 화면 | 원본의 어느 화면인가 |
| 상태 | 진행도 · 보유 재화 · 선택 대상 · 활성 탭 — 비면 A/B 불가. 「상태 미기록」으로 적고 재촬영 대상에 남긴다 (「A/B 측정」) |
| 애니메이션 | 끝 상태를 강제했나 — 비면 한 프레임을 정색으로 오인한다 (오염 3갈래) |
| 근거 | 그리는 원본 코드 위치 — 비면 캡처가 유일 근거 = 오염 |
| 회차 | 어느 빌드의 캡처인가 |

애니메이션 화면은 끝 상태를 강제하고 찍는다(t=0 이면 「기능이 없다」로 오판한다). 커밋 여부는 프로젝트가 정하고, 커밋하면 `_대장.md` 가 회차를 갖는다.

### 에셋 등록은 양방향으로 감사한다

동기화 도구는 「파일 → 주소」만 보장한다. 반대 방향은 감사 3종으로 화면 완료 전에 돌린다.

| 항목 | 잡는 것 |
|---|---|
| 코드에 박힌 주소 리터럴 전수 → 등록 여부 | 이름이 어긋난 것 |
| 아트 파일명의 공백·복사본 접미 | 주소를 깨뜨리는 파일명 |
| 등록됐는데 파일이 없는 고아 | 지운 뒤 남은 것 |

- 파일을 만드는 생성기가 등록까지 책임진다.
- 주의: 감사기는 폴더 엔트리(예: `Enemies/normal`)와 폴더 접두어를 오탐한다. 디렉터리 예외를 넣고, 폴더면 실제 장수를 세고, 접두어는 Play Mode 로딩으로 확인한다.

사례: `Intro_start 1.mp4` 로 주소가 어긋나 `InvalidKeyException` 이 났는데 동기화 도구는 「제거 0 · 건너뜀 0」이었다.

### 원본 실측은 장면 그래프 덤프로 한다 — 스크린샷을 남기지 않는다

캡처는 원본을 여는 길이 되는지 확인할 때만 쓴다(「캡처는 쌓지 않는다」).

- 덤프 모양: 개체마다 한 줄, 열은 `id parent depth name x y sx sy alpha visible tint frame font text cx cy w h`.
- `frame`·`sx/sy`·`w/h` 는 셋 같이 읽는다(`분석로직.md` 「덤프의 열은 셋 같이 읽는다」).
- 덤프에 없는 생성자 인자(9슬라이스 인셋 등)는 소스에서 캔다. 못 캤으면 못 캤다고 적고 공식으로 지어내지 않는다(`재발방지` #161).

### 에디터를 못 돌려도 컴파일 판정은 된다

유니티 `.csproj` 는 포커스를 받아야 갱신되어, `dotnet build Assembly-CSharp.csproj` 가 새 파일을 빼고 「0 에러」로 통과한다. 에디터 없이 임시 프로젝트로 직접 컴파일한다.

```xml
<!-- 스크래치패드에 둔다. 프로젝트 안에 만들지 않는다 -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>netstandard2.1</TargetFramework>
    <EnableDefaultCompileItems>false</EnableDefaultCompileItems>
  </PropertyGroup>
  <ItemGroup>
    <Compile Include="<프로젝트>\Assets\Scripts\**\*.cs" />
  </ItemGroup>
  <ItemGroup>
    <Reference Include="UnityEngine.CoreModule">
      <HintPath><Unity설치경로>\Editor\Data\Managed\UnityEngine\UnityEngine.CoreModule.dll</HintPath>
      <Private>false</Private>
    </Reference>
  </ItemGroup>
</Project>
```

주의: `HintPath` 는 절대경로로 적는다. 엔진 프로젝트 파일의 상대경로를 복사하면 참조가 조용히 빠져 「그 API 가 없다」 오류가 난다.

| 잡는 것 | 못 잡는 것 |
|---|---|
| 문법 · 타입 · 누락된 `using` · 시그니처 불일치 | `UnityEditor.*` — 참조를 따로 건다 |
| 새로 추가한 파일 전부 | 패키지 의존 코드 — 그 DLL 을 참조에 추가한다 |
| 어셈블리 분리와 무관하게 전수 | 프리팹·에셋 참조 무결성 |

임시 프로젝트는 스크래치패드에 둔다(Transfer_Programmer 「검증 산출물을 유니티 프로젝트 안에 만들지 않는다」).

### 에디터가 열려 있으면 — 끄지 말고 다리로 시킨다

**에디터 작업의 기본 경로는 다리다.** 이 저장소는 `Tools/unity-batch.sh` 가 열린 에디터에 시키고, 재생 검사도 `PLAYMODE=1` 로 다리를 탄다.
이유: 배치모드가 필요한 이유는 같은 프로젝트를 두 인스턴스가 못 연다는 것뿐이다.

다리의 모양 (에디터 안에 지켜보는 스크립트를 상주시킨다):
1. 셸이 요청 파일을 쓴다(`{"id":…, "method":…}`).
2. 에디터가 틱마다 보다가 에셋을 새로고침한다(포커스 없이는 자동 새로고침이 안 온다).
3. 컴파일·임포트가 끝날 때까지 기다린다. 도메인 리로드 뒤에도 요청 파일이 남아 이어받는다.
4. 메서드를 실행하고 콘솔 로그를 잡아 응답 파일로 쓴다. 판정은 로그다.

- 요청·응답 파일은 `Temp/` 에 두지 않는다(재발방지 #38).
- 재생 검사기는 `SessionState "JinHyung.EditorBridge.Driving"` 이 참이면 `Exit` 대신 `ExitPlaymode` 로 끝낸다(재발방지 #140).
- 검사기는 시작할 때 `Application.runInBackground = true` 를 켠다. 안 켜면 포커스 없는 재생이 throttle 되어 「다리는 느리다」로 오판한다(재발방지 #156).
- 다리 스크립트의 첫 활성화만 재시작이 필요하다.

### 에디터 툴은 배치모드로 직접 실행한다 — 사람에게 메뉴를 누르라고 하지 않는다

배치는 에디터가 꺼져 있거나 `BRIDGE=0`·`BRIDGE_PLAY=0` 일 때의 예외 경로다(「에디터를 끄는 것은 예외다」). 원칙은 「사람에게 엔진 조작을 요구하지 않는다」(SKILL.md 「세 번째 목적이 나머지 둘의 완료 기준을 바꾼다」).

```bash
# 인자 없는 static 메서드를 헤드리스로 실행하고 로그를 파일로 받는다
<Unity실행파일> -batchmode -quit -nographics -silent-crashes \
  -projectPath <프로젝트> -executeMethod <Namespace.Class.Method> -logFile <로그>
```

순서 — 닫고 · 돌리고 · 연다:
1. 에디터 프로세스가 살아 있는지 본다.
2. 살아 있으면 저장 안 된 작업이 날아갈 수 있다고 알리고 승인을 받는다.
2-b. 재부팅 문구를 남긴다(「(예외로) 재부팅할 때는 항상 같은 문구를 남긴다」).
3. 정상 종료를 요청하고 프로세스가 실제로 사라질 때까지 기다린다(저장 확인 대화상자가 막을 수 있다).
4. 잔재 락파일이 남았으면 지운다.
5. 배치모드로 실행하고 로그를 파일로 받는다.
6. 다시 연다. 열기 전에도 같은 문구를 남긴다.

- 종료 코드만 믿지 않는다. 컴파일 에러에도 0이 나올 수 있다. 로그에서 `error CS` · `Exception` · 성공 문구를 같이 본다.
- 배치는 임포트를 동반해 느리다. 백그라운드로 돌리고 로그를 읽는다.

#### 재부팅 문구를 빠뜨리지 않는다

문구와 시점은 「(예외로) 재부팅할 때는 항상 같은 문구를 남긴다」에 둔다. 러너가 닫는 경로와 여는 경로에서 대신 찍게 만든다.

#### 배치 로그는 다음 실행이 지운다

임시 폴더의 로그는 다음 배치 시작 때 지워진다. 각 단계 출력을 실행 직후 갈무리하고, 여러 단계면 로그를 임시 폴더 밖에 쓴다.

#### 「성공 표시」와 「실패 표시」의 모양이 다르면 요약이 잘린다

성공 표식으로 결과를 잘라 내면 실패가 안 보이고, 줄 수를 자르면 마지막 요약(N/N)이 먼저 잘린다. 요약 줄은 따로 한 번 더 찍는다.

#### 비동기 에디터 API 는 `-quit` 전에 안 끝난다

요청만 거는 API(패키지 임포트 등)는 배치 종료와 함께 작업이 날아가도 성공 로그는 찍힌다.
- 「요청했다」가 아니라 생겼는지 같은 메서드 안에서 파일로 확인한다.
- 동기 API 나 직접 처리가 있으면 쓴다. 없으면 한 배치에서 요청하고 다음 배치에서 결과를 쓴다.
- 패키지 파일은 대개 gzip tar(`<guid>/pathname` · `<guid>/asset`)다. 직접 풀어 쓰는 것이 가장 결정적이다.

#### 입력 판정은 재생 안에서만 잰다 — 편집 모드 레이캐스트는 원리적으로 빈다

편집 모드에서는 캔버스가 안 그려져 그리기 깊이가 `-1` 로 남고 레이캐스터가 전부 건너뛴다. `-nographics` 를 빼도 같다.
- 대조군(사람이 눌러서 되는 모드 버튼 등)을 같이 쏜다. 그것도 안 맞으면 검사 환경 문제다.
- 재생 모드에서 실제 포인터 이벤트를 흘린다. 기본은 다리(`PLAYMODE=1`)다.
- 진단을 같이 찍는다: `raycastTarget` · 깊이 · `cull` · 부모 캔버스.
- 매니저를 직접 부르지 않는다. 레이캐스트 결과에 이벤트를 흘려야 배선 끊김·가로막힘이 걸린다.

배치로 재생에 들어갈 때(`BRIDGE_PLAY=0`):
1. `-quit` 을 뺀다(진입 메서드 종료와 함께 꺼져 재생이 시작되지 않는다).
2. `-nographics` 도 뺀다.
3. 진입 메서드는 씬을 열고 재생을 요청만 한다(안에서 기다리면 재생이 시작되지 않는다).
4. 재생 시작 훅에서 검사기를 심는다. 도메인 리로드를 넘는 저장소에 표시를 남긴다.
5. 검사기가 스스로 끝내고, 바깥에도 시간 제한을 건다.

#### 자동 검사에서 프레임 수로 기다리지 않는다

화면 없는 재생은 초당 수천 프레임이 돌아 「60프레임 대기」가 0.01초 수준이다. 틱·타이머·연출은 시간으로 기다리고, 실제 경과 프레임 수를 같이 찍는다.

### 하네스가 초기화를 대신할 때는 게임과 같은 호출로 한다

창이나 컴포넌트를 직접 만지면 진입 경로가 끊겨도 통과한다. 게임 코드가 부르는 그 한 줄(화면 전환 함수 등)을 그대로 부르고, 모르면 초기화 코드의 마지막 줄을 본다.

### 「영향이 없다」도 실측으로 확증하고 등재한다

「이 순서로 넣으면 변화 0」을 벡터로 등재한다. 안 보이는 상태도 그대로 옮긴다. 이유: 지우면 원본과 상태 기계가 갈려 나중에 어긋난 곳을 못 찾는다.

### 컴파일·툴 실행 순서

#### ⓪ 에디터가 재생 중이면 먼저 멈춘다 — 물어보지 말고 멈춘다

| 증상 | 원인 |
|---|---|
| `isCompiling=True` 고착 | 「Recompile After Finished Playing」으로 컴파일 보류 |
| 새 메뉴·새 타입이 안 뜬다 | 옛 어셈블리가 돈다 |
| 프리팹을 구워도 반영이 안 된다 | 재생 중 `AssetDatabase` 쓰기는 신뢰할 수 없다 |
| 하네스가 실행 중인 게임 상태를 갈아엎는다 | Client 「ⓕ 하네스는 사용자 세이브를 건드릴 수 없어야 한다」 |

```
[재생 멈춤]     ← 작업 시작 전에 무조건 한 번
```

- `[...]` 는 무엇을 하는가다. 무엇으로 되는지는 그 프로젝트의 「도구 제약」 표가 정본이고, 스킬 문서에 특정 도구 이름을 박지 않는다.
- 멈추는 것은 파괴적이지 않다. 재생 상태는 휘발이고 디스크 세이브는 남는다.

#### ⓪-b 「에디터가 새 코드를 안 먹는다」의 첫 번째 용의자는 컴파일 에러다

컴파일이 실패하면 유니티는 직전 어셈블리를 문다. `isCompiling=False` + 옛 DLL 이라 웨지와 같아 보이고 콘솔에 에러가 아직 없을 수 있다. `dotnet build` 가 바로 보여 준다.

더 사나운 얼굴: 도구가 옛 어셈블리로 정상 실행되어 성공 로그를 찍는데 결과가 낡았다.
- 판별법 ①: 이번에 바꾼 값(경로·스위치·개수)을 도구가 성공 로그에 찍게 한다.
- 판별법 ②: 도구를 돌린 직후 엔진 로그에서 컴파일 에러를 훑는다. 성공 로그와 컴파일 성공은 다른 사건이다(`재발방지 #176`).

```bash
# 엔진 로그 자리는 플랫폼마다 다르다
grep -E "error CS" <엔진 로그> | tail
```

순서를 고정한다.

```bash
dotnet build Assembly-CSharp.csproj -nologo -v q          # 항상 여기부터 (런타임 csproj)
dotnet build Assembly-CSharp-Editor.csproj -nologo -v q   # (에디터 csproj)
```

| 관찰 | 뜻 |
|---|---|
| `dotnet build` 에러 있음 | 컴파일 에러. 웨지가 아니다 |
| `dotnet build` 0 에러 + 옛 DLL + `isCompiling=False` | 진짜 웨지 — 에디터 창 클릭이 필요하다 |
| `isCompiling=True` 고착 | 재생 중(⓪)이거나 포커스 대기 |

- 0 에러 확인 전에는 에디터를 의심하지 않는다. 컴파일 검증은 에디터를 기다리지 않고 바로 돌린다(프로젝트는 한 번에 하나).
- 0 에러는 파일이 맞다는 증명일 뿐이다. 재생·측정 전에 로드된 어셈블리에 새 멤버가 있는지 리플렉션으로 찍는다.
- 에디터 툴 실행은 `새로고침 → 컴파일 완료 확인 → 메뉴 실행 → 콘솔 확인`. 컴파일 전에 돌리면 옛 어셈블리가 실행된다.
- 웨지는 `AssetDatabase.Refresh` + `RequestScriptCompilation` 으로 안 풀리고 에디터 창을 한 번 클릭해야 한다. 판별: 읽은 상수 배열 길이가 소스와 다르면 옛 어셈블리다.
  ```csharp
  return Generator.Ratios.Length;   // 소스는 7인데 5가 나오면 리로드 안 된 것
  ```
  급하면 같은 수식으로 외부(파이썬 등)에서 굽고 나중에 에디터 툴로 재생성한다.
- `AddObjectToAsset` 은 재임포트로 앞서 채운 리스트를 되돌린다. 서브에셋을 먼저 붙여 저장하고, 데이터를 채운 뒤 `SetDirty` + `SaveAssetIfDirty(asset)` 로 확정한다.
- 아이콘 생성기는 텍스처 메모리 매핑 중 IO 예외로 뒤 전부를 안 굽는다. 내용이 같으면 건너뛰고, 실패하면 재시도하고, 그래도 안 되면 경고한다.
- 빌드 중 NRE 를 넘기지 않는다. `AddComponent` 뒤 참조 주입이면 굽는 시점 `Awake` 가 null 을 만진다. `Awake` 에 null 가드를 넣어 경고 0을 완료 기준으로 쓴다.

### 점수를 믿기 전에

- 헤드리스 캡처는 색 프로파일로 원본 PNG 보다 밝을 수 있다. 점수가 낮으면 원본 에셋과 직접 대조한다.
- 기준 캡처가 렌더 전 상태일 수 있다. 원본 코드가 실제로 그리는 것을 만들어 빈 자리에 넣는다.
- 캡처에서 읽어낸 것을 사양으로 삼지 않는다(판정 순서는 「캡처는 쌓지 않는다」). 글자·숫자·라벨은 DOM/JS 문자열에서 확인한다.
- 직관과 반대인 값도 원본과 같으면 맞다. 원본에서 같은 상태를 만들어 같은 값이 나오는지 확인한 뒤 판단한다.

## 사람에게 엔진 조작을 요구하지 않는다

**이관을 의뢰한 사람은 코딩도 엔진도 모를 수 있다.**

| 하지 않는다 | 한다 |
|---|---|
| 「메뉴에서 이걸 눌러 주세요」 | 러너로 직접 실행 |
| 「인스펙터에서 지정해 주세요」 | 에디터 API 로 코드가 지정 |
| 「프리팹을 만들어 주세요」 | 빌더가 초안을 굽고, 이후엔 에디터 API 로 프리팹을 고친다 (확정표 10-b) |
| 「패키지를 설치해 주세요」 | 매니페스트를 직접 고친다 |

- 사람에게 남기는 것은 ① 원본을 건네주기 ② 마지막에 열어서 보기, 둘뿐이다.
- 비개발자 의뢰가 품질을 낮출 이유가 되지 않는다. 기준은 우리가 지킨다.

### 에디터를 끄는 것은 예외다

| 언제 | 경로 |
|---|---|
| 에디터가 열려 있다 (보통) | 다리 |
| 재생 검사 | 다리 (`PLAYMODE=1`), 검사기는 `ExitPlaymode` 까지만 |
| 에디터가 꺼져 있다 · `BRIDGE=0` · `BRIDGE_PLAY=0` | 배치 |

- 끄는 것은 빌드처럼 배치가 필수일 때뿐이다.
- 끌 때는 러너가 ① 저장 후 정상 종료를 시키고 ② 응답이 없을 때만 강제 종료하고 ③ 열기 전에 복구 백업을 치워 「_recovery backup scene?」에 No 를 대신 누른다. 이유: 강제 종료(`taskkill`)하면 복구 대화상자를 사람이 눌러야 한다.
- 주의: 다리로 돌 때 검사기가 에디터 프로세스를 끄면 이 전부가 무너진다(재발방지 `#140`).

### (예외로) 재부팅할 때는 항상 같은 문구를 남긴다

문구: `유니티를 재부팅 중입니다. 기다려주세요.` (`Tools/unity-batch.sh` 가 찍는 문구)
이유: 사람은 화면이 사라진 것만 보고 「멈췄나」로 읽는다.

| 언제 | 무엇 |
|---|---|
| 닫기 전 | 문구 + 저장 안 된 작업이 사라진다는 경고 |
| 다시 열 때 | 문구 |
| 여러 단계를 이어 돌릴 때 | 마지막 단계에서만 연다 (중간에 열면 락에 막힌다) |

말없이 프로세스를 죽이지 않고, 이름으로 죽이지 않는다. 같은 엔진으로 연 다른 프로젝트가 함께 죽는다(`재발방지` #75).

## 재기 전에 「이 원본이 같은 답을 내는가」부터 잰다

정답지·A/B·창 대조는 「같은 입력 → 같은 결과」를 전제한다.

1. 대표 입력을 n≥3 회 돌린다(2회로는 못 가른다).
2. 갈리면 첫 갈림 지점을 본다. 그곳이 비결정의 씨앗이다.
3. 갈리는 입력은 「비결정」으로 분류해 정답지에서 뺀다. 지우지 않는다.
4. 제외 건수를 리포트에 찍는다.

- 웹 원본은 프레임 간격이 고정이 아니어서 갈린다. 연쇄가 길수록 증폭되니 짧게 결판나는 입력을 고른다.
- 비결정을 면죄부로 쓰지 않고 빈도를 같이 잰다. 원본 10회 중 9회 성공에 우리 0회면 우리 결함이다.

## 원본을 여는 도구를 먼저 고른다 — 도구가 입력을 바꿔 버린다

| 함정 | 증상 | 대책 |
|---|---|---|
| 에디터 내장 브라우저(CDP)는 단발 클릭만 전달 | 누르고 있기가 0 ms 로 압축돼 홀드·드래그 입력이 안 들어간다 | `mouse.down()` → 대기 → `mouse.up()` 이 실제 시간으로 가는 외부 자동화로 연다 |
| 게임 프레임 직접 접속 | 핫링크 차단으로 흰 화면·오류 | 서비스 페이지째로 열고 프레임을 전수 순회해 찾는다 |
| `file://` | 정적 스냅샷 (「`file://` 은 정적 스냅샷이 될 수 있다」) | 로컬 HTTP 서버로 연다 |

도구가 되는지는 착수 때 한 번 찔러 보고 확정표 13 에 적는다.

## 런타임에서 직접 캐내는 법 — URL 제공형 심화

「런타임을 찔러 오브젝트 좌표를 읽는다」(`PD.md`)의 다음 단계다. 좌표로 안 풀리는 물음(언제 무엇을 했나 · 자산의 원래 색·모양 · 도달할 수 없는 입력값 · 무작위의 경계)은 관찰을 늘리지 말고 보는 자리를 바꿔 푼다.

### ⓪-a 먼저 열어서 해 본다 — 소스를 읽는 것이 플레이를 대신하지 않는다

URL 로 온 원본은 심판이다(`PD.md` 「원본 형태 판정」).

| 언제 | 무엇부터 |
|---|---|
| 사람이 증상을 말했다 (「깜빡인다」·「이상하다」) | 원본을 열어 같은 자리를 해 본다. 그다음 소스 |
| 사람이 값을 물었다 | 소스·덤프 |

- 증상은 사양인지 결함인지부터 가른다. 원본에도 있으면 사양이다(`#170`).
- 게임은 대개 교차 출처 iframe 이라 바깥에서 JS 훅·픽셀 읽기가 안 되고, 프레임 URL 직접 접속은 막힌다. 서비스 페이지로 열어 키·클릭과 눈 확인으로 증상을 가른다.
- 값은 ⓪ 번들을 받아 읽고, 자산은 파일 URL 로 받아 바이트로 잰다(`#169`).
- 「플레이로 증상 가르기」 → 「소스로 규칙 캐기」 → 「우리 화면 재서 대조」는 서로 대신하지 않는다.

### ⓪ 번들 소스를 받는다 — ①~⑤ 전부보다 먼저

「언제·왜」는 PD 「번들 소스를 받아 읽는다」.

| 단계 | 어떻게 |
|---|---|
| 스크립트 URL 수집 | 게임 프레임 안에서 `performance.getEntriesByType('resource')` 로 `*.js` 를 모은다. 동적 `import()` 청크는 한 판을 돈 뒤 다시 모은다 |
| 프레임 안에서 받는다 | 게임 프레임 컨텍스트에서 `fetch` 하고(다른 출처면 차단) 청크 이름·해시 그대로 로컬에 저장한다 |
| 앵커 grep | 관측한 값·문자열(목표 배열 · 로케일 키 · 개체 이름 · 텍스처 이름)을 찾는다. 매치 앞뒤 2~3KB 가 그 시스템의 클래스다 |
| 이름 복원 | 난독화 이름은 구조로 읽고 `99_원본지도.md` 소스 지도에 적는다 |
| 기록 | 「원본 위치」 = `[소스] <청크>:<앵커>`. 줄번호는 적지 않는다 |

- 에셋은 받지 않는다. 규칙만 읽는다(저작권).
- 소스가 있어도 실측은 남긴다. 둘이 갈리면 번들 버전 차이를 먼저 의심한다(그래서 청크 해시를 기록한다).
- 관측치와 맞물린 앵커 없이 숫자를 줍지 않는다.

### ① 순서·횟수는 후킹으로 읽는다 — 관찰로는 못 간다

시계열 관찰로 반영하면 가설을 코드에 박는다. 엔진 메서드를 감싸(prototype/속성 교체) 호출 시각·인자·횟수를 기록한다.
- 한 틱 안의 실행 순서(시뮬레이션 → 이벤트 실행인가 반대인가).
- 한 프레임의 실행 횟수(고정 스텝 · 누적기 · 따라잡기).
- 인자(스텝 간격이 프레임 간격 그대로인가, 클램프가 걸리나).

후킹은 「무엇을 했나」에 답하고 원본을 바꾸지 않는다(원래 함수를 그대로 부른다).

### ② 색·모양·크기는 소스 자산을 꺼내서 잰다

화면 색 = 자산 색 × 런타임 착색이다. **원본 이미지 파일을 내려받아 파일 바이트를 읽는다.** 아틀라스(`main.png` 등)는 Pillow 같은 파일 디코더로 열고 좌표는 `main.json` 에서 얻는다. 브라우저는 「어디에 무엇이 있나」까지만 쓴다.

| 하지 않는다 | 한다 |
|---|---|
| 캡처에서 색을 집는다 | 소스 텍스처를 꺼내 픽셀을 센다 |
| 캔버스 `getImageData` 로 뜬다 | 파일 바이트를 읽는다 — 캔버스는 저알파 RGB 를 왜곡한다 (`재발방지 #169`) |
| 알파를 있다/없다로만 뜬다 | 알파를 색과 별개의 축으로 뜬다 (`재발방지 #167`) |
| 반경별 알파 평균으로 모양을 판단 | 마스크를 그려서 본다 |
| 굽고 끝낸다 | 구운 결과를 소스와 픽셀 대조(IoU)해서 닫는다 |

- 단색 마스크로 나오면 결과 색을 여러 벌 굽지 말고 착색 기전을 옮긴다.
- 인스턴스가 0이면 클래스에도 자산 목록이 없다. 사건 목록(성공 · 실패 · 전환 · 최초 진입)을 만들고 사건 프레임 훅으로 참조를 붙잡아 사라진 뒤 꺼낸다.
- 가속 캔버스는 픽셀 읽기가 전부 0일 수 있다(읽을 수 없는 것이지 검은 화면이 아니다). 그때는 스크린샷으로 잰다.
- 다 굽고 나면 원본 파일과 바이트 단위로 같은지로 닫는다. RGB 나 알파 한쪽만 보면 다른 쪽이 틀린 채 100% 가 나온다(`#167` · `#169`).

#### 자산은 네 단(段)으로 뜬다 — 어디까지 갈지는 사람이 정한다

**어느 단까지 갈지는 정책이다.** 착수 질문으로 묻고 확정표에 적는다.

| 단 | 무엇을 뜨나 | 닫히는 것 | 열려 있는 것 |
|---|---|---|---|
| 1 | 존재·주소 | 빠진 자산 | 크기·모양·색 |
| 2 | 규격 — 시트/컷 크기 · 컷 수 · fps · 표시 배율 | 컷 수·크기 | 그림 자체 |
| 3 | 형태·색 — 실루엣 마스크 · 팔레트(색+비중) · 채움률 | 윤곽과 색조 | 안을 무엇으로 칠했나 |
| 4 | 픽셀 배치 — 팔레트 인덱스맵 | 그림이 같은가 | 없음 |

- 3단 만점이어도 픽셀은 틀릴 수 있다(「대조 항목은 원본이 가진 최소 단위에서 고른다」).
- 작은 스프라이트(≤32px)는 3단과 4단 사이에 중간이 없다.
- 4단으로 갔으면 「재제작」이라는 말을 쓰지 않고 의도된 차이 목록에서 그 줄을 지운다.
- 사람이 정한 것을 측정으로 뒤집지 않는다. 측정은 보고하고 결정을 따른다(재발방지 #184).

### ③ 입력값은 대리 축으로 겨냥하지 말고, 실제 값을 폴링해서 끊는다

```
하지 않는다: 누른 시간 T 를 계산해서 T 만큼 누른다      → 도달 값이 흔들린다
한다:        누르는 동안 실제 값을 매 프레임 읽다가      → 원하는 값에서 끊는다
             목표에 닿는 순간 입력을 끝낸다
```

- 되먹임 보정에는 이상치 게이트가 필수다. 포화 표본 한 발이 뒤 시행을 망친다.
- 도달 값이 이산 격자일 수 있다. 격자 사이 값은 「도달 불가」이고 정답지 값을 격자 위로 옮긴다. 격자의 시작·간격을 먼저 잰다.

### ④ 무작위는 경계를 직독한다 — 표본으로 유도하지 않는다

엔진이 파라미터를 식으로 들고 있으면 수천 번 호출해 최소·최대와 서로 다른 값의 개수(distinct)를 센다.
min/max 만 보면 오독한다. −100~+100 에 흩어져도 distinct 가 2 면 둘 중 택일이다.

### ⑤ 그 전에 — 저작값이 적혀 있는지부터 본다

①~④ 는 저작값을 못 찾았을 때 쓴다. 이벤트 시트 · 스크립트 · 씬 데이터에 적힌 상수가 답이고 부호·단위까지 나온다. 실측값을 시트 상수와 교차 확인해 오귀속도 잡는다.

### ⑥ 사건 프레임 덤프 — 스크린샷 대신 그 프레임의 값을 뜬다

규격은 `분석로직.md` 「frames/ · motion/ · paths.md」.

| 단계 | 어떻게 |
|---|---|
| 기록기 | 후킹으로 루트를 잡고 rAF 마다 가벼운 상태(표식 문구 · 주인공 좌표/틴트/알파 · 개체 수 · 포인터)를 읽는다 |
| 사건 판정 | 표식 묶음(문구 집합 + 틴트 + 개체 존재)을 한 줄 키로 만들고 키가 바뀌면 전체 덤프. 고정 시각(3·12·30·60s…)도 몇 개 |
| 전체 덤프 | 노드마다 `getGlobalPosition` · `worldTransform`(배율) · `worldAlpha` · 가시성(부모 사슬) · 텍스처 이름(아틀라스 사각형 역추적) · 문구 · 폰트 크기 → TSV 한 줄. 보이는 것만 들여쓰기 트리로 |
| 시계열 | 움직이는 값(주인공·카메라·버튼 배율)은 매 프레임 한 줄. 앵커는 프레임 수 |
| 봇 | 사람이 하는 조작만 — 위협 회피 › 보석 › 포인터 목표. 창은 사람처럼 누른다(카드 → 선택, 부활, 확인). 경로 분기(「첫 사망에 거절」)는 인자로 준다 |
| 저장 | 20초마다 파일로 내려 쓴다 |

- 움직이는 것은 두 번 플레이한다. 첫 플레이로 주기를 재고, 두 번째에 주기로 계산한 프레임 수만큼 뜬다. 10 프레임은 밑바닥이지 기준이 아니다(`분석로직.md` 「두 번 플레이한다」).
- 우리 쪽도 재생 검사기가 같은 사건에서 원본 논리 좌표로 떠 `frames/` 와 줄 단위 diff 한다. 이미지 비교는 그 뒤 눈 확인이다.

#### 덤프는 도달한 상태만 준다 — 그래서 도달을 설계한다

조건부 개체·상태는 거기까지 가지 않으면 안 보이고 이관율에도 안 잡힌다(`재발방지` #130).

1. 소스의 상태 전환(모드·퀘스트 단계·화면 전이)을 `grep` 해 상태 목록을 전수로 만든다. 관측으로 세지 않는다.
2. 상태마다 도달 방법(조건 · 걸리는 시간 · 선행 상태)을 한 줄 적는다.
3. 봇이 그 경로를 밟게 한다. 도달 못 한 상태는 「없음」이 아니라 미측정이다.
4. 실패하면 정지 여부 · 남은 거리 · 체력 · 경과를 같이 찍는다.

- 봇은 게임을 멈추는 창(레벨 업·부활·보상)을 치운다. 안 누르면 시뮬이 한 틱도 안 돈다.
- 같은 코드로 두 번 돌린 결과가 다르면 도달을 먼저 본다(`재발방지` #147).
- 맞추는 값은 앵커 좌표가 아니라 경계 상자(중심 cx, cy · 크기 w, h)다. 글자는 글리프 경계로 재고 서체가 다르면 높이만 본다.

| 무엇 | 허용 오차 (예시 — 프로젝트가 정한다) |
|---|---|
| 중심 좌표 | ±1.5 논리 px |
| 크기 | ±6% (글자는 높이만 ±20%) |
| 알파 · 실효 글자 크기 | ±0.02 · ±8% |
| 문구 | 정확 (숫자는 자릿수까지 지우고 비교) |

### 대조 항목은 원본이 가진 최소 단위에서 고른다

**주 지표는 결과물의 최소 단위다** — 그림이면 픽셀, 글이면 글리프, 배치면 좌표.
윤곽·색 목록·개수처럼 잴 수 있는 것은 부분 지표로 이름 붙이고, 부분 지표 하나로 통과 판정하지 않는다.

- 지표를 만들 때 「이 값이 100% 인데도 원본과 다를 수 있는 경우는?」을 한 줄 적는다. 못 적으면 판정에 쓰지 않는다.
- 「완료」라고 말하기 전에 원본과 나란히 한 번 본다. 눈으로 다른데 100% 면 지표를 고친다.

사례: 실루엣 IoU·팔레트 거리 만점으로 완료 보고했는데 픽셀로 재니 13~34% 였다.

### 채록 위생 — 이것 때문에 회차가 날아간다

| 규칙 | 이유·방법 |
|---|---|
| 얕은 덤퍼 + 관심 개체만 + 중간 저장 | 무필터 전 프레임 채록은 메모리 한계로 죽어 회차가 유실된다 |
| 앵커는 시각(ms)이 아니라 프레임 수 | 프레임 수는 안 흔들린다 |
| 극값은 보간 꼭짓점으로 | 프레임 샘플 최대값에는 샘플링 위상이 섞인다 |
| 같은 입력을 n≥3 회 | 「재기 전에 「이 원본이 같은 답을 내는가」부터 잰다」 |
| 원본지도의 함정은 프로브 공통 조각으로 굳힌다 | 가시성 판정(부모 사슬의 visible·alpha)을 한 함수로 두고 모든 프로브가 지난다 (재발방지 `#132`) |
| 시계열 대조 전에 둘의 0시를 맞춘다 | 원본은 심은 순간, 우리는 전투 시작부터 센다. 사건 프레임 시각만큼 민다 |
| 파일 이름에 사건 라벨을 그대로 쓰지 않는다 | `?` · `:` 로 윈도 파일 쓰기가 터진다. 라벨은 파일 첫 줄에, 이름은 금지문자를 바꾼다 |
| 양쪽 덤프가 같은 항목을 뜨는지 먼저 맞춘다 | 열 이름·단위·기준점(중심/앵커)을 표로 못 박고 양쪽 덤퍼가 지난다. 한쪽에만 있는 열은 영원히 대조되지 않는다 |
| 우리 쪽 덤프는 원본 화면비에서 뜬다 | 배치 재생 기본 게임 뷰는 4:3 이다. 재생 전에 해상도를 못 박고 첫 줄에 화면 크기와 논리 폭을 찍는다 |
| 경계 상자는 네 귀 전부로 | 돌아간 것을 대각 두 귀로 재면 폭이 반이 된다 |
| 덤프는 마우스 없는 상태를 잰다 | 이벤트 시스템을 끄고 뜨기 직전에 호버를 내린다 (재발방지 `#147`) |
| 판마다 다른 것과 틀린 것을 갈라 적는다 | 씨앗·진행으로 자리가 바뀌는 개체(나무·적·보석·팝업)는 크기와 존재만, 난이도 곡선은 시계열로 본다 |
| 관측 최솟값은 값이 아니라 하한 | `≥ N [관측 하한]` 으로 적고 소스·후킹으로 닫는다 (재발방지 `#134`) |

## 원본 코드에서 답 찾는 법

함수명·CSS 클래스명은 원본마다 다르다. 모양만 쓰고 이름은 그 원본의 것으로 바꾼다.

```bash
# 화면/함수 찾기
grep -n "function drawBay\|function drawSpaceWindow" 원본.html
# CSS 규칙
grep -n "^\.collect-chip\|^\.stat{" 원본.html
# 화면이 부르는 draw 트리를 재귀적으로 끝까지 편다
grep -n "function drawBay" -A 12 원본.html
# 그리기 파라미터를 전수로 뽑는다 (연출 필수)
grep -n "lineWidth\|shadowBlur\|globalAlpha\|globalCompositeOperation" 원본.html
# 메인 루프의 게이트 조건 (클라 필수)
grep -n "_loopBody\|requestAnimationFrame" -A 6 원본.html
```

### 문서의 라인 번호를 믿지 마라

기획서·플레이북의 라인 번호는 작성 시점 기준이고 오프셋이 구간마다 달라(앞 +7, 뒤 +103 식) 일괄 보정이 안 된다. 항상 grep 으로 확정한다.

### 실측 지도 — 학습 단계에서 그 프로젝트의 것으로 만든다

구간 → 담당 표를 한 번 만들고 인용할 때마다 갱신한다. 표는 그 프로젝트 원장에 두고 여기에는 특정 원본의 라인을 적지 않는다.

| 구간 | 적을 것 |
|---|---|
| CSS 전량 | 시작~끝 라인 · 규칙 수 (UI/UX 치수) |
| DOM 구조 | screen 단위 · 오버레이 목록 (화면 수의 분모) |
| 모듈 계약 | 전역으로 노출하는 객체 (인터페이스 경계) |
| 스탯 계산 본체 | 파생 스탯 함수. 수치 환원의 중심이라 표시해 둔다 |
| 단계·누적 보정 | 스테이지/방치/메타 보정 함수 (계산 순서가 결과를 가른다) |
| draw 계열 | 유닛·적·발사체 그리기 (연출 진입점) |
| 스프라이트 캐시 | 원본이 미리 굽는 자리 (우리도 굽는다) |
| 생성 · 피격 · 사망 | 전투 상태 전이 3점 |
| 상한·공간분할 상수 | 개체 수 캡·셀 크기 (A/B 개체 수 기준) |
| 메인 루프 | `dt` 클램프 · 정지 게이트 조건. 한 줄씩 옮긴다 |
| 합성 정책 | `globalCompositeOperation` 이 바뀌는 지점 전부 |
| 화면 전환 · 재화 갱신 | 플로우 diff 기준점 |
| 표기 테이블 | 수치를 문자열로 바꾸는 규칙 |
| 치트·디버그 훅 | A/B 상태 맞추기용 |
| 저장 스키마 | 세이브 구조, 상태 주입의 계약 |

주의: 원본 id·변수명이 화면 이름과 어긋난 경우가 흔하다(예: `#hangar`). 그리는 내용으로 판정하고 어긋난 쌍은 즉시 지도에 적는다.
