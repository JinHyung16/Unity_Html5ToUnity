# 07 기대값 — Client

상태: 학습 끝 · 실행 단계 (2026-09-21) — 원본 해시 대조 22/22 · 재생 흐름 210/210

정답지의 유일한 자리다. 값마다 `[소스] <청크>:<찾을 글자>` 또는 `[실측]` + 재현 방법을 붙인다.
`n` = 잰 횟수. `-1` = 소스 직독. `n=1` 은 표본이지 정답이 아니다.

## 정답지 — 원본 시뮬을 돌린 틱 해시

2026-09-17 기준 `FrontWarsDeterminismCheck` 22/22 검사 통과 (시나리오 13개 · 해시 · 결과 대조 포함).

- ⚠ 봇 이름이 해시를 바꾼다 — 원본은 플레이어 이름 해시로 고립 조각 검사 박자를 정한다. 원본 실행에도 우리 봇 이름 표(`FrontWarsBotNameTable`)를 끼워 넣고 정답지를 다시 만들었다 (처음엔 2명씩 팀전만 520틱에서 갈렸다).

- 해시 = 1 + Σ 플레이어 해시(id) × (병력 + 칸 수) + 유닛 해시. 사람만 있는 판은 해시에서 병력 + 칸을 역산할 수 있다 — 1000틱 뒤 121,370 (병력 121,318 + 칸 52).
- 유닛 해시에 유닛 칸 · 종류 · id 가 들어가므로 건물 · 배 · 핵 경로가 어긋나도 갈린다. 사람 명령(intent)이 들어간 판도 대조했다 — `human_play` 는 스폰 · 공격 · 건설 명령을 원본과 같은 턴에 같은 칸으로 넣고 100/100 일치했다.

## 갈래

| 갈래 | 뜻 | 채점 |
|---|---|---|
| 정답지 | 원본이 같은 입력에 같은 답을 낸다 | 센다 |
| 비결정 | 원본 자신이 갈린다 (n≥3 으로 확인) | 빼되 「제외 N건」 을 찍는다 |
| 미측정 | 아직 안 쟀다 | 빼지 않는다 |

- 싱글 판은 시드가 판마다 달라 봇 이름·위치가 바뀐다 `[실측]` (두 판의 1위 이름이 다름). 라이브 사이트에서 시드를 고정하는 방법은 아직 안 잼. 턴 대조(합격 기준 3)는 원본 번들을 node 에서 같은 게임 id 로 돌려서 한다 (위 「원본 시뮬을 돌린 틱 해시」).
