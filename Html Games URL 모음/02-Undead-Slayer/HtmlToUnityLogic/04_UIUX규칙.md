## ★★ 좌표계 · 논리 해상도 — **해소 (확정표 3-d)**

**원본은 «세로 580 고정 · 가로는 화면비만큼 확장»이다.** [실측 · 회차 1]

Pixi 씬 그래프의 **루트 컨테이너 scale** 이 렌더러 높이에 따라 바뀐다 — **`scale = 렌더러높이 / 580`**.
가로 scale 도 같은 값이라 **균등 스케일**이다(찌그러지지 않는다).

| 렌더러 크기 [실측] | 루트 scale [실측] | 검산 `h / 580` |
|---|---|---|
| 1031 × 580 | 1 (변화 없음 → 전수에 안 잡힘) | 580/580 = 1 |
| 836 × 470 | **0.8103448275862069** | 470/580 = 0.8103448275862069 ✅ |
| 640 × 360 | **0.6206896551724138** | 360/580 = 0.6206896551724138 ✅ |

→ **설계 논리 높이 = 580**. 16:9 일 때 설계 폭은 `580 × 16/9 = 1031.1 ≈ 1031` 로 실측 캔버스와 일치한다.

### Unity 환산 (확정표 3 = 1920×1080)

| 항목 | 값 | 근거 |
|---|---|---|
| **세로 환산 배율** | **1080 / 580 = 1.8620689655…** | 위 규칙 |
| 가로 배율 | **계산하지 않는다** — 화면비가 정한다 | 원본이 세로만 고정한다 |
| **확정표 3-b (Canvas Screen Match)** | **Match Width Or Height · Match = 1 (Height)** ← **이 실측에서 파생 확정** | 원본 불변식이 «세로 고정»이다. Match=0(Width)이나 Expand 를 쓰면 화면비가 달라질 때 **원본과 갈린다** |
| 게임 카메라 | **직교 크기를 세로로 고정**하면 원본 거동이 자동으로 나온다. 원본 단위 1:1(PPU 기준)로 두면 **ortho size = 290** (= 580/2) | Blumgi 선례와 같은 구조 |

⚠ **미측정 — 16:9 가 아닌 캔버스는 관측하지 못했다.** Poki 는 뷰포트를 1600×900 · 1280×720 ·
1024×768 · 800×600 · 900×1600 으로 바꿔도 게임 iframe 을 **항상 16:9**(1031×580 / 836×470 / 640×360)로 만든다.
따라서 「가로가 화면비만큼 확장된다」는 **루트 scale 이 높이로만 정해진다는 사실에서 나온 추론**이고,
**넓은/좁은 화면에서 실제로 무엇이 더 보이는지는 못 봤다.** → 재측정 대기.

⚠ **카메라 컨테이너에 별도 zoom 이 있다 — 미측정.** 루트 아래 깊이 5 의 컨테이너가
`1.0240`(1031폭) · `1.0138`(836폭) · `1.0147`(640폭) 로 **단조가 아니게** 흔들린다.
고정값이 아니라 **동적 줌**(전투 상황·개체 수에 반응)일 가능성이 있다. 깊이 4 컨테이너는 **0.95 고정**.
