# 04_UIUX규칙 — Blumgi Bounce

**원본 형태: URL 제공형.** 단 **블랙박스가 아니다** — 게임 iframe 안에서 Construct 3 런타임이
`window.c3_runtimeInterface._localRuntime` 로 그대로 읽힌다 [실측]. 2026-08-29 UIUX 회차.

> ★ 이 문서의 좌표·크기는 **캡처 눈대중이 아니라 런타임 인스턴스 조회값**이다.
> C3 의 `worldInfo.GetBoundingBox()` → `layer.LayerToCanvasCss()` 로 **캔버스 CSS 픽셀**까지
> 엔진이 직접 환산해 준 값을 받아 적었다. 화면 캡처는 **교차 확인용**으로만 썼다.

**재현** — 스크래치패드 `uiux_rt3.mjs` (`out_rt3/`) · **2회차 `uiux_rt4.mjs`(`out_rt4/`) · `uiux_rt5.mjs`(`out_rt5/`)**.
`channel:'chrome'` headless · 뷰포트 1280×720 · `https://poki.com/kr/g/blumgi-bounce` → 18초 대기 →
게임 프레임(`*.gdn.poki.com/**/index.html`)에서 `c3_runtimeInterface` 조회 → 인스턴스 전수 덤프 →
iframe 박스(167,16,836×470) 클립 캡처. 인게임은 (0.31,0.34) 클릭 후 5.5초.

> ★★ **2회차에 「레벨 귀속」 문제가 기계적으로 풀렸다** [실측].
> `인스턴스._worldInfo._layer._layout._name` 이 **`"W1L1"`·`"W1L2"`… 그대로 나온다.**
> 콘솔 `Level_Started` 이벤트(2.2초 지연)를 기다릴 필요가 없다 — **덤프 자체가 자기가 어느 레벨인지 말한다.**
> 2회차의 모든 레벨 표는 **덤프 안의 `layout.name` 으로 귀속을 확인한 것**이며,
> 실제로 파일 이름과 어긋난 회차가 있었다(홀드 600ms 가 W1L3 를 그 시점에 못 깼다) — **파일명이 아니라 `layout.name` 을 믿는다.**

### 1-c. 1920 × 1080 환산 배율 (확정표 3-d 제안 — 확정은 PD)

**환산 배율 = 1080 / 1280 = `0.84375`** (world → Unity px). 세로가 심판이다.

```
UnityPxY(위 기준) = worldY * 0.84375                       // worldY 0~1280 → 0~1080
UnityPxX(좌 기준) = (worldX + 497.7778) * 0.84375          // worldX -497.78~1777.78 → 0~1920
역변환           : worldX = UnityPxX / 0.84375 - 497.7778
```

검산 — 1777.7778 world → `(1777.7778+497.7778)*0.84375 = 1920.0` ✓ · 1280 world → `1080.0` ✓

| 기준 해상도 후보 | 세로 | 가로(16:9 world) | 배율 | 평가 |
|---|---|---|---|---|
| **A. 1920 × 1080** (확정표 3) | 1080 | 2275.556 world | **0.84375** | 확정표대로. 다만 **블록 한 칸 50 world = 42.1875 px** — 4의 배수가 아니다 |
| **B. world 단위를 그대로 쓴다** (권장 — 게임플레이 레이어) | 1280 | 2275.556 | **1.0** | 원본 수치를 **하나도 환산하지 않고** 레벨 데이터·물리·골든 벡터에 그대로 쓴다. 카메라는 Orthographic, 세로 1280 world 고정 |
| C. 2560 × 1440 | 1440 | — | 1.125 | 블록 56.25 px — 역시 4의 배수 아님 |

> **★ PD 확정 요청 ①** — **UI 캔버스(1920×1080, 배율 0.84375)와 게임 월드(world 1:1, 배율 1.0)를 분리**할 것을 권한다.
> 원본이 이미 그렇게 되어 있다 — 아래 1-d 의 「UI 레이어는 레이아웃 스케일을 안 탄다」가 그 증거다.
> 게임 월드까지 0.84375 를 곱하면 레벨 좌표·물리 상수·골든 벡터가 전부 **환산값**이 되어
> 원본과 수치 대조가 불가능해진다 (UIUX.md 「환산 상수는 한 곳에서만」).

### 1-e. 앵커 규칙 — 좌표를 픽셀로 굽지 않는다 [실측]

`UI` 레이어는 **확장된 뷰포트에 앵커된다.** 오른쪽 끝 world X = `1778.383`(측정 캔버스 기준) 일 때:

| 요소 | world x | 오른쪽 끝에서 | Unity(1920) 오른쪽 끝에서 |
|---|---|---|---|
| 🏠 홈 | 1718.38 | **−60** | 50.6 px |
| ⠿ 맵 | 1618.38 | **−160** | 135.0 px |
| 🔊 사운드 | 1518.38 | **−260** | 219.4 px |
| ↺ 재시작 | 1418.38 | **−360** | 303.8 px |
| Blumgi 로고 | 1598.38 | **−180** | 151.9 px |

⇒ **버튼 4개는 「오른쪽 정렬 · 간격 100 world(84.375 px) · 각 100×100 world(84.375 px²)」다.**
`WORLD n` 텍스트와 레벨 도트는 반대로 **레이아웃 가운데(x=640)** 기준이다 — 화면 중앙이 아니라 **설계 폭의 중앙**인데,
스크롤이 640 정중앙이라 **결과적으로 화면 중앙과 같다.**

⚠ **화면비가 넓어져도 버튼은 오른쪽에, 텍스트는 중앙에 붙는다.** 고정 x 로 구우면 1920 이 아닌 화면에서 전부 어긋난다.

### 1-f. ★ PD 확정 요청 ② — 확정표 3-b 「Screen Match = Expand」는 원본과 다르다

| | 원본 | Unity `Expand` | Unity `Match=1 (Height)` |
|---|---|---|---|
| 화면이 넓어지면 | **세로 유지 · 가로가 더 보인다** | 세로·가로 둘 다 줄여 안에 넣는다 (요소가 작아진다) | **세로 유지 · 가로가 더 보인다** ✔ |
| 화면이 좁아지면 | 세로 유지 · 가로가 덜 보인다 | 요소가 작아진다 | 세로 유지 ✔ |

⇒ **`Screen Match Mode = Match Width Or Height` · `Match = 1 (Height)` 이 원본의 scale outer 와 1:1이다.**
확정표 3-b 를 **Expand → Match Height(1.0)** 로 고칠 것을 요청한다. (확정은 PD 소관이라 여기서 고치지 않았다.)

### 1-g. y축

원본(C3 캔버스)은 **아래가 +y** (worldY 0 = 화면 위, 1280 = 화면 아래). UGUI 는 **위가 +y**.
아래 표의 `y` 는 전부 **위에서 잰 값**이다 — UGUI 로 옮길 때 상단 피벗을 쓰거나 부호를 뒤집는다.

### 2-f-2. ★★ 8회차 정정 — **줌은 «탄성»이고, 셰이크는 «배율»이 아니라 «스크롤»이다** [실측]

**위 2-f 의 수치는 «화면 크기비로 잰 근사»였다.** 8회차가 시트에서 트윈과 액션을 직접 읽어 통째로 바꿨다.
**틀린 서술을 지우지 않고 남긴다** — 왜 틀렸는지가 다음 사람에게 필요하다.

| 줌 곡선 | ~~단조 복귀~~ · 미측정 | **easeOutElastic** (`ease[6]` · p = 0.3·d = **0.6 s**) — **탄성 진동** |

- **이관 지침(개정)** — 직교 카메라 `size 640` 고정에 ① 레벨 시작 시 **직교 크기에 `zoom` 을 곱한다**
  (`zoom` = 0.8 → 1.0 · 2 s · easeOutElastic) ② 착탄 시 **위치만** ±20 world 무작위, 0.4 s 선형 감쇠.

### 2-g. ★★ 스프라이트 픽셀 크기 전수 [실측 — Fx 의 「미측정」 해소]


##### ★★ 화면에는 사인이 **«60 Hz 계단»으로 나온다** [실측]

시트(`eStart` 블록 389 · `eMap` 343)의 조건이 **`Every 0.0166666… s` = 1/60 s** 다. 실제로 —

```
offsetY 값이 «바뀐» 간격 : 중앙값 16.7 ms · 최소 10.3 · 최대 21.5    (n = 252 변화 / 4.2 s)
rAF 는 8.3 ms  ⇒  «같은 값이 2 프레임 유지»되는 것을 그대로 관측
```

⇒ **이관에서 매 프레임 갱신하면 원본보다 «부드럽다».** 원본은 **60 Hz 로 양자화된 사인**이다.
시간을 `floor(t · 60) / 60` 으로 계단화한 뒤 식에 넣는다.

### 5-b-8. 이 표를 다시 만들어야 할 때

**게임 오브젝트를 늘리거나 화면을 새로 만들면 그 화면의 행을 다시 센다.** 원본 쪽 정본을 뜨는 법:

```js
// 그 레이아웃의 «전 인스턴스»를 tint·vis·zIndex 까지 한 번에 (26회차 gap26/A.mjs)
const L = rt.GetMainRunningLayout();
for (const c of rt._allObjectClasses) for (const i of (c._instances || [])) {
  const w = i._worldInfo; if (!w || w._layer._layout !== L) continue;
  // cls · uid · layer · GetBoundingBox() · GetUnpremultipliedColor() · IsVisible() · GetZIndex()
}
```

- ⚠ **`vis === false` 인 인스턴스를 「빠진 것」으로 세지 않는다** — 원본도 안 그린다.
- ⚠ **같은 uid 가 여러 클래스로 뜬다** (C3 «패밀리»). `FX` = `FXChling` · `Tuto9Scale` = `UI_9P` 는 **한 개체**다.
  클래스 수를 그대로 개수로 쓰면 **없는 요소를 만들게 된다.**
- ⚠ **`tint` 를 반드시 같이 뜬다.** 같은 스프라이트가 «흰 본체»와 «검정 그림자»로 두 번 놓이는 것이
  이 원본의 상용 수법이다 (카드 · 튜토 판 · 마우스 · 골 화살표 — **네 자리**).

### ★★★ 6-a. `BG` 레이어 world → 화면 환산 [실측 · 유도 · 23회차 · n=5]

**대응표가 아니라 «식»이다.**

```
canvasCssX = (worldX − vpLeft) × (canvasW / (vpRight − vpLeft))
canvasCssY = (worldY − vpTop ) × (canvasH / (vpBottom − vpTop ))
        vp = layer.GetViewport()            ← 레이어마다 다르다. 이것이 전부다.
```

**W1L1~W1L5 5레벨 전부 같은 값** [실측 · n=5]:

| 레이어 | `GetViewport()` | 폭 × 높이 | 캔버스 배율 (캔버스 836×470) |
|---|---|---|---|
| **`BG`** (`zElevation −200`) | `[−2775.149, −1280.5, 4055.149, 2559.5]` | **6830.298 × 3840** | **0.1223958** |
| 그 밖 8개 (`z 0`) | `[−498.383, −0.5, 1778.383, 1279.5]` | **2276.766 × 1280** | **0.3671875** |

비가 **정확히 3.0000** (6830.298 / 2276.766 = 3.000000 · 3840 / 1280 = 3) ⇒ **`BG` 는 화면에서 ×1/3 이다.**

> **`k(z) = cameraZ / (cameraZ − z)` 표현과 등가다** — `z = −200`, `cameraZ = 100` ⇒ `k = 1/3`,
> 소실 중심 `C = (layout._scrollX, _scrollY) = (640, 639.5)`.
> `등가world = C + (world − C)/3` 을 «그 밖 8개»의 뷰포트로 환산하면 위 식과 **소수 2자리까지 같다** (검산 완료).
> ⇒ 5회차가 낸 「×1/3 원근」과 **같은 것**이고, 이번에 **레이어 뷰포트에서 직접 유도**해 5레벨로 닫았다.
