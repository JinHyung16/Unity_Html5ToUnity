# 99_원본지도 — Blumgi Bounce

**URL 제공형(코드 파일 없음)이라 「라인 지도」 대신 «실측 세션 지도»다** (분석로직 「URL 제공형이면」).
PD 가 지식 담당자 4인의 세션을 병합했다. 학습 1회차 (2026-08-29).

## ★ 이 게임은 블랙박스가 아니다 — 후속 실측자가 가장 먼저 읽을 것

게임은 **서비스 페이지의 첫 iframe 이 아니라 더 안쪽 프레임**(`*.gdn.poki.com/**/index.html`)에 있고,
거기서 Construct 3 런타임이 그대로 읽힌다.

```js
// [실측] 프레임을 «전수 순회»해서 찾는다. 첫 iframe 만 보면 못 찾는다.
window.c3_runtimeInterface._localRuntime
```

얻어지는 것 — 오브젝트 클래스 155개 · 인스턴스 전수 · `worldInfo.GetBoundingBox()`(위치·크기) ·
`layer.LayerToCanvasCss()`(엔진이 직접 하는 좌표 환산) · 애니메이션 프레임 수 · 레이어 `scaleRate`/시차.

> **[사고]** 첫 담당자가 프레임을 전수 순회하지 않고 `canvas` 를 못 찾자 **「블랙박스」로 결론**냈다.
> 뒤에 온 담당자가 같은 페이지에서 런타임을 그대로 읽었다.
> **못 찾았을 때 첫 의심은 「없다」가 아니라 「안 뒤진 곳이 있다」**다.

### ★★★ 파워는 «곡선을 피팅할 것»이 아니라 **런타임 변수에서 읽는 기전**이다 [3회차]

발사 파워는 홀드 중 **전역 변수 하나가 선형으로 차오르는 것**이다 — 피팅할 필요가 없었다.

```
forceShoot_P1 : 10 → 100 · 초당 55 · 1633ms 에서 100 으로 «고정(clamp)»
|v0| = 20.95 × force          ⇒  |v0| = 210 + 1.152 × «실» 홀드ms  (상한 2098)
```

**이 두 줄이 33점짜리 피팅 표를 통째로 대체한다.** 그리고 상한도 여기서 나온다 —
force 가 100 에서 멈추므로 **더 오래 눌러도 세지지 않는다.**

⚠ **파워는 «프레임 단위로 양자화»된다** — 1프레임 = force 0.4585 = `|v0|` 9.6px/s.
프레임 dt 가 8.33±0.28ms 로 흔들리고 실제 홀드도 6~16ms 지터가 있어 **같은 공칭 홀드가 갈린다.**
(원본 이상 #2 의 정체가 이것이다 — 아래)

### ★ 레벨이 갖는 것은 **조준각과 발사 위치뿐**이다 [3회차 정정]

2회차가 「파워 곡선·상한이 레벨마다 다르다」고 적었으나 **틀렸다.**
같은 홀드를 4레벨에 쏘면 `|v0|` 가 **0.7~1.2% 안에서 같다.** 달라 보였던 것은
**공칭 홀드를 축으로 썼기 때문**이다(실제 홀드가 스크립트마다 달랐다).

조준각도 피팅하지 말고 **읽어라** — `spr_SpriteRotator` 인스턴스 변수, **화면각 = 360 − 값**
(L1 300 · L2 290 · L3 300 · L4 230 — 실측 각도와 전부 일치).

### ★★ 엔진이 주는 «편의 환산 함수»를 검산 없이 믿지 마라 [5회차]

`layer.LayerToCanvasCss()` 는 **레이어의 z(원근)를 반영하지 않는다** — z 가 걸린 레이어에 대고 불러도
z=0 레이어와 **똑같은 값**을 조용히 돌려준다. 1회차가 「배경 y 가 화면 아래인데 캡처엔 하단에 보인다」는
모순을 만나 **미측정으로 남긴 원인이 이것**이었다. 환산은 `GetViewport()` 로 **직접** 해야 한다.

> **원근이 걸린 레이어의 환산 규칙** — `k(z) = cameraZ / (cameraZ − z)` ·
> 소실 중심 `C = (layout._scrollX, _scrollY)` ⇒ **등가좌표 = `C + (world − C)·k` · 등가크기 = `크기·k`**
> 한 z 평면에 다 있으면 **원근 카메라 없이 «상수 배율»로 축약**된다 (카메라 중심에 피벗을 둔 부모 스케일).

### 런타임을 읽을 때의 함정 — 전부 실제로 걸렸다

| 함정 | 증상 | 회피 |
|---|---|---|
| **인스턴스 하나만 본다** | `_instances[0]` 이 미끼·대기 개체라 「마우스 왼쪽 → 각도 −90°」라는 **오판**이 나왔다 | **전 인스턴스 열거** |
| **화면 밖 대기 개체** | `Touch_Button`·`Players` 는 y 음수, 공 물리체는 y≈31775 | 좌표를 그대로 옮기지 않는다 |
| **한 화면에 배율이 둘** | 웰컴의 `Start` 레이아웃은 `Main` 레이어만 `layout._scale = 2` | 한 배율로 환산하면 **카드가 화면 밖으로** |
| **연속 조작이 상태를 오염** | 같은 홀드가 신규 컨텍스트에선 클리어, 연속 발사에선 미클리어 | 판정용 실측은 **시행마다 새 컨텍스트** |
| **속성 이름이 비슷한 것이 둘** | 각도를 `_angle` 로 읽으면 **조용히 전부 0°** 가 나온다 — 실물은 **`_a`** | 값이 전부 같은 기본값이면 **이름부터 의심**한다 |
| **보이는 것과 부딪히는 것이 «다른 인스턴스»** | 그림용과 충돌용이 따로 있고 **프레임 인덱스도 다를 수 있다** | 둘을 각각 열거하고 **어느 쪽을 재는지 명시** |
| **애니메이션 정보가 한 겹 아래** | 인스턴스 최상위에 없다 — **`_sdkInst`** 에 있다 | 못 찾으면 한 겹 더 내려가 본다 |
| **자식 인스턴스의 `_x/_y` 가 «부모 상대값»** | 그대로 옮기면 **원점 근처로 간다** | **bbox 를 정본으로** 쓴다 |
| **판정 도형 ≠ 물리 도형** | 골 감지는 물리 원이 아니라 **사각**으로 겹침을 본다 | 판정에 쓰는 도형을 **따로** 확인한다 (엔진 `TestOverlap` 으로 채점하면 갈린다) |

### ★★★★ **게임 «로직»이 통째로 읽힌다** — 규칙을 역추론하지 마라 [6회차]

```js
rt._eventSheetManager._allSheets     // 이벤트 시트 22개 — 조건·액션 «원문»
param.Get(0)                         // ★ 파라미터의 «값»까지 연다 [8회차]
```

⚠ **`_expressionNumber` 는 «표 인덱스»가 아니라 파라미터마다 붙은 «컴파일된 식»이다.**
덤프에 `{"_expressionNumber":49}` 로 보이던 자리가 `param.Get(0)` 으로는
`0.1` · `"easeoutsine"` · `"charge_p1"` 같은 **실제 값**으로 열린다.
**여기까지 가야 시트가 «완전히» 읽힌다** — 조건 이름만 읽고 멈추면 수치·이징·대상이 안 나온다.

⚠ **엔진 문서의 열거형 순서를 믿지 마라.** 이징 인덱스가 문서 순서와 **달랐다** —
채록으로 확정한 것만 쓴다. 문서 순서로 옮겼으면 **탄성 진동이 통째로 사라졌을 것**이다.

**이 게임의 규칙은 여기 다 있다.** 오브젝트·좌표·물리 속성만 읽고 멈추면
**규칙을 공 쏴서 역추론**하게 되고, 그건 몇 회차가 걸려도 확정이 안 된다.

> **[사고]** 골인 조건을 알아내려고 여러 회차에 걸쳐 «쏴 보고 관찰»했다.
> 실제로는 **시트의 이벤트 두 개가 전부**였고, 읽으니 **한 번에 확정**됐다.
> ⚠ ACE 함수 이름이 난독화로 지워져 있어도 **`C3` 네임스페이스를 훑어 함수 동일성으로 역해석**하면
> 전부 이름이 붙는다(사전 1968개). **이름이 없다고 못 읽는 것이 아니다.**

#### ★★ 「그 조건이 **없다**」는 쏴서는 증명되지 않는다

방향 조건·속도 임계가 **없다**는 사실은 **아무리 많이 쏴도 증명이 안 된다** — 못 본 것뿐일 수 있다.
**조건 목록을 읽어야 「없다」가 확정된다.** 부정 사실은 관찰이 아니라 **열거**로만 닫힌다.

### ★★★ 지금 어느 레벨인지는 **런타임에 직접 물어라** — 시간으로 추론하지 마라

```js
// [실측] 덤프가 «자기 레벨»을 말한다. "W1L1"·"W1L2"… 그대로 나온다.
rt.GetMainRunningLayout()._name          // ← 이것을 써라
inst._worldInfo._layer._layout._name     // 인스턴스에서 거슬러 올라가도 된다
```

> ⚠ **`runtime.layout._name` 은 틀렸다** (3회차에 정정). `_currentLayoutStack` 이
> **틱 «밖»에서는 비어 있어** 그 경로는 실패한다. 위 두 경로를 써라.

**이 한 줄이 아래 「이벤트 지연」 문제를 통째로 무의미하게 만든다.** 2회차에 이걸 찾기 전까지
두 회차가 이벤트 타이밍과 싸웠고, 그 싸움에서 나온 오귀속이 **「원본 이상」 오보 2건**을 만들었다.
실제로 이 기법이 「홀드 600ms 가 W1L3 를 못 깬 회차」를 즉시 잡아냈다.

> **[사고]** 상태를 **관측 가능한 상태값**이 아니라 **이벤트가 도착한 시각**으로 추론했다.
> 시간 창은 연출 길이·기기 성능·월드 경계마다 달라져 **절대 안정되지 않는다.**
> **상태를 묻는 방법이 있으면 타이밍 추론을 쓰지 않는다.**

#### (참고) 그 이벤트 지연이 실제로 얼마였나 — 시간 창이 왜 실패했나

`Level_Started` 는 「클리어 시각」이 아니라 **「다음 레벨 시작 시각」**에 찍힌다.
릴리즈 기준 **4.1~8.3초**, **월드 마지막 레벨은 10.9~11.1초** [2회차 실측].
1회차가 잡은 「2.2초」는 **연출 길이(플래시 420 + `YES!` 1550 + 전환 280)** 였고 전부가 아니었다.
4~5초 대기로는 절반을 놓치고, 놓친 이벤트가 **다음 발사의 창에 들어온다.**

**콘솔 이벤트를 굳이 쓴다면 시간 창이 아니라 «레벨 id 전이»로 귀속한다.** 그래도 위 `layout._name` 이 낫다.

> ### ★★ 「남은 미측정」 칸은 **«그 회차가 끝난 시점»의 기록이다 — 현황이 아니다** [23회차]
>
> 이 표는 **로그**다. 각 줄의 「남은 미측정」은 **그 회차가 문을 닫을 때 남겨 둔 것**이고
> **뒤 회차가 닫은 것도 그대로 적혀 있다.** 예를 들어 —
>
> | 여기 적힌 것 | 실제 | 닫은 곳 |

## 이 게임을 다시 재는 사람에게 — 회차를 넘겨 배운 것

1. **레벨을 물어라, 시간을 재지 마라** — `GetMainRunningLayout()._name` (맨 위)
2. **피팅하기 전에 «그 값을 만드는 변수»가 런타임에 있는지 찾아라** — 파워를 두 회차에 걸쳐
   곡선으로 피팅했는데, 실제로는 **전역 변수 하나가 초당 55씩 차오르는 것**이었다.
   기전을 찾으면 **33점짜리 표가 두 줄로 줄어든다.** 조준각도 마찬가지다(회전 인스턴스 변수)
3. **공칭 입력값을 축으로 쓰지 마라 — «실제» 입력을 재라.** 「파워가 레벨마다 다르다」는
   2회차 결론은 **공칭 홀드를 축으로 썼기 때문에 생긴 가짜 구조**였다. 실제 홀드로 재니 전역이었다
4. **홀드 중 캡처가 홀드 시간을 늘린다.** 「이 홀드는 갈린다」의 한 건이 그 아티팩트였다 —
   재는 행위가 재려는 값을 바꾼 것이다. **판정용 시행에서는 캡처를 최소화**한다
5. **소스 텍스처 크기 ≠ 표시 크기** — 최대 2.43배 차이. 굽기 전에 둘 다 확인
6. **파일명을 믿지 마라** — 스크립트가 「다음 레벨로 갔겠지」로 붙인 이름이 실제와 어긋난 캡처가
   두 회차에 걸쳐 나왔다. **어긋난 파일명은 고치지 말고 대조표를 남긴다** — 고치면 사고가 안 보인다

7. **「레벨마다 다르다」를 확정하기 전에 «오프셋»으로 빼 봐라** [7회차] — 감지기 좌표를 레벨마다

   **그건 직접 읽힌다.** ⚠ **「공칭 + 추정 바이어스」로 만든 입력 레이블은 골든에 넣지 마라** —

9. **「계수가 흩어진다」는 «계수가 없다»가 아니라 «축이 틀렸다»는 신호다** [9회차].

### ⚠ 다음 사람에게 — **왜 185건이 쌓였나**

세 가지가 반복됐다. **표시를 안 지우는 것 자체가 결함이다.**

1. **「저쪽이 고칠 것」로 남긴 줄은 아무도 안 고친다.** `04 §6` 이 `03` 의 낡은 줄을 알면서
   「해당 문서 수정은 그 담당자 소관」이라 적고 넘겼고, **두 회차 동안 그대로였다.**
   ⇒ **닫은 사람이 «양쪽 다» 닫는다.**
2. **「미측정」과 「원리 불가」와 「범위 밖」을 한 칸에 섞었다.** 셋을 가르지 않으면
   **가서 재도 안 나오는 것**이 재측정 대기에 영원히 남는다 (재발방지 #112).
3. **한 항목을 여러 문서에 복사해 두고 한쪽만 고쳤다.** 위 「같은 뿌리」 표가 그 결과다.
   ⇒ **정본을 한 곳에 두고 나머지는 «참조»로 적는다.**
