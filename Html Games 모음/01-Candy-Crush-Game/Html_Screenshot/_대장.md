# 캡처 대장 — Candy-Crush-Game

**무엇을 왜 찍었는지 여기 없으면 그 PNG 는 다음 회차에 못 쓴다.**
찍을 때의 «조건»이 안 적혀 있으면 다시 찍어도 같은 그림이 안 나오기 때문이다.

| # | 파일 | 무엇 | 찍은 조건 | 쓴 곳 |
|---|---|---|---|---|
| 01 | `01_원본_게임화면_1200x900.png` | 원본 Endless 진행 화면 | Chrome 헤드리스 · 창 1200×900 · **시드 고정** · **`setInterval` 무력화(판 정지)** · 아트 로컬 · 웹폰트 제거 | G4 요소 대조의 «정본» |
| 02 | `02_Unity_게임화면_1080x1920.png` | Unity Endless 진행 화면 | 배치 재생 · **캔버스를 월드 공간 1080×1920 으로 세워** 전용 직교 카메라로 렌더 · `StopTick()` 으로 판 정지 | G4 대조의 Unity 쪽 |
| 03 | `03_Unity_모드선택_1080x1920.png` | Unity 모드 선택 화면 | 위와 같음 | 레이아웃 육안 확인 |

## 다시 찍는 법

```bash
# 원본 — 하네스 페이지를 만들고 헤드리스로 찍는다 (절차는 공통절차.md)
#   ⚠ file:// 로 열면 패널이 «정적 스냅샷»으로 바꿔 스크립트가 안 돈다. 로컬 서버로 연다.

# Unity
PLAYMODE=1 Tools/unity-batch.sh JinHyung.EditorTools.RenderCheck.RunAll
```

⚠ **판을 얼리지 않으면 두 그림이 같은 상태가 아니다.** 원본은 `setInterval` 을 막고,
우리 쪽은 `StopTick()` 을 부른다. 안 그러면 찍는 순간마다 판이 달라 대조가 무의미해진다.

⚠ **두 그림의 배경은 «다르게 놓인다»** (원본은 흐름 배치, 우리는 세로 화면 타일).
그래서 요소를 통째로 겹쳐 세면 안 된다 — 요소가 실제로 칠하는 자리만 센다.
