# 02 시스템 · 매치퍼즐 — Design + Client (최종 기입 Client)

> 규격은 `.claude/skills/htmltounity/references/분석로직.md`.
> **원본 라인은 인용할 때마다 grep 으로 재확정한다.** 아래 라인은 학습 1회차에 grep 으로 확정한 값이다.

**상태: 1회차 작성**

## 무엇인가

8×8 보드의 칸마다 6색 중 하나가 들어 있다. 인접한 두 칸을 드래그로 교환하면
같은 색 3개 또는 4개가 가로·세로로 이어질 때 사라지고 점수가 오른다.
빈 칸은 위 칸이 한 칸씩 내려와 메우고, 맨 윗줄은 새 사탕이 무작위로 채운다.

## 상태

| 변수 | 자료형 | 초기값 | 저장되나 | 원본 위치 |
|---|---|---|---|---|
| `width` | int (const) | **8** | 아니오 | `script.js:16` |
| `squares` | Element[] | `[]` → 64개 | 아니오 | `script.js:17` · `44` |
| `score` | int | **0** | **아니오** | `script.js:18` · `193` 에서 재설정 |
| `colorBeingDragged` | string | undefined | 아니오 | `script.js:56` · `59` |
| `colorBeingReplaced` | string | undefined | 아니오 | `script.js:56` · `76` |
| `squareIdBeingDragged` | int | undefined | 아니오 | `script.js:56` · `60` |
| `squareIdBeingReplaced` | int / null | undefined | 아니오 | `script.js:56` · `77` · `93` |

⚠ **칸의 상태가 곧 `style.backgroundImage` 문자열이다.** 원본은 별도 색 배열을 들고 있지 않다.
**빈 칸의 표현은 빈 문자열 `""`** 이다 (`script.js:108` · `117` · `128` …).
유니티에서는 이것을 **색 인덱스(0~5) + 빈칸 표현**으로 바꾼다 —
문자열 비교를 그대로 옮기면 안 된다 (PD 「대원칙」: 값은 옮기고 구조는 다시 설계한다).

## 보드 생성

```js
// script.js:34~53
function createBoard() {
    grid.innerHTML = "";
    squares.length = 0;
    for (let i = 0; i < width * width; i++) {
        const square = document.createElement("div");
        square.setAttribute("draggable", true);
        square.setAttribute("id", i);
        let randomColor = Math.floor(Math.random() * candyColors.length);
        square.style.backgroundImage = candyColors[randomColor];
        grid.appendChild(square);
        squares.push(square);
    }
    // dragstart/dragend/dragover/dragenter/dragleave/drop 6종 등록
}
```

- **재추첨이 없다.** 초기 보드에 매치가 생기면 그대로 두고, 첫 틱에 터진다.
- 인덱스 `i` 가 곧 DOM `id` 다. **행 = `i / 8`, 열 = `i % 8`.**

## 판정 함수 전수 — **루프 상한의 파생 규칙**

| 함수 | 찾는 것 | 상한 | 파생식 | 열 스킵 조건 | 점수 | 원본 위치 |
|---|---|---|---|---|---|---|
| `checkRowForFour` | 가로 4 | **60** | `width² − 4` = 60 | `i % width >= width - 3` (=5) | **+4** | `script.js:123~135` |
| `checkColumnForFour` | 세로 4 | **40** | `width × (width − 3)` = 40 | 없음 | **+4** | `script.js:137~148` |
| `checkRowForThree` | 가로 3 | **62** | `width² − 2` = 62 | `i % width >= width - 2` (=6) | **+3** | `script.js:150~162` |
| `checkColumnForThree` | 세로 3 | **48** | `width × (width − 2)` = 48 | 없음 | **+3** | `script.js:164~175` |

**숫자만 옮기면 보드 크기가 바뀌는 순간 전부 틀린다.** 위 파생식을 코드에 남긴다.

### ★★ [실측 확정] `checkRowForFour` 의 상한만 파생식과 거동이 어긋난다

`rowOfFour = [i, i+1, i+2, i+3]` 이 성립하려면 상한이 **61** 이어야 한다
(`i=60` → `[60,61,62,63]`, 전부 마지막 행 안). 원본은 **60** 이라 **`i=60` 을 검사하지 않는다.**

**브라우저 실측으로 확증했다** (학습 1회차). 매치가 하나도 없는 기저 패턴
(`color = (col + 2*row) % 3`) 을 깔고 점수 증분을 쟀다:

| 실험 | 점수 증가 | 뜻 |
|---|---|---|
| 기저 패턴 방치 | **0** | 하네스가 유효하다 |
| `i=56` 시작 4연속 (row7 col0~3) | **+4** | 4매치로 정상 인식 |
| **`i=60` 시작 4연속 (row7 col4~7)** | **+3** | **4매치를 놓치고 `checkRowForThree` 가 `[60,61,62]` 를 3매치로 먹는다** |

> **결론 — 원본은 「마지막 행 오른쪽 4연속」을 3점으로 처리하고 사탕 하나(63)를 남긴다.**
> 이건 추측이 아니라 실측이다. **「더 나은 공식」으로 고치면 원본과 달라진다.**
> 고칠지 말지는 **PD 확정 사항**이지 이관 담당자가 정할 것이 아니다.

### 판정 코드 원문 (대표 1종 — 나머지 셋도 형태가 같다)

```js
// script.js:123~135
function checkRowForFour() {
    for (let i = 0; i < 60; i++) {
        if (i % width >= width - 3) continue;
        let rowOfFour = [i, i + 1, i + 2, i + 3];
        let decidedColor = squares[i].style.backgroundImage;
        const isBlank = squares[i].style.backgroundImage === "";
        if (rowOfFour.every(index => squares[index].style.backgroundImage === decidedColor && !isBlank)) {
            score += 4;
            scoreDisplay.innerHTML = score;
            rowOfFour.forEach(index => squares[index].style.backgroundImage = "");
        }
    }
}
```

⚠ **점수 표시가 판정 안에서 즉시 갱신된다** (`scoreDisplay.innerHTML = score`).
한 틱에 여러 매치가 나면 그 틱 안에서 여러 번 갱신된다 — 화면에는 마지막 값만 보인다.

⚠ **`isBlank` 는 루프 밖 첫 칸 기준으로만 판정한다.** `decidedColor` 가 `""` 면
나머지 칸도 `""` 일 때 `every` 가 참이 되지만 `!isBlank` 가 거짓이라 막힌다. **빈칸 4연속은 매치가 아니다.**

## 낙하 · 재생성

```js
// script.js:105~120
function moveIntoSquareBelow() {
    for (let i = 0; i < width; i++) {                       // ① 맨 윗줄 빈 칸을 새 사탕으로
        if (squares[i].style.backgroundImage === "") {
            let randomColor = Math.floor(Math.random() * candyColors.length);
            squares[i].style.backgroundImage = candyColors[randomColor];
        }
    }
    for (let i = 0; i < width * (width - 1); i++) {          // ② 위 칸을 아래로 한 칸
        if (squares[i + width].style.backgroundImage === "") {
            squares[i + width].style.backgroundImage = squares[i].style.backgroundImage;
            squares[i].style.backgroundImage = "";
        }
    }
}
```

| 사양 | 값 | 왜 중요한가 |
|---|---|---|
| 새 사탕 생성 위치 | **0행만** | 중간에서 안 생긴다 |
| 한 틱당 낙하 거리 | **한 칸** | 연쇄가 100ms 씩 끊겨 보인다 |
| 순서 | **채우기(①) → 내리기(②)** | 뒤집으면 첫 틱에 한 칸 더 내려간다 |
| ② 의 진행 방향 | `i` **오름차순** (위→아래) | 한 번의 호출에서 같은 사탕이 여러 칸 내려갈 수 있다 (`i` 가 커지며 방금 내린 칸을 다시 본다) |
| 낙하 애니메이션 | **없다.** 값이 즉시 바뀐다 | `05_연출.md` 참조 — 유니티에서 트윈을 넣으면 원본에 없는 연출이다 |

### ★★ [실측 확정] ②의 순회 방향 때문에 **「한 틱에 한 칸」이 아니다**

`i` 를 **올려 가며** 훑으므로 **방금 내린 칸을 같은 호출에서 다시 본다.**
그래서 사탕 하나가 **빈 칸이 이어지는 만큼 한 번에 미끄러진다.**

| 실측 | 결과 |
|---|---|
| `16,24,32` 를 BLANK (세로 연속 3) | **바뀐 칸이 2개뿐** — `8 → BLANK`, `32` 가 8의 색을 받는다. **`16,24` 는 BLANK 로 남는다** (`07_기대값.md` V13) |
| `16,32` 를 BLANK (사이 `24` 채워짐) | `8→16` · `24→32` 로 **각각 한 칸씩** (V15) |
| `32,33,34` 를 BLANK (가로 3) | 각 열에서 **한 칸씩** (V14) |

> ⚠ **유니티에서 「중력」을 자연스럽게 짜면 한 틱에 열 전체가 압축된다 — 원본과 완전히 다르다.**
> 아래에서 위로 훑거나, 열 단위로 모아 압축하거나, 사탕마다 한 칸씩 내리면 **전부 틀린다.**
> **원본과 같은 방향으로 같은 배열을 제자리 수정해야** 벡터가 맞는다.

## [실측 확정] 판정 순서가 점수를 바꾼다

`gameLoop` 의 ①~④ 는 **먼저 먹은 쪽이 뒤 판정을 막는다.** 즉시 제거 + `isBlank` 가드의 조합이다.

| 심은 것 | 점수 | 왜 |
|---|---|---|
| 가로4 `[16~19]` + 세로3 `[16,24,32]` (16 공유) | **+4** (7이 아니다) | ①이 `16~19` 를 비우면 ④가 `squares[16]` 을 볼 때 이미 빈 칸이라 `isBlank` 로 걸러진다. **`24,32` 는 판에 남는다** |
| 가로5 `[16~20]` | **+4** (7이 아니다) | ①이 `i=16` 에서 4개를 먹고 비운다. `i=17` 부터는 첫 칸이 비어 걸러진다. **다섯 번째(20)가 살아남는다** |
| 떨어진 가로3 두 개 | **+6** | 서로 안 겹치므로 둘 다 같은 틱에 먹는다 |

**이 결과는 「매치 판정을 잘 만들면」 저절로 나오지 않는다.**
**판정 순서 · 즉시 제거 · `isBlank` 가드** 셋을 그대로 옮겨야만 나온다.
전수 벡터는 `07_기대값.md` V16~V18.

## 드래그 판정 — **[실측 확정] 세 가지가 직관과 다르다**

```js
// script.js:82~102
function dragEnd() {
    let validMoves = [
        squareIdBeingDragged - 1,
        squareIdBeingDragged - width,
        squareIdBeingDragged + 1,
        squareIdBeingDragged + width
    ];
    let validMove = validMoves.includes(squareIdBeingReplaced);

    if (squareIdBeingReplaced && validMove) {
        squareIdBeingReplaced = null;
    } else if (squareIdBeingReplaced && !validMove) {
        squares[squareIdBeingReplaced].style.backgroundImage = colorBeingReplaced;
        squares[squareIdBeingDragged].style.backgroundImage = colorBeingDragged;
    } else {
        squares[squareIdBeingDragged].style.backgroundImage = colorBeingDragged;
    }
}
```

브라우저에서 `dragstart` → `drop` → `dragend` 를 직접 디스패치해 확인했다
(핸들러가 `dataTransfer` 를 안 쓰므로 순수 `Event` 로 재현된다).

| # | 실험 | 결과 | 원인 | 판정 |
|---|---|---|---|---|
| 1 | **1번 칸을 0번 칸에 드롭** | `red·blue` → **`blue·blue`** | `squareIdBeingReplaced` 가 **0이면 falsy** 라 `else` 로 빠져 **드래그한 칸만 되돌린다** | **사탕이 복제되고 하나가 소멸한다** |
| 1-b | **0번 칸에서 1번 칸으로 드롭** | 정상 교환 | `squareIdBeingReplaced` 가 `1` 이라 falsy 가 아니다 | **정상.** 이상은 **`0` 이 목적지일 때만** 난다 |
| 2 | **8번 칸을 7번 칸에 드롭** (행 경계) | `blue·green` → **`green·blue`** | `validMoves` 의 `±1` 에 **열 경계 가드가 없다** | **가로 랩어라운드 교환이 성립한다** |
| 3 | 20↔21 (정상 인접) | 정상 교환 | — | 원본대로 |
| 4 | 20↔40 (비인접) | 되돌림 | — | 원본대로 |

### 그 밖에 코드에서 읽히는 것 — **미실측**

| 의심 | 근거 | 상태 |
|---|---|---|
| `squareIdBeingReplaced` 가 **유효 이동일 때만** `null` 로 리셋된다 (`script.js:93`) | 무효 이동 후 값이 남는다. 다음에 그리드 밖으로 드롭하면 `drop` 이 안 불려 **직전 값**으로 판정한다 | **미측정(③ 하네스 없음)** — 골든 벡터 항목으로 올린다 |
| 매치가 안 나는 교환도 **되돌리지 않는다** | 원본에 「매치 없으면 스왑 취소」 로직이 없다 | 코드상 확실. 실측은 미측정 |

⚠ **원본에 「매치가 생기는 교환만 허용」 규칙이 없다.** 캔디크러시 원작과 다른 지점이다 —
**원작을 기억으로 구현하면 원본과 달라진다.**
