### ★ 원본에 **없는** 화면 — 만들면 안 되는 것

| 흔히 만들게 되는 화면 | 원본에 있나 | 근거 |
|---|---|---|
| 게임 오버 / 결과 팝업 | **없다.** `alert()` 한 줄이 전부다 | `script.js:228` |
| 일시정지 화면 | **없다** | 정지 코드 없음 |
| 설정 / 사운드 | **없다** | 사운드 코드 자체가 없다 |
| 재시작 버튼 | **없다.** [Change Mode] → 모드 선택 → 다시 고르는 경로뿐 | `script.js:232~240` |

⚠ **`alert()` 는 브라우저 모달이다.** 유니티에 대응물이 없으므로 **원본에 없는 창을 하나 만들게 된다** —
그 창의 사양(문구·버튼·닫는 경로)을 여기서 정하지 않으면 패스 ③에서 임의로 생긴다.

**확정 — 최소 팝업** (원장 「결정 사항」 4)

| 항목 | 사양 |
|---|---|
| 문구 | **`Time's Up! Your score is {score}`** — 원본 `script.js:228` 과 바이트 단위로 같다 |
| 버튼 | **확인 1개** |
| 닫으면 | **보드가 잠긴 채 그대로 남는다** (원본 `draggable=false` 와 같다). 재시작 버튼을 만들지 않는다 |
| 빠져나가는 경로 | **`[Change Mode]` 하나뿐** — 원본과 같다 |

[경고] **이 팝업은 「원본에 없는 창」이므로 플로우 diff 에서 예외로 등재한다.** 그 외에는 예외가 없다.

## 셀 입력 — 드래그 전수

| 이벤트 | 핸들러 | 하는 일 | 원본 위치 |
|---|---|---|---|
| `dragstart` | `dragStart` | `colorBeingDragged`·`squareIdBeingDragged` 기록 | `script.js:58~61` |
| `dragover` | `dragOver` | `preventDefault()` 만 | `script.js:63~65` |
| `dragenter` | `dragEnter` | `preventDefault()` 만 | `script.js:67~69` |

⚠ **순서가 사양이다.** `drop` 에서 **먼저 바꾸고**, `dragend` 에서 **틀렸으면 되돌린다.**
유니티에서 「검사 후 교환」으로 뒤집으면 화면 결과는 같아 보여도
**아래 「0번 칸」 거동이 재현되지 않는다.**

### 틱 1회가 하는 일 — **순서가 사양이다**

```js
// script.js:178~184
function gameLoop() {
    checkRowForFour();      // ①
    checkColumnForFour();   // ②
    checkRowForThree();     // ③
    checkColumnForThree();  // ④
    moveIntoSquareBelow();  // ⑤
}
```

⚠ **낙하(⑤)가 판정(①~④) **뒤**에 온다. 그리고 한 틱에 **한 칸만** 내려간다.**
그래서 연쇄 제거가 **100ms 씩 끊겨서** 진행된다 — 이게 원본의 체감 속도다.
유니티에서 낙하를 한 프레임에 끝내면 **원본보다 빨라져 파리티가 깨진다.**

### 시작 직후 자동 매치

`createBoard()` 는 **매치가 생기지 않게 막지 않는다** (`script.js:34~53` 에 재추첨 없음).
그래서 **판을 켜자마자 점수가 오른다.** 실측: 게임 시작 후 방치만 해도 점수가 증가한다.
**이것이 원본 거동이다 — 「초기 보드에 매치가 없어야 한다」고 고치면 원본과 달라진다.**
