# 07 기대값 — 골든 벡터 (Client)

규격: `.claude/skills/htmltounity/references/분석로직.md`. 원본 실측 기록이며, 유니티가 이 표와 다르면 유니티가 틀린 것이다.

상태: 1회차 작성 · 벡터 22개 (매치 9 · 낙하 6 · 합성 3 · 드래그 9 중 중복 제외)

모든 값은 원본을 돌려 잰 것이다 (코드 추론 아님). 의심되면 아래 「하네스」로 다시 잰다.

## 왜 파일이 유니티 프로젝트 밖에 있나

검증용 에셋(`_Verify/` · `GoldenVector.asset`)을 프로젝트에 두면 비개발자가 커밋 여부를 판단할 수 없고, `.gitignore` 로 감출 기록도 아니다. 정답 출처가 원본이므로 원본 옆에 둔다 (`CLAUDE.md` 「검증 산출물 규칙」).

## 기저 보드 — 매치가 하나도 없는 판

잰 값이 심은 패턴에서만 나오도록, 매치가 불가능한 보드를 깔고 그 위에 패턴을 심는다.

```
color(i) = N[(col + 2*row) % 3]        col = i % 8,  row = i / 8,  N = [red, blue, green]
```

| 왜 매치가 안 되나 | |
|---|---|
| 가로 | 이웃 칸끼리 `(col+1) - col = 1` 만큼 어긋난다 → 인접 동색 없음 |
| 세로 | 이웃 행끼리 `2` 만큼 어긋난다 → 인접 동색 없음 |

실측: 이 보드를 방치하면 점수 증가 0 (하네스 유효).
심는 색은 purple(index 5). 기저가 red/blue/green 뿐이라 심은 패턴 외에 purple 은 없다.

## 한 틱이 하는 일 — 벡터를 읽는 법

```js
// 원본 script.js:178~184
gameLoop() {
    checkRowForFour();      // ①
    checkColumnForFour();   // ②
    checkRowForThree();     // ③
    checkColumnForThree();  // ④
    moveIntoSquareBelow();  // ⑤  ← 판정 뒤에 낙하가 같은 틱에 붙는다
}
```

⑤가 같은 틱에 메우므로 제거된 칸 자체는 관찰할 수 없다. 표의 「보드 변화」는 한 틱 전체(①~⑤) 결과이며 유니티도 이 단위로 대조한다.

주의: 0행이 비면 무작위 색으로 채워진다 (`script.js:107~112`). 그 자리는 대조에서 제외.

### V13 — 한 틱에 한 칸이 아니다

```js
// 원본 script.js:114~119 — i 오름차순
for (let i = 0; i < width * (width - 1); i++) {
    if (squares[i + width].style.backgroundImage === "") {
        squares[i + width].style.backgroundImage = squares[i].style.backgroundImage;
        squares[i].style.backgroundImage = "";
    }
}
```

`i` 오름차순이라 방금 내린 칸을 같은 호출에서 다시 본다. 사탕 하나가 빈 칸이 이어지는 만큼 한 번에 미끄러지고(V13: 8 → 32, 세 칸) 중간 빈 칸은 남는다.

주의: 일반적인 중력(열 전체 압축, 아래→위 순회, 열 단위 압축, 사탕마다 한 칸)은 전부 불일치. 원본과 같은 방향으로 같은 자료구조를 제자리 수정해야 맞는다.

### D6 vs D9 — 이상의 범위

| | 결과 |
|---|---|
| `0` 에서 시작해 다른 칸으로 (D9) | 정상 교환 |
| 다른 칸에서 `0` 으로 떨어뜨림 (D6) | 복제 |

원인: `script.js:92` 의 `if (squareIdBeingReplaced && validMove)`. `squareIdBeingReplaced` 가 `0` 이면 falsy 라 `else` 로 빠져 드래그한 칸만 되돌리는데, `drop`(`script.js:75~80`)이 이미 교환을 끝냈으므로 두 칸이 같은 색이 되고 한 색이 사라진다. 원본의 falsy 판정과 실행 순서를 그대로 옮겨야 나온다.

## 하네스 — 이 값을 다시 재는 법

원본을 띄우고(`python -m http.server 8123`) Endless 모드 진입 후 개발자 콘솔에 붙여 넣는다. 파일을 만들지 않는다.

```js
const N=["red","blue","green","yellow","orange","purple"];
const C=n=>`url("https://raw.githubusercontent.com/arpit456jain/Amazing-Js-Projects/master/Candy%20Crush/utils/${n}-candy.png")`;
const cells=()=>[...document.querySelectorAll('.grid div')];
const S=()=>parseInt(document.getElementById('score').innerHTML);
const nameOf=e=>{const m=e.style.backgroundImage.match(/([a-z]+)-candy/);return m?m[1]:'BLANK'};
const snap=()=>cells().map(nameOf);
const sleep=ms=>new Promise(r=>setTimeout(r,ms));
const paintBase=()=>{const cs=cells();for(let i=0;i<64;i++){const r=(i/8)|0,c=i%8;
  cs[i].style.backgroundImage=C(N[(c+2*r)%3])}};
const settle=async(quietMs=350)=>{let last=S(),lastB=snap().join(),quiet=0;
  while(quiet<quietMs){await sleep(50);const s=S(),b=snap().join();
    if(s===last&&b===lastB){quiet+=50}else{quiet=0;last=s;lastB=b}}};

// 매치 벡터 — 점수가 처음 변하는 순간의 보드를 잡는다
async function runTick(idx,colorName="purple",timeoutMs=3000){
  paintBase(); await settle();
  const cs=cells(), s0=S();
  idx.forEach(i=>cs[i].style.backgroundImage=C(colorName));
  const input=snap(); let waited=0;
  while(waited<timeoutMs){ await sleep(10); waited+=10;
    if(S()!==s0){ const after=snap(), diff=[];
      for(let i=0;i<64;i++) if(input[i]!==after[i]) diff.push(`${i}:${input[i]}>${after[i]}`);
      return {점수:S()-s0, 변경:diff.join(' ')}; } }
  return {점수:0, 변경:"(timeout)"};
}

// 낙하 벡터 — 점수가 안 변하므로 보드 변화로 잡는다
async function runBoardTick(mutate,timeoutMs=3000){
  paintBase(); await settle();
  mutate(cells());
  const input=snap(), key=input.join(); let waited=0;
  while(waited<timeoutMs){ await sleep(10); waited+=10;
    const after=snap();
    if(after.join()!==key){ const diff=[];
      for(let i=0;i<64;i++) if(input[i]!==after[i]) diff.push(`${i}:${input[i]}>${after[i]}`);
      return {변경:diff.join(' ')}; } }
  return {변경:"(timeout)"};
}

// 드래그 벡터 — 핸들러가 dataTransfer 를 안 쓰므로 순수 Event 로 된다
function swap(from,to){const cs=cells();
  cs[from].dispatchEvent(new Event('dragstart',{bubbles:true}));
  cs[to].dispatchEvent(new Event('drop',{bubbles:true}));
  cs[from].dispatchEvent(new Event('dragend',{bubbles:true}));}

// 사용 예
// await runTick([60,61,62,63])                     → V6
// await runBoardTick(cs=>[16,24,32].forEach(i=>cs[i].style.backgroundImage=""))  → V13
```

주의: `requestAnimationFrame` 을 쓰지 않는다. 브라우저 패널이 숨겨지면 rAF 가 멈춰 하네스가 정지한다. `setInterval` 타이머로 폴링한다 (실측: 숨긴 상태에서도 틱 59ms).

## 잔존 상태 벡터 — 무효 스왑 뒤 남는 값 (2회차 실측)

원본 `dragEnd` 는 `squareIdBeingReplaced` 를 유효 이동일 때만 지운다 (`script.js:92~101`). 무효 이동 뒤 값이 남고, 드롭 없는 다음 드래그가 그 값으로 판정한다.

재는 법: 시드 고정 + `setInterval` 차단으로 판을 얼리고 `dragstart`/`drop`/`dragend` 순서 디스패치 (드롭을 빼면 그리드 밖 드롭과 같다).

| # | 순서 | 보드 변화 |
|---|---|---|
| R1 | `dragstart(10)` → `drop(30)` → `dragend` (비인접) | 0칸 — 원본은 둘 다 되돌린다 |
| R2 | R1 뒤 `dragstart(29)` → `dragend` (드롭 없음) · 잔존 30 은 `29+1` 이라 유효로 판정 | 0칸 |
| R3 | 다시 R1 뒤 `dragstart(5)` → `dragend` (드롭 없음) · 잔존 30 은 비인접 | 0칸 |

결론(실측): 잔존 값은 관측 가능한 판 변화를 만들지 않는다. 유효면 잔존만 지워지고, 무효면 같은 값을 제자리에 다시 쓴다.
주의: 그래도 잔존 자체는 그대로 옮긴다. 지우면 상태 기계가 원본과 갈려 이후 어긋남 추적이 불가능하다.

### 미측정에서 뺀 이유

| 항목 | 파리티로 재는 것 | 어떻게 닫혔나 |
|---|---|---|
| 타이머 | 감소 횟수와 종료 시점 — 120에서 시작해 1씩 줄고 0에서 끝난다 | 플로우 검사가 틱 인자를 1초씩 먹여 0까지 몰고 종료 팝업이 뜨는 것까지 센다 |
| 초기 자동 매치 | 시작하자마자 점수가 오른다는 사실 (원본이 초기 보드를 정리하지 않는다) | 재생 검사가 드래그 없이 방치했을 때 점수가 오르는 것을 센다 |

벽시계 오차(1000ms 간격 누적 드리프트)는 브라우저 타이머와 엔진 프레임의 플랫폼 성질이라 파리티 대상이 아니다. 점수 규모도 무작위라 값이 아니라 「오른다」가 사양이며, 오르는 양은 골든 벡터 규칙이 이미 고정한다.
