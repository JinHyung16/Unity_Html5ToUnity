검증용 에셋(`_Verify/` · `GoldenVector.asset`)을 프로젝트에 만들면

## 기저 보드 — **매치가 하나도 없는 판**

벡터를 재려면 **잰 값이 심은 패턴에서만 나왔다는 보장**이 필요하다.
그래서 매치가 원천적으로 불가능한 보드를 먼저 깔고 그 위에 패턴을 심는다.

```
color(i) = N[(col + 2*row) % 3]        col = i % 8,  row = i / 8,  N = [red, blue, green]
```

| 왜 매치가 안 되나 | |
|---|---|
| 가로 | 이웃 칸끼리 `(col+1) - col = 1` 만큼 어긋난다 → 인접이 절대 같은 색이 아니다 |
| 세로 | 이웃 행끼리 `2` 만큼 어긋난다 → 인접이 절대 같은 색이 아니다 |

**실측 확인** — 이 보드를 깔고 방치하면 점수 증가가 **0** 이다. 하네스가 유효하다는 증거다.

심는 색은 **purple(index 5)** 을 쓴다. 기저가 red/blue/green 3색만 쓰므로
**심은 패턴 말고는 purple 이 존재하지 않는다.**

## 한 틱이 하는 일 — 벡터를 읽는 법

```js
// 원본 script.js:178~184
gameLoop() {
    checkRowForFour();      // ①
    checkColumnForFour();   // ②
    checkRowForThree();     // ③
    checkColumnForThree();  // ④
    moveIntoSquareBelow();  // ⑤  ← 판정 뒤에 낙하가 같은 틱에 붙는다
}
```

**그래서 「제거된 칸」은 관찰할 수 없다.** ⑤가 같은 틱에 이미 메우기 때문이다.
아래 표의 「보드 변화」는 **한 틱 전체(①~⑤)의 결과**다 — 유니티도 이 단위로 대조한다.

⚠ **0행이 비면 무작위 색으로 채워진다** (`script.js:107~112`). 그 자리는 대조에서 제외한다.

### ★ V6 — 원본 이상 #1 의 결정적 증거

**같은 「마지막 행 가로4」인데 V5 는 +4, V6 은 +3 이다.**
`checkRowForFour` 의 상한이 `i < 60` 이라 `i=60` 이 검사에서 빠지고,
`checkRowForThree`(`i < 62`)가 `[60,61,62]` 를 3매치로 대신 먹는다.
**네 번째 사탕(63)이 판에 남는다.**

> **유니티가 여기서 +4 를 내면 「고쳐서 옮긴 것」이고, 그건 결함이다.**
> 정책은 「그대로 재현」이다 (원장 「결정 사항」 1).

## 낙하 벡터 — **순회 방향이 사양이다**

매치가 없으므로 점수는 안 변한다. **보드 변화**로 잡았다.

| # | 만든 상태 | 보드 변화 (한 틱) |
|---|---|---|
| **V10** | `32` 를 BLANK | `24 → BLANK` · `32` 가 24의 색을 받는다 (**한 칸**) |
| **V11** | `8` 을 BLANK | `0 → BLANK` · `8` 이 0의 색을 받는다 (**한 칸**) · **0행 재생성은 다음 틱** |
| **V12** | `0` 을 BLANK (0행) | `0` 이 **무작위 색**으로 채워진다. 그 외 변화 없음 |
| **★V13** | `16,24,32` 를 BLANK (세로 연속 3) | **바뀐 칸이 2개뿐이다** — `8 → BLANK` · `32` 가 8의 색을 받는다. **`16,24` 는 BLANK 로 남는다** |
| **V14** | `32,33,34` 를 BLANK (가로 3) | `24,25,26 → BLANK` · `32,33,34` 가 각각 위 색을 받는다 (**각 한 칸**) |
| **V15** | `16,32` 를 BLANK (사이 `24` 는 채워짐) | `8 → BLANK` · `16` 이 8의 색 · `24 → BLANK` · `32` 가 24의 색 (**각 한 칸**) |

### ★★ V13 이 말하는 것 — 「한 틱에 한 칸」이 아니다

```js
// 원본 script.js:114~119 — i 오름차순
for (let i = 0; i < width * (width - 1); i++) {
    if (squares[i + width].style.backgroundImage === "") {
        squares[i + width].style.backgroundImage = squares[i].style.backgroundImage;
        squares[i].style.backgroundImage = "";
    }
}
```

`i` 를 **올려 가며** 훑으므로 **방금 내린 칸을 같은 호출에서 다시 본다.**
그래서 사탕 하나가 **빈 칸이 이어지는 만큼 한 번에 미끄러진다** (V13 은 8 → 32, 세 칸).
그러면서 **중간 빈 칸은 그대로 남는다.**

> ⚠ **유니티에서 「중력」을 자연스럽게 짜면 한 틱에 열 전체가 압축된다 — 원본과 완전히 다르다.**
> 아래에서 위로 훑거나, 열 단위로 모아 압축하거나, 사탕마다 한 칸씩 내리면 **전부 틀린다.**
> **원본과 같은 방향으로, 같은 자료구조를 제자리 수정해야** 이 벡터가 맞는다.

| # | 심은 것 | **점수** | 결과 |
|---|---|---|---|
| **★V16** | 가로4 `[16~19]` + 세로3 `[16,24,32]` (16 공유) | **+4** | **가로4만 먹는다.** `24,32` 는 **purple 그대로 남는다** |
| **V17** | 떨어진 가로3 두 개 `[16,17,18]` · `[40,41,42]` | **+6** | 둘 다 같은 틱에 먹는다 (변경 칸 12개) |
| **★V18** | 가로5 `[16~20]` | **+4** | `16~19` 만 먹는다. **`20` 은 purple 그대로 남는다** |

### 왜 V16 은 +7 이 아닌가

`checkRowForFour`(①)가 먼저 돌아 `16~19` 를 비운다.
그 다음 `checkColumnForThree`(④)가 `i=16` 을 볼 때는 **`squares[16]` 이 이미 빈 칸**이라
`isBlank` 가드(`script.js:168`)에 걸려 건너뛴다.

### 왜 V18 은 +7 이 아닌가

`checkRowForFour` 가 `i=16` 에서 `[16,17,18,19]` 를 먹고 비운다.
`i=17` 부터는 첫 칸이 빈 칸이라 `isBlank` 로 걸러진다.
`checkRowForThree` 도 `[18,19,20]`·`[19,20,21]` 의 첫 칸이 비어 있어 못 먹는다.
**5연속의 다섯 번째는 살아남는다.**

> **이 둘은 「매치 판정을 잘 만들면」 저절로 나오지 않는다.**
> 원본의 **판정 순서 + 즉시 제거 + `isBlank` 가드**를 그대로 옮겨야만 나온다.

`dragstart` → `drop` → `dragend` 를 순서대로 디스패치해 쟀다
(원본 핸들러가 `dataTransfer` 를 안 쓰므로 순수 `Event` 로 재현된다).

| # | 드래그 | 결과 | 판정 |
|---|---|---|---|
| **D1** | `20 → 21` (오른쪽) | 교환됨 | 정상 |
| **D2** | `20 → 19` (왼쪽) | 교환됨 | 정상 |
| **D3** | `20 → 12` (위) | 교환됨 | 정상 |
| **D4** | `20 → 28` (아래) | 교환됨 | 정상 |
| **D5** | `20 → 40` (비인접) | **변화 없음** | 되돌림. 정상 |
| **★D6** | **`1 → 0`** | **`0` 만 바뀐다** (`0` 이 1의 색이 되고 **`1` 도 그 색 그대로**) | **사탕 복제 · 원본 이상 #2** |
| **★D7** | **`8 → 7`** (행 경계) | **교환됨** | **행을 넘어 교환 · 원본 이상 #3** |

### ★ D6 vs D9 — 이상의 범위가 정확히 여기서 갈린다

| | 결과 |
|---|---|
| **`0` 에서 시작**해 다른 칸으로 (D9) | **정상 교환** |
| 다른 칸에서 **`0` 으로 떨어뜨림** (D6) | **복제** |

원인은 `script.js:92` 의 `if (squareIdBeingReplaced && validMove)` 다.
**`squareIdBeingReplaced` 가 `0` 이면 falsy** 라 `else` 로 빠져
드래그한 칸만 원래 색으로 되돌린다 — 그런데 `drop`(`script.js:75~80`)이 **이미 교환을 끝낸 뒤**라,
결과적으로 **두 칸이 같은 색이 되고 한 색이 사라진다.**

> **「0을 특별 취급하지 않는」 정상적인 구현으로는 이 거동이 나오지 않는다.**
> 원본의 **falsy 판정과 실행 순서**를 그대로 옮겨야 한다.

## 유니티에서 어떻게 대조하나

**검증용 에셋·씬·테스트 파일을 만들지 않는다** (`CLAUDE.md` 「검증 산출물 규칙」).

| # | 하는 일 |
|---|---|
| 1 | 보드를 기저 패턴 `(col + 2*row) % 3` 으로 세우는 **임시 디버그 진입점**을 만든다 |
| 2 | 패턴을 심고 **한 틱만** 돌린다 |
| 3 | `Log.Success` 로 **점수 델타 + 보드 변화**를 찍는다 |
| 4 | 콘솔을 이 문서의 표와 대조하고, 결과를 **원장에 `N/N` 으로** 적는다 |
| 5 | **대조가 끝나면 임시 로그와 진입점을 지운다** |

`Log` 는 `[Conditional("UNITY_EDITOR")]` 라 지우는 것을 깜빡해도 빌드에 안 들어간다.
다만 **진입점(디버그 메뉴·테스트 버튼)은 코드라 남는다** — 그건 지운다.

### 승격 기준 — 언제 진짜 테스트로 올리나

- 벡터가 **수십 개를 넘어** 손으로 대조하는 데 회차마다 시간이 든다
- **같은 벡터를 3회차 이상** 다시 재고 있다

그때 `Assets/Tests/` **EditMode 테스트**로 올린다. **임의 폴더에 만들지 않는다.**

## 하네스 — 이 값을 다시 재는 법

원본을 띄우고(`python -m http.server 8123`) **Endless 모드로 들어간 뒤**
개발자 콘솔에 붙여 넣는다. **파일을 만들지 않는다.**

```js
const N=["red","blue","green","yellow","orange","purple"];
const C=n=>`url("https://raw.githubusercontent.com/arpit456jain/Amazing-Js-Projects/master/Candy%20Crush/utils/${n}-candy.png")`;
const cells=()=>[...document.querySelectorAll('.grid div')];
const S=()=>parseInt(document.getElementById('score').innerHTML);
const nameOf=e=>{const m=e.style.backgroundImage.match(/([a-z]+)-candy/);return m?m[1]:'BLANK'};
const snap=()=>cells().map(nameOf);
const sleep=ms=>new Promise(r=>setTimeout(r,ms));
const paintBase=()=>{const cs=cells();for(let i=0;i<64;i++){const r=(i/8)|0,c=i%8;
  cs[i].style.backgroundImage=C(N[(c+2*r)%3])}};
const settle=async(quietMs=350)=>{let last=S(),lastB=snap().join(),quiet=0;
  while(quiet<quietMs){await sleep(50);const s=S(),b=snap().join();
    if(s===last&&b===lastB){quiet+=50}else{quiet=0;last=s;lastB=b}}};

// 매치 벡터 — 점수가 처음 변하는 순간의 보드를 잡는다
async function runTick(idx,colorName="purple",timeoutMs=3000){
  paintBase(); await settle();
  const cs=cells(), s0=S();
  idx.forEach(i=>cs[i].style.backgroundImage=C(colorName));
  const input=snap(); let waited=0;
  while(waited<timeoutMs){ await sleep(10); waited+=10;
    if(S()!==s0){ const after=snap(), diff=[];
      for(let i=0;i<64;i++) if(input[i]!==after[i]) diff.push(`${i}:${input[i]}>${after[i]}`);
      return {점수:S()-s0, 변경:diff.join(' ')}; } }
  return {점수:0, 변경:"(timeout)"};
}

// 낙하 벡터 — 점수가 안 변하므로 보드 변화로 잡는다
async function runBoardTick(mutate,timeoutMs=3000){
  paintBase(); await settle();
  mutate(cells());
  const input=snap(), key=input.join(); let waited=0;
  while(waited<timeoutMs){ await sleep(10); waited+=10;
    const after=snap();
    if(after.join()!==key){ const diff=[];
      for(let i=0;i<64;i++) if(input[i]!==after[i]) diff.push(`${i}:${input[i]}>${after[i]}`);
      return {변경:diff.join(' ')}; } }
  return {변경:"(timeout)"};
}

// 드래그 벡터 — 핸들러가 dataTransfer 를 안 쓰므로 순수 Event 로 된다
function swap(from,to){const cs=cells();
  cs[from].dispatchEvent(new Event('dragstart',{bubbles:true}));
  cs[to].dispatchEvent(new Event('drop',{bubbles:true}));
  cs[from].dispatchEvent(new Event('dragend',{bubbles:true}));}

// 사용 예
// await runTick([60,61,62,63])                     → V6
// await runBoardTick(cs=>[16,24,32].forEach(i=>cs[i].style.backgroundImage=""))  → V13
```

⚠ **`requestAnimationFrame` 을 쓰지 않는다.** 브라우저 패널이 숨겨져 있으면 rAF 가 멈춰
하네스가 통째로 정지한다. `setInterval` 은 계속 돌므로 **타이머로 폴링**한다 (실측: 숨긴 상태에서도 틱 59ms).

## 잔존 상태 벡터 — **무효 스왑 뒤 남는 값** (2회차 실측)

원본 `dragEnd` 는 `squareIdBeingReplaced` 를 **유효 이동일 때만** 지운다 (`script.js:92~101`).
무효 이동 뒤에는 값이 남고, **드롭이 없는 다음 드래그**가 그 남은 값으로 판정한다.

**재는 법** — 시드를 고정하고 `setInterval` 을 막아 판을 얼린 뒤,
`dragstart`/`drop`/`dragend` 를 순서대로 디스패치했다 (드롭을 뺀 것이 「그리드 밖 드롭」과 같다).

| # | 순서 | **보드 변화** |
|---|---|---|
| **R1** | `dragstart(10)` → `drop(30)` → `dragend` (비인접) | **0칸** — 원본은 둘 다 되돌린다 |
| **R2** | R1 뒤 `dragstart(29)` → `dragend` (드롭 없음) · 잔존 30 은 `29+1` 이라 **유효**로 판정된다 | **0칸** |
| **R3** | 다시 R1 뒤 `dragstart(5)` → `dragend` (드롭 없음) · 잔존 30 은 **비인접** | **0칸** |

> **결론 — 잔존 값은 «관측 가능한 판 변화»를 만들지 않는다.**
> 유효로 갈리면 잔존만 지워지고, 무효로 갈리면 **이미 같은 값을 제자리에 다시 쓴다.**
> 그래서 세 갈래가 전부 0칸이다. **추론이 아니라 실측이다.**
>
> ⚠ 그래도 **잔존 자체는 그대로 옮긴다.** 「어차피 안 보이니 지우자」로 고치면
> 원본과 상태 기계가 갈리고, 다음에 원본이 바뀌면 어디가 어긋났는지 못 찾는다.

### 이 둘을 「미측정」에서 뺀 이유

| 항목 | 파리티로 재는 것 | 어떻게 닫혔나 |
|---|---|---|
| 타이머 | **감소 횟수와 종료 시점** — 「120에서 시작해 1씩 줄고 0에서 끝난다」 | 플로우 검사가 틱 인자를 1초씩 먹여 **0까지 몰고 종료 팝업이 뜨는 것**까지 센다 |
| 초기 자동 매치 | **「시작하자마자 점수가 오른다」는 사실** (원본이 초기 보드를 정리하지 않는다) | 재생 검사가 «드래그 없이 방치»했을 때 점수가 오르는 것을 센다 |

> ⚠ **벽시계 오차(1000ms 간격의 누적 드리프트)는 파리티 대상이 아니다.**
> 브라우저 타이머와 엔진 프레임의 «플랫폼 성질»이라 값이 같아질 수 없고, 같아야 할 이유도 없다.
> **점수 규모도 무작위라 값이 아니라 「오른다」가 사양**이다 —
> 얼마나 오르는지는 골든 벡터가 «규칙»으로 이미 못 박고 있다.
